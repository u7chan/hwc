# 操作と検証

見た目だけでなく、操作前後と入力中も一貫させる。[基礎仕様](foundations.md)、[レイアウト](layout.md)、[コンポーネント](components.md) と組み合わせて確認する。

## 状態とフィードバック

| 状態                 | 表現                                                                     |
| -------------------- | ------------------------------------------------------------------------ |
| 通常                 | 情報の優先順位に沿った文字・面                                           |
| ホバー               | hover 可能な入力装置だけに `raised`。選択中は選択の面を維持              |
| 押下                 | 操作可能な要素だけ不透明度 0.72                                          |
| 選択中               | 選択の面・名前とアイコンの強調・意味を持つ選択属性                       |
| フォーカス           | 3px のアクセント色の輪郭、外側へ 3px 離す                                |
| 入力枠内のフォーカス | 枠全体へ 2px のアクセント色の輪郭、外側へ 2px 離す                       |
| 無効                 | 無効時の面と文字、実行抑止、必要なら短い理由                             |
| 読み込み中           | 実際に待っている対象を示す。確定済みの情報まで理由なく消さない           |
| 空・未選択           | 状態の理由と、可能なら次の操作                                           |
| 失敗                 | 起きたことと、再試行など実行できる対応。入力を勝手に消さない             |
| 完了                 | 操作した場所で短く結果を伝える。実際に終わっていない処理を完了と呼ばない |

色と背景色の遷移は `120ms ease` を標準とする。移動や回転のアニメーションを必須の意味表現にしない。
`prefers-reduced-motion` ではトランジションを止め、スクロールを即時にする。
入力の内側の輪郭を消す場合は、枠全体のフォーカス表示を必ず残す。

## 開閉と遷移

- 開閉と項目への遷移を一つの曖昧な操作に混ぜない。開閉はボタン、遷移はリンクを基本にする。
- 開閉ボタンは `aria-expanded` を現在の状態に合わせ、`aria-controls` で対象と結ぶ。閉じた内容は画面だけでなく支援技術や Tab 移動からも除く。
- disclosure は閉じた状態で右向き、開いた状態で下向き。向きを変えるだけで開閉を伝えず、属性も更新する。
- 現在の項目、詳細見出し、内容、操作対象を一致させる。識別のためのデータと表示名を混同しない。
- 戻る操作とブラウザ履歴を確認する。詳細へ移動した後、狭い画面では見出しへフォーカスを移すなど、新しい文脈を認識できるようにする。
- 一覧へ戻ったときは、選択や開閉、必要なスクロール位置をむやみに失わせない。保持する範囲は対象の要件に合わせる。
- 開閉の都合で業務上の関係を組み替えたり、自動で別のグループを閉じたりしない。そうした動作が必要なら仕様として明示する。

## 入力

- プレースホルダーとは別にラベルを付ける。入力先が変わる画面では、現在の対象をラベルや見出しから常に識別できるようにする。
- 空白だけなど実行できない入力では送信を無効にする。無効条件は本来の操作の要件に合わせる。
- 複数行入力では Enter を改行として扱う。送信ショートカットを設けるなら Ctrl/⌘+Enter などとし、操作ヒントで知らせる。
- 日本語などの IME の変換確定で送信しない。キー操作を送信へ割り当てる場合は composition 中でないことを確認する。
- 対象を切り替えても別の対象へ下書きを混入させない。保存期間や再読み込み後の保持はデザインから勝手に追加しない。
- 送信中・成功・失敗を区別する。重複送信を抑え、消すべきタイミングが確定する前に入力を消さない。
- モックでは「プレビュー」などの表示で実処理との違いを示す。見た目のために認証・接続・保存の成功を装わない。

## アクセシビリティ

- 操作領域は縦横 44px 以上を標準とする。アイコン自体を大きくするのではなく、周りの余白を確保する。
- アイコンだけの操作には名前を付け、装飾アイコンは読み上げ対象から除く。ツールチップだけを名前の代わりにしない。
- 状態は色と記号と文言を組み合わせる。文字コントラストは基礎仕様の基準を満たす。
- Tab と Shift+Tab で論理順に進め、Enter と Space で標準の操作ができるようにする。フォーカスを閉じた領域や画面外へ置き去りにしない。
- 通常のフォーカス輪郭を消さない。遷移後の見出しへプログラムで移動した場合と、操作要素のキーボードフォーカスを混同しない。
- 状況通知には必要に応じて `aria-live` を使う。連続更新する本文全体を毎回読み上げさせない。
- 文字を 200% に拡大しても読めるようにし、重要な名前や操作を固定高で切り落とさない。
- タップ後の押下表示とキーボードフォーカスを残す。独自のタップ表示を使う場合だけブラウザのタップハイライトを抑え、ピンチによる拡大を禁止しない。
- 強制カラーや高コントラスト設定でも操作と選択が分かるようにする。色を固定してシステムの補正を妨げない。

## ブラウザでの確認

対象環境で使えるブラウザ自動化とスクリーンショットを用い、必要な点は実機で確認する。
このスキルは特定のテストフレームワークや実装ライブラリの追加を要求しない。

### 構造と見た目

- 狭い画面・広い画面・ブレークポイントの両側。標準構成なら 899px と 900px を比較する。
- 幅 320 / 375 / 390 / 768 / 1280px をストレス確認の目安にする。対象の対応幅が別にあればそちらも確認する。
- ライトとダーク、文字サイズ 200%、動きを減らす設定。
- 長い名前、長い補助情報、内容がゼロ件・一件・多数の場合。
- 横はみ出し、重なり、見切れ、意図しない多重スクロールがない。
- コンポーネントの色・文字・余白・角丸が仕様に一致する。

### 操作の流れ

- 一覧がある場合、開閉 → 選択 → 詳細 → 戻るを確認する。
- 名前、選択状態、詳細、操作対象が一致し、別の項目へ入力が混入しない。
- 設定やアカウントがある場合、入口、戻る、離脱までを確認する。
- 空入力、IME 入力、キー操作、無効状態、処理中、成功、失敗を確認する。
- マウスだけでなく Tab 移動とフォーカス、タッチ領域を確認する。
- 開閉状態や遷移に関するスクリプトエラーがない。

### 実機での確認

- 仮想キーボード表示時に入力欄と主操作が見え、本文をスクロールできる。
- safe area、横向き、ブラウザのツールバーが伸縮した場合も操作できる。
- デスクトップのエミュレーションだけで実機のキーボードや safe area を確認済みとしない。
- 確認した環境と未確認の点を分けて報告する。
