# ADR 0045: ターンが始まらない送信は TUI のコマンドとして履歴に残す

- Status: Accepted
- Date: 2026-11-08

## Context

[ADR 0013](0013-pi-session-chat.md) は、送信直後からセッションに user 発話が現れるまでの間、ローカルの pending を「送信中」として chat に出す。確定は「送信時点の最後の user 発話より後に新しい user 発話が現れたか」で判定し、ターン終了または 60 秒で打ち切る。[ADR 0016](0016-composer-command-chips.md) の `/new` と `/compact` は user 発話を残さないため、そもそも pending を積まない。`/compact` は代わりにローカルの控えを履歴に置く。

pi の TUI には、モデルへ渡さず TUI 内だけで処理する入力がある。`/reload`、`/model`、`/settings` などのスラッシュコマンドと、`!` で始まる bash がそれにあたる。これらはセッションに user 発話を書かず、Herdr の `agent_status` も `working` にしない。Web から `/reload` を送ると、TUI では再読み込みが走るのに、hwc は確定しない「送信中」を 60 秒間出し続けていた。

送信したコマンドをすぐ消すと、何を実行したかが Web に残らない。セッションに無いものを履歴に出すのは正と食い違うが、`/compact` の控え（ADR 0016）と同じく、その画面で送った操作としてローカルに残す価値がある。

hwc は各 CLI の TUI コマンドの一覧を持たない（ADR 0016）。スラッシュで始まる文字列をコマンドとみなす判定は、pi が未知の `/...` を本文としてモデルへ渡す場合を誤る。`!` も取りこぼす。

## Decision

- 送信が成功したあと、送信時に idle だった pending について、Herdr の `agent_status` が `working` にならないまま 3 秒経ったら、コマンドの控えに切り替える。消さない
- コマンドの控えは、`/compact` の控えと同じ見た目（等幅・raised 面・時刻）で chat に出す。コピーは付けない
- 控えは送信したときに会話へあったメッセージ数を `after` に持ち、その位置へ差し込む。末尾へ足すだけだと、次の発話が届いたときにコマンドがその後ろへ回る
- 控えは、セッションに同じ文言の user 発話が現れたときだけ置き換える。位置だけで判定すると、次の通常のメッセージでコマンドの控えまで消える。CLI が本文を展開する prompt template では文言が変わるため、控えは残る（送った `/name` の記録として扱う）
- 送信時に `working` だった pending は従来どおりターン終了で畳む。60 秒の打ち切りはコマンドの控えには適用しない
- 猶予は pending を積んだ時刻（送信が通った後）から測る。POST が遅いときに、入力が届く前の控えを作らない
- 判定と並びは純関数（`idleEchoExpired` / `chatRows`）にし、component の外でテストする
- コマンドの一覧・スラッシュの構文・`!` の有無は見ない。TUI がどう解釈したかは `agent_status` だけを材料にする
- 控えはリロードやペイン切り替えで消える。永続化しない。畳んだことを notice では知らせない

## Consequences

- `/reload`、`/model`、`!ls` など、user 発話を残さない入力は、送信直後の数秒だけ「送信中」に見え、その後はコマンドの控えとしてその画面の履歴に残る
- 控えはセッションの会話ではない。リロードやペイン切り替えで消え、別の端末や TUI には出ない。会話の正がセッションであることは変えない
- 入力が TUI に届かなかった場合もコマンドの控えになる。送信は Herdr の受理までしか保証しない（[ADR 0002](0002-herdr-socket-integration.md)）
- Herdr の `working` 反映が 3 秒を超えた通常のメッセージは、一度コマンドの控えになり、セッションに同じ文言が現れた時点で置き換わる。CLI が本文を展開する prompt template では文言が変わるため、控えと展開後の発話が並ぶ
- 3 秒は `agent_status` がエージェントのイベントで動く前提の値。状態の報告が遅いエージェントを足すときは見直す
- TUI のコマンド実行結果（`Reloaded ...` など）は Web に出ない。端末出力を会話に混ぜない ADR 0013 の判断を変えない

## Verification

- unit で、猶予の境界、コマンドの控えが同じ文言でだけ置き換わること、送信位置への差し込みと送信順を確かめる
- 架空 Herdr の E2E で、`/reload` がセッションに user 発話を増やさず、控えとして履歴に残ることを確かめる
