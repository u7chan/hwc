# ADR 0042: 1 枚表示の見出しに、ブランチの PR 番号を出す

- Status: Accepted
- Date: 2026-11-08

## Context

[ADR 0019](0019-pane-row-content.md) で、1 枚表示の見出しは、一覧が隠れる狭い画面に限りブランチを出すことにした。スマホでペインを開いたとき、いまどの作業にいるかはこの行で分かる。

一方、ブランチに対応する PR は hwc から見えない。レビュー結果を確認するときは、会話の中のリンクを探すか、ブラウザで GitHub を開く必要がある。ワークツリーはタスクごとに作って捨てるので、「このワークツリーの PR」は作業の現在地そのものになる。

ブランチは `.git/HEAD` の読み取りで足りるが、PR は GitHub にしか無い。`gh` の起動と認証、ネットワークを伴うため、同じ層には置けない。

## Decision

- PR の番号を、狭い画面の 1 枚表示の見出しにだけ、ブランチの右へ `#123` として出す。分割セルと広い画面には出さない（広い画面は一覧がブランチを持っている）
- 表示するのは open の PR だけ。複数あれば先頭の 1 件。merged / closed は出さない
- PR が無い・引けないときは何も出さない。行の見た目は今までと同じにする
- 問い合わせは BFF が `gh pr list --head <branch> --state open --limit 1 --json number,url` をチェックアウトで実行して行う。ブランチ名は remote に無いことがある（Herdr の自動生成名は push するまで PR にならない）
- 状態のスナップショットには載せない。`GET /api/workspaces/:id/pull-request` で、見えているスペース 1 件だけを求めたときに引く
  - 状態は Herdr のイベントごとに取り直している。ここに gh の待ちを混ぜると、一覧全体が gh 待ちになる
  - 取得できなくても 200 で `null` を返す。失敗・期限切れ・未認証を 5xx にしない
- BFF で `(checkoutPath, branch)` ごとにキャッシュする。ヒットは 60 秒、空の結果は 120 秒
  - PR の無いブランチの方が多い。ペインを開き直すたびに gh を起動しない
  - 空の結果には、gh の失敗も含める。表示はどちらもチップ無しで、区別しても利用者に伝えることがない
- `checkoutPath` はブランチを読むのと同じ解決（`checkoutPaths`）を共有する。読む場所と PR を引く場所を揃え、見出しのブランチと PR が食い違わないようにする
- `gh` の応答の URL は `https://github.com/<owner>/<repo>/pull/<n>` だけを受け付け、番号と一致することを確かめてから `<a href>` に入れる
- チップは `flex: none`、縮むのはブランチ側。ブランチが長いときは末尾が省略される
- タップ領域は見出しの高さ（32px）いっぱいにする。`--tap`（44px）に広げると、見出しの下の会話領域に重なる
- リンクは新しいタブで開く（`target="_blank" rel="noreferrer"`）。Markdown のリンクと同じ扱い

## Consequences

- 見出しを開いた直後はチップが無く、取得できた時点で現れる。そのときブランチの省略位置が一度だけ動く
- PR を開いた直後は、最大でキャッシュの TTL ぶん古い。PR が無い間は 120 秒、後から開いた場合は次に開き直すまで出ないことがある
- fork 運用で upstream にだけ PR がある場合、`gh` はチェックアウトの remote を見るのでチップが出ない
- ブランチが remote に push されていなければ出ない。merge 済みの PR も出ない
- `gh` が無い・未認証・オフラインの環境では、常にチップが出ない。エラーは表示しない
- 状態の取得経路は変わらない。gh が遅くても一覧と会話は止まらない

## Alternatives

- **一覧の見出し行に出す**: 行が既に展開のトグルボタンで、リンクを中に置けない。行ごとに lookup が要り、狭い画面ではタップ対象が増える
- **状態に載せる**: refresh のたびに全スペースぶん gh を起動することになる。イベント駆動の取り直しと噛み合わない
- **ブランチ名を先頭省略してチップを確保する**: `direction: rtl` のハックになり、長押しコピーと選択の挙動を崩す。チップは flex で潰れないので、確保のためには要らない
- **GitHub API を直接叩く**: トークンの保管と更新を持つことになる。`gh` の認証をそのまま使える方が、設定も失敗時の扱いも小さい
- **表示対象に merged / closed を含める**: どれを出すかの規則が増える。レビューを見に行く用途では、open だけ分かれば足りる
