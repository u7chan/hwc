# ADR 0056: 入力欄からプロジェクトを選び、ペインの cwd からの相対パスを入れる

- Status: Accepted
- Date: 2026-11-10

## Context

モノレポでは、どのプロジェクトを直すのかを指示の最初に書く。CLI の TUI では `@` などの補完でパスを選べるが、hwc は TUI の編集操作を肩代わりしていない。`pane.send_input` は完成した文字列を bracketed paste として流すだけなので、TUI の補完は使えず、候補も見えない。

全ディレクトリを列挙する方法は、モノレポでは候補が多すぎる。パッケージ管理ファイルがあるディレクトリをプロジェクトとみなせば、モノレポでも意味のある集合になり、言語が混在していても候補を出せる。

相対パスの基準は、スペースのチェックアウトではなく**ペインの cwd（エージェントの起動位置）**にする。エージェントは `./server` をその cwd から解決するため、スペースの起点を使うと、ペインの cwd とずれたときに別の場所を指す。

ペインの cwd がリポジトリのサブディレクトリのとき、兄弟プロジェクトは候補に出さない。エージェントが `server` にいるなら `client` は `../client` になり、`./` で始まる相対パスだけを入れたいという前提を崩すため。全体を見たいときはリポジトリルートで開いたペインを使う。

## Decision

### 検出

- パッケージ管理ファイルがあるディレクトリをプロジェクトとする。対象は次の表に固定し、`src/server/projects.ts` を正とする
  - Node / Bun: `package.json`
  - Python: `pyproject.toml`, `setup.py`
  - Rust: `Cargo.toml`
  - Go: `go.mod`
  - Java / Kotlin: `pom.xml`, `build.gradle`, `build.gradle.kts`, `settings.gradle`, `settings.gradle.kts`
  - Ruby: `Gemfile`, `*.gemspec`
  - PHP: `composer.json`
  - .NET: `*.csproj`, `*.fsproj`, `*.vbproj`
  - Swift: `Package.swift`
  - Dart / Flutter: `pubspec.yaml`
  - Elixir: `mix.exs`
  - Deno: `deno.json`, `deno.jsonc`
- `*.sln`、`CMakeLists.txt`、`Makefile`、`flake.nix`、`requirements.txt`、lockfile 単体は入れない。ソリューション・ビルド定義・共有の依存一覧は、プロジェクトの位置を表さない
- `git ls-files -z --cached --others --exclude-standard` をペインの cwd で実行し、basename が表に一致したものを dirname で重複排除する。`.gitignore` 済みの生成物に加え、`node_modules`、`.venv`、`target`、`vendor`、`dist`、`build` などは明示的に落とす
- **cwd 自身は候補にしない**。エージェントは既にそこにいるので、`.` や `./` を本文へ入れる意味がない
- 並びは深さの昇順、同じ深さはパスの昇順。300 件を上限にし、超えたら `truncated` を立てる。結果は cwd ごとに 30 秒キャッシュする
- 走査は `Bun.spawn` に `env` を明示して git を呼ぶ。E2E の偽 git を PATH で差し替えられるようにするため

### API

- `GET /api/panes/:id/projects` を足す。返すのは `{ projects: [{ name, path }], truncated }`。`name` はディレクトリ名、`path` は cwd からの相対パス
- 会話を持つペインだけを受ける。シェルペインは 404 `no_chat`。ペインが消えていた場合は既存の `paneFailure` に任せる
- cwd は `store.workspaceRoot()` ではなく `panes.directory()` から取る
- 走査に失敗したら 502 `projects_unavailable`。空の一覧と失敗を同じ応答にしない

### 入力欄

- - のメニューから「プロジェクトを選ぶ」を開き、検索付きのダイアログで選ぶ（[ADR 0055](0055-composer-add-menu.md)）
- 検索は名前の完全一致、前方一致、部分一致、パスの前方一致、パスの中間一致の順に順位を付ける。同じ順位はサーバーが返した順を保つ
- 選択すると `./<path>/` をカーソル位置へ入れる。前後に文字が接しているときは空白を 1 つ足し、選択範囲があれば置き換える。ダイアログを閉じた後に本文へフォーカスを戻し、カーソルを挿入末尾へ置く
- パスはチップにせず本文の一部にする。送る内容が見え、そのまま編集できるため
- 挿入は文字を打ったときと同じ規則でチップを扱う。`new` は解除し、`compact` の指示は残す
- 一覧が空のとき、検索に一致しないとき、取得に失敗したときを分けて表示する。失敗には再試行を出す

## Consequences

- pane の cwd がリポジトリのサブディレクトリなら、兄弟プロジェクトは出ない。`client` を選ぶにはリポジトリルートのペインを使う。これは相対パスを `./` で保つための制約
- マニフェストの無いプロジェクト、untracked の空ディレクトリ、サブモジュール内のプロジェクトは出ない。git 管理外のペインでは常に空になる
- test fixture や examples に `package.json` があると候補に混ざる。深さ順と検索で実用上は足りるが、除外規則は持たない
- マニフェストの追加は 1 行とテスト 1 つで済む。ただし表を増やすほど、実際にはプロジェクトでない設定ファイルを拾う可能性も増える
- キャッシュは 30 秒。マニフェストを追加した直後は、再読み込みか TTL 経過まで候補に出ない
- LAN に認証無しで公開しているため、ペインの cwd 配下のディレクトリ名は誰でも列挙できる。チェックアウトの外は走査しない
- 入れるのはパスの文字列だけなので、エージェントがそのディレクトリを読む保証はない。画像添付と同じく、内容の注入はしない
- `./` はエージェントの cwd 基準で解決される。エージェントが起動後に cwd を変える運用には対応しない

## Alternatives

- **全ディレクトリを列挙する**: マニフェストの無いフォルダも選べるが、モノレポでは候補が多すぎ、モバイルの一覧と検索が重くなる
- **ワークスペース定義を読む**: `pnpm-workspace.yaml` などを読めば精度は上がるが、言語・ツールごとの規約を hwc が追うことになる。マニフェストの有無で十分
- **絶対パスを入れる**: cwd に依存せず確実だが、スマホでは長すぎて本文が読みにくい
- **選択をチップとして持ち、送信時に展開する**: 見た目は短いが、チップの状態と本文の両方を管理することになり、送る内容が見えなくなる
- **TUI の補完をキー入力で使う**: 候補を hwc が見えず、矢印キーと確定キーを送る汎用操作が必要になる。入力契約を変えない範囲では実現できない
- **cwd 自身を「このディレクトリ」として含める**: 既にいる場所を選ぶ意味が薄く、`.` を本文へ置く不自然さがある
