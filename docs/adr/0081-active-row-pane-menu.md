# ADR 0081: アクティブ一覧の行からペインのメニューを開く

- Status: Accepted
- Date: 2026-11-13
- Revises: [ADR 0017](0017-active-agents-view.md) の「アクティブの行にはメニューを出さない」、[ADR 0021](0021-pane-close.md) の「アクティブの行には足さない」

## Context

アクティブ一覧の行は状態を読むための面で、閉じる入口は詳細のペイン見出しと `すべて` ツリーの行メニューだけだった。非ワークツリーのスペースは `ワークツリーを削除` も持たないため、片付けたいエージェントのために詳細を開くか、`すべて` へ切り替えてツリーをたどる必要があった。アクティブ一覧は待機中のエージェントも並べるので、この行から直接片付けられることに意味がある。

帯のメニューに足す案も検討したが、同じスペースに複数のエージェントが居ると、どのペインを閉じるかを選べない。行の近くに無い入口でもある。行に常設の × を置く案は最短だが、取り消せない操作が常に見え、確認の前に触れてしまう。

行のメニューはツリー・詳細と同じ [PaneMenu](../../src/client/PaneMenu.tsx) と [CloseConfirm](../../src/client/CloseConfirm.tsx) を使える。BFF の `POST /api/panes/:id/close` と `/exit` も既にあるため、入口だけを足せばよい。

## Decision

- アクティブ一覧の各ペイン行の右端に `…` を置き、ツリーと同じペインのメニューを開く。入口は全帯に出す。非ワークツリーだけに限定すると、同じ見た目の行でも帯によって操作の有無が変わる
- 行を開くボタンとメニューボタンは分ける。メニューを開くだけでは行の選択・既読（`agent.focus` の保留）を変えない
- メニューの内容は変えない。最後のペインは `エージェントを終了`、複数ペインは `ペインを閉じる`。確認、API、失敗時の扱いは [ADR 0021](0021-pane-close.md)・[ADR 0029](0029-preserve-last-pane.md) のまま
- 押下領域は 44px を確保する。ポインタの画面では hover / focus / 選択中の行だけ `…` を出し、触れる画面では常に出す
- 選択中・スロット位置の枠は行全体に掛ける。`…` を押しただけでは枠も動かさない
- 幅が足りない行ではタブ名、次に時刻を省く。名前と 44px の操作領域を残す。タブ名は読み上げには残す（視覚的に隠すだけ）
- メニューは一覧のスクロールで閉じる。既存の `Menu` の `closeOnScroll` を使う

## Consequences

- 非ワークツリーの帯でも、アクティブ一覧から直接エージェントを終了できる。ワークツリー帯では「ワークツリーを削除」と併存する
- 行の右端に 44px の操作領域が増えるため、狭い行ではタブ名と時刻のどちらかを省く。タブ名を先に隠し、時刻は状態の手掛かりとして残す
- メニューを開いても選択と既読は動かない。行を開いて離れたときに既読を送る規則は変えない
- 非ワークツリーに限定しないため、ワークツリーの行にも同じ入口が出る。帯のメニューの「ワークツリーを削除」はスペース全体、行のメニューはペイン単位の操作として残る
- `すべて` のツリー・詳細のメニューと同じ項目になる。アクティブの行だけ項目を減らすと、同じペインの操作が入口ごとに変わる

## Alternatives

- **帯のメニューに足す**: 複数エージェントのとき対象が曖昧で、行から遠い。非ワークツリーだけに限定できる点だけが利点
- **行に × を常設する**: 最短だが、取り消せない操作が常に見え、誤タップしやすい。確認の前に触れてしまう
- **非ワークツリーの帯だけに足す**: 同じ行の見た目と操作が帯の種類で変わり、覚えられない。ワークツリーでもエージェントだけ終了したい場面は同じ
- **長押しでメニューを開く**: 入口が見えず、触れる画面で発見できない
- **`…` をメニューではなく閉じる専用にする**: ペイン ID のコピー・新しいペインなど、ツリーと同じ操作を入口ごとに分けることになる
