# ADR 0084: 新しいペインのエージェント起動は作成の応答後に回し、起動中も入力を受け付ける

- Status: Accepted
- Date: 2026-11-14
- Amends: [ADR 0027](0027-new-pane-agent.md), [ADR 0074](0074-created-pane-starting.md), [ADR 0078](0078-starting-pane-mask.md)

## Context

ADR 0027 のダイアログは split → `agent.start` → rename を 1 リクエストで待ち、起動が終わるまで閉じられない。ADR 0074 / 0078 は起動待ちの間、入力欄そのものを隠す。スマホでは、モデルの再検証と `agent.start` の待ち（最大 30 秒 + シェル準備 5 秒）の間、何も打てない。プロンプトは起動前に決まっていることが多く、待つ理由がない。

分割の応答にペイン id が要る。起動中はスナップショットの `pane.agent` が null なので、入力欄をエージェント仕様にするには、ダイアログで選んだ内容をクライアントが持つ必要がある。

## Decision

- ダイアログはペインができた時点で閉じる。分割は `{ name, agent: null }` の split（layout → split → rename）まで。既存のシェルからの起動は待たない
- 起動は `POST /api/panes/:id/agent` に回す。クライアントは起動意図 `{ paneId, agent, model, effort, waitForShell }` をペイン id ごとに持ち、新しいペインがスナップショットに現れてから 1 回だけ要求する。分割の応答より先に BFF の状態が届かず、その間は BFF もペインを知らないため
- `POST /agent` は `waitForShell` を受ける。分割直後のペインだけ true にし、シェルが起動を受け付けるまで BFF が待つ
- 起動意図があるペインは、スナップショットの `pane.agent` が null でも入力欄をエージェント仕様にする。`$` を出さず、placeholder を「メッセージを入力」にし、「エージェントを起動」を出さない。テキストは入力できる
- 準備ができるまで送信・添付・コマンド・引用・停止を出さない。送信ボタンは無効のままスピナーを出す。送信の入口（Enter・form・チップ）はボタンの disabled に頼らず塞ぐ
- 待ちの終わりはスナップショットで決める。エージェントが検出され、会話を読むエージェントは `pane.chat` が true、読まないエージェントは検出 + settle。上限は起動応答から 10 秒。過ぎたら「起動を確認できませんでした」へ移す
- 起動要求の結果は手がかりにだけ使う。`pane.agent` が現れたら失敗や timeout の表示を捨てる。起動意図は ready になったら消す。残すと、後で `/exit` してシェルに戻ったときに失敗表示が蘇る
- 失敗はダイアログではなくペイン内の行に出す。理由と「再試行」「シェルとして使う」を出し、入力欄はエージェント仕様のまま、送信は閉じたままにする。シェルに戻すのは利用者が選んだときだけ。打った自然文のプロンプトをシェルコマンドとして送らないため
- 本文は起動待ちの間スケルトンのまま（ADR 0078）。失敗・不明になったら端末出力を出す
- 入力欄のモデル表示は、会話が読めるまでは起動意図の値を使う（ADR 0033 の補いの前）
- フォーカスは起動意図のあるペインを開いたときに一度だけ入力欄へ移す。iOS は非同期の後にキーボードを出さないことがあるので、焦点だけを合わせる

## Why not

- **split の前にダイアログを閉じる**: ペイン id が無く、入力先も下書きのキーも決まらない
- **BFF に起動ジョブと状態を持たせる**: 待ちの正はスナップショットで足りる。ジョブの寿命・再取得・失敗の配信を増やす割に、この画面だけが使う
- **失敗時にシェル入力欄へ戻す**: 打った自然文がシェルコマンドとして送れる
- **準備完了を待たずに送信を予約する**: 準備完了の判定はスナップショットと settle の近似で、早すぎる送信はシェルに文字が届く
- **楽観的なペインを先に描く**: split は数百 ms で返る。スナップショットを正とする分割ビューと二重の状態になる

## Consequences

- 起動中も打てるが、送信できるのは準備後。長い起動ではスピナーが数十秒残る
- 一覧とタブでは、起動が終わるまでそのペインがシェルとして見える。名前は split で付く
- 起動の途中で再読み込みすると起動意図は失われる。ペインはシェルかエージェントの実態で表示され、やり直しはメニューから
- ダイアログの失敗表示は、ペインができる前の失敗（上限・Herdr 不達・結果不明）だけになる。起動の失敗はペイン側
- ワークツリーの作成は root pane ができるまでダイアログを待ち、起動はサーバーが済ませる。その結果は started の起動意図として同じ入力欄の待ちに入る。作成と起動を分ける改訂は別に行う
