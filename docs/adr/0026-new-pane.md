# ADR 0026: 新しいペインは詳細の見出しから作り、タブ内 4 枚まで自動で並べる

- Status: Accepted
- Date: 2026-11-04

## Context

hwc にはペインを作る手段が無かった。新しい作業を始めるには Herdr TUI で分割するか、エージェントに指示する必要がある。

Herdr は `pane.layout` でタブの領域と各ペインのセル矩形を返し、`pane.split` で 1 枚増やせる。`pane.split` の params は `target_pane_id` / `direction` / `ratio` で、応答は `pane_info`、既定ではフォーカスを変えない。分割は `pane.created` を流すので、BFF のイベント経由の `store.refresh()` と SSE のスナップショットで表示が追随する。

スマホから操作する以上、分割方向を毎回選ばせたくない。一方で、狭いペインは TUI の幅に依存する UI を壊す。Claude の `ask_user` の応答が幅不足でできない事例が観測されている。並びは hwc 側で決め、追加できる枚数にも上限を置く。

## Decision

- 入口は詳細のペイン見出しの「…」メニューの「新しいペイン」だけに置く。タブバーと一覧の行メニューには足さない（ADR 0021 と同じく、操作は詳細に寄せる）
- 作るのはシェルペインだけにする。エージェントを選んで起動するのは別スコープ
- 分割方向はユーザーに選ばせない。BFF が `pane.layout` を読み、次の規則で 1 回の分割を行う
  - 最大面積のセルを対象にする。同面積ならレイアウト順で先のセル
  - `ratio` は 0.5
  - 方向は、セル比 0.48 で幅・高さをピクセル相当に直し、分割後の縦横比が目標 1.4 に近い方。同等なら右（0.7–2.6 は Herdr の pane-layout と同じ目安で、半分に割る 2 択では近い側がこの範囲へ寄る）
  - 結果として、1 枚からは横並びか縦積み、3 枚は L 字、4 枚で 2x2 になる
- タブ内 4 枚を上限にする。TUI 側で作ったペインも含めた、そのタブの全ペイン数で数える
  - クライアントは 4 枚のときメニュー項目を無効表示にし、「このタブは 4 ペインまで」と添える
  - BFF でも 409 `pane_limit` で拒否する。画面が古い場合や同時操作の取りこぼし用
- BFF に `POST /api/panes/:id/split` を足す。`application/json` 以外は 415、スナップショットが無ければ 502、BFF の状態にペインが無ければ 404、4 枚なら 409。Herdr の失敗は focus / close と同じ規則（404 / 400 / 502）。成功は `{ paneId }`
- 応答でスナップショットを取り直さない。状態は `pane.created` のイベントに任せる。focus / close と同じ理由で、成功した分割が再取得の失敗で 502 にならないようにする
- `pane.split` は既定の `focus: false` のまま呼ぶ。TUI を見ている人のフォーカスをスマホから奪わない
- cwd は指定しない。Herdr の `terminal.new_cwd` を分割元に追随させる
- 作成後は新しいペインを開く。応答の `paneId` を保持し、そのペインがスナップショットに現れてから選択する（先に選ぶと一覧が一瞬出る）
- 作成は確認を挟まない。失敗（BFF 停止・Herdr エラー・タイムアウト）はメニュー内に 1 行出す
  - 送信中は項目を「作成中…」で無効にし、in-flight の ref でも二度押しを防ぐ
  - クライアントの期限は 8 秒。abort は失敗として扱う
- 404（BFF の状態に無い / Herdr が `pane_not_found`）は失敗として扱う。close の「404 = 成功」とは逆で、作成の目的（新しいペイン）は達していない
- ペインの並べ替え・移動、タブ・ワークスペースの作成、5 枚以上、最小幅を保証するガードは持たない
- ADR 0017 の「操作は詳細に寄せる」は、破壊的な close だけでなく作成にも適用する。ツリーの行とタブバーは状態を見る面のままにする

## Consequences

- 3 枚の時点では L 字になる。2x2 の 1 マスが縦に伸びた形で、幅を半分より狭くしないための結果
- 分割対象はメニューを開いたペインとは限らない。タブ単位の操作として最大のセルを選ぶ
- タブ自体が狭いと、4 枚上限でも 1 枚あたりの幅は足りない。`ask_user` の幅問題は Herdr ウィンドウ側の制約として残る
- セル比 0.48 は Herdr の pane-layout と同じ近似で、実際のフォントやセル寸法とはずれる。比率が変われば方向の判定も変わる
- 作成するペインはシェルなので、一覧の「エージェント」スコープには出ない。「すべて」では出る
- 1 回の作成で `pane.layout` と `pane.split` の 2 往復になる。セルの形はスナップショットに無いため、レイアウトを都度読む
