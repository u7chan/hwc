# ADR 0090: ペインの中にチェックアウトのファイルツリーを置く

- Status: Accepted
- Date: 2026-11-16
- Revises: 2026-11-16 に広いセルではチャットの左に並べる
- Revises: 2026-11-17 にテキストと HTML をチャット領域のプレーン表示で開く
- Revises: 2026-11-17 に開閉の動きを付ける
- Revises: 2026-11-17 にツリーを並べるときの見出しを 2 列にする
- Revises: 2026-11-17 に Markdown を描画して開くようにした（[ADR 0093](0093-file-preview-markdown.md)）
- Revises: 2026-11-17 に並べる側を「表示」の設定で選べるようにした
- Revises: 2026-11-17 にツリー側の見出し列に選択中のパスを出した

## Context

hwc でファイルを開く入口は、エージェントの本文に書かれたパス（チップとリンク）だけだった（[ADR 0051](0051-agent-html-preview.md)、[ADR 0084](0084-relative-path-links.md)）。会話に出てこないファイルを見るには、ターミナルのペインで `ls` を打つしかない。

ほしいのは、チェックアウトの構造を地図として見て、気になったファイルを既存の見せ方で開くこと。ソースを読むためのエディタではなく、リファクタ候補や置き場所を探すための一覧で、人間が見るのは結果と地図という前提に立つ。

置き場所は、対象ペインの内側の右か左という案から始めた。しかし hwc のセルは detail の 1/1〜1/4 で、右に 280px を常設できるのは、サイドバーを含めて画面幅が約 1750px を超えるときだけ。スマホと分割セルでは、同じ機能を全幅表示に切り替えることになる。

最初は、ツリーを会話の上に重ねる形で実装した。会話をアンマウントせず、スクロール位置と追従を保つため。しかし広いセルでは会話とツリーを同時に見たいという要求があり、幅が足りるセルだけ左に並べることにした。狭いセルでは従来どおり重ねる。同じ機能に 2 つの表示を持つが、切り替えはセルの実幅だけで決まり、状態は 1 つ。

並べる側は左に固定していたが、ツリーをどちらに置きたいかは、本文と一覧のどちらに視線を置くか、一覧の幅や位置、利き手で変わる。左に固定すると、ツリーを開くたびに本文が右へ寄り、行の頭の位置が動く。並べる側だけは端末ごとに選べるようにする。狭いセルでは重ねるので、選んだ側が効くのは広いセルだけ。

## Decision

### 置き場所

- ペイン見出しのファイルアイコンで開閉する。広い画面では「ファイル」のラベルを添え、狭い画面とセルではアイコンだけにする。開いている間は押下状態（accent）にし、戻りも同じアイコン。ツリー専用のヘッダーは置かない
- セルの胴（ペイン見出しと入力欄の間）の実幅が 680px 以上のときは、ツリーを会話の左右どちらかに 260px で並べる。どちらにするかは「表示」の設定で選び、既定は左。会話と入力欄は反対の列に揃え、ツリーは入力欄の下まで伸ばす。会話は生かしたままなので、スクロール位置・追従・画像の読み込みは保たれる
- ツリーを並べるときは、ペイン見出しも胴と同じ 2 列にする。ツリーの側の 260px は、選択中ファイルの根からのパスを出す場所にする。ペイン名・ブランチ・操作は会話の列に寄せ、区切り線はツリーの側に引き、タブ帯の下から胴の下端まで通して列の境目を全高で見せる
- 見出しのパスはツリーの見出しそのものとして読めるよう、モノスペースの補助文字で出す。未選択なら何も指していないので空のままにする。長いパスは列の幅に合わせて先頭を `…` で置き換え、末尾のファイル名と直近のフォルダを残す。文字数ではなく表示幅で詰めるので、全角を含むパスでも末尾が残る。全文は `title` に残し、コピーはプレビュー見出しの既存の操作に任せる
- 並べる側は端末ごとの見え方なので、テーマや分割の好みと同じく `localStorage` に置き、BFF には送らない。選ぶとその場で並びが入れ替わり、ペインを開き直しても保つ
- 狭いセルでは、ツリーを会話の上に絶対配置で重ね、会話のスクロール領域に `inert` と `aria-hidden` を付ける。入力欄は残る
- 切り替えはウィンドウ幅ではなくセルの実幅で行う。サイドバーの幅と分割の枚数で使える幅が変わるため。260px を引いても本文に 420px 残る幅を閾値にする（`TREE_SIDE_MIN_WIDTH`）
- チャットを持たないシェルのペインには出さない。開くファイルは会話と同じ `/preview` と `/files` の経路を使い、どちらもペインのチャットを要求するため。配信を全ペインへ広げるかは別の判断にする

### 開閉の動き

- 開くときは、面を 160ms でフェードし、中身を並べた側から 8px 収める。狭いセルの重ね表示では会話とのクロスフェードになり、広いセルの並べ表示では空いた列に一覧が差し込まれる
- 幅（260px）は補間しない。開いた瞬間に 1 フレームで確定させ、本文の折り返しは 1 回だけやり直す。幅を動かすと本文が毎フレーム再折り返しして文字が揺れ、長い端末出力では重い
- 閉じるときは 120ms でフェードし、store の close をその分だけ遅らせる。閉じている間は一覧を `inert` にして、消えていく行を押せないようにする
- 見出しの区切り線もツリーと同じ 160ms（閉じは 120ms）でフェードし、開閉と一緒に出入りする
- 動きは開閉操作のときだけ流す。セルの実幅が 680px をまたいだときと、ペインを切り替えて戻ったときは再生しない。動きを減らす設定では開閉とも待たずに切り替える

### 一覧

- 根はそのペインのワークスペースのチェックアウトだけ。`/tmp` と `HWC_PREVIEW_ROOTS` は出さない。エージェントが `/tmp` に書いたものは、会話のチップが既に拾う
- 表示するのは `.git` 以外の全エントリ。ドットファイルも出す。中身を配る形式は ADR 0084 の allowlist（拡張子なしと `.env` 系以外のドットファイルを含む）と `.env` ブラックリストのままで、開けないファイルは淡色で押せない行にする。ツリーに穴を空けないため
- 子は開いたときにだけ 1 ディレクトリずつ取る（遅延）。折りたたんでも取得済みの子は保持し、開き直しでは取り直さない
- フォルダの開閉は高さ 160ms で動かし、シェブロンも 90 度回す。子は折りたたみ中も DOM に残してクリップし、再展開では取得も描画もしない。読み込みが終わるまでは高さ 0 のままにし、届いてから開く。動きを減らす設定ではアニメーションを切る
- 1 ディレクトリ 200 件で切り、`total` と `truncated` を返して画面に 1 行出す。ディレクトリ優先・名前順（大文字小文字を無視し、同じなら表記で決める）
- サイズは出さない。ツリーは名前と構造だけにし、サイズは開いたファイル側で確認する（未実装）。行数・サイズ順・検索・ソート切替も持たない
- 絶対パスは返さない。名前は根からの相対パスだけ（[ADR 0041](0041-agent-message-images.md)）
- `realpath` で根の配下を確かめる。根の外を指す symlink は名前だけ返し、展開・open をさせない。壊れたリンクも名前だけ残す。根からの相対パスに `.git` セグメントを含むものは、一覧にも配信にも出さない。`.git` を指す symlink は名前だけ残す
- 全体を歩く API は作らない。無視規則（`node_modules`、`dist` など）と件数上限をサーバーに持つことになり、リポジトリごとの正解も変わる

### 状態

- 開閉・展開・取得済みの子はペインごとにクライアントの store が持つ。セルはペイン切り替えやプレビューでアンマウントされるため、コンポーネントの寿命から切り離す（添付チップと同じ）
- 選択中のファイルは一覧とは別に store が持つ。ツリーを閉じてもプレビューは残し、ペインが消えたら捨てる
- プレビューやタブ切り替えから戻ったときは、同じ開閉で戻る。スクロール位置は先頭に戻る
- ツリーを閉じたら一覧の状態は捨てる。開き直しがそのまま取り直しになる。選択中のファイルは残す。watch と手動更新は持たない
- ペインがスナップショットから消えたら状態も捨てる

### 開き先

- テキストと HTML は、チャット領域にプレーン表示する。会話の DOM は残したまま上に重ね、入力欄とツリーはそのまま使える。上部にファイル名と「会話に戻る」を置き、別のファイルを選ぶと差し替える
- 狭いセルでは、ファイルを選んだ時点でツリーを閉じる。ツリーが会話を覆ったままではプレビューが見えないため
- 狭いセルで開いたときは「会話に戻る」へフォーカスを移す。広いセルでは選択した行のフォーカスを残し、閉じたらツリーの「ファイル」ボタンへ戻す
- 内容は `?raw=1` の既存の配信を使う。HTML もまずはソースをプレーン表示し、レンダリング済みのプレビューは会話のチップに任せる
- 先頭 256KB まで表示し、超えたら注意と全文へのリンクを出す。10MB をそのまま DOM に置くとスマホで重い
- 本文には行番号を添える。行番号と本文は同じ文字寸法の `pre` を横に並べ、折り返さずに横スクロールする。行ごとの要素を作らず、数万行でも軽くする
- プレビュー中だけ、推論の帯との境界に 1px の区切りを出す。通常会話では帯と本文を同じ面のままにする
- バイナリは内容を表示せず、中央に「バイナリファイルのため表示できません」を出す。NUL の判定は配信時とクライアントの両方で行う
- 画像は既存の拡大ダイアログ。URL はプレビューの配信 URL を使う（`no-store` なので版は要らない）
- プレビュー中に新しい返答が届いたら、「会話に戻る」に小さなバッジを出す。会話に戻ると消える。自分の送信では出さない
- 広いセルでは開いたまま。狭いセルではファイルを選んだ時点で閉じ、開き直すとルートから

## Consequences

- 会話に出てこないファイルを、スマホと狭いセルでは重ねて、広いセルでは並べて辿れる。どちらも同じツリーで、状態は 1 つ。整形・検索・編集は持たず、プレーン表示だけを持つ
- テキストを開いても新しいタブは増えない。会話は DOM に残したまま隠すので、戻るとスクロール位置がそのまま
- プレビュー中も会話は裏で更新される。返答が届いたことはバッジで知らせ、会話に戻るまで内容は見せない
- 行番号を揃えるため、本文は折り返さず横スクロールになる。長い行は横に送って読む
- HTML はソース表示になる。レンダリング済みのプレビューは会話のチップから開く
- 256KB を超えるファイルは先頭だけを表示する。全文は注意の行のリンクから新しいタブで開く
- バイナリは選んでも内容を出さず、中央のラベルだけになる。ツリーの行は拡張子で開ける扱いのままなので、選ぶまで分からない
- 広いセルでは会話の列が 260px 狭くなる。1280px の 1 枚表示なら本文は約 600px 残り、読み幅として足りる。分割セルは幅次第で重ねる側に落ちる
- ツリーを並べると、見出しの中身は会話の列に揃い、反対の 260px に選択中のパスが出る。680px 付近の狭いセルでは、見出しのリポジトリ名やペイン名がさらに省略される
- 並べる側を切り替えると、本文の行の頭と見出しの名前の位置が 260px 動く。ツリーは並び位置が変わるため作り直され、展開したフォルダは残るがスクロール位置は先頭に戻る
- 認証なし LAN に、チェックアウト内の全エントリ名が出る（[ADR 0010](0010-lan-access.md)）。中身は allowlist と `.env` ブラックリストのままだが、「パスを知っている人だけ読める」から「ツリーを列挙できる」へ変わる
- ツリーを閉じている間はパスの出る場所も消える。選択したままツリーを閉じても、パスはプレビューの `title` とコピーに残る
- `node_modules` のような巨大なディレクトリも開けるが、200 件で切れる。ignore の解釈はしない
- ドットファイルも開ける。`.env` とその派生（`.env.local` など）だけは名前だけ出て開けない。`.github/workflows/*.yml` のように、ドットディレクトリの中のファイルも開ける（[ADR 0084](0084-relative-path-links.md)）
- ツリーは閉じるまで古い。エージェントが作ったファイルは、閉じて開き直すまで出ない
- 開閉には 160ms（開き）と 120ms（閉じ）の動きが入る。閉じている間も一覧は DOM に残り、120ms だけ `inert` になる
- 深い階層では字下げが名前の幅を削る。名前は 1 行で ellipsis にし、パスは `title` と読み上げに回す
- 折りたたんだフォルダの子は DOM に残る。展開済みの大きな木はメモリを使うが、再展開で取得も描画も走らない
- サイズはツリーに出ない。行の右端は空き、プレビューでは切り詰めたときだけ全サイズを添える
- シェルのペインでは使えない。ターミナルで `ls` を打つか、そのペインにエージェントを起動する
- 一覧の取得はディレクトリを開くたびに `readdir` と選択した 200 件の `stat` を行う。巨大なディレクトリでも stat は 200 回で止まる

## Alternatives

- **常に左右に並べる**: スマホと狭い分割セルでは本文が読めない。幅が足りるセルだけ並べ、残りは重ねる
- **並べる側をペインごとの状態にする**: ペインや端末をまたいで揃うが、ツリーの開閉と同じく、見え方は画面幅と端末の都合で決まる。設定として 1 つ持つ方が小さい
- **並べる側を BFF に持たせる**: 端末をまたいで揃うが、画面の向きと幅で本文の残りが変わるのと同じく、見え方は端末側の都合。テーマと同じく `localStorage` に置く
- **常に重ねる**: 広いセルでも会話とツリーを同時に見られない。最初の実装はこれで、同時に見たいという要求で広いセルだけ並べる形にした
- **プレビューと同じ一時タブ**: detail 全体を占有し、分割セルのほかのペインが見えなくなる。対象ペインの内側で見る目的に合わない
- **プレビューを別タブで開く**: 会話とファイルを同時に見られない。当初の判断はこれだったが、指示を書きながらファイルを見る要求で改めた
- **HTML をレンダリングして表示**: iframe のプレビューをチャット領域に埋め込むと、まずはソースを見る目的と操作が増える。レンダリング済みはチップのタブに任せる
- **全サイズを表示**: 10MB のテキストを DOM に置くとスマホで重い。256KB で切る
- **最初にツリー全体を 1 リクエストで返す**: `.gitignore` の解釈と巨大ディレクトリの扱いが要る。遅延展開なら、開いたディレクトリだけ読めば足りる
- **開けるファイルだけを出す**: `bun.lock` や `Makefile` が消えてツリーに穴が空き、構造に見えない
- **行数を出す**: 一覧を開くたびにディレクトリ内のファイルを読むことになり、件数・サイズの上限とキャッシュが要る。行数は開いたとき（将来のビューア）の責務にする
- **ドットファイルを隠す**: `.github` のような正当なディレクトリも消え、CI の定義へ辿れない
- **`/preview` と `/files` のチャット条件を外す**: シェルのペインでも開けるようになるが、配信の対象を全ペインへ広げる判断になる。ツリーの入口をチャットのあるペインに限る方が小さい
