# ADR 0090: ペインの中にチェックアウトのファイルツリーを重ねる

- Status: Accepted
- Date: 2026-11-16

## Context

hwc でファイルを開く入口は、エージェントの本文に書かれたパス（チップとリンク）だけだった（[ADR 0051](0051-agent-html-preview.md)、[ADR 0084](0084-relative-path-links.md)）。会話に出てこないファイルを見るには、ターミナルのペインで `ls` を打つしかない。

ほしいのは、チェックアウトの構造を地図として見て、気になったファイルを既存の見せ方で開くこと。ソースを読むためのエディタではなく、リファクタ候補や置き場所を探すための一覧で、人間が見るのは結果と地図という前提に立つ。

置き場所は、対象ペインの内側の右か左という案から始めた。しかし hwc のセルは detail の 1/1〜1/4 で、右に 280px を常設できるのは、サイドバーを含めて画面幅が約 1750px を超えるときだけ。スマホと分割セルでは、同じ機能を全幅表示に切り替えることになる。左右に並べる相手（中身）も、一覧だけの段ではまだ無い。

## Decision

### 置き場所

- ペイン見出しのファイルアイコンで開閉する。開いている間は押下状態（accent）にし、戻りも同じアイコン。ツリー専用のヘッダーは置かない
- ツリーは `.hwc-output-wrap` の中に絶対配置で重ね、会話のスクロール領域は生かしたまま `inert` と `aria-hidden` を付ける。会話のスクロール位置・追従・画像の読み込みを捨てず、閉じたときに読んでいた場所へそのまま帰れる
- 入力欄は残す。一覧を見ながらエージェントへ指示を送れる
- チャットを持たないシェルのペインには出さない。開くファイルは会話と同じ `/preview` と `/files` の経路を使い、どちらもペインのチャットを要求するため。配信を全ペインへ広げるかは別の判断にする

### 一覧

- 根はそのペインのワークスペースのチェックアウトだけ。`/tmp` と `HWC_PREVIEW_ROOTS` は出さない。エージェントが `/tmp` に書いたものは、会話のチップが既に拾う
- 表示するのは `.git` 以外の全エントリ。ドットファイルも名前だけ出す。中身を配る形式は既存の allowlist のままで、開けないファイルは淡色で押せない行にする。ツリーに穴を空けないため
- 子は開いたときにだけ 1 ディレクトリずつ取る（遅延）。折りたたんでも取得済みの子は保持し、開き直しでは取り直さない
- 1 ディレクトリ 200 件で切り、`total` と `truncated` を返して画面に 1 行出す。ディレクトリ優先・名前順（大文字小文字を無視し、同じなら表記で決める）
- サイズは表示する（`stat` の副産物）。行数・サイズ順・検索・ソート切替は持たない
- 絶対パスは返さない。名前は根からの相対パスだけ（[ADR 0041](0041-agent-message-images.md)）
- `realpath` で根の配下を確かめる。根の外を指す symlink は名前だけ返し、展開・open をさせない。壊れたリンクも名前だけ残す
- 全体を歩く API は作らない。無視規則（`node_modules`、`dist` など）と件数上限をサーバーに持つことになり、リポジトリごとの正解も変わる

### 状態

- 開閉・展開・取得済みの子はペインごとにクライアントの store が持つ。セルはペイン切り替えやプレビューでアンマウントされるため、コンポーネントの寿命から切り離す（添付チップと同じ）
- プレビューやタブ切り替えから戻ったときは、同じ開閉で戻る。スクロール位置は先頭に戻る
- ツリーを閉じたら状態を捨てる。開き直しがそのまま取り直しになる。watch と手動更新は持たない
- ペインがスナップショットから消えたら状態も捨てる

### 開き先

- HTML は既存のプレビューのタブ
- 画像は既存の拡大ダイアログ。URL はプレビューの配信 URL を使う（`no-store` なので版は要らない）
- テキストは既存の raw 配信を新しいタブで開く。リンクにしておき、中クリックと URL のコピーはブラウザに任せる
- 開いたファイルから戻ったときも、ツリーは開いたまま

## Consequences

- 会話に出てこないファイルを、スマホでも分割セルでも同じ形で辿れる。読むためのビューア（整形・検索・編集）は持たない
- 認証なし LAN に、チェックアウト内の全エントリ名とサイズが出る（[ADR 0010](0010-lan-access.md)）。中身は allowlist のままだが、「パスを知っている人だけ読める」から「ツリーを列挙できる」へ変わる
- `node_modules` のような巨大なディレクトリも開けるが、200 件で切れる。ignore の解釈はしない
- ドットファイルは名前だけ出る。`.env` や `.gitignore` の中身は開けない。`.github/workflows/*.yml` のように、ドットディレクトリの中の普通名ファイルは開ける（[ADR 0084](0084-relative-path-links.md)）
- ツリーは閉じるまで古い。エージェントが作ったファイルは、閉じて開き直すまで出ない
- 深い階層では字下げが名前の幅を削る。名前は 1 行で ellipsis にし、パスは `title` と読み上げに回す
- シェルのペインでは使えない。ターミナルで `ls` を打つか、そのペインにエージェントを起動する
- 一覧の取得はディレクトリを開くたびに `readdir` と選択した 200 件の `stat` を行う。巨大なディレクトリでも stat は 200 回で止まる

## Alternatives

- **セルの右に固定幅パネル**: 広い 1 枚表示でしか成立せず、スマホと分割セルでは全幅表示に切り替えることになる。同じ機能に 2 つの表示を持つ
- **プレビューと同じ一時タブ**: detail 全体を占有し、分割セルのほかのペインが見えなくなる。対象ペインの内側で見る目的に合わない
- **最初にツリー全体を 1 リクエストで返す**: `.gitignore` の解釈と巨大ディレクトリの扱いが要る。遅延展開なら、開いたディレクトリだけ読めば足りる
- **開けるファイルだけを出す**: `bun.lock` や `Makefile` が消えてツリーに穴が空き、構造に見えない
- **行数を出す**: 一覧を開くたびにディレクトリ内のファイルを読むことになり、件数・サイズの上限とキャッシュが要る。行数は開いたとき（将来のビューア）の責務にする
- **ドットファイルを隠す**: `.github` のような正当なディレクトリも消え、CI の定義へ辿れない
- **`/preview` と `/files` のチャット条件を外す**: シェルのペインでも開けるようになるが、配信の対象を全ペインへ広げる判断になる。ツリーの入口をチャットのあるペインに限る方が小さい
