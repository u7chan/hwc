# ADR 0040: フォーカス輪郭は最後の入力手段で決める

- Status: Accepted
- Date: 2026-11-08

## Context

iOS の Safari / Chrome は、タッチでメニューやダイアログを開き、その中でプログラムからフォーカスを移すと、`:focus-visible` の輪郭を残すことがある。メニューを閉じてトリガーへフォーカスを戻した場合も同じで、別の要素をタップするまで輪郭が残る。タッチ操作の画面に、キーボード向けの表示が居座る。

hwc は `:focus-visible` に輪郭を任せ、プログラム的フォーカスを次の箇所で使っている。

- メニューを開いたときの最初の項目、閉じたときのトリガー
- ダイアログを開いたときの `data-autofocus` またはダイアログ本体、閉じたときのトリガー
- フォルダ信頼確認の見出し
- アクティブの帯から移ったときのスペース見出し
- コピー後のコピー元への復帰
- 入力ヒントをフォーカスで開く判定

## Decision

- `<html>` の `data-input-modality` に最後の入力手段を持つ。値は `pointer`（タッチ・ペン）/ `mouse` / `keyboard`
  - `pointerdown` の `pointerType` が `touch` / `pen` なら `pointer`、それ以外は `mouse`
  - `keydown` で `keyboard`
  - 初期値は主ポインタが粗ければ `pointer`、細ければ `mouse`
- `pointer` の間は `:focus-visible` の `outline` を出さない。`mouse` と `keyboard` はブラウザの `:focus-visible` に任せる
- 入力欄（`input` / `textarea` / `select`）はこの規則から除く。作成ダイアログの入力欄は、タップで入ったフォーカスを自前の輪郭で示す
- 入力ヒントは `:focus-visible` ではなく、最後の入力手段が `keyboard` のときだけフォーカスで開く

## Consequences

- タッチ・ペン操作では、プログラム的フォーカスに輪郭が残らない
- 入力欄はタッチでも自前の輪郭を出す。それ以外のプログラム的フォーカスは輪郭を出さない
- マウスとキーボードは従来どおりブラウザの `:focus-visible` に従う。フォーカス自体は移したまま、輪郭だけを消す
- タッチ端末の初期表示でも輪郭を出さない。最初のキー入力でキーボード扱いに戻る
- 個別の `:focus-visible` スタイルより優先するため、輪郭の抑制は 1 か所で完結する
- タッチ端末にハードウェアキーボードをつないだ場合も、キー入力後は輪郭が出る
- ADR 0036 の入力ヒントを `:focus-visible` で開く判定は、この ADR が置き換える

## Alternatives

- **`@media (pointer: coarse)` で輪郭を消す**: タッチ端末にハードウェアキーボードをつないだときも輪郭が消え、キーボード操作の手掛かりを失う
- **プログラム的フォーカスをやめる**: メニューやダイアログをキーボードで続けられなくなる
- **コンポーネントごとに輪郭を消す**: 新しい部品を足すたびに漏れる。フォーカスを移す箇所が複数あるため、共通の判定に寄せる
