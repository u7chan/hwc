# ADR 0121: イベントの無い cwd とブランチを、可視中の取り直しで追う

- Status: Accepted
- Date: 2026-11-21
- Revises: [ADR 0048](0048-git-remote-sync.md) の「ポーリングや自動フェッチはしない」

## Context

シェルで `cd` しても、hwc のスペースのパス（`workspace.path`）とファイルツリーの根は古いままだった。シェルでブランチを切り替えても、一覧と見出しのブランチ・上流との差が古いままだった。どちらも、Herdr のイベント契機でしか状態を取り直していない（ADR 0005）ためである。

Herdr 0.9.5 は cwd の変化をイベントで流さない。`/tmp` のシェルで `cd` して `pane.get` の `cwd` / `foreground_cwd` が `$HOME` に変わっても、`pane.updated` などのイベントは 0 件だった。スナップショットには新しい cwd が載っているので、データはあるが、取り直す契機が無い。

ブランチは Herdr の関心事ではない。`git checkout` でもイベントは 0 件で、スナップショットの cwd も変わらない。hwc は `.git/HEAD` を読んでいる（ADR 0048）が、読み直すのは Herdr のイベントか、フェッチ / プルの後だけだった。

ADR 0048 は「ポーリングや自動フェッチはしない。状態は Herdr のイベントによる取り直しと、操作後の取り直しで更新する」と決めた。cwd とブランチを追うには、この決定を見直す必要がある。

## Decision

### 取り直しの契機

- クライアントは、画面が可視の間だけ一定の間隔で `POST /api/state/refresh` を呼ぶ。非表示の間は止め、可視に戻った時点で 1 回呼ぶ。前景プロセスのポーリングと同じ可視判定（[ADR 0069](0069-shell-pane-stop.md)）
- BFF は既存の `store.refresh()` を実行する。読み取りの経路は増やさない。git のネットワーク操作（fetch / pull）は自動では行わない
- 状態は従来どおり SSE で配る。`/api/state/refresh` の応答は受け付けたことだけを返し、クライアントはその本文を状態として適用しない。ポーリングを状態の転送経路にはしない（ADR 0005）
- 変化の無い状態は SSE に流さない。3 秒ごとの再描画を避ける
- ブランチの読み取り TTL を 4 秒から 1 秒へ下げる。HEAD のファイル読みだけで、プロセスは起動しない。上流との差の 10 秒 TTL は変えない
- スペースのパスの決め方は変えない。`worktree.checkout_path`、先頭ペインの cwd、agent の cwd の順に落とす（[ADR 0049](0049-copy-space-path.md)）。worktree を持つスペースはチェックアウトのままなので、そのスペースで `cd` してもパスは動かない
- ファイルツリーの根が変わったら、開いているツリーの取得済みの一覧・展開と、選択中のプレビューを捨てて新しい根で取り直す。相対パスは根からの相対なので、根が変われば同じ `""` や `docs` が別の場所を指す

### 間隔の設定

- 既定は 3 秒。設定画面の「ライブ更新」で、オフ / 1 秒 / 3 秒 / 5 秒 / 10 秒から選ぶ
- 設定は端末ごとの好みとして localStorage（`hwc-live-update`）に置く。テーマ・ペイン分割と同じく、見え方と電池の好みであり、取り直しを頼むのはクライアントだから（[ADR 0111](0111-auto-split-on-delegation.md)）
- オフは、Herdr のイベントが起きるまで cwd とブランチを追わない従来の動きに戻す

## Consequences

- シェルの `cd` とブランチ切替が、間隔ぶんの遅れで hwc に反映される。スペースのパス、ファイルツリーの根、一覧と見出しのブランチ、スペースメニューのパスが同じ状態から動く
- ツリーの根が変わったときは、そのツリーを開いたまま新しい根で取り直す。展開していたフォルダとプレビューは閉じるが、古い根の相対パスで行を選んだりドラッグしたりはしない
- 上流との差は、ブランチ切替では新しいブランチのキーで読み直される。同じブランチへのコミット・プッシュは最大 10 秒遅れる（ADR 0048 のまま）
- 見ている間だけ、間隔ごとにスナップショットを 1 回読む。git のプロセス起動は TTL で頭打ちになる。非表示の端末は何も呼ばない
- 複数の端末が見ていても、BFF は実行中の取り直しを 1 つに畳む。端末ごとに間隔が違ってもよい
- 隠れている間の変化は、可視に戻った直後の 1 回で追いつく。設定を変えると、次の間隔からではなく、その場で新しい間隔になる
- オフにすると、cwd とブランチは Herdr のイベントか再起動まで古いままになる
- 状態の公開は、内容が同じなら SSE を流れない。購読側は、変化が無いことを通知されなくなる

## Alternatives

- **BFF の常時タイマー**: クライアントを変えずに済むが、誰も見ていない間もソケットと git を読み続ける。可視の判定ができない
- **出力イベント（`pane.output_changed`）で取り直す**: イベント駆動のままに見えるが、ビルド中は大量のイベントが流れ、出力の無い変化を取りこぼす。ADR 0048 の「出力のたびに取り直さない」とも合わない
- **`.git/HEAD` を fs.watch する**: ブランチだけは即時にできるが、cwd は結局ポーリングが要り、機構が 2 つになる
- **Herdr に cwd 変更イベントを追加してもらう**: 根本的だが upstream 待ち。ブランチは Herdr の概念の外なので、これだけでは足りない
- **クライアントが取り直した状態を直接適用する**: ポーリングの応答と SSE の順序が競合し、再描画の整合性を保てない（ADR 0005 の懸念）

## Verification

- unit で、`POST /api/state/refresh` が状態を取り直すこと、失敗を 502 に畳むこと、内容の変わらない公開が購読者へ流れないこと、間隔の読み書きと可視判定、ファイルツリーの根が変わったときに一覧とプレビューを捨てることを確認する
- 架空 Herdr の E2E で、シェルの `cd` がイベント無しでスナップショットの cwd を変えたとき、スペースメニューのパスとファイルツリーの根が間隔以内に追随すること、ブランチ切替が一覧と見出しに反映されること、設定をオフにすると追随が止まることを確認する
- 実 Herdr で、`/tmp` のスペースのシェルから `cd` したとき、再読み込みなしでスペースのパスが `$HOME` に変わることを 1 度だけ確認する
