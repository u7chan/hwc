# ADR 0065: プレビューの根の外にあったファイルを会話に示す

- Status: Accepted
- Date: 2026-11-11
- Revises: [ADR 0051](0051-agent-html-preview.md) の「根の外は黙って出さない」部分
- Revises: 2026-11-11 に移動の依頼を廃止（[ADR 0066](0066-tmp-preview-root.md)）

## Context

[ADR 0051](0051-agent-html-preview.md) は、本文に書かれたパスをチェックアウトと追加根から解決し、見つかったものだけをチップにする。根の外にあるファイルは、実在していても何も出ない。

エージェントは使い捨てのモックやスクリーンショットを `/tmp` に書く。そのとき画面にはチップが出ないだけで、エラーも案内も無い。利用者から見ると「プレビューのボタンが消えた」と区別がつかず、原因（置き場所）にたどり着けない。欠陥は文書が足りないことではなく、失敗が無言なことにある。

根を広げる案は採れない。`/tmp` を根にすると、本文に書かれた HTML からの相対参照で隣接ディレクトリが読めるようになり、認証の無い LAN 公開（[ADR 0010](0010-lan-access.md)）と噛み合わない（この判断は [ADR 0066](0066-tmp-preview-root.md) で覆した）。

規約をエージェントへ配る案も、欠陥の修正にはならない。グローバル指示の置き場所は Pi・Codex・OpenCode で別々で、hwc が起動していないペインには効かず、過去の会話も直らない。

## Decision

### 検出

- 対象は `role: "agent"` の本文にある絶対パスの候補。どの根の配下でもない場所に実在し、配信対象の形式（画像か HTML）なら、**ファイル名だけ**を `ChatMessage.outsideFile` に載せる。1 通につき 1 件
- 絶対パスはクライアントへ渡さない（[ADR 0041](0041-agent-message-images.md) の契約をそのまま使う）
- 相対パスは「根の外」の判定をしない。本文だけからは、どのディレクトリを基準に読むべきか決まらない
- 実在しても、サイズ 0・上限超え・配信対象外の形式なら「根の外」とは言わない。理由が違ううえ、案内しても移す先で同じ結果になる
- `etag` に `outsideFile` を混ぜる。本文が変わらないまま案内だけが現れる・消えることがあるため、304 で古いスナップショットを返さない

### 画面

- メッセージの下に 1 行。ファイル名と、根の外にあること（`移動を依頼` のボタンは [ADR 0066](0066-tmp-preview-root.md) で廃止）
- 色は `secondary`、ファイル名だけ `text` と等幅。主操作（送信）と強さを競わせない
- ボタンは文字リンクと同じ寸法（最小高 44px、内側 8px、`accent`）。タップ領域を広げるのは周りの余白で、文字は小さくしない（以下、廃止）

### 移動の依頼（[ADR 0066](0066-tmp-preview-root.md) で廃止）

`/tmp` を既定の根にしたため、押す入口ごと消した。以下は廃止時点の記録。

- 押すと user 発言を 1 通送る。hwc はファイルを動かさない。移送の確認・取り消しは会話の中で行う
- プロンプトは名前だけを渡す（絶対パスを渡さない契約を守る）。移動元は、エージェント自身が過去に書いた発話に残っているパスを読む。案内はすべての発話に付くので、最新でない発話から押したときも同じ前提で解決する
- 依頼の文面は 1 か所 (`moveRequestText`)。チェックアウト配下のコミット対象外の場所（`例: .artifacts/`）へ、相対参照ごと、中身を変えずに移すことを伝える
- 実行中（`replying`）でも押せる。入力欄と同じく、実行中への追加指示として扱う
- 送信中と閲覧専用（プレビュー・選択）では送らない。失敗は既存の `.hwc-send-notice` で返す
- 送信の控え（pending）は入力欄からの送信と同じ仕組みで積む。ポーリングの間隔だけ無反応に見えるのを避ける

## Consequences

- 根を広げずに、チップが出ない理由が画面で分かる。既存の会話にも効く
- 移送を依頼する入口は `/tmp` を既定の根にしたことで消えた（[ADR 0066](0066-tmp-preview-root.md)）。残る案内は理由の表示だけ
- 移送はエージェントの仕事なので、断られる・失敗することはある（廃止）
- 押すと user 発言が 1 通増える。取り消しはできない（廃止）
- 依頼の文面は `.artifacts/` を例として挙げていた（廃止）
- 古いメッセージの案内は、ファイルが動けば次の取得で消える（`etag` が変わる）
- 同じ名前のファイルが複数のディレクトリにあると、エージェントが移動元を取り違える余地が残った。依頼文に名前しか入れない代わりに、取り違えは会話の中で訂正する前提だった（廃止）
- 圧縮で古い発話が文脈から消えていると、エージェントは名前からパスを探すことになった（廃止）
- 配れない絶対候補の数だけ `realpath` と `stat` が増える。候補は 20 件で打ち切っている

## Alternatives

- **規約をグローバル指示へ配る**: CLI ごとに置き場所が違い、hwc 起動でないペインには効かない。既存の会話も直らない
- **`/tmp` を根に加える**: 本文に書かれた HTML から相対参照で隣接ディレクトリが読める。[ADR 0010](0010-lan-access.md) の前提と噛み合わない（[ADR 0066](0066-tmp-preview-root.md) で採った。露出は同 ADR の Consequences に記載）
- **hwc がファイルをコピーして配信する**: 相対参照のフォントや CSS ごと複製する必要があり、同じ実体を二重に持つ
- **案内だけ出してボタンを置かない**: 次の一手が分からず、利用者が同じ指示を打ち直すことになる（[ADR 0066](0066-tmp-preview-root.md) で採った。`/tmp` を許した後は、残るケースが少数になった）
- **押さなくても移送プロンプトを送る**: 利用者が触っていない操作で、リポジトリの中身が変わる
