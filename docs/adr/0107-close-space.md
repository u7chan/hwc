# ADR 0107: 最後の 1 つを除いて、どのスペースもメニューから閉じられるようにする

- Status: Accepted
- Date: 2026-11-20
- Revises: [ADR 0034](0034-remove-worktree.md) の「リポジトリ本体のスペースを一般的に閉じる操作は持たない」。[ADR 0060](0060-duplicate-native-spaces.md) の「閉じられるのは、同じ場所に他にも Herdr が管理しないスペースがあるときだけ」「拒否は 409 `not_duplicate_space`」「同じ場所の close を直列化する」

## Context

ADR 0034 は、`workspace.close` がチェックアウトのフォルダを残すため「ワークツリーを削除」には向かないとして、リポジトリ本体のスペースを閉じる操作を持たないと決めた。ADR 0060 は重複したネイティブスペースの整理に限って例外を足したが、閉じる入口は重複があるときだけ出る。

その結果、hwc から片付けられるのは linked worktree に限られる。リポジトリ本体、git 管理外のシェルだけのスペース、Herdr が管理していないチェックアウトは、終わった作業でも Herdr TUI に戻らないと閉じられない。スペース見出しのメニューはどのスペースにもあるのに、一番下の片付けの項目だけがスペースの種類で途切れる。

`workspace.close` はフォルダを残す。チェックアウトを消す操作ではないので、リンクの削除（`worktree.remove`）とは目的が違う。0 スペースになると、hwc の画面は対象を持つスペースを失う。

## Decision

### 入口

- スペース見出しのメニューの一番下に `スペースを閉じる` を置き、`POST /api/workspaces/:id/close` を呼ぶ。入口はスペース見出しの 1 つだけにする（ADR 0034 のまま）
- 危険色（`hwc-menu-item--danger`）で出し、確認ダイアログで、実行中のエージェントも終了すること、チェックアウトのファイルは残ることを伝える（ADR 0060 の確認をそのまま使う）
- 名称は `スペースを閉じる` / `閉じる`。フォルダを消す `ワークツリーを削除` と対比を保ち、`workspace.close` がフォルダを残すことを文言で裏切らない

### 対象

- そのスペースを除いても他にスペースが残るときだけ閉じられる。重複しているかどうかは問わない。最後の 1 つでは項目を出さず、BFF も 409 で拒否する
- Herdr が管理する linked worktree（`worktree.managed === true && isLinkedWorktree`）は対象外。閉じてもフォルダが残り、hwc からはそのチェックアウトを開き直せない。片付けは `ワークツリーを削除`（`worktree.remove`）に一本化し、同じメニューに危険な項目を 2 つ並べない
- Herdr が管理しない linked チェックアウト（git から補った表示用の worktree 情報）は閉じられる。`worktree.remove` の対象外（ADR 0075）なので、閉じる以外に hwc から片付ける手段が無い
- パスの無いスペースも閉じられる。`workspace.close` は id だけで閉じ、確認にはパスの代わりにラベルを出す

### BFF

- `workspace.close` を `close_group` なしで呼ぶ（ADR 0060 のまま）。グループを巻き込む閉じ方はしない
- 拒否は 409 `not_closable_space` にする。対象の条件が「重複」ではなくなったため、`not_duplicate_space` から改名する
- 閉じている間と、閉じた直後の状態が届くまでの workspace id を覚え、残りの数から外す。場所ではなく id 単位のガードに変え、別々のスペースを同時に閉じても 0 スペースにならないようにする。同じ id の再送も 409 にする
- 消えたスペースは目的の状態に達しているため、Herdr の `workspace_not_found` は 404 とし、クライアントは成功として扱う（ADR 0060 のまま）

## Consequences

- リポジトリ本体、git 管理外のスペース、Herdr が管理しないチェックアウトも hwc から片付けられる。終わった作業のために Herdr TUI に戻る必要が無くなる
- 最後の 1 つは閉じられないので、hwc が持つスペースは常に 1 つ以上ある
- linked worktree のメニューには `スペースを閉じる` が出ず、`ワークツリーを削除` だけが出る。フォルダを残して閉じたい場合は Herdr TUI を使う
- 閉じたスペースの会話・下書き・未読は一覧から消える（ADR 0034 の削除と同じ）。フォルダとブランチは残る
- 状態が追いつくまでの間は、残りの数の判定が古い状態を元にするので、残ったスペースの close も一時的に 409 になる。状態が届けば解ける（ADR 0060 と同じ）
- 重複の片付けは今までどおり `すべて` の場所の束で行う。束が解けた後も、他にスペースがあれば残ったスペースを閉じられる

## Alternatives

- **重複スペースだけに限る（ADR 0060 のまま）**: リポジトリ本体は Herdr TUI に戻らないと閉じられない。hwc から片付けられるスペースの種類が linked worktree だけになる
- **0 スペースも許す**: Herdr が 0 スペースを許すか未確認で、hwc の画面は対象を持つスペースを失う。最後の 1 つは残す
- **linked worktree も閉じられるようにする**: `ワークツリーを削除` と同じメニューに危険な項目が 2 つ並び、フォルダが残ったチェックアウトを hwc から開き直せない
- **Herdr が管理しない linked も閉じさせない**: `worktree.remove` の対象外なので、hwc から片付ける手段が無くなる
- **名称を「スペースを削除」にする**: `workspace.close` はフォルダを残す。`worktree.remove` と意味が濁る
- **項目を出したまま無効にする**: 最後の 1 つしかない状態で、できない操作を並べる意味が無い（ADR 0060 の UI 規則と同じ）
