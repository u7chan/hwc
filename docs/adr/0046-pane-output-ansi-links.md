# ADR 0046: ペイン出力は ANSI の色を残して描き、裸の URL をリンクにする

- Status: Accepted
- Date: 2026-11-08（2026-11-11 追記）

## Context

ペイン出力の取得に `format: "text"` を使っていたため、端末が付けた ANSI の色と装飾が落ちていた（[#5](https://github.com/u7chan/hwc/issues/5)）。Herdr の TUI では色が状態や重要度の手がかりになっており、シェルでは `git` の差分や開発サーバーの起動ログが色で読まれている。Web 側でも最低限は再現したい。

出力に含まれる URL（`hwc ready: http://localhost:30000` など）も、ただの文字として出ていた。スマホからはアドレスバーへコピーする手段が無く、踏めるようにする必要がある。

出力はシェルスクリプトのソースではなく、任意のプログラムが吐いた文字列と端末の画面である。言語を判定して文法どおりに色を付ける「シンタックスハイライト」は当てにならず、色は端末がすでに決めている。Herdr の `pane.read` は `format: "ansi"` を受け付け、SGR 付きの文字列を返す。実機で確認した範囲では、付いてくる制御シーケンスは SGR だけで、カーソル移動や OSC は混ざっていなかった。

（2026-11-11 追記）Starship のプロンプトは、セグメントの背景色で区間を示す。hwc は背景色を描かないため、Web では前景色の矢印だけが残り、TUI の帯と見た目が異なる。背景色を描く案は、下の Alternatives に残した理由で採らない。

## Decision

- `pane.read` は `format: "ansi"` / `strip_ansi: false` で読む。BFF は受け取った文字列をそのまま返し、ANSI の解釈はクライアントで行う
- クライアントは SGR を `span` に変換して描く。HTML 文字列は作らず、`innerHTML` も使わない（[ADR 0014](0014-markdown-rendering.md) と同じ方針）
- 対応する SGR は前景色（8/16 色・256 色・24bit）、bold、dim、italic、underline、strike とする。背景色と反転は採らない。テーマの地色と組み合わせると読めない組み合わせが作れるため
- SGR 以外の制御シーケンス（CSI・OSC・C0/C1）は表示しない。改行とタブだけ残す
- 8/16 色は `tokens.css` の `--ansi-0`〜`--ansi-15` に置く。明るいテーマと暗いテーマで値が逆転するので、`theme.ts` の `scheme` を `data-scheme` として `:root` に出し、2 組のパレットを切り替える。この固定パレットが対象とするのは 8/16 色だけ
- 256 色と 24bit は端末の値を基本にする。ただし、明暗それぞれの保守的な基準地色（light: `#eff1f5`、dark: `#2d353b`）に対してコントラストが 4.5:1 を下回るときだけ、黒（light）または白（dark）へ寄せて読める値にする。基準地色は実際の `--color-content` ではなく、それより厳しい面（light: Catppuccin Latte の `--color-surface`、dark: Everforest の `--color-bg`）を使う
- 出力中の裸の `http://` / `https://` URL をリンクにする。新しいタブで開く。末尾の句読点と対応の取れていない閉じ括弧は URL に含めない
- リンクの色は変えず、下線だけで示す。端末が付けた色を上書きしないため
- URL のホストは読み替えない。スマホから `localhost` を開くとスマホ自身を指すが、別端末からは PC の IP とポートで直接アクセスする運用にする
- 対象は出力欄だけ。会話の Markdown は既存のリンク描画のまま

## Consequences

- 色付きの出力が Web でも読める。`git diff` の追加・削除や、開発サーバーの URL が端末と近い見た目になる
- 色は端末の配色そのものではない。8/16 色は明暗 2 組の固定パレット、256 色と 24bit は読めないときだけ補正するので、利用中の端末テーマや Herdr の配色とはずれる
- 256 色と 24bit の色は、地色とのコントラストが足りない場合に黒または白へ寄る。端末で見た色と完全には一致せず、色相や彩度も薄れることがある
- 背景色・反転・点滅・文字の隠蔽は無視する。これらで強調する TUI の出力は、端末より弱い見た目になる（2026-11-11 追記: Starship の背景帯も出ず、シェルでは前景色の矢印だけが残る）
- 出力の文字列は ANSI 付きで BFF を通るため、`format: "text"` のときより長くなる。表示は直近 200 行に限るので、通信と描画への影響は小さい
- SGR の切れ目が URL の途中にあると、その URL はリンクにならない。1 つの色の区間に収まる URL だけが対象
- 端末幅で折り返された URL は、行をまたぐため 1 行目だけが途中までの URL としてリンクになる。画面では 1 つの URL が続いて見えるが、押すと途中までの URL を開く。表示上の折り返し位置は端末幅に依存し、正しく復元できないので、行をまたぐ URL の結合は行わない
- OSC 8 のハイパーリンクは解釈しない。`ls --hyperlink` のように表示文字だけをリンクにする出力は、裸の URL が出ないため対象外
- `www.` やドメインだけの文字列はリンクにしない。シェル出力ではファイル名との区別が付かないため
- `localhost` のリンクは、スマホからは開けない。表示されたとおりの URL を開く仕様で、読み替えはしない

## Alternatives

- **出力を言語判定してシンタックスハイライトする**: 出力は複数のプログラムの混在で、文法も言語も決まらない。端末が付けた色を捨てて推測で塗り直すことになる
- **BFF で ANSI を解析して構造化した JSON を返す**: 表示の都合が BFF に漏れる。ポーリングのたびに BFF で組み立て直す必要もあり、クライアントの純関数で足りる
- **`format: "text"` のまま独自に色を推測する**: `git` や `bun` の出力をパターンで塗ることはできるが、ツールごとの知識が増え、外れたときに静かに崩れる
- **端末の 8 色をそのまま使う**: 暗い地を前提にした色が明るいテーマで読めない。明暗 2 組を持つ方が安全
- **256 色と 24bit を常に端末の値のまま使う**: 端末とテーマの明暗が逆になると、本文が地色に埋もれて読めない。コントラスト不足のときだけ補正する
- **256 色と 24bit を常に `--color-text` に落とす**: 読めるが、truecolor の TUI がすべて単色になり、色の情報を捨てることになる
- **`localhost` をページのホストへ読み替える**: スマホからは踏めるが、ペインが別ホストで動く場合や、端末で別のサービスを指している場合に誤った宛先になる。利用者は PC の IP とポートで直接アクセスする運用を選んだ
- **`www.` や裸のドメインもリンクにする**: シェル出力では拡張子付きのファイル名と区別が付かず、誤リンクが増える
- **背景色と反転を描く**: Starship のセグメント背景や TUI の帯を再現できる。しかし、端末の背景はセル全体を塗るのに対し、HTML のインライン要素の背景は文字の内容領域にしか付かない。セル単位で正確に描くには、行をセルへ分割して描く構造へ変える必要がある。hwc は TUI の全機能を再現しない補助であり、プロンプトの帯だけを特別扱いすると他の TUI 出力との一貫性も崩れる。コストに見合わないため採らない（2026-11-11 追記）
- **OSC 8 を解釈する**: 現状の Herdr の出力には付いておらず、まず裸の URL で足りる（YAGNI）
