# ADR 0091: 会話が空に戻ったときも、起動時のモデルの預かりで表示を補う

- Status: Accepted
- Date: 2026-11-17
- Revises: [ADR 0033](0033-launch-model-before-first-message.md) の「スナップショットにモデルが載ったら預かりを捨てる」、[ADR 0087](0087-default-model-display.md) の「会話にモデルが載ったときに解決済みの値を捨てる」

## Context

pi の `/new` はセッションを 0 メッセージに戻す。pi は最初の user / assistant メッセージまでセッション JSONL を書かないため、`/new` の後は会話スナップショットからモデルと effort が消える。hwc は起動時の指定（[ADR 0033](0033-launch-model-before-first-message.md)）と既定モデル（[ADR 0087](0087-default-model-display.md)）を表示用に預かっているが、どちらも会話にモデルが載った時点で捨てていた。そのため `/new` の後は入力欄からモデル名と effort が消え、1 通送るまで戻らない（[#76](https://github.com/u7chan/hwc/issues/76)）。

`/new` 後のモデルは「直前まで使っていたモデル」ではない。pi の `createRuntime` は新しいセッションでも起動時の引数をやり直すため、`--model` / `--provider` を渡していればそのモデル、渡していなければ設定の既定に戻る。最後に見た値を据え置くと、途中でモデルを切り替えたペインで必ず外れる。

ADR 0033 と ADR 0087 の「会話にモデルが載ったら預かりを捨てる」は、預かりが「最初のメッセージまで」の補いだという前提に立っていた。`/new` は同じペインでその前提をもう一度作る。

## Decision

- モデルを指定して起動したときに預かる選択（ADR 0033）は、会話にモデルが載っても捨てない。ペインのエージェントが終わる（`close` / `exit`）まで持ち、`GET /api/panes/:id/chat` はスナップショットの `model` が `null` の間だけ補う。補うときの etag の印は変えない。`/new` は `--model` / `--thinking` の指定を引き継ぐので、同じ値が正しい
- 既定モデルで起動したペインの預かり（ADR 0087）も、会話にモデルが載っても捨てない。捨てるのは解決済みの値だけにして、会話が空に戻ってクライアントが読み直したときは、その時点の既定を `pi --offline --mode rpc --no-session` の `get_state` から取り直す。`/new` はモデル未指定なら設定の既定に戻るので、これが正しい
- 既定の口（`GET /api/panes/:id/default-model`）は「そのペインを既定モデルで起動したか」に答える。会話にモデルが載っている間にその値を表示するかは、ADR 0087 のとおりクライアントが決める（スナップショットにモデルも effort も無いときだけ読む）
- クライアントは変えない。`/new` でスナップショットからモデルが消えると、既定を読む条件が再び成り立ち、同じ経路で読み直す
- 最後に見たモデルを表示し続ける案は採らない。`/new` でモデルが既定へ戻る場合に、実際と違う値を出すことになる

## Consequences

- hwc から起動したペインは、`/new` の後もモデル名と effort を出し続ける。モデル指定なら起動時の値、既定起動ならその時点の既定
- 会話が空に戻るたびに、既定起動のペインでは既定の解決が 1 回走る（チャット画面を開いている間だけ）。ペインの作成は遅くならない
- コンテキスト使用量は 0 メッセージでは材料が無いので、`/new` の後は最初の 1 通まで出ない（従来どおり）
- hwc 以外から起動したペイン、BFF 再起動を挟んだペインは対象外のまま（ADR 0087）。預かりは永続化しない
- TUI で `/quit` して同じペインに別のモデルで起動し直した場合は、最初のメッセージまで前の値が残る。預かりを捨てる契機が `close` / `exit` だけになるため、hwc の `/exit` を通さない再起動では残る（ADR 0033 と同じ制約）
