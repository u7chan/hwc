# ADR 0061: 分割ビューは方向つきの二分木で持ち、常設の追加帯をやめる

- Status: Accepted
- Date: 2026-11-11
- Revises: [ADR 0058](0058-split-view-tab-history.md) のレイアウト・追加帯・空きスロット・ドラッグの落とし先
- Revises: 2026-11-11 にスロット色の順を深さ優先から読み順へ、自分自身の端へのドロップで空くセルの補充を開いた順から表示順へ変更した（[ADR 0063](0063-tab-order-by-pane-layout.md)）
- Revises: 2026-11-11 に固定ゾーンのタブをドロップの落とし先にした（[ADR 0064](0064-tab-strip-swap.md)）

## Context

ADR 0058 の分割ビューは、詳細の右端に幅 40px の追加帯を常に出していた。追加帯はスロットを増やすためだけの領域で、中身を持たない。1 枚表示でも本文幅をわずかに削り、何も無い帯が画面の一部として見える。分割の入口がこの帯だけなので、利用者はまず「ここへドラッグする」と覚える必要がある。

分割の方向も選べなかった。スロットは追加のみで、レイアウトは枚数で固定される（3 枚 = 左 1 + 右 2）。左右に並べたあと、片方の上下へ積むことはできない。実際に並べて作業すると、この制約が先に来る。

ADR 0058 は「自由なドラッグ・リサイズ」を却下している。これはウィンドウマネージャになるという判断で、方向を選ぶ分割やドラッグ中のプレビューは含まない。リサイズを持たないまま、方向だけを選べるようにする。

## Decision

### 状態

`slots` を `layout` に置き換える。開いたタブ（`openTabs`）と選択（`current`）は変えない。

```ts
type SplitNode =
  | { kind: "leaf"; pane: string }
  | { kind: "split"; dir: "row" | "col"; children: SplitNode[] };
```

- `layout` は二分木。`leaf` はペイン、`split` は横（`row`）か縦（`col`）の並びで、子は 2 つ
- 葉は最大 4 つ。一意で `openTabs` の部分集合
- `current` は実在するペインのときだけ葉に 1 回現れる。実在しないときは葉に現れない
- 空きの葉は持たない。ペインが外れたら葉を除き、親を畳む
- 同じ向きのネストは作らない（3 列・3 段を作らない）。分割できる向きは、そのセルの親の分割軸と直交する向きだけ。親が無い単独セルは 4 方向すべて
- 葉を除いた結果、同じ向きの入れ子や子 3 つ以上の分割ができることがある。その場合は葉の順を保ったまま 2 つずつに組み直す（3 枚 = T 字、4 枚 = 2x2）。保存値の正規化でも同じ組み直しをする

遷移は `src/client/split-view.ts` の純関数が持つ。

| 出来事                                                                                          | `openTabs`       | `layout`                                                        | `current`                                                         |
| ----------------------------------------------------------------------------------------------- | ---------------- | --------------------------------------------------------------- | ----------------------------------------------------------------- |
| 一覧 / タブでペインを開く（木に無い）                                                           | 無ければ右端追加 | current の葉を置換。current が無ければ最初の葉。木が空なら 1 枚 | そのペイン                                                        |
| 一覧 / タブでペインを開く（木にある）                                                           | 変えない         | 変えない                                                        | そのペイン                                                        |
| タブから外す（current）                                                                         | 削除             | その葉を除いて畳む                                              | 後継。後継が木にあればそのペイン、無ければ最初の葉、無ければ null |
| タブから外す（current 以外）                                                                    | 削除             | その葉を除いて畳む                                              | 変えない                                                          |
| ペインがスナップショットから消える                                                              | 削除             | その葉を除いて畳む                                              | ID を保持（表示は一覧）                                           |
| 消えた current が再出現                                                                         | 右端追加         | 空なら 1 枚。木があれば最初の葉を置換                           | そのペイン                                                        |

| ドラッグ: 中央へ落とす（木の外）                                                                | 無ければ右端追加 | 対象の葉を置換                                                  | 動かしたペイン                                                    |
| ドラッグ: 固定ゾーンのタブへ落とす（2026-11-11 追記、[ADR 0064](0064-tab-strip-swap.md)）       | 変えない         | 中央へ落とす（木の中）と同じく 2 つの葉を入れ替える             | 動かしたペイン                                                    |
| ドラッグ: 端へ落とす                                                                            | 無ければ右端追加 | 対象の葉を、その向きの分割に置き換える                          | 動かしたペイン                                                    |
| ドラッグ: 自分自身の端へ落とす（2026-11-11 改訂、[ADR 0063](0063-tab-order-by-pane-layout.md)） | 変えない         | その葉を、表示順で次の（木に無い）タブに置き換えてから分割する  | 動かしたペイン                                                    |

### 追加帯と空きスロット

- 追加帯を廃止する。詳細の右端は常に最後のセルが埋める
- 空きスロットを廃止する。タブから外したペインの位置は残さず、隣のセルが広がる。空きスロット用の × も無くなる
- 分割の入口はドラッグだけ。分割トグルは持たない（ADR 0058 の判断を維持）
- 4 枚を超える追加は受け付けない。ドラッグ中にオーバーレイを出さず、落としても何も起きない

### ドラッグ

- 起点はタブバー、セルの見出し、一覧のペイン行（`すべて` のツリーと `アクティブ`）
- ドラッグ中、ポインタの下の落とし先に**ドロップのプレビュー**を出す。常設の帯は出さない
  - セルの中央（32〜68%）: セル全体を囲み、「ここで入れ替え」／グリッド外のタブなら「この位置に表示」
  - セルの端（上下 32%、左右 32%）: 分割後に新しいセルが入る半分を塗り、「上に追加」「下に追加」「左に追加」「右に追加」
  - 固定ゾーンのタブ（2026-11-11 追記、[ADR 0064](0064-tab-strip-swap.md)）: タブを枠で囲む。意味はセルの中央へ落とすのと同じ入れ替えで、セル側の枠は出さない
  - プレビューの色は対象セルのスロット色。落とせない場所（空く側へ入れるタブが無い、4 枚を超える、同じ向きのネスト、固定ゾーンの外のタブ）では出さない
- 分割できる向きだけをプレビューに出す。左右並びのセルは上下、上下並びのセルは左右。単独セルは 4 方向
- 落としたあとは、動かしたペインを current にする
- ドラッグ中は、掴んでいるタブの名前とグリップをポインタの近くに出す。画面上端に近いときは上に出すと画面外へ切れるので、ポインタの下に出す

### 自分自身への端ドロップ（2026-11-11 改訂）

1 枚のセルに複数のタブがあるとき、current のタブをそのセルの端へドラッグしても分割できなかった。VSCode と同じく、自分の組からタブを切り出す操作として扱う。

- 木の中のペインを自分自身の端へ落とすと、そのペインを指定した側の新しいセルへ出し、元のセルには表示順で次（無ければ手前）のタブを入れる。次が既に木に並んでいれば、さらにその次を使う（2026-11-11 改訂、[ADR 0063](0063-tab-order-by-pane-layout.md)）
- 例: `[frontend, review]` のタブで `review` だけが表示されているとき、`review` を右端へ落とすと `frontend | review` になる
- 空くセルへ入れるタブが無い（タブが 1 枚、他のタブがすべて木にある）、4 枚を超える、同じ向きのネストになるときはプレビューを出さず、落としても何も起きない。中央へのドロップも従来どおり受け付けない
- タブバーとセル見出しのどちらの起点でも同じように動く。セル見出しから始めたときも、掴んでいるペインの名前を出す

### 一覧の行からのドラッグ（2026-11-11 改訂）

起点がタブバーとセルの見出しだけだと、まだ開いていないペインを分割の端へ入れるには、先に開いてタブにしてから掴み直す必要があった。一覧のペイン行も起点に加え、開く操作と分割を同じドラッグで行えるようにする。

- 起点は `すべて` のツリーのペイン行と `アクティブ` の行。どちらもペインを表す行だけを使う
- 落とし先と結果はタブからのドラッグと同じ。木の外のペインを端へ落とすと、`openTabs` の右端に足して分割する
- 行のタップは従来どおりそのペインを開く。ドラッグが成立した後の click では選択を動かさない（タブと同じく、次の押下で解除する）
- 落としたときの選択はレイアウト操作として扱い、既読の保留は作らない（タブからのドラッグと同じ）。既読は `アクティブ` の行をタップして離れたときにだけ進む（[ADR 0017](0017-active-agents-view.md)）
- `すべて` の束の見出しは並べ替えの起点（[ADR 0052](0052-workspace-order-drag.md)）なので、分割には使わない
- 一覧は縦にスクロールする。触れる画面では縦の動きをスクロールに譲り、セルの方へ向かう横の動きだけをドラッグの開始とみなす。行に `touch-action: pan-y pinch-zoom` を置く

### スロット色

- 4 色のまま。葉を読み順（上端→左端）にたどり、左上から右下の順に 1〜4 を割り当てる（2026-11-11 改訂、[ADR 0063](0063-tab-order-by-pane-layout.md)）。木の構造順（深さ優先）は T 字と 2x2 の組み直しにだけ使う
- タブの左端のバー、セルの枠、一覧の現在行で同じ色を使う
- 同じ向きのネストを作らないので、1 ペインの幅は最低でも 1/2（2 列のとき）になり、本文の読み幅を確保できる

### アニメーション

- 位置が変わるセルは、前の位置から新しい位置へ滑らせる（FLIP、200ms、ease-out）。入れ替えと移動が対象
- 分割で新しく増えたセルは 160ms のフェードで入れる。寸法まで補間すると文字が伸びるので、大きさの変化は補間しない
- `prefers-reduced-motion: reduce` では動かさない。初回表示とウィンドウのリサイズでも動かさない

### 永続化

- キーは `hwc-split-view` のまま。形は `{ openTabs: string[], recent: string[], current: string | null, layout: SplitNode | null }`（`recent` は 2026-11-11 追記、[ADR 0063](0063-tab-order-by-pane-layout.md)）
- 壊れた値は空として扱う。葉が重複していたら後から出た方を捨て、4 つを超えたら切る。子が 2 つでない分割、同じ向きに入れ子になった分割は、葉の順を保って 2 つずつに組み直す
- 旧形式（`slots`）は `layout` を持たないので空として読み、`current` があれば 1 枚で復元する。移行はしない（ADR 0058 の「既存キーは移行しない」を踏襲）

### 変えないこと

- タブの履歴、タブの ×（ペインは閉じない）、プレビュー、モバイルの扱い
- 分割は広い画面だけ。モバイルはタブの切り替えだけ
- リサイズ（サッシュ）は持たない。ADR 0058 の「ウィンドウマネージャにしない」判断を維持する

## Consequences

- 右端の常設帯が消え、1 枚表示の本文幅が戻る。分割の入口はドラッグだけになるので、初めて使う人はタブをドラッグして気付く必要がある
- タブが 2 枚以上あれば、1 枚表示の current タブをそのまま端へドラッグして分割できる。空く側には、開いた順で次のタブが入る
- ドラッグ中は掴んでいるタブ名がポインタに付いてくるので、どのタブを動かしているかを見失いにくい
- 左右並びの片方の上下へ積む、上下並びの片方の左右へ並べる、といった局所的な分割ができる。3 枚・4 枚の形は利用者が決める
- 空き枠が無いので、タブから外したペインの位置は残らない。隣のセルが広がる。同じ向きの入れ子になる場合は、残ったペインを T 字か 2x2 に組み直すため、位置が入れ替わることがある
- 4 枚を超える追加はできない。5 枚以上はタブで切り替える（従来どおり）
- 一覧から、まだ開いていないペインを直接セルの端へ入れて分割できる。一度開いてからタブを掴み直す手間が減る
- 旧保存値は 1 枚に戻る。再読み込み後に並べ直す必要がある
- 同じ向きのネストを作らないので、1 ペインの最小幅は 1/2（ルート 2 列）または 1/4（2x2）。3 列・3 段は作れない

## Alternatives

- **追加帯を残して方向だけ足す**: 常設の帯という違和感が残る。入口が帯と端の 2 つになり、操作も増える
- **固定グリッドに鏡像を足す**: 3 枚の T 字は作れるが、4 枚の形が固定のまま。分割の方向を選ぶたびにレイアウト表を増やすことになる
- **リサイズ（サッシュ）も入れる**: 自由な比率を持つとウィンドウマネージャになる。ADR 0058 の却下理由は今も有効
- **旧 `slots` の移行**: 4 枚までの並びを木へ写す規則は書けるが、初回だけの利益。ADR 0058 の移行しない方針を踏襲する
- **中央ドロップを「常に置換」にする**: 木の中のペインを動かすときに、移動ではなく置換になり、元のセルが消える。入れ替えの方が結果を予測しやすい
- **自分自身への端ドロップを拒否し続ける**: 別のタブを開くと current のセルが置き換わるため、1 枚表示の current タブを分割できず、VSCode のタブ切り出しと逆になる。空く側を別のタブで埋める案を採る
