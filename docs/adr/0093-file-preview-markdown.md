# ADR 0093: ファイルプレビューの Markdown を描画する

- Status: Accepted
- Date: 2026-11-17
- Revises: [ADR 0090](0090-pane-file-tree.md) の「テキストと HTML はプレーン表示する」

## Context

ペインのファイルツリーから開くテキストは、行番号付きのソース表示で出している（[ADR 0090](0090-pane-file-tree.md)）。[ADR 0092](0092-file-preview-syntax-highlight.md) で色も付いたが、Markdown の記号は読むためのものではなく、目次や表、コード例としては読みにくい。チェックアウトの `README.md` や `docs/*.md` は、エージェントの会話に出てこなくても開く機会がある。

会話の本文には、移植した Markdown パーサと描画層がある（[ADR 0014](0014-markdown-rendering.md)）。HTML 文字列を経由せず、生 HTML も実行しない。ファイルプレビューのために新しい依存や描画経路を足す必要はない。

ファイルプレビューはチェックアウトの任意のファイルを開ける。Markdown の中の相対参照は、会話の本文と違って「どのファイルからの参照か」が 1 つに決まる。

## Decision

- `.md` をファイルツリーから開いたときは、`src/client/Markdown.tsx` で描画した表示を既定にする。拡張子が `.md` 以外のファイルは今までどおりソース表示にする。中身を見て Markdown かどうかを判定しない
- プレビューの見出しに「ソース」/「プレビュー」の切り替えを置く。ソース表示は行番号とシンタックスハイライトを保つ（[ADR 0092](0092-file-preview-syntax-highlight.md)）。表示の選択は開いているファイルごとで、開き直すと描画に戻る
- 相対参照は、表示中のファイルのディレクトリを基準にチェックアウトの根からの相対パスへ直す。先頭の `/` は根からの絶対パス、`..` は根より上へ出たら解決しない。外部 URL・プロトコル相対・フラグメントだけの参照は、既存の描画層に任せる
- 画像は、解決したパスの拡張子が画像の配信対象（`previewContentType` が `image/*`）のときだけ本文の位置に描く。BFF の allowlist が配信の境界で、会話のチップと違って実在の事前確認はしない（任意のファイルを解決する API を通していない）。見つからない画像はブラウザの壊れた画像になる
- 相対リンクは会話と同じ行き先にする。テキストは生の中身を新しいタブ、HTML はペインのプレビュータブ、画像は拡大ダイアログで開く（[ADR 0109](0109-relative-path-links.md)）
- 解析上限（200KB）と表示上限（先頭 256KB）は今までどおり。上限を超えた本文は Markdown にならず、注意の行は描画の上にも出す
- コードフェンスはハイライトしない（[ADR 0014](0014-markdown-rendering.md)）。タスクリストはチェックボックスとして描くが、押した結果は保存しない
- 描画は会話と同じ読み幅（`--hwc-measure`）に収め、広いセルでは中央へ寄せる。ソース表示は行番号を揃えるため全幅のまま横スクロールする

## Consequences

- `README.md` や設計メモを、記号ではなく見出し・リスト・表・コードとして読める。ソースを行番号付きで確認したいときは切り替えで戻れる
- Markdown の描画とソース表示で、同じファイルの見た目が大きく変わる。見出しはページのアウトラインに混ぜないよう h3〜h6 になる（[ADR 0014](0014-markdown-rendering.md)）
- 相対画像は実在を確かめずに `<img>` にする。壊れた参照は壊れた画像として出る。配信は BFF の根と allowlist の内側に限られる
- 相対リンクの `.md` は生のソースを新しいタブで開く。描画したまま別のファイルへ移る導線は持たない
- 画像やリンクの解決はファイルの場所に依存する。同じ Markdown でも、置き場所が変われば参照先も変わる
- ソース表示に戻すと、シンタックスハイライトのトークンを作り直す。切り替えのたびにファイル 1 つ分の走査が走る
- 200KB を超える Markdown は描画されず、プレーンなテキストになる。上限はソース表示でも同じ
- チェックボックスは押せるが保存されない。ファイルを編集する機能ではないことが、読み上げの説明だけでは伝わりにくい

## Alternatives

- **外部ライブラリ（marked / markdown-it）を追加**: [ADR 0009](0009-dependency-policy.md) に反する。既存のパーサで足りる
- **描画だけにしてソース表示をなくす**: 記法やインデントを確認したいときに、新しいタブで生の中身を開く往復が要る。行番号とハイライトも失う
- **拡張子ではなく中身やファイル名で判定**: `README` のような拡張子の無いファイルを Markdown として扱うには、全ファイルを読んで判定することになる。誤判定したときの影響も大きい
- **すべてのテキストを Markdown として描く**: ソースコードの `#` や `*` が見出しや強調に化ける
- **相対画像の実在を BFF に問い合わせる**: 画像ごとにリクエストが増える。会話のチップは本文の解析結果を BFF がまとめて照合するが、ファイルプレビューにはその経路が無い
- **相対リンクで同じプレビューを開き直す**: 戻る履歴が無く、「会話に戻る」しか出口がなくなる。ファイルを移る導線はツリーに任せる
- **HTML も同時に描画する**: HTML は iframe のプレビューが既にあり、ファイルツリーからはソースを見る用途が残っている（[ADR 0090](0090-pane-file-tree.md)）
