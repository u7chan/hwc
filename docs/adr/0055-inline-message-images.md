# ADR 0055: 本文の画像記法をその位置に描く

- Status: Accepted
- Date: 2026-11-10
- Supersedes: [ADR 0018](0018-pasted-image-attachments.md) の「Markdown への画像描画をしない」、[ADR 0041](0041-agent-message-images.md) の「メッセージの下にまとめて並べる」

## Context

ADR 0041 / 0051 は、本文に書かれた画像と HTML のパスを拾い、メッセージの末尾にまとめて出していた。画像記法 `![alt](path)` は描画せず原文のまま残すため、4 枚のスクショを画像記法で並べた返答では、記法の行が 4 つ続いたあとに画像が下へ並ぶ。どの行がどの絵かを読み手が突き合わせることになる。

記法を残していた理由は、ADR 0018 の「コピーできるように原文を残す」だった。しかしメッセージ全体のコピーボタンがあり、本文のパスもそのまま残る。記法だけを残す必要はない。

変えてよい範囲には制約がある。描画の対象は BFF が実在を確認したファイルだけにする。クライアントが destination から直接 `<img src>` を作ると、認証の無い LAN 公開（[ADR 0010](0010-lan-access.md)）で任意のパスを読む口が開き、SVG を配信しない判断（ADR 0018）も崩れる。

## Decision

- インライン解析は `![alt](path)` を `image` ノードにする。`literal` に落とすのは、描画先が決まらないときだけ
- 描画するかは、BFF が返す `ChatFile.imageRefs` と destination の一致で決める。`imageRefs` は画像記法の destination として本文に現れた表記そのもので、URL ではなく照合キー。一致しなければ従来どおり原文を等幅で出す
- `imageRefs` は `kind: "image"` のときだけ付ける。同じ実体を複数の表記が指す場合はすべて持つ
- インラインで描画した画像は、メッセージ末尾の一覧から外す。末尾に残るのは、本文で裸のパスとしてだけ書かれた画像と、HTML のチップ
- 末尾から外すのは、解析の結果その位置に `image` ノードになったものだけ。フェンスの中の記法や、解析上限を超えてプレーン表示に落ちる本文は、描いていないので末尾に残す
- 画像記法だけでできた段落が連続するときは、1 つの行にまとめる。行は折り返し、横スクロールはしない（スマホで絵を見失わない）
- 押すと既存の拡大ダイアログ（[ADR 0042](0042-image-preview-dialog.md)）を開く。alt は拡大ボタンの読み上げ名に使い、空ならファイル名にする。img は装飾として alt を空にする（ADR 0042）
- 根・対象形式・件数と大きさの上限は ADR 0041 / 0051 のまま。実在しないパス、根の外、未対応形式は原文のまま残る

## Consequences

- 画像記法の文字列は本文から消える。コピーはメッセージのコピーボタンで行う
- 表・リスト・引用の中でも、書かれた位置に出る
- 画像を並べた返答は縦に長くならない。幅が足りない分は折り返す
- 本文のパス文字列は残るので、パスだけをコピーしたいときは今までどおり選べる
- 検出の上限（1 通 20 候補・4 ファイル）を超えた画像記法は、原文のまま残る
- 同じ画像を 1 通の中で 2 回書けば 2 回出る。URL は同じなので追加の取得は起きない

## Alternatives

- **クライアントが destination から直接 `<img>` を作る**: 実在確認を飛ばす。任意パス配信の口になり、SVG も描けてしまう
- **末尾の一覧のまま**: 位置が分からず、記法の行と絵を突き合わせる手間が残る
- **インラインと末尾の両方に出す**: 同じ絵が 2 回出て、メッセージが長くなる
- **HTML も画像記法の位置にチップとして差し込む**: HTML を指す画像記法は普通書かれない。まず画像だけで足りる
