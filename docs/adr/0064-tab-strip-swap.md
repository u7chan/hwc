# ADR 0064: 固定ゾーンのタブをドロップの落とし先にし、タブバーから入れ替える

- Status: Accepted
- Date: 2026-11-11
- Revises: [ADR 0058](0058-split-view-tab-history.md) のドラッグの落とし先、[ADR 0061](0061-split-view-directional-tree.md) の状態遷移表とプレビュー、[ADR 0063](0063-tab-order-by-pane-layout.md) のタブ順の変え方

## Context

[ADR 0063](0063-tab-order-by-pane-layout.md) でタブ順はセルの読み順に固定された。タブの位置とセルの位置、色が 1:1 で対応するので、どのタブがどのセルかは目で追える。

ペインの位置を入れ替える手段は、セルの中央へドロップする 1 つだけだった（[ADR 0061](0061-split-view-directional-tree.md)）。落とし先は `dropTargetAt` が `closest("[data-drop-pane]")` で引くセルに限られる。

- セルが狭いと、中央の判定帯（幅または高さの 32〜68%）も狭くなる。狙いを外すと端へのドロップになり、入れ替えではなく分割になる
- T 字・2x2 では「このタブはどのセルか」を色と名前で照合してから、そのセルまで運ぶ必要がある

タブバーの固定ゾーンはセルの読み順そのものなので、タブを直接入れ替えられる方が対応を追わずに済む。

## Decision

### 落とし先に固定ゾーンのタブを足す

`DropTarget` に落とし先の種類（セル / タブ）を持たせ、`dropTargetAt` はセル、次にタブの順で見る。

- タブ側は `closest("[data-drop-tab]")` で引く。`data-drop-tab` は固定ゾーンのタブ（`slot >= 0`）の `.hwc-tab-item` に置く
- 落とし先の意味は起点で変えない。固定タブへ落とすのは、セルの中央へ落とすのと同じ入れ替えとして扱い、適用は既存の `dropOnPane(view, source, target, "center", wide)` をそのまま使う。状態遷移は増やさない

| 掴む（起点）                                       | 落とす先         | 結果                                                 |
| -------------------------------------------------- | ---------------- | ---------------------------------------------------- |
| 固定ゾーンに居るペイン（タブ・セル見出し・一覧）   | 固定ゾーンのタブ | 2 つのセルの中身を入れ替える。current は掴んだペイン |
| 固定ゾーンに居ないペイン（タブ・セル見出し・一覧） | 固定ゾーンのタブ | 何も起きない。プレビューも出さない                   |
| タブ・セル見出し・一覧の行                         | セル中央 / 端    | 今どおり（入れ替え / 置換 / 分割）                   |
| どの起点                                           | それ自身         | 何も起きない                                         |

- 掴む起点は変えない。タブのうち固定ゾーンの外に居るものも掴める。起点を固定ゾーンに絞ると、木の外のタブをセルの端へ落として分割する経路と、特定のセルへ中央ドロップで差し替える経路がタブバーから消える
- 起点はタブ・セル見出し・一覧の行の 3 系統あるが（[ADR 0061](0061-split-view-directional-tree.md)）、同じペインを同じ場所へ落としたときに、掴んだ場所で結果が変わらない方が説明しやすい
- 受け付けの判定は純関数 `canSwapTabs(view, source, target, wide)` が持つ。真になるのは、`wide` が真で、`source !== target`、`source` と `target` の両方が `readingOrder(view.layout)` に含まれ、その長さが 2 以上のときだけ。`canDrop` と同じく広い画面を引数で受け取る
- 葉の数を見るのは防御。固定ゾーンは `wide` かつ葉が 2 枚以上のときだけ出るが（`tabPanes`）、`TabBar` は 1 枚表示でも `slots` を受けるため `data-slot` が付く

これにより、タブバーのドラッグで固定ゾーンの**メンバーは変わらない**（並びだけ変わる）。メンバーの入れ替えはセルへのドロップ、タブの ×、開く操作に限る。

### ドロップの枠

- 落とし先が固定タブのときは、セル側のドロップ枠を出さない。タブ側だけに枠を出す
- タブの枠は `data-drop-target="true"` と `box-shadow: inset 0 0 0 1px var(--slot-color)` で描く。`border` だと幅が内容依存のタブ列が対象のたびにずれ、外側の `outline` は `.hwc-tabs` の `overflow-x` で上下が切れる
- セルの枠は落とし先がセルのときだけ出す。セルのプレビューは落とし先のペイン ID の一致だけで出しているので、タブを落とし先にしたときも ID は一致する。種類で分けないとセル側にも枠が出る
- HTML プレビューの表示中は固定タブを落とし先にしない。グリッドが見えないままレイアウトが変わると結果を確認できない。プレビュー中に追加帯を出さない既存の判断（[ADR 0058](0058-split-view-tab-history.md)）に合わせる。`TabBar` は既に持っている `previewing` で `data-drop-tab` を出し分けるので、プレビュー判定用の prop は増やさない

### 永続化と木の形

- 木の形は変わらない。`swapLeaves` は葉のペイン ID を入れ替えるだけなので、保存は `layout` の変化として `hwc-split-view` にそのまま乗る。タブ順は保存しない（[ADR 0063](0063-tab-order-by-pane-layout.md)）

### アニメーション

- セルの移動は既存の FLIP がそのまま効く。タブは並び順の導出なので、同じフレームで即座に入れ替わる

## Consequences

- タブバーだけで 2 つのセルを入れ替えられる。セルの中央の判定帯を狙う必要がなく、T 字・2x2 でもタブの位置とセルの位置を照合せずに済む
- タブバーのドラッグで固定ゾーンのメンバーは変わらない。並びだけが変わるので、`recent` の意味は保たれる
- セルを経由しない入れ替えが増えるが、状態遷移は増えない。`dropOnPane` の中央ドロップと同じ経路を通る
- タブは滑らず、セルだけが滑る。入れ替え直後はタブの位置とセルの位置が一瞬ずれて見えることがある
- 固定タブの端へ落としても分割しない。タブの端判定には分割の向きが要るが、タブはセルと違って親方向を持たない。タブの幅で 32% の端判定帯を作ると狭すぎる

## Alternatives

- **挿入してずらす（タブの並べ替えと同じ）**: 掴んでいないセルまで動く。2 枚では同じ結果になるが、3〜4 枚で結果を予測しにくい。入れ替えを採る
- **固定ゾーンの外のタブも落とせる**: `recent` は選択履歴から導出する値なので、手で並べ替えると意味が壊れる
- **固定ゾーンの外のタブを固定タブへ落として差し替える**: タブバーは並べ替えの場に一本化する。差し替えはセルの中央へ落とす経路に残す
- **タブの端へのドロップで分割**: タブは親方向を持たないので、分割の向きを決められない。セルの端へ落とす既存の経路を使う
- **プレビュー中も落とし先にする**: グリッドが見えないままレイアウトが変わり、結果を確認できない
- **タブの入れ替えも FLIP で滑らせる**: タブは `layout` から導出した並びで、位置を持つ要素ではない。滑らせるには前後の位置を別に持つことになり、導出できる値を state に置く原則に反する
