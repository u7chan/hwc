# ADR 0120: 入力欄の `@` でプロジェクトを補完する

- Status: Accepted
- Date: 2026-11-21
- Amends: [ADR 0037](0037-enter-newline-on-touch.md) の「Enter の意味は入力機器だけで決める。添付の有無やコマンド候補の出方では変えない」
- Revises: [ADR 0056](0056-project-picker.md) の入力欄（入口が + メニューだけだった）

## Context

プロジェクトを本文へ入れる入口は、+ メニューの「プロジェクトを選ぶ」だけだった（[ADR 0056](0056-project-picker.md)）。+ は、入力欄を 1 行に畳む分割セルには出ない（[ADR 0055](0055-composer-add-menu.md)）。PC で分割ビューを使うと、モノレポで修正対象のプロジェクトを選ぶ手段が無い。

CLI の TUI は `@` でパスを補完するので、PC の利用者は本文を打ちながら選びたい。+ → メニュー → ダイアログ → 検索 → 選択の 4 手を、`@` と数文字と確定に縮められる。

主端末はスマホだが、この入口は PC だけを対象にする。スマホでは `@` を打つのに記号キーボードへの切り替えが要り、候補をタップすると本文がフォーカスを失ってソフトキーボードが閉じる。ダイアログは残るので、スマホの入口は変わらない。

## Decision

### 出す条件

- 会話を持つペインで、編集中でなく、起動待ちでも入力無効でもないときに出す。+ が出るかどうかには依存せず、分割セルでも出す
- 主ポインタが粗い端末（`(pointer: coarse)`）には出さない。判定は Enter の判定（[ADR 0037](0037-enter-newline-on-touch.md)）と同じ方式で、描画のたびに行う
- キャレット直前の語が `@` で始まるときに出す。`@` は行頭か空白の直後に限り、`a@example.com` のような語中の `@` は拾わない。範囲選択中は出さない
- 置き換える範囲は `@` からキャレットまで。キャレットより後ろの文字は読まない

### 候補

- 一覧は [ADR 0056](0056-project-picker.md) の API と並び替え・件数（`filterProjects`）をそのまま使う。多いときはスクロールで見て、語を足して絞る
- 一致が 0 件、読み込み中、取得失敗のときは何も出さない。失敗の再試行はダイアログに任せる
- 一覧は `@` が候補の対象になるたびに取り直す。BFF が cwd ごとに 30 秒キャッシュするので走査は増えない。取り直す間は前の一覧を残し、別ペインの一覧は使わない。取得はダイアログと共有のフック（`use-projects.ts`）に置く
- 強調している候補は path だけを state に持つ。入力があれば先頭に戻し、閉じた記録も消す。閉じた記録は `@` の位置と語を持つ

### 表示と操作

- 候補は入力欄の上に重ねる縦のリスト（popup）にする。1 行に名前とパスを並べ、強調は面の色で示す。見出しは「プロジェクト」で、CLI の `@` のようにファイルが出ると思わせない。入力欄の高さと会話の位置は動かさず、高さはセル（分割セルを含む）の半分までに収める。位置の決め方は、入力欄の上に重なる情報パネル（[ADR 0036](0036-input-hint-panel.md)）に倣う
- 候補はキーボードのある端末にしか出ないので、固定行に置く理由（ソフトキーボードに隠れる。[ADR 0016](0016-composer-command-chips.md)）は当たらない。コマンド候補とチップは固定行のまま
- クリックと Tab と Enter で確定する。↑↓ で強調を動かし（端で折り返し、見えない行はスクロールで追う）、Esc で閉じる。マウスは動かしたときだけ強調を移す。閉じたあとは次の入力まで同じ語では出さない
- 修飾キー付きの Tab / Enter は確定にしない。Shift+Enter は改行のまま。IME の変換中は何もしない
- クリックは本文のフォーカスを外さない。選んだあともそのまま続けて打てる

### 挿入

- `@語` を `./<path>/` で置き換える。`@` は残さない。`@path` の意味は CLI ごとに違い、内容を読ませる保証が無いので、[ADR 0056](0056-project-picker.md) と同じくパスの文字列だけを入れる
- 前後の空白、キャレット、チップの扱いは [ADR 0056](0056-project-picker.md) と同じ。`new` は解除し、`compact` の指示は残す

### Enter

- 候補が出ている間だけ、Enter は送信ではなく候補の確定にする。[ADR 0037](0037-enter-newline-on-touch.md) の「候補の出方では変えない」は、この 1 つを例外とする
- 候補は PC にしか出ないので、タッチ端末の Enter は改行のまま。一致が 0 件、Esc で閉じたあと、読み込み中は、従来どおり Enter で送信する

## Consequences

- `@ai` を本文のままで送りたいときは、Esc で閉じてから Enter を押す
- 初回は、BFF の走査が終わるまで候補が出ない。その間の Enter は本文として送られる
- 補完するのはマニフェストのあるディレクトリだけで、ファイルは出ない。CLI の `@` と同じ期待で `@src/index` と打っても何も出ない
- `@types` のようにプロジェクト名の途中まで一致する語を打つと、確定する気のない間も候補が出る。Esc か、そのまま続けて打てば消える
- キャレットはフォーカス・クリック・キー入力・キーアップで読み取る。マウスのドラッグで範囲を作っている間は 1 拍遅れる
- popup は会話の末尾を一時的に隠す。Esc か、一致しない語までの入力で消える
- ダイアログは残す。全体の一覧、取得失敗の再試行、タッチ端末の入口はそちらにしかない

## Alternatives

- **分割セルにも + を出す**: 分割セルは入力欄を 1 行に畳んで会話へ高さを回す設計で、+ を足すと本文の幅を削る（[ADR 0055](0055-composer-add-menu.md)）
- **Tab だけで確定し、Enter は送信のままにする**: [ADR 0037](0037-enter-newline-on-touch.md) を変えずに済むが、CLI の習慣で `@ai` と打って Enter を押すと、未完成のまま送信される
- **固定行のチップ**: 最初の実装。コマンド候補と同じ作りで済むが、プロジェクトのパスが長く、5 件でも 2 行に折り返し、名前を見比べにくい。候補が出入りするたびに会話の位置も動き、件数も絞らざるを得ない
- **スマホにも出す**: タップで本文がフォーカスを失い、ソフトキーボードが閉じる。回避には実機での確認が要るので、必要になるまで足さない
- **`@./path/` と `@` を残す**: CLI によって意味が違い、[ADR 0056](0056-project-picker.md) の「パスの文字列だけを入れる」と食い違う
