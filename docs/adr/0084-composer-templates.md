# ADR 0084: 設定で登録した定型文を、+ メニューから本文へ入れる

- Status: Accepted
- Date: 2026-11-14

## Context

主端末はスマホで、同じ指示を何度も打つ。本文へ入れる入口は、選択範囲を引用する返信（[ADR 0062](0062-selection-toolbar.md)）と、プロジェクトの相対パスを入れる選択（[ADR 0056](0056-project-picker.md)）だけで、文章そのものを使い回す手段が無い。

入力欄の + は、本文に足すものの置き場として始めた（[ADR 0055](0055-composer-add-menu.md)）。画像・ファイル・プロジェクトと同じ入口に定型文を載せれば、入力欄の近くに常設の選択肢ができる。

定型文の本文は長いことがある。入力欄へ入れてから読むと、選び直すたびに入力欄をスクロールすることになる。似た名前の定型文を見分けるには、入れる前に本文を読める場所が要る。

## Decision

### 保存

- 定型文は BFF が正とし、状態ディレクトリの `templates.json` に置く。通知・再起動の設定と同じ形で、読み書きの失敗は起動を止めない
- `GET /api/templates` は `{ templates }` を返し、`PUT /api/templates` は一覧をまるごと置き換える。応答は保存後のスナップショットで、クライアントはそれをそのまま表示する
- 上限は 30 件・名前 40 文字・本文 2000 文字。名前は 1 行に畳み、本文は前後の空白を落として CRLF を LF に直す。コードポイントで数える
- id はクライアントが振る。`crypto.randomUUID()` は secure context に限られ、LAN の HTTP では使えないため、時刻と乱数から作る。サーバーは英数字・ハイフン・アンダースコア 64 文字までを受け、重複を拒む
- 壊れたファイルは読めた行だけを使う。API の入力は 1 件でも壊れていれば全体を 400 で拒み、メモリ上の一覧を変えない

### 設定

- 設定画面の「表示」の次に「定型文」を置く。行は名前と本文の 1 行目だけを出し、タップで編集フォームを開く。削除はフォームの中に置き、確認ダイアログを挟む
- 行に「編集」「削除」を並べると、390px では名前と本文プレビューの幅が足りない。0 件のときは空状態と追加ボタンを出す
- 保存は一覧まるごと送る。成功したら応答の一覧で置き換えてフォームを閉じる。失敗したらフォームと入力を残し、理由を出す
- 上限に達したら追加ボタンを無効にし、理由を補足文に出す。長さの超過は保存時に理由を出す（本文は文字数カウンタでも示す）

### + メニュー

- 区切りの下の先頭に「定型文を入れる」を置く。補助文は「登録した文を入力欄へ入れる」
- 0 件のときは無効にし、補助文を「設定で登録できます」にする。空のダイアログを開かせない
- 会話を圧縮のチップ中は無効にし、補助文を「圧縮の指示には使えません」にする。入力欄が圧縮の指示になるため、長い定型文を入れる先ではない
- 表示は会話を持つペインだけ。シェルと 1 行に畳んだ分割セルには + を出さない（ADR 0055）

### ダイアログ

- 名前の札を折り返して並べ、タップした札の本文を下に出す。札のタップは選択だけで、入れるのは「本文に入れる」を押したとき。似た名前の定型文を読み比べられる
- 札は最小高 44px の名前だけにし、`role="radiogroup"` / `role="radio"` と `aria-checked` で選択を表す。矢印キーで札を移動する
- 検索は名前の部分一致。自動フォーカスしない（キーボードがプレビューを潰すため）。絞り込みで選択中の札が消えたら選択を解除する
- ダイアログの高さは `min(560px, 100dvh − 32px)` で固定する。札を切り替えるたびに伸び縮みすると、選び直すたびに位置が動く
- 札の領域は 44px の札 3 行まで（最大 148px）で内部スクロール。プレビューは残りの高さで枠内スクロールし、本文と文字数を出す。低い画面では札とプレビューを縮める
- 高さ 380px 以下では、札 1 行（44px）とプレビューの最小 120px を同時に確保できない。この範囲だけダイアログの中身を 1 つのスクロールにし、札は自然な高さのまま並べ、プレビューはその下に自然な高さで置く。札のタップを潰さず、本文もスクロールで読めるようにするため。380px は、札 1 行とプレビュー最小 120px を同時に確保できる下限
- 主操作は「本文に入れる」で、選択が無いとき・一致が無いとき・読み込みに失敗したときは無効。読み込み中はスピナー、失敗は理由と「再試行」、0 件と一致なしは別の文言にする
- 入れるとダイアログを閉じ、本文へフォーカスを戻してカーソルを挿入末尾へ置く。閉じただけなら + にフォーカスが戻る

### 挿入

- 本文はカーソル位置（選択範囲は置換）へ入れる。前後の文字とくっつかないよう空行 1 つを挟み、既に空行が続く側には足さない
- 入れた本文は普通の下書きにし、チップにはしない。送る内容が見えたまま編集でき、取り消しも文字の削除だけで済む（ADR 0056 の「本文の一部にする」と同じ扱い）
- チップは文字を打ったときと同じ規則で扱う。`new` は解除し、`compact` の指示は残す。下書き・添付・引用はそのまま残す

## Consequences

- - メニューは 5 項目になり、会話の末尾を隠す面積が増える。画面より高くなれば内部をスクロールする
- 定型文は全ペイン共通で、ペイン・エージェント・プロジェクト別の出し分けは持たない。増えたら検索で絞る
- 変数展開（ブランチ名など）、即時送信、並べ替えは持たない。本文は 2000 文字までなので、超える指示は分割して登録する
- 保存は一覧まるごと。2 台から同時に編集すると、最後に保存した一覧が勝つ。競合の解決は持たない
- 挿入は空行で区切る。カーソルが行の途中にあるときも段落として入るので、続けて書くときは改行を消す
- 高さ 380px 以下では、札とプレビューを同時に見せられない。札を選んだ後に本文を読むには、ダイアログの中身をスクロールする。フッターの「本文に入れる」は常に見える
- 設定画面を開くとペイン詳細が外れ、戻ると + メニューのために定型文を読み直す。読めないときは押せる側に倒し、ダイアログが読み直して失敗を出す
- 定型文の本文は BFF の状態ディレクトリに残る。ブラウザを変えても同じ一覧を使える

## Alternatives

- **localStorage に保存する**: サーバー変更は不要だが、スマホと PC で同じ定型文を使えず、ブラウザのデータ削除で消える。設定画面の他の項目は BFF が正なので、置き場所が分かれる
- **+ メニューに定型文を直接並べる**: 選択は 1 タップで済むが、項目数が増えるとメニューが会話を覆い、長い本文を出せない。並び順も固定になる
- **選んだら即送信する**: 誤タップがそのままエージェントへの指示になる。入れるだけにして、送信は既存の操作に任せる
- **入力欄でチップに畳む**: 長い本文を入力欄に置かずに済むが、送る内容が見えず、そのまま編集もできない。ADR 0056 の判断と衝突する
- **変数展開を持つ**: ブランチ名やパスを差し込めると便利だが、置換の失敗が本文に残り、どの変数が使えるかを CLI ごとに決める必要がある
- **設定を別画面にする**: 設定の中の 1 セクションで足りる。入口を増やすと、+ から登録への導線も分かれる

## Verification

- unit: 名前・本文の正規化と上限、保存ファイルの読み書き、API の検証・保存失敗、絞り込み、挿入位置と空行の扱い
- 架空 Herdr の E2E: 設定での登録・編集・削除、+ メニューの有効・無効と補助文、ダイアログの選択・プレビュー・検索・一致なし、挿入後の本文とフォーカス。844×390 と 844×320 の低い画面で、札が潰れずに選べることと本文が読めることを確かめる
