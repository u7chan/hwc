# ADR 0016: 入力欄は文字列をそのまま送り、コマンドは 2 つだけ候補に持つ

- Status: Accepted
- Date: 2026-11-03

## Context

hwc の入力欄は、書かれた文字列をそのままペインへ送る。BFF は `POST /api/panes/:id/input` で受け取り、Herdr の `pane.send_input` に `{ text, keys: ["enter"] }` として渡すだけになる（[ADR 0002](0002-herdr-socket-integration.md)）。

エージェントの TUI コマンドもこの経路で発火するが、hwc は候補も検証も持たないため、誤入力の壊れ方がエージェントごとに違う。

- pi は未知のコマンドをエラーにせず、そのまま本文としてモデルへ渡す
- Claude Code と opencode は `Unknown command:` で止める
- ピッカーを開くコマンド（`/model` など）は、hwc が汎用のキー入力を持たないため、開いたあと GUI から操作も取消もできない。停止の Esc だけは例外（[ADR 0025](0025-stop-working-agent.md)）

GUI で意味のあるのは、ピッカーを開かず、即時実行される「新しいセッション」と「会話を圧縮」に限られる。4 つの CLI はいずれも `/new` と `/compact` を受け付ける（Claude Code の `/new` は `/clear` の別名、opencode の `/clear` は `/new` の別名、Codex CLI の `/clear` は端末表示も消すため別物）。

引数の扱いはコマンドごとに違う。`/compact` だけは要約の指示を取り（pi の `dist/modes/interactive/interactive-mode.js` は `/compact <指示>` を解釈する）、hwc はこの 1 コマンドの引数だけをチップ経由で組み立てる。

`/compact` は履歴が小さいと失敗する。pi の `prepareCompaction()` が `undefined` を返すと `Nothing to compact (session too small)` になり、要約対象が無いのは履歴が `keepRecentTokens`（既定 20000）に収まっている場合などに起きる。この失敗は hwc の画面に出ない。chat ペインは端末出力を表示しておらず、pi は失敗をセッションにも残さず、Herdr の `pane.send_input` も結果を返さない。

## Decision

- 入力契約は「hwc は入力欄の文字列を解釈しない」のままにする。例外は hwc が存在を知っている `/new` と `/compact` だけで、送信経路は通常の文字列送信と同じ（BFF と Herdr の変更なし）
- 送る文字列の基底は `src/client/commands.ts` の 1 つの表に固定し、`commands.test.ts` が文字列そのものを見張る。`/compact` だけは入力欄の文字列を後ろに付けて組み立てる純関数（`commandSendText()`）を通す
- 表示名は「新しいセッション」「会話を圧縮」。`/compact` の結果は履歴の区切りで「圧縮」と呼んでいる（`compactionLabel`）ため、チップ・メニュー・placeholder の語を揃える
- 詳細の「…」メニューにも同じ 2 コマンドを置く。メニューは入力欄の状態に依存しない経路として bare の `/new` / `/compact` を送り、`draft`・添付・引用は残す。`compact` の指示には使わない（指示付きはチップか直接入力）。表示はコマンド対応 agent のペインだけ、`working` と送信中は無効、`compact` は閾値未満で無効にして理由を 1 行添える
- 候補は `draft` が `/` で始まり空白を含まず、表の文字列の前方一致（大文字小文字を無視）のときだけ出す。判定は `PaneState`・`draft`・`ChatContext | null` を受け取る純関数にし、DOM なしでテストする。`context` は呼び出し元が `snapshot.context` から渡し、`PaneState` には持たせない（サーバー状態の二重持ちになる）
- `context.tokens` が閾値 `20000` 未満のときは `compact` を候補から外す。閾値は `commands.ts` の定数 1 箇所に置く。`context` か `tokens` が `null` のとき（compaction 直後など）は判定できないので出し、押せて失敗する側に倒す
- `compact` のチップを選ぶと入力欄をそのまま指示の入力に使う。文字を打ってもチップは解除しない。指示は `draft` に入れ、指示用の state を増やさない。送信は `draft` が空なら `/compact`、非空なら `/compact <指示>` で、指示は前後の空白を落とし、改行と連続空白を空白 1 個に畳んでから 1 行で送る
- `compact` のチップ中は `draft` を下書き保存しない。`chip` は state なのでリロードで消えるが `draft` は残り、指示だけが復元されると次回は素の本文として送られてしまう
- 送信が成功したら `chip` と `draft` を両方空にし、失敗したら両方残す。チップの × は両方消す
- チップが `compact` のときは placeholder を「圧縮の指示（任意）」にする。簡略セルでは placeholder を出さない既存規則を変えず、チップのラベルで意味を伝える
- 候補を出すのは `agentGlyph` が `pi` / `claude` / `codex` / `opencode` のペインだけ。`generic` とシェルは TUI のコマンドを持たない
- `agentStatus === "working"` の間は候補を出さず、チップの送信も無効にする
- 候補とチップは入力フレーム内の固定行に置く。絶対配置にするとキーボードに隠れる
- チップは id だけを state に持つ。表示名と送信文字列は表から引く
- コマンド送信では送信中バブルを積まない。`/new` と `/compact` は user メッセージを残さないため、`isPendingConfirmed` の判定では最大 60 秒残る。`/compact` は代わりに、送信した本文（`/compact` または `/compact <指示>`）をローカルの吹き出しとして chat に残す。`/new` は何も残さない
- ローカルの `/compact` の吹き出しは、実行中は末尾、新しい compaction を観測したら区切りの直前へ移す。リロードやペイン切り替えで消える（永続化は別スコープ）
- 手動 `/compact` の直後など、直近の compaction の後ろに発話がない（`compaction.index === messages.length`）ときは `/compact` を候補・メニューから外し、直接入力は「会話は圧縮済みです」の notice にして送らない。pi は `Already compacted` で即失敗し、その失敗はセッションに残らないため、押させると進捗表示だけが残る
- 圧縮中の行は、`/compact` の送信が成功してから、新しい compaction が届くか上限時間（10 分）に達するまで出す。手動の `/compact` は pi の `compaction_start` を Herdr の pi 拡張が拾わず、`agent_status` が `working` にならないため、表示はローカルの開始記録を条件にする。working を観測した場合は idle 復帰から 3 秒で畳む。開始時刻はローカルの state に置き、リロードやペイン切り替えでは失う。完了ログの所要時間も同じくローカルで、リロード後は tokens とホバー時の時刻だけになる（永続化は別スコープ）
- 進捗行の「中断」は Esc を送り、ローカルの開始記録と吹き出しを畳む。10 分の上限は、利用者が中断せず、完了も失敗も観測できない場合の最後の逃げ道
- 画像の添付がある間は候補を出さず、`pick` もしない。添付を持つペインの `Enter` は常に本文（と添付）の送信になる（[ADR 0018](0018-pasted-image-attachments.md)）。画像を貼るとチップは解除するが、`draft` は残す。書きかけの指示を黙って捨てないため
- 引用を開始したときもチップだけを外し、`draft` は残す（[ADR 0022](0022-reply-quote.md)）。残した `draft` は引用に続く返信本文として送り、`/compact` には戻さない。チップは復元しない。引用中は候補を出さない

## Consequences

- 2 つのコマンドは、候補から選ぶ経路では打ち間違えても本文としてモデルへ渡らない。前方一致の候補が 0 件になる入力（`/c` など）は、`Enter` で従来どおり本文として送られる。閾値未満で `compact` を隠している間は、この経路が `compact` でも起きる
- 語彙は増えない。3 つ目が要るときは、4 つの CLI が同じ名前で受け付けることを確かめてから表に 1 行足す
- 入力欄は `/` で始まる本文を候補として扱う。`/` で始まる文章を送りたいときは、候補を選ばずに送信を続ければ従来どおり本文になる。ただし `compact` のチップ中は `/xxx` と打っても本文にならず `/compact /xxx` になる。通常のメッセージへ戻る逃げ道は × だけ
- `/compact 指示` と直接打っても候補は出ず、本文として送られる。チップ経由なら入力欄の文字列が指示になり、`/compact <指示>` として送られる。hwc は `{ text, keys: ["enter"] }` を 1 回で送るため、途中改行は TUI 側の途中送信になり得るので畳んでから送る
- 閾値未満で `compact` を隠しても、手で `/compact` と打てば従来どおり送れる。hwc は入力欄の文字列を解釈しないため
- 閾値 20000 は pi の `keepRecentTokens` の既定値の写しであり、pi 側の既定が変われば追随する義務がある。`keepRecentTokens` を変更しているユーザー、モデル別の上書き、日本語中心の履歴では近似が外れ得る。`tokens` は provider usage の実測で、pi が打ち切り位置に使う推定（`Math.ceil(chars / 4)`）とは別物なので、`tokens >= 20000` でも失敗し得る。閾値が効くのは `context` を持つペイン（現在は pi と opencode）で、agent ではなく context の有無で判定する。opencode の compaction 閾値は pi と同じとは限らないが、履歴が小さいうちに `/compact` を隠す近似として同じ値を使う。将来ほかの CLI に会話を足すとこの定数が黙って適用される
- 直近のエントリが既に `compaction` のとき（`Already compacted`）は `tokens` が `null` になるため防げない。閾値未満で隠した理由も画面には出ない
- `/compact <指示>` を受け付けることは pi で実装を確認し、Claude Code / opencode / Codex CLI はユーザーの確認による。実機で 1 つずつ確かめてはいない。解釈が違う CLI が見つかったら、送信文字列とこの記述を直す
- ピッカーを開くコマンドの GUI 操作は持たない。汎用の Esc と矢印を送れないため、開いた先で詰まる。停止の Esc は入力欄の停止ボタンに限る（[ADR 0025](0025-stop-working-agent.md)）
- コマンドの実行結果は hwc には伝わらない。chat ペインは端末出力を表示しておらず、pi は失敗をセッションに残さないため、`/compact` が `Nothing to compact` で失敗しても画面は無反応に見える。hwc は完了も失敗も検知しない。失敗を可視化するのではなく、起きにくくする方向で扱う
- #47 の受け入れ条件「チップ中に文字を打つと解除され、従来のテキスト送信に戻る」は `new` にだけ当てはまる。`compact` は文字を打っても解除しない（この ADR が #47 の受け入れ条件を `compact` について上書きする）
- 添付がある間は候補も `pick` も出さない点で、「候補は `draft` が `/` で始まるときだけ出す」と「× はチップと `draft` を両方消す」の 2 つが上書きされる。`/compact` と打っても本文として送られ、チップの × は `draft` を消さない

## Alternatives

- **ヘッダにボタンを置く**: 常時見えるが、幅 390px のヘッダは ID・コピー・経過で埋まっており、スマホでは押しにくい
- **候補と確認ダイアログを併用する**: `/new` の破壊性は伝わるが、毎回 1 タップ増える。送る内容が確定しているチップでは不要
- **完全パススルーのまま（現状）**: 実装ゼロだが、2 つの頻用コマンドを毎回手で打つことになり、誤入力が pi では本文としてモデルに渡る
- **エージェント別のコマンド表を持つ**: 語彙と意味が CLI ごとに変わるため、CLI の更新に hwc が追従し続けることになる。この 2 つは 4 つで共通なので表を持たない
