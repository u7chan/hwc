# ADR 0045: 広い画面の会話は読み幅の列に中央寄せする

- Status: Accepted
- Date: 2026-11-08

## Context

広い画面の詳細は、一覧の右の残り全幅をそのまま使う。1920px では本文が 1500px を超え、行長が読みにくい。入力欄も端から端まで伸び、本文の左端と数十 px どころか数百 px ずれる。

DESIGN 仕様は設定や短いフォームの内容を 560px としているが、会話の本文には上限がない。広い画面では行長がそのまま画面幅で決まる。560px を会話に当てるのは狭すぎ、設定画面と同じ値を強いる理由もない。

## Decision

- 読み幅を `--hwc-measure: 52rem`（832px）として tokens.css に置く。本文・ペインの見出し・入力欄・送信失敗の帯・実行中の段階の行・閲覧のみの案内で共有する
- 左右の余白は、広い画面の `.hwc-detail-inner` で `--hwc-gutter: max(var(--space-6), calc((100% - var(--hwc-measure)) / 2))` として導出し、`padding` の左右（`padding-right` と `padding-left`）に当てる。中央寄せのための内側の wrapper は置かない
- 面は全幅のまま残す。入力欄の背景と上罫線、送信失敗の帯の地色、実行中の段階の行の地色は端まで伸ばし、中身だけ列に揃える。カード化しない（広い画面で詳細をカードにしない既存の判断に従う）
- 分割セルはセル幅で同じ式を解く。読み幅に満たないセルは下限の 24px に落ちる。狭い画面（900px 未満）は 16px のまま変えない
- タブバーと詳細バーは列に含めない。画面全体のクロームとして全幅に置く
- 最新へ戻るボタンは `.hwc-output-wrap` の中央のまま。列も同じ中心なので変更しない
- スクロールバーが本文の幅を食う環境では、本文だけ最大 5px 左へ寄る。入力欄とのずれとして許容する

## Consequences

- 1920px では本文・見出し・入力欄が同じ x で始まり、同じ x で終わる
- 実行中の段階の行と閲覧のみの案内も列に入る。経過時間は列の右端に揃い、待機中や閲覧のみでも列から外れた行が出ない
- 分割セルの見出しと入力欄は、広い画面で 24px に揃う（従来は 16px と、本文の 24px からずれていた）
- 列幅はトークン 1 つで変わる。本文だけ広げたい場合は分割セルの下限と合わせて見直す

## Alternatives

- 本文の内側に wrapper を足し、`max-width` と `margin-inline: auto` で狭める案。スクロールバーの扱いは変わらず、DOM が増えるだけなので採らない
- 入力欄だけ別の幅（例: 720px）にする案。本文と左右端が揃わず、狭く見えるので採らない
- 入力欄を角丸のカードとして浮かせる案。詳細をカードにしない方針に反する。上罫線が途中で切れ、分割セルの見た目とも揃わない

## Verification

- 1440px と 1920px で、本文・ペインの見出し・入力欄・送信失敗の帯・実行中の段階の行の左右端が一致すること
- 閲覧のみのペインで、案内の左右端が本文と一致すること
- 分割して表示で、各セルの中身が 24px の余白に揃い、本文と入力欄の左端が一致すること
- 900px 未満で 16px のまま変わらないこと
- 引用ボタンと最新へ戻るボタンの位置が列の中に収まること
