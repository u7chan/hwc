# ADR 0053: すべての一覧に見出しのエージェントの有無を出す

- Status: Accepted
- Date: 2026-11-09
- Supersedes: [ADR 0047](0047-worktree-task-summary.md) の「すべてツリーの見出しの 2 行目」

## Context

`すべて` のツリーは、シェルだけのスペースも残す（[ADR 0017](0017-active-agents-view.md)）。見出しの 2 行目は PR のタイトル、無ければ `repoName · N ペイン`（[ADR 0047](0047-worktree-task-summary.md)）。折りたたみ中は右端に状態の集約を出す。

Herdr の `agent_status` は、シェルだけのスペースにも `idle` を返す。新しいワークツリーの root ペインはシェルだが、スペースの状態は `idle` になる。状態の記号だけでは、エージェントが居るスペースとシェルだけのスペースを見分けられない。`アクティブ` はエージェントの居るスペースだけを並べる（[ADR 0050](0050-active-lists-every-agent.md)）のに、`すべて` ではどれがそれか分からない。

副題に `エージェント N` / `シェルのみ` と書くだけでは、長い一覧で行を目で追うときに見落とす。PR があるスペースでは副題がタイトルに変わるため、そこに有無を出すこともできない。

## Decision

- エージェントの数は `pane.agent !== null` のペインで数える。`agent_status` は数えない
- エージェントが 1 体以上居るグループは、名前の行に数の札を出す。札は `AgentIcon` と件数の小さなチップで、状態の記号とは別に置く。副題が PR のタイトルに変わっても消えない
- 札はワークスペース・タブ・リポジトリ束のそれぞれに出す。束の数はホストとリンクワークツリーの合計
- エージェントの居ないグループは、副題を `シェルのみ` にする（PR がある間はタイトルを優先する）。右端は状態の記号ではなくシェルの記号にする。状態の集約はエージェントのものなので出さない
- エージェントの居るグループの副題は今までどおり。PR のタイトル、無ければペイン数（リンクワークツリーは `repoName · N ペイン`）、束はワークツリー数
- 開いている間は右端の記号を今までどおり淡く消す。子の行を見れば有無が分かる

## Consequences

- 長い一覧でも、エージェントの居るスペースを札で見つけられる。PR があるスペースでも同じ
- シェルだけのグループの副題からペイン数が消える。ペイン数より、エージェントが居ないことの方が知りたい情報になった
- シェルだけの束では、ワークツリー数と状態の集約（待機・不明）が見えなくなる。状態はエージェントのものなので、意味のある情報ではなかった
- 名前の行に札の幅が加わる。長い名前は今までより少し早く省略される
- 束の右端の状態は今までどおりホストの値で、束全体の状態ではない

## Alternatives

- **副題に `エージェント N` / `シェルのみ` と書く**: 長い一覧では文字が埋もれ、PR がある行ではタイトルの幅を削る。名前の横の札なら、副題の内容に関係なく目で追える
- **状態の記号の形や色だけを変える**: `agent_status` が `idle` のシェルだけの束と、待機中のエージェントの居る束を区別できない
- **シェルだけの行を淡くする**: エージェントの居る行は目立つが、シェルだけのスペースを開く・片付ける操作まで弱く見える
- **シェルだけの束を `すべて` から外す**: 片付けたいスペースを見つけられなくなる（ADR 0017 の決定を戻すことになる）
- **全ペインの状態を hwc で集約する**: Herdr の集約と二重になり、どちらが正か分からなくなる。有無はペインの `agent` だけで足りる
