# ADR 0048: 上流との差を表示し、フェッチ / プルをスペースメニューから実行する

- Status: Accepted
- Date: 2026-11-08

## Context

リモートのあるリポジトリで、いま作業しているブランチが上流より何コミット進んでいるか・遅れているかを見たい。遅れているときに最新を取り込むためだけに、チャットでエージェントへ「プルして」と頼むのも避けたい。

ブランチはワークスペース（ワークツリー）の属性で、[ADR 0019](0019-pane-row-content.md) は一覧のペイン行に、[ADR 0043](0043-pane-head-pull-request.md) は狭い画面の 1 枚表示の見出しにブランチを出している。[ADR 0047](0047-worktree-task-summary.md) はツリーの見出し 2 段目を PR のタイトルにした。上流との差もワークスペースの属性なので、ペインごとに繰り返すと同じ数字が並ぶ。

操作の入口は [ADR 0034](0034-remove-worktree.md) が「スペースの操作はスペース見出しのメニューに 1 つ」と決めている。一方、チャット画面の「…」はペインメニューで、スペースメニューは一覧の見出しにしかない。チャットからプルするためにペインメニューへスペースの操作を混ぜると、この原則が崩れる。

## Decision

- `WorkspaceState` に `sync: { upstream, ahead, behind, hasRemote } | null` を足す。`branch` は今までどおり別に持つ
- BFF は `git remote` と `git for-each-ref --format=%(upstream:short)\t%(upstream:track) refs/heads/<branch>` をチェックアウトで実行して読む。上流が `[gone]` のときは上流なしとして扱う
- 読む場所はブランチと同じ `checkoutPaths`。git の失敗・期限切れ・リポジトリ外では `sync` を `null` にし、状態そのものは流す
- 結果はチェックアウトとブランチごとに 10 秒キャッシュする。フェッチ / プルの後はそのチェックアウトのキャッシュを捨て、状態を取り直して SSE で配る
- 表示は上流がある間だけ。`↑N ↓N` を出し、0 の側は淡色、進みは `success`、遅れは `attention` にする。上流が無い・読めないときは数字を出さない
- 表示場所は次の 3 つ。いずれもワークスペースに 1 つだけ出す
  - すべてツリー: ワークスペース見出しの右端。上流がある間は同じメニューを開く「…」を出さず、状態表示がメニューの入口を兼ねる。ペイン行には繰り返さない
  - アクティブ帯: ブランチ / PR タイトルの 2 段目の後ろ
  - チャット: 1 枚表示の見出しで、ブランチと PR チップの間。広い画面でも出す。分割セルには出さない（同じ値が並ぶため）
- 状態表示自体をボタンにし、押すと既存のスペースメニューを開く。ペインメニューは変えない。入口はスペースメニューに 1 つという原則を保ちつつ、チャットからも同じメニューへ届くようにする
- スペースメニューに「フェッチ」と「プル」を足す
  - フェッチは `git fetch`
  - プルは `git pull --ff-only`。マージや rebase はしない。作業ツリーの変更と競合する場合や分岐している場合は失敗し、メニューに理由を出す
  - どちらも確認ダイアログを出さない。フェッチは読み取りだけで、プルは fast-forward だけに限るため
  - 実行中は項目を無効にし、メニューを閉じても状態を保つ。実行中に背景タップや Esc で閉じない
- `POST /api/workspaces/:id/git` を足す。body は `{ "action": "fetch" | "pull" }`。`application/json` 以外は 415
  - 状態が無ければ 502 `herdr_unavailable`、スペースが無ければ 404 `workspace_not_found`
  - チェックアウトが無ければ 409 `not_git_worktree`、リモートが無ければ 409 `no_remote`、上流が無ければ 409 `no_upstream`
  - git の失敗は 502 `git_fetch_failed` / `git_pull_failed`
  - 成功後はキャッシュを捨てて状態を取り直す。取り直しに失敗しても、git の操作自体は成功として返す
- git は `GIT_TERMINAL_PROMPT=0` で起動し、認証プロンプトで固まらせない。読み取りは 5 秒、フェッチ / プルは 60 秒で切る
- ポーリングや自動フェッチはしない。状態は Herdr のイベントによる取り直しと、操作後の取り直しで更新する

## Consequences

- 一覧の見出しと帯、チャットの見出しで、同じワークスペースの上流との差が読める。ペイン行には繰り返さない
- チャットからは状態表示を押すとスペースメニューが開き、フェッチ / プルを選べる。一覧の見出しの「…」からも同じメニューを開ける
- 上流が無いブランチでは数字が出ない。フェッチはスペースメニューから実行できるが、プルは出ない
- フェッチ / プルの結果はメニュー内に出す。成功時は状態が SSE で更新される。失敗時はメニューを開いたまま理由を出す
- プルは fast-forward できないときに失敗する。マージコミットを作る代替は持たない
- git の読み取りが 10 秒キャッシュされるため、エージェントがコミット・プッシュした直後は最大 10 秒古いことがある。フェッチ / プルの後は即座に更新する
- 状態の取り直しに git の待ちが加わる。10 秒キャッシュと 5 秒期限で、一覧全体を長時間止めない
- リモートが複数ある場合、`git fetch` は現在のブランチの上流のリモート（無ければ `origin`）を使う。どのリモートを見るかは選べない
- 認証が対話を要求する環境ではフェッチ / プルが失敗する。メニューに失敗だけを出し、認証情報は hwc で持たない

## Alternatives

- **ペインメニューにフェッチ / プルを足す**: チャットからは最短だが、[ADR 0034](0034-remove-worktree.md) の「スペースの操作はスペース見出しに 1 つ」を崩し、一覧のペインメニューにも同じ項目が並ぶ
- **状態表示専用の新しいメニューを作る**: スコープはきれいになるが、メニューが 2 つになり、既存のスペースメニュー（PR・ワークツリー）との関係が分かりにくい
- **ペイン行や分割セルにも数字を出す**: 同じワークスペースの同じ値が最大 4 行並ぶ。狭い画面で名前を圧迫する
- **上流が無くても `↑0 ↓0` を出す**: 比較対象が無いのに同期しているように見える。フェッチだけ可能なことはメニューで示す
- **`git status --porcelain=v2 --branch` で読む**: 作業ツリー全体を走査する。上流との差だけなら `for-each-ref` で足りる
- **状態のスナップショットに載せず、専用 API をクライアントから引く**: PR と同じ形にできるが、エージェントのコミットやプッシュの後に数字が古いままになりやすい。ローカルの git なので、状態の取り直しに載せて TTL で抑える
- **自動フェッチ**: 見ていない間もネットワークを使い、認証失敗の扱いも増える。明示操作に限る
- **プルでマージ / rebase を許す**: 作業ツリーの変更を勝手に作り変える。fast-forward だけに限る
- **確認ダイアログを出す**: フェッチは読み取りだけで、プルも fast-forward に限る。毎回の確認は操作を遅くする

## Verification

- unit で、`%(upstream:track)` の解析（ahead / behind / gone / 上流なし）、TTL キャッシュ、invalidate、git 失敗時の `null`、フェッチ / プルのコマンドを確認する
- BFF で、fetch / pull の成功、リモートなし、上流なし、チェックアウトなし、不正な action、git 失敗、状態の取り直しを確認する
- 架空 Herdr と架空 git の E2E で、一覧の両タブとチャット見出しの `↑N ↓N`、状態表示からスペースメニューを開くこと、プル後に数字が変わることを確認する
