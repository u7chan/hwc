# ADR 0105: OpenCode のサービスは、候補を読むときに hwc が起動する

- Status: Accepted
- Date: 2026-11-20
- Amends: [ADR 0030](0030-new-pane-model.md) の「一覧取得時にサービスは自動起動しない」「デフォルト起動による通常の CLI のサービス起動に任せる」。[ADR 0104](0104-launch-with-explicit-model.md) の「サービスは hwc から起動しない（ADR 0030 のまま）」「OpenCode のサービス未起動は『サービスを起動してから再取得』と案内する」

## Context

OpenCode のモデルと effort の候補は、バックグラウンドサービスの API から読む（ADR 0030）。ADR 0030 がサービスを自動起動しないと決めたのは、「デフォルトモデル」で起動すれば、CLI が通常どおりサービスを起動するからだった。

ADR 0104 で「デフォルトモデル」の起動を無くしたため、この前提は成り立たなくなった。サービスが止まっていると、設定画面でも作成ダイアログでも候補を読めず、hwc から OpenCode を起動できない。サービスを起動するには端末で `opencode service start` を実行するしかなく、主な利用端末のスマホからは操作できない。

OpenCode 2.3.2 の `opencode service start` は、待ち受けを始めて `service.json` を書いてから終わる（約 1 秒）。起動済みならすぐに成功する。サービスは自分で setsid して常駐し、起動した側の環境変数を引き継ぐ。

一方、OpenCode を使わないときにまでサービスを常駐させる必要はない。

## Decision

- OpenCode の候補を読む操作（モデル一覧・effort 候補・起動時のモデル確認とセッション作成）で、サービスが未起動と分かったら、BFF が `opencode service start` を実行して 1 回だけ読み直す。設定画面で OpenCode を開いたとき、作成ダイアログで OpenCode を選んだとき、再取得したときがこれにあたる
- 未起動と見なすのは、`service.json` が無いときと、接続が拒否されたときだけ（ADR 0030 と同じ判定）。loopback 以外の URL・認証失敗・タイムアウトでは起動しない
- 同時に来た読み取りは、1 回の起動を待ち合わせる
- 起動はホームディレクトリで行い、`HERDR_` で始まる環境変数を除く。常駐するサービスに、hwc の作業ディレクトリやペインの環境を持ち込まないため
- 起動に失敗したときや、起動後も読めないときは、これまでどおり `opencode_not_running` を返す。画面は「OpenCode サービスを起動できませんでした。再取得すると起動し直します。」と「再取得」を出す
- 会話の読み取り（ADR 0028）からは起動しない。OpenCode のペインがあればサービスは動いているので、未起動なら端末出力へフォールバックするだけでよい
- hwc はサービスを止めない。起動したサービスは、hwc を止めても残る

## Consequences

- サービスが止まっていても、設定画面と作成ダイアログから OpenCode のモデルを選んで起動できる。初回の候補の表示は、起動を待つ分（約 1 秒）遅れる
- OpenCode を開かない限り、サービスは起動しない
- `opencode` コマンドが PATH に無い、または `service start` の形が変わったときは、起動できず以前と同じ未起動の表示になる
- E2E では、PATH 上の架空の `opencode` が `service start` だけを受け、架空サービスの接続情報を戻す

## Alternatives

- **「サービスを起動」ボタンを出す**: サービスの起動を利用者の操作に限れる。ただ、OpenCode を開いた時点で使う意図ははっきりしており、毎回 1 回多く押させるだけになる
- **hwc の起動時にサービスも起動する**: 候補をすぐ読める。ただ、OpenCode を使わないときもサービスが常駐する
- **候補を読めないときだけ CLI の既定で起動する**: ADR 0104 の Alternatives で採らなかった案と同じ
