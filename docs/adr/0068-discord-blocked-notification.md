# ADR 0068: 要対応を Discord Webhook で通知する

- Status: Accepted
- Date: 2026-11-12
- Revises: [ADR 0063](0063-discord-done-notification.md) のトリガー、本文、設定画面のラベル

## Context

ADR 0063 は完了（`done`）だけを通知する。しかし `blocked` は許可待ちや質問でペインが止まっており、人間が答えるまで作業が進まない。hwc を開いていない間（スマホが別アプリ・画面ロック中など）にこれを見落とすと、完了より先に手が止まる。

完了通知の対象は「PR の作業だけ」と「すべての作業」から選ぶ。要対応をこの対象で絞ると、PR のない調査や雑務が止まったときに通知されず、見落とす。

## Decision

### トリガー

- `agent !== null` のペインが `blocked` に入った瞬間に 1 回だけ送る。親ペインに限らず、子の許可待ちも対象にする。シェルのペインは数えない
- `blocked` のまま留まっている間は再送しない。`blocked` を離れて再び `blocked` になったら、そのたびに送る
- 起動直後・再接続直後（`StateStore.breakObservation` の後、`observed` が false の publish）は基準を作るだけで送らない
- 通知が無効・URL 未登録でも blocked の集合は追跡する。有効化した時点で既に blocked だったペインには遡らない
- 送信直前に状態と設定を読み直し、ペインがまだ blocked でない・通知が無効になった・URL が消えた場合は送らない

### 通知の対象（scope）

- scope は完了通知だけに適用する。要対応は、通知が有効で URL が登録されていれば scope に関係なく送る
- 設定画面の見出しを「通知する対象」から「完了通知の対象」へ変え、要対応はこの対象に関係なく送ることをその場に書く
- scope の表示は「PR がある作業だけ」「すべての作業」とし、対象が完了であることを見出しで示す
- テスト通知の本文は、完了と要対応の両方が届くことを伝える

### 本文

PR は引かない。要対応は hwc で答えるもので、`gh` の待ちで通知を遅らせたり、`gh` の失敗で通知ごと落としたりしない。

同じ publish で同じスペースの複数ペインが blocked になったときは 1 通にまとめる。ペインごとに送ると、同時に確認を求められたときに Discord のレート制限へ当たりやすい。スペースが違えば別の通にする。

```text
hwc: <workspace label> が対応を待っています
ペイン: <pane label>, <pane label>
ブランチ: <branch>
```

- ペイン名は `label`、無ければ `agent`、それも無ければペインの id
- ブランチが null ならブランチ行を出さない
- ワークスペースのラベルが空のときは、完了通知と同じくリポジトリ名、id の順に落とす

### 送信

送信・失敗の扱いは ADR 0063 と同じ。自動送信は再試行せず、失敗が続く間だけ URL を出さずに 1 回ログする。

## Consequences

- 同じエージェントが短時間に何度も許可を求めると、そのたびに通知が届く。1 回の質問に 1 通という対応はしない
- 同時に複数のスペースが blocked になると複数通になる。Discord のレート制限に当たった分は再送しない
- Pi のフォルダ信頼確認のように Herdr が `blocked` にしない確認は届かない（[ADR 0044](0044-pi-project-trust.md)）
- hwc を見ている最中でも届く。閲覧中のペインを判定する状態を hwc は持っていない
- 完了通知の対象が「PR がある作業だけ」でも、PR のない作業の要対応は届く。設定画面のラベルでこの違いを示す

## Alternatives

- **scope に従って要対応も絞る**: PR のない調査や雑務が止まったときに通知されず、要対応を見落とす
- **要対応専用のトグルを足す**: 設定と状態が増える。通知 ON は「人間が動く番」を全部知らせる意味にした
- **ペインごとに 1 通送る**: 同じスペースで複数が止まると鳴りすぎる。スペース単位でまとめる
- **要対応の本文に PR の URL を入れる**: `gh` の待ちで通知が遅れ、`gh` が失敗すると通知自体が落ちる。答える場所は hwc なので PR は要らない
- **blocked が続く間、一定間隔で再送する**: 未回答を見落とさないが、回答するまで鳴り続ける。まずは遷移だけで送る
