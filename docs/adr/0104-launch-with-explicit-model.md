# ADR 0104: 新しいペインは、hwc の既定から選んだモデルと effort で必ず起動する

- Status: Accepted
- Date: 2026-11-20
- Amends: [ADR 0030](0030-new-pane-model.md) の「初期値は『デフォルトモデル』」「未指定ならモデルの起動引数を追加せず、CLI の既定に任せる」「既定設定の保存はしない」「取得中・取得失敗・候補なしでも『デフォルトモデル』での作成は妨げない」、effort の「初期値は『デフォルト（CLI に任せる）』」「モデルを明示選択していても、effort 未指定での起動は妨げない」。[ADR 0096](0096-claude-model-effort.md) の「初期値はこれまでどおり『デフォルトモデル』」

## Context

作成ダイアログのモデルと effort の初期値は「デフォルトモデル」で、未指定なら `--model` を渡さず、CLI が既定を解決する（[ADR 0030](0030-new-pane-model.md)、[ADR 0096](0096-claude-model-effort.md)）。

この「CLI 任せ」のために、入力欄のモデル表示の作りがエージェントごとに分かれている。hwc から見える既定の解決方法は CLI ごとに違い、Pi だけが専用の RPC で解決している（[ADR 0087](0087-default-model-display.md)）。Claude には解決の手段が無い。SessionStart hook の入力はモデルを含まず、設定ファイルや status line から推測する案は [ADR 0101](0101-launch-model-while-chat-unavailable.md) が採らないと決めた。そのため、デフォルトで起動した Claude は、最初の応答まで入力欄にモデルも effort も出ない。

一方、モデルを明示した起動は、起動時の指定を BFF が預かり、全エージェントが同じ経路で表示できる（[ADR 0033](0033-launch-model-before-first-message.md)、ADR 0101）。hwc が起動時にモデルを確定させれば、CLI ごとの既定の解決を足し続けずに済む。

毎回モデルを選ばせるだけでは手間が増えるので、初期値を hwc 側で持つ必要がある。

## Decision

- 作成ダイアログから起動するエージェントは、必ずモデルを明示して起動する。4 つ（Pi / Claude / Codex / OpenCode）ともモデル選択に対応している。「デフォルトモデル」の選択肢は無くし、未選択の間は「モデルを選択」と出す
- effort の「デフォルト（CLI に任せる）」も無くす。選択中のモデルの effort 候補が 1 件以上なら、effort も選ぶ。候補が空（effort 非対応のモデル）なら、effort なしで起動する
- 作成ボタンは、モデルを選び、そのモデルの effort 候補が届き、effort が必要なら選ぶまで押せない。シェルを作るときは従来どおり
- 候補を取得できないとき（取得失敗・OpenCode サービス未起動・候補なし）は、起動できない。理由と「再取得」ボタンを出す。OpenCode のサービス未起動は「サービスを起動してから再取得」と案内する。サービスは hwc から起動しない（ADR 0030 のまま）。effort 候補を取得できないときも同じ
- 既定は、エージェントごとに任意で 1 組のモデルと effort にする。effort は、保存したモデルが effort 非対応なら `null`。BFF が状態ディレクトリの `launch-defaults.json` に置き、[定型文](0084-composer-templates.md)と同じく、一意な tmp 名で書いて rename で置き換える。読めない・壊れた値は捨てて未設定で始める
  - `GET /api/launch-defaults` は `{ defaults: { <agent>: { model, effort } } }` を `cache-control: no-store` で返す
  - `PUT /api/launch-defaults` は `{ agent, value }` を受け、そのエージェントの既定だけを置き換える。`value: null` で解除する。応答は全エージェントの既定。書けなければ 500 にし、メモリ上の既定は変えない
- ダイアログの初期選択は、利用者の選択・既定・候補から描画中に導く
  - モデルは、利用者が選んだモデル。無ければ既定のモデル。どちらも、いまのモデル候補にあるときだけ使う。既定が未設定・読めない・候補に無いときは未選択にする
  - effort は、利用者が選んだ effort。無ければ既定の effort（選択中のモデルが既定のモデルのときだけ）。どちらも、いまの effort 候補にあるときだけ使う
  - 既定の読み出しが遅れて届いても、利用者が選んだ値は上書きしない。モデルを変えたら effort の選択を解き、エージェントを変えたらモデルと effort の選択を解く
  - 既定の選択肢は「モデル名（既定）」「effort（既定）」と表記する
- 既定は設定画面だけで設定・解除する。作成ダイアログには既定を変える操作を置かない。設定画面に「エージェント」のまとまりを足し、エージェントごとの行に現在の既定を出す。行を開くと、モデルと effort を選んで保存・解除できる
- 設定画面にはペインが無いので、候補は `GET /api/models?agent=...` と `GET /api/efforts?agent=...&provider=...&model=...` から読む。BFF はホームディレクトリで `AgentModelsClient` を呼び、失敗の形はペイン別の口（`opencode_not_running` / `models_unavailable` / `efforts_unavailable`）に揃える。候補はその画面を開いたときだけ読む
- 起動 API（`POST /api/panes/:id/split` / `agent`）は、モデル未指定の起動を引き続き受け付ける。hwc の画面からは送らない

## Consequences

- hwc から起動したペインは、Claude を含めて、起動直後から入力欄にモデルと effort が出る（ADR 0033 / 0101 の経路）
- ADR 0087 の Pi の既定の解決と、ADR 0101 の「デフォルトモデルで起動した Claude」は、hwc の画面から起動するペインでは起きなくなる。hwc 以外から起動したペインと、モデル未指定の起動 API には残る。この仕組みと、起動 API のモデル未指定を拒否するかは、別に扱う
- CLI の設定にある既定のモデルと effort は、hwc から起動するペインには効かない。ダイアログから CLI の既定へ戻す手段も無い
- 既定が未設定のエージェントは、毎回モデルと effort を選ぶ。既定以外のモデルを選ぶと、effort も選び直す
- OpenCode は、サービス未起動だと hwc から起動できない（以前はデフォルトモデルなら起動できた）。Pi / Codex でも、候補の取得が一時的に失敗すると、再取得するまで作れない
- Pi は毎回、モデル一覧と effort の RPC（期限は各 20 秒）を待ってから作成ボタンを押せる。候補はキャッシュしない
- 設定画面の候補はホームディレクトリで読むので、ペインの cwd で候補が変わる構成では、既定が候補に無く未選択で開くことがある
- 状態ディレクトリにファイルが 1 つ増える。既定が読めないときも、ダイアログは未選択で開き、起動は妨げない

## Alternatives

- **エージェントごとの前回の起動値を初期値にする**: 設定画面が要らない。ただ、前回値・モデル候補・effort 候補がそろうまでの適用待ちと、適用済みの印を持つ状態管理が要る。一度試した高価なモデルが初期値に居座り、ダイアログから CLI の既定へ戻す手段も無い
- **候補を取得できないときだけ、CLI の既定で起動する**: OpenCode をサービス未起動でも起動できる。ただ、CLI の既定での起動が例外として残り、モデル表示の経路も二通りのままになる
- **作成ダイアログに「既定にする」を置く**: 実際に起動するペインの候補をそのまま使える。ただ、作成の操作に設定の変更が混ざる
- **effort の「指定なし」を残す**: 選ぶ手間は減る。ただ、Claude と Pi は最初の応答まで effort を出せない。既定の effort がある状態で「指定なし」を選んだことを、まだ選んでいない状態と区別する必要もある
- **設定画面の候補を hwc の作業ディレクトリで読む**: hwc リポジトリのプロジェクト設定を拾う
