# ADR 0098: ファイルツリーを F キーでも開閉する

- Status: Accepted
- Date: 2026-11-19
- Revises: [ADR 0090](0090-pane-file-tree.md) の入口に関する記述

## Context

ツリーの入口はペイン見出しのファイルアイコンだけ（[ADR 0090](0090-pane-file-tree.md)）。PC でセルを並べていると、会話を読みながらツリーを開くたびにポインタを見出しまで運ぶことになる。開閉だけをキーボードで往復したい。

一方、この画面の主戦場は入力欄で、送信の後もフォーカスは入力欄に残る（[ADR 0084](0084-launch-after-create.md)）。文書全体で文字キーを拾うと、打っている `f` を奪う。

## Decision

- `f` でツリーを開閉する。対象は current（枠線がハイライトしているセル）1 つだけで、listener を持つのはそのセルだけにする
- 入力欄（`input` / `textarea` / `select` / `contenteditable`）にフォーカスがある間は効かせない。`Shift` は許し、`Ctrl` / `Alt` / `Meta`、押しっぱなし（`repeat`）、IME の変換中（`isComposing`）は受けない
- 開いているダイアログとメニューの中では受けない。Escape を二重に走らせないのと同じ理由
- フォーカスが body にあるときは current を、他のセルや設定にあるときは何もしない
- キーで開いたときは、根の一覧が届いた時点で選択中の行（無ければ先頭）へフォーカスを移す。ポインタで開いたときは移さず、見出しのボタンに残す
- キーで閉じたとき、ツリーの中にフォーカスがあれば見出しの「ファイル」ボタンへ戻す。行の展開で一覧が増えても、フォーカスを取り直さない
- ツリーの中にフォーカスがある間、↑↓ で行を移り、→ でフォルダを開く（開いていれば最初の子へ降りる）、← で閉じる（フォルダでなければ親へ戻る）。修飾キー付きの矢印はブラウザと読み上げに返す
- 行はボタンのままにする。Tab での移動はそのまま残し、矢印はその上乗せの高速路にする（roving tabindex にはしない）
- 見出しのボタンと同じ経路を通す。store を直接叩かず、キーでも開閉の動きを出し、閉じる途中の再押下は開き直しとして扱う

## Why not

- **`Ctrl` / `Cmd` + `B`**: VS Code のサイドバーと同じで覚えやすいが、Firefox ではブックマークツールバーの表示と衝突する
- **入力欄でも効かせる**: 打っている `f` を奪う。ツリーの開閉より入力を優先する
- **押しっぱなしで往復させる**: ツリーは閉じると一覧を捨てるので（ADR 0090）、キーの連打が取得の連打になる
- **`role="tree"` と roving tabindex**: 標準のツリーキーになるが、Tab で行を抜けられなくなる。開いた後に Tab で行を渡りたいという要求と衝突する
- **ダイアログの中でも効かせる**: 開いている面のキー操作を横取りする

## Consequences

- 送信の直後は入力欄にフォーカスがあるので効かない。会話をクリックして読み始めるか、一度フォーカスを外すと使える
- 開いた後はそのまま Tab で行を移動し、Enter でフォルダを開いたりファイルを開いたりできる。折りたたんだフォルダの子は `inert` なので Tab から外れる
- 矢印では行を移れるが、End や Home、文字を打っての絞り込みは持たない。開けないファイル（淡色の行）はボタンではないので Tab も矢印も止まらず飛ばす
- まだ子を読んでいないフォルダでは、→ を押して開いた直後は子が無いので、届いてからもう一度 → を押すと降りる
- キーの存在は画面に出ない。見出しのボタンは入口として残る
- 分割セルでは、最後にクリックしたセルのツリーが動く。フォーカスが他のセルにあるときは動かない
