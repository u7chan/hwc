# ADR 0017: アクティブなエージェントはツリーではなくフラットに並べ、既読は Herdr の seen に任せる

- Status: Accepted
- Date: 2026-11-03

## Context

hwc の一覧はワークスペース → タブ → ペインのツリーで、`agent` と `all` の 2 スコープしか持たない。エージェントを多数並行で動かすと、どのワークスペースのどのタブで何が動いているのかをツリーから読み取れない。動いているものだけを見たいときも、ツリーを開いて回る必要がある。

Herdr は `idle` と `done` をサーバー側の seen 状態で区別し、seen は明示的な focus でしか進まない。hwc はこれまで focus を一度も送っていなかったため、終わったペインの `done` は hwc で開いて読んでも消えず、未読のまま溜まっていた。hwc 側に既読の状態は無い。

`done` の作り方は「エージェントに短い依頼を終わらせ、そのペインを Herdr TUI で focus しない」。TUI 側で見ただけでも消えるため、hwc が必ず消す、という関係ではない。

経過時間は手元の ref に稼働開始時刻を持っていたため、リロードで 0 秒に戻っていた。Herdr は変化の順序（`state_change_seq`）しか返さず、開始時刻を持たない。

## Decision

### アクティブはフラットに並べる

- 3 つ目のスコープ `active` を足し、ツリーをやめて 1 行 1 ペインで並べる。行数が増えても、所在（ワークスペース · タブ）と名前を同じ高さで読める
- 1 行は 2 段。上段に状態アイコンと `ワークスペース名 · タブ名`、下段に `pane.label ?? pane.agent`。タブ名が空なら区切りの `·` ごと落とす
- 端末タイトル（`π - hwc` など）は同じリポジトリのペインで同じ値になるため主にしない。ラベルの無いペインは Herdr ネイティブの agents パネルと同じくエージェント種別（`pi` など）を出す
- 右端は `working` が経過時間、`blocked` が「要対応」、`done` は無し。`done` はアイコンの色で分かる
- 強調は名前側（下段）に置く。所在を太字にすると、どこにいるかだけが目に入って何が動いているかが読めない
- 行のメニュー（ペイン ID のコピーなど）は出さない。一覧を状態を見るためだけの面にし、操作は詳細に寄せる
- 空状態は「対象のエージェントはいません」とし、`done` を含むスコープなので「動いている」とは書かない

### 対象と並び

- 対象は `pane.agent !== null` かつ `agentStatus` が `working` / `blocked` / `done`。`idle` と `unknown` は出さない
- 並びは `blocked` → `working` → `done`、同順位は state の並び（ワークスペース → タブ → ペイン）のまま
- `activePanes(state)` は `selectedPaneId` を取らない。既存の `scopeWorkspaces()` は「絞り込んでも、いま開いているスペースだけは残す」という逆向きの規則を持つが、`active` は idle を出さない以上、選択中のペインが一覧から消えるのが正しい。この非対称は型でも表し、ツリー用の絞り込みには `active` を渡せないようにする

### 既読は Herdr の seen に寄せる

- 既読は `agent.focus` を pane id で呼んで Herdr の seen を進める。hwc 側に既読の独自状態は持たない（二重管理を避ける）
- 送るのは `active` スコープで `done` の行を開いたときだけ。`working` / `blocked` の行を開いても送らない。seen を進める必要があるのは `done` だけで、TUI のフォーカスを動かす副作用を最小にする
- `agent.focus` は TUI 側のフォーカスも動かす。`done` の行に限るのはこのため
- 送信は一覧の行ハンドラから行う。`select` は詳細のタブバーとも共有しており、そこに置くとペインの切替でも送られてしまう
- 送信に失敗しても選択は成立させる。既読は best-effort とし、失敗は通知しない（次にその行を開いたときに再試行される）。利用者にできることが無いため、失敗の可視化は持たない
- focus 後の状態の取り直しは Herdr のイベント（`pane.focused` / `pane.agent_status_changed`）に任せる。BFF はこれらを購読して状態を取り直し、SSE で全クライアントへ配る。実際に `agent.focus` を呼ぶと、`pane_focused`・`tab_focused`・`pane.agent_status_changed`（`done` → `idle`）が届き、hwc の状態は追加の取得なしに更新された。エンドポイントで再取得を待つと、成功した focus が再取得の失敗で 502 になる
- `POST /api/panes/:id/focus` は `application/json` 以外を 415 で弾く。TUI のフォーカスを動かす操作なので、LAN 内の任意ページから form POST で叩ける状態にしない

### 経過時間は localStorage に置く

- 起点（最後に `working` を観測した時刻）は localStorage のキー `hwc-working-since` に `{ [paneId]: epochMs }` で保存する。Herdr が開始時刻を持たないため、これは二重管理ではなく唯一の情報源になる
- 保存も復元も `working` のペインだけを対象にする。値は有限数だけ受け、`now` より未来の値は捨てる（端末の時計が戻っても `NaNs` や負の経過を出さない）
- セマンティクスは「その端末が最後に `working` を観測した時刻から数える」。`working` を離れた時点で値を捨てるため、`working → blocked → working` では数え直しになる。厳密な開始時刻ではない
- 端末ごとに独立し、同じ端末の複数タブでも同じ値を使う
- localStorage が使えない環境では保存だけ諦め、その場の表示は続ける

### クライアントは BFF を素の fetch で叩く

- クライアントは `src/client/api.ts` の素の fetch で BFF を叩く（[ADR 0005](0005-bff-client-transport.md)）。`hc` の型共有は使わない

## Consequences

- `active` は `done` を含むため、Herdr TUI を触っていないと行が残り続ける。hwc で開けば消えるが、`done` が溜まること自体は防がない
- `done` の行を開くと TUI のフォーカスが動く。`working` / `blocked` では動かない
- hwc は既読を共有するための仕組みを持たない（非ゴール）。既読は `agent.focus` で Herdr の seen を進めるだけなので、結果としてどの端末で開いても既読になる。端末ごとに既読を分けることはできない
- 経過時間は端末ごとに独立する。別端末で開くと短く見える。厳密な開始時刻が必要になったら別 Issue とする
- 一覧の行は SSE の更新で出入りする。key は pane id
- 通知（プッシュ・音・未読バッジの数）と focus 失敗の可視化は持たない
- 既存 2 スコープ（`agent` / `all`）のツリー表示は変えない

## Alternatives

- **ツリーに絞り込みだけを足す**: 実装は小さいが、多数並行時に行が点在し、ツリーを開いて回る手間が残る
- **hwc 側に既読を持つ**: `done` を読んだら握りつぶせるが、Herdr の seen と二重管理になり、TUI 側で見た結果とずれる。`agent.focus` は TUI のフォーカスも動かすため、副作用を `done` の行だけに限って受け入れる
- **経過時間を BFF で持つ**: プロセス再起動で消えるうえ、Herdr が起点を持たない以上どこかで持つ必要がある。端末ごとに閉じる話なので、端末側に置く
- **focus 後に `/api/state` を取り直す**: キャッシュが返るため意味が無く、BFF 側で再取得を待つと成功した focus が 502 になる。イベントで足りることを実測してから、この経路は持たない
