# ADR 0017: アクティブなエージェントはワークスペース単位で束ね、既読は見終わったときに送る

- Status: Accepted
- Date: 2026-11-03（2026-11-08 改訂、2026-11-10 改訂）

## Context

hwc の一覧はワークスペース → タブ → ペインのツリーで、`agent` と `all` の 2 スコープを持っていた（`agent` はエージェントのいるスペースだけを出す）。エージェントを多数並行で動かすと、どのワークスペースのどのタブで何が動いているのかをツリーから読み取れない。動いているものだけを見たいときも、ツリーを開いて回る必要がある。

`agent` を既定にしていたため、ワークツリーの最後のエージェントを終了すると、Herdr 側に残っているシェルのペインとスペースが一覧からスペースごと消えていた。片付けたいスペースを探すにはスコープを切り替える必要があった。[ADR 0034](0034-remove-worktree.md) でスペース見出しのメニューからワークツリーを削除できるようにしたので、既定の一覧からその入口を隠す理由が無くなった。

Herdr は `idle` と `done` をサーバー側の seen 状態で区別し、seen は明示的な focus でしか進まない。hwc はこれまで focus を一度も送っていなかったため、終わったペインの `done` は hwc で開いて読んでも消えず、未読のまま溜まっていた。hwc 側に既読の状態は無い。

`done` の作り方は「エージェントに短い依頼を終わらせ、そのペインを Herdr TUI で focus しない」。TUI 側で見ただけでも消えるため、hwc が必ず消す、という関係ではない。

経過時間は手元の ref に稼働開始時刻を持っていたため、リロードで 0 秒に戻っていた。Herdr は変化の順序（`state_change_seq`）しか返さず、開始時刻を持たない。その後、時刻を端末の localStorage へ移したが、端末ごとに独立するため、スマホと PC で経過時間と終了時刻が一致しなかった。

窓口（スペースに 1 体いる会話相手）は `done` を開くと `idle` になり `アクティブ` から消えるため、次の会話を始めるときにツリーをたどる必要があった。休んでいるペインがいつ終わったのかも、一覧からは分からなかった。

フラットな並びは、行ごとに `ワークスペース · タブ` を上段に置いていた。同じワークスペース名が行の数だけ繰り返され、長い名前はタブ名の手前で切れる。切れた後に残る文字列が同じになり、`…-impl` と `…-review` の区別が付かない。並びが状態順なので同じワークスペースの行も離れ、どれが同じワークツリーかを目で追えない。

既読も、`done` の行を開いた瞬間に `agent.focus` を送っていたため、読んでいる間に行が消えた。束の最後の行なら見出しごと消える。

## Decision

### 一覧のスコープは `すべて` と `アクティブ` の 2 つ

- スコープは `all`（すべて）と `active`（アクティブ）の 2 つだけにし、既定を `all`、並びも `すべて` → `アクティブ` とする。既定が先頭に来る
- `agent` を廃止する。当初の決定（`エージェント` を既定にして、シェルだけのスペースは `すべて` で探す）を撤回する。ADR 0034 でスペースを片付ける入口ができたため、既定の一覧から片付けられるスペースを隠さない。絞り込みは `アクティブ` が担う
- ツリーは常に全スペースを出す。シェルだけのスペース、最後のエージェントを終了したスペースも残る。一覧からスペースが消えるのは、Herdr 側でスペースが閉じたとき（`ワークツリーを削除` を含む）だけにする
- シェルだけのペイン行の見せ方は変えない。枠付きのアイコン、エージェント記号なし、スナップショット順のまま
- 保存済みのスコープが `agent` や未知の値なら `all` に倒す。移行処理は持たない

### アクティブはワークスペース単位で束ねる

- `active` はツリーをやめ、アクティブの行をワークスペース（ワークツリー）ごとにまとめる。1 行 1 ペインは保つ
- 束の先頭に帯を置く。1 段目はタスク名（ブランチの最新 PR のタイトル、無ければワークスペース名。本文サイズ・600）、2 段目はブランチ（mono・`secondary`、取れないときは出さない）と上流との差、状態の件数（要対応・完了・実行中の非ゼロを状態記号 + 数で。要対応は `attention` 色）を持つ。件数は 2 段目が無ければ 1 段目の右端に置く（[ADR 0047](0047-worktree-task-summary.md)）
- 帯は一覧のスクロール領域の上端に sticky で貼り付き、次の束の帯に押し出されるまで残る
- 帯はその場所の入口でもある。帯全体を押すと `すべて` へ切り替え、そのスペース・代表タブ・親リポジトリの束を開き、一覧をそのスペースの見出しまで送る。右端には移動を示す矢印を添える
  - 代表ペインは先頭の空でないタブの先頭ペイン。広い画面ではそれを選び、狭い画面では一覧と詳細を同時に出せないため選ばずに一覧のまま移る
  - リポジトリ束のホスト（自分の見出しを持たないスペース）は、束の見出しをその場所の入口にする。メニュー（新しいワークツリー）はその見出しにある
  - 移動先の見出しへフォーカスを送り、次の Tab でそのスペースのメニューへ進めるようにする
  - 自分で畳んでいた束でも、帯から来たときは開く（その場で見たいという指示を優先する）
- 行は状態記号、ペイン名、タブ名、時刻。名前は 400、選択中の行だけ 600 + `accent`
- タブ名は `workspace.tabs.length > 1` のときだけ `· タブ名` で添える。1 タブの既定名「1」は、どの行でも同じ値なので出さない
- 行の最小高は `--row-pane`（64px）、帯は `--row-head`（56px）に揃える
- 行の名前からは、帯が持つワークスペース名で区切りを挟んで始まる / 終わる部分を落とす（例: `demo-live-thinking-review` → `review`）。残りが空なら元のラベルを使う。元のラベルは `title` と詳細で読める
- 端末タイトル（`π - hwc` など）は同じリポジトリのペインで同じ値になるため主にしない。ラベルの無いペインは Herdr ネイティブの agents パネルと同じくエージェント種別（`pi` など）を出す
- 右端は `working` が開始からの経過、`blocked` が「要対応」、`done` と `idle` は終わった時刻（時:分）。増え続ける経過は稼働時間とも読めるため、終わった時刻そのものを出す。時刻を知らない行は何も出さない
- 強調は行の名前側に置く。場所は帯が持つので、行では名前だけを太くする
- アクティブの行にはメニューを出さず、状態を見る面にする。ツリーの行の操作は [ADR 0021](0021-pane-close.md)・[ADR 0026](0026-new-pane.md) に従う
- 空状態は帯が 1 つも無いときだけ出す。文言は [ADR 0050](0050-active-lists-every-agent.md) が持つ
- ツリー（`すべて`）と詳細のタブ・セルの命名は [ADR 0019](0019-pane-row-content.md) のまま。アクティブの帯と、帯の名前を落とした表示用ラベルはこの ADR が持つ。`pane.label` は書き換えない

### 対象と並び

対象・並び・帯の件数は [ADR 0050](0050-active-lists-every-agent.md) が持つ。`idle` と `unknown` も並べ、窓口は持たない。

### 既読は Herdr の seen に寄せる

- 既読は `agent.focus` を pane id で呼んで Herdr の seen を進める。hwc 側に既読の状態は持たない（二重管理を避ける）
- 送るのは、**アクティブ一覧の行を開いてから、そのペインを離れたとき**。離れる時点でそのペインが `done` なら送る。開いた時点では送らない
- 開いた瞬間に送ると、読んでいる間に完了の印が消えて行が束の最後へ動く。読み終わったときに進める
- 保留を登録するのはアクティブ一覧の行を開いたときだけ。開いた時点の状態は問わない（閲覧中に `working` / `blocked` → `done` になっても、離れる時点で `done` なら送る）
- ツリー（`all`）の行、詳細のタブバー、起動時の復元（`restorePane` / `defaultView`）では保留を作らない。これらは従来どおり `agent.focus` を送らない
- 離れる経路は、一覧で別の行を選ぶ / 詳細のタブバーで別のペインを選ぶ / 狭い画面で詳細から戻る / ペインを閉じた後の次のペインへの移動 / 新しいペインが現れて自動で開くとき。選択の変更はクライアントの 1 つのヘルパーを通す
- 同じ行をもう一度押しただけでは離れていないので送らない。復元で開いた行は、一覧でその行を押してから離れたときに送る
- スコープを `active` → `all` に切り替えても保留は消さない。その後にペインを離れたら送る
- ペインが消えた場合は送らない（保留を捨てる）。開いたままアプリを閉じた場合も送らない（未読のまま）
- 送るのは `done` だけ。`working` / `blocked` では TUI のフォーカスを動かさない。seen を進める必要があるのは `done` だけで、`agent.focus` は TUI 側のフォーカスも動かすため
- 保留はクライアントのメモリ（App の ref）だけに置く。再描画を増やさず、localStorage にも既読状態を置かない
- 送信に失敗しても選択は成立させる。既読は best-effort とし、失敗は通知しない（次にその行を開いて離れたときに再試行される）。利用者にできることが無いため、失敗の可視化は持たない
- focus 後の状態の取り直しは Herdr のイベント（`pane.focused` / `pane.agent_status_changed`）に任せる。BFF はこれらを購読して状態を取り直し、SSE で全クライアントへ配る。実際に `agent.focus` を呼ぶと、`pane_focused`・`tab_focused`・`pane.agent_status_changed`（`done` → `idle`）が届き、hwc の状態は追加の取得なしに更新された。エンドポイントで再取得を待つと、成功した focus が再取得の失敗で 502 になる
- `POST /api/panes/:id/focus` は `application/json` 以外を 415 で弾く。TUI のフォーカスを動かす操作なので、LAN 内の任意ページから form POST で叩ける状態にしない

### 経過時間・完了時刻は BFF に置く

- 起点（`working` を観測した時刻）と完了時刻は BFF が持つ。Herdr が開始時刻を持たないため、これは二重管理ではなく唯一の情報源になる。BFF は 1 プロセスで全ペインの状態変化を受け取るので、どの端末から見ても同じ値になる
- 遷移の判定は端末に持っていた規則をそのまま移す。`working` に入った時刻を起点にし、`working` から `done` か `idle` へ移ったときだけ完了時刻を記録する。`working` と `blocked` に入ったら完了時刻を消し（要対応は待ち時間ではなく、こちらが動く番）、`working` を離れたら起点も捨てる（`working → blocked → working` は数え直し）
- 記録するのは BFF が観測した遷移だけ。購読が切れて再接続した後と、取得に失敗した後の最初の取得は「観測の切れ目」として完了時刻を記録せず、既に持っている時刻だけを残す。切れ目は store の内部フラグで表し、次の公開が 1 回だけ消費する（取得中の要求は 1 つに畳まれるため、呼び出し側の引数では合流時に落ちる）
- 切れ目が止めるのは完了時刻の記録だけ。起点は `working` を見た時点で作る。止める側に倒すと、切断中に働き始めたペインの経過が出ない
- 「今」は状態に持たせず、`/api/state` と SSE の送信時に `{ state, now }` の封筒で渡す。状態に持たせると、キャッシュされた状態に古い時刻が残り、状態が動かない間は経過が止まって見える。ハートビートはコメント行なので時刻を運べない
- クライアントは受信のたびにサーバー時計との差を取り、その差で刻んだ「今」を表示に使う。端末の時計がずれていても、経過も完了時刻もサーバーの時計の値になる
- 保存先は [ADR 0018](0018-pasted-image-attachments.md) の状態ディレクトリ配下の `pane-times.json`。形は `{ [paneId]: { status, at } }` で、`blocked` と `unknown` は時刻を出さないので保存しない
- 書くのは時刻か状態が変わったときだけ。同じディレクトリの tmp に書いて rename で置き換える。読むのは起動時の 1 回で、壊れた JSON・非数・読んだ時刻より未来の値は捨てる
- 再起動時は、保存した `status` が今の `status` と一致する項目だけを引き継ぐ。一致しない `working` は最初の観測から数え直す（数えないと、後で `done` になっても完了時刻を記録できず、表示が今より減る）。保存が無い間に `done` になったペインには完了時刻を出さない
- 書き込みに失敗しても表示は続ける（メモリ上の値で動く）。失敗は 1 回だけログに出す
- 窓口の記憶は持たない（[ADR 0050](0050-active-lists-every-agent.md)）

### クライアントの transport

- JSON エンドポイントは `hc`、SSE は `EventSource`、生バイトは `hc` の対象外とする（[ADR 0024](0024-json-hc-streaming-raw.md)）

## Consequences

- `active` は `done` を含み、行はエージェントが終了するまで残る（[ADR 0050](0050-active-lists-every-agent.md)）。Herdr TUI を触っていないと完了の印が残り続けるが、hwc で開いて離れると `idle` に変わる
- `git` 管理外のシェルだけのスペースも既定で出る。エージェントのいないスペースが並ぶが、積極的に片付けたいときは削除（ADR 0034）か Herdr TUI で閉じる。ノイズが問題になったら別 Issue で扱う
- `done` の行を開いても TUI のフォーカスは動かない。離れたときに動く（`working` / `blocked` なら動かない）
- 既読は「離れたとき」なので、開いたままにした `done` は未読のまま残る。一覧の行を押してから離れるまでが既読の単位になる
- 1 行だけの束は帯のぶん高さが増える（約 56px）。折衷（1 行の束だけ帯を出さない）は持たない。形が 2 つになると、場所の探し方が行ごとに変わる
- 束の順位は状態変化で入れ替わるため、一覧が動く。sticky と帯の件数で場所を見失わないようにするが、並びの安定は持たない
- 同じ束・同じタブに同名のペインが 2 つあると、束ねても行は同名のまま。ペイン id を出すかは別 Issue
- ラベルの接頭辞・接尾辞の除去は、ワークスペース名と偶然一致するラベルで短く見えることがある。区切りを要求し、元のラベルを `title` と詳細に残す
- 既読の保留はクライアントのメモリだけに置くので、再読み込みで消える。復元で開いた `done` の行は、一覧で押してから離れるまで既読にならない
- hwc は既読を共有するための仕組みを持たない（非ゴール）。既読は `agent.focus` で Herdr の seen を進めるだけなので、結果としてどの端末で開いても既読になる。端末ごとに既読を分けることはできない
- 経過時間と完了時刻は全端末で一致する。BFF が止まっている間の遷移は観測できないため、その間に終わったペインには完了時刻が出ない。再起動をまたいだ `working` は保存した起点を引き継ぐが、BFF の停止中に `working → done → working` と動いた場合は状態の一致だけで区別できず、古い起点のまま長く見える
- 端末の時計が NTP で大きく飛ぶと、次の状態変化までは表示が飛ぶ。状態が動かない間は最後に受信した `now` との差を使い続けるため、差は数時間で数秒ずれる（分単位の表示には影響しない）
- 状態ディレクトリに保存が 1 つ増える。BFF と別ユーザー・別ホストで動かすと時刻を引き継げない
- 帯からの移動は、広い画面では詳細を代表ペインへ切り替え、一覧をその場所の見出しへ送る。狭い画面では一覧を残すため、代表ペインは自動で開かない
- 一覧の行は SSE の更新で出入りする。key は pane id
- 通知（プッシュ・音）と focus 失敗の可視化は持たない。件数は「アクティブ」のラベルにだけ出し、他の場所のバッジや端末通知は持たない
- 件数は、アクティブ一覧に出ている帯（スペース）の数。行数ではない。同じスペースで並列に動かしても 1 と数え、`done` だけ・待機だけの帯も 1 と数える（一覧に並ぶ帯と数を一致させる）。0 のときは出さず、99 を超えたら `99+`
- ツリー（`all`）のペイン行は、左のアイコン枠を状態記号に置き換え、Provider の記号を 14px でペイン名の手前に添える。状態の文言は行の内側（右）へ開き、見出し行のまとめは左のまま。シェルの行は枠付きのアイコンを残す

## Alternatives

- **ツリーに絞り込みだけを足す**: 実装は小さいが、多数並行時に行が点在し、ツリーを開いて回る手間が残る
- **Herdr の agents（grouped）に合わせたフラットな並び**: 場所を太字の上段、ペインを淡い下段に置く。束ねないので、同じ場所の行が状態順で離れ、ワークスペース名を行の数だけ繰り返す。長い名前はタブ名の手前で切れ、切れた後に残る文字列が同じになって `…-impl` と `…-review` の区別が付かない。場所を主にするなら帯で 1 度だけ言う方が読みやすく、行の幅も名前の識別に使える
- **既読の行をセッション中だけ淡く残す**: hwc 側に一覧用の記憶を持つと、Herdr の seen と二重管理になり、TUI で見た結果とずれる。`agent.focus` を遅らせるだけなら状態を増やさずに済む
- **案 A: `エージェント` を残したまま、シェルだけのスペースも出す**: シェルも出すなら「エージェントのいるスペース」という意味が消え、`すべて` と同じものになる。スコープを 2 つ持つ理由が無い
- **案 B: リポジトリ束の見出しが出ている間だけ、その束のスペースをシェルでも残す**: そのリポジトリの最後のエージェントを終了した時点で束ごと消えるため、消える問題は残る。「どの束に入っているか」で見え方が変わる規則も読み取りにくい
- **案 C: 直前にエージェントを終了したスペースだけ、次に削除するまで残す**: Herdr TUI から終了した場合と終状態が同じなのに表示が変わる。クライアントに「残す」状態を持つことになり、サーバー状態の正を BFF に置く前提とも噛み合わない
- **hwc 側に既読を持つ**: `done` を読んだら握りつぶせるが、Herdr の seen と二重管理になり、TUI 側で見た結果とずれる。`agent.focus` は TUI のフォーカスも動かすため、副作用を `done` の行だけに限って受け入れる。セッション中だけ残す案も、結局 seen を進める時点を遅らせるだけなら、保留をクライアントに置く今の形で足りる
- **経過時間と完了時刻を端末に置く**: サーバーに状態を増やさずに済むが、端末ごとに起点が違い、端末の時計にも依存する。ペインが働き始めた後に開いた端末は短く見え、hwc を閉じている間に終わったペインには時刻が出ない。保存を BFF に寄せれば、保存の失敗や再起動の扱いも 1 箇所で済む
- **focus 後に `/api/state` を取り直す**: キャッシュが返るため意味が無く、BFF 側で再取得を待つと成功した focus が 502 になる。イベントで足りることを実測してから、この経路は持たない
