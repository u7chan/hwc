# ADR 0095: ファイルツリーの行を入力欄へ運び、パスを本文へ入れる

- Status: Accepted
- Date: 2026-11-18

## Context

ファイルツリー（[ADR 0090](0090-pane-file-tree.md)）でチェックアウトのファイルを開けるが、そのファイルを指示の対象にするには、パスを手で書くか、プレビューの「パスをコピー」で写して貼るしかない。PC では、見えている行をそのまま入力欄へ運べる方が速い。

hwc の入力は文字列と添付名だけで（[ADR 0013](0013-pi-session-chat.md)、[ADR 0018](0018-pasted-image-attachments.md)）、エージェントは同じチェックアウトを読める。ファイルを参照するのに実体を渡す必要はなく、パスを本文に書けば届く。

パスの基準は 2 つある。ツリーの根はスペースのチェックアウトで、相対パスは根から数える。一方、[ADR 0056](0056-project-picker.md) は相対パスの基準をペインの cwd（エージェントの起動位置）と決めている。ペインの cwd がチェックアウトのサブディレクトリのとき、根からの `./path` は別の場所を指す。クライアントはペインの cwd を知らない。

主端末はスマホだが、iOS の Web では HTML5 の drag が発火しない。スマホにはプレビューの「パスをコピー」があり、同じ用途に使える。

composer は OS からのファイルドロップを既に受ける。受け入れの判定は `Files` 型で、それ以外のドラッグは既定動作のままにしている。

## Decision

### 運ぶ

- ツリーの行を `draggable` にし、composer で離すとパスを下書きへ入れる。対象は PC のマウスだけにし、タッチ用の代替は作らない
- HTML5 の DnD を使う。運ぶ値は `application/x-hwc-file-reference` の 1 種類だけにする。`dragover` では `getData` を読めない（保護モード）ので、受け入れるかは `types` の有無だけで決める。`text/plain` は付けない。ほかの入力欄やページへ落としたときに、意図しない挿入や遷移を起こさないため
- 運ぶ文字列は、プレビューの「パスをコピー」と同じ絶対パス（`<スペースの作業ディレクトリ>/<根からの相対パス>`）。フォルダは末尾に `/` を付ける。組み立ては `fileReference` に集約し、2 つの入口で同じ文字列を入れる
- 淡色の行（`.env`、根の外を指す symlink）も運べる。淡色は hwc が配信できないという意味で、パスはエージェントにとって有効
- 落とし先は composer の form 全体（入力欄・チップ・送信ボタン）。ドラッグ中は入力欄の枠を既存の `data-drop` で示す。ツリーの外へ落としたときは何もしない
- 起動中と編集中は受け付けない。添付のドロップと同じ条件に揃える

### 入れる

- 差し込み先は、行を掴む直前にフォーカスしていた入力欄の選択位置。行の `mousedown` で入力欄がフォーカスを失うので、`blur` の時点の `selectionStart` / `selectionEnd` を控える。まだ一度もフォーカスしていないときは末尾へ足す
- 選択範囲は置き換える。前後の文字とくっつかないよう、必要なら空白を 1 つ足す（プロジェクト選択と同じ `insertAtSelection`）。キャレットは入れたパスの直後へ置く
- 1 回のドラッグで運ぶのは 1 行。続けて運べば、キャレットの位置に空白区切りで並ぶ
- 差し込んだ後は入力欄へフォーカスを戻す。同じパスを選択範囲に落として下書きが変わらないときも、その場で戻す。コマンドチップは文字を打ったときと同じ規則で、`/new` は解除し、`/compact` の指示は残す
- 改行を含むデータは捨てる。`File` のドロップとは分岐し、アップロードにはしない。チェックアウトの中身はパスで読めるので、保存ディレクトリへの複製は要らない

### 契約

- BFF・Herdr・エージェントの入力契約は変えない。パスは本文の文字列になる
- 新しい store は持たない。下書きの一部なので、保存・復元・編集は既存の draft に乗る

## Consequences

- 会話に出てこないファイルを、パスを打たずに指示へ載せられる。`@` のような独自記法は使わないので、TUI でも同じ本文として読める
- メッセージ本文にホストの絶対パスが残る。チェックアウトの絶対パスは既にペインのメニュー（コピー）とサイドバーの `title` にあるが、認証の無い LAN では会話を開いた端末の画面にも出る（[ADR 0010](0010-lan-access.md)）
- フォルダを運ぶと、その配下を対象にできる。中身は列挙しない
- 淡色の行も運べるので、押しても開けない行に「ドラッグはできる」という隠れた操作ができる。開けないことと参照できないことを分けて扱う
- スマホでは使えない。プレビューの「パスをコピー」を代わりにする。コピーされる文字列はドロップと同じ絶対パス
- Firefox と Safari は `<button>` からの drag 開始に難がある。Chromium 系では動く。必要になったら行のラッパーへ `draggable` を移すか、ポインタ実装へ替える
- ドラッグの見た目はブラウザ標準の行のスナップショットになる。並べ替えのような専用のゴーストは持たない
- 落とす位置がキャレットなので、長い下書きの途中へ入れると前後関係が読みにくい。送信前に手で動かせる
- パスは下書きの一部として `localStorage` に残る
- 起動中のドロップを受け付けないので、起動を待つ間は運べない

## Alternatives

- **自前のポインタドラッグ（並べ替えと同じ方式）**: タッチでも動き、ゴーストも揃うが、PC だけで足りる用途に 2 つ目のドラッグ実装を持つ。並べ替えのドラッグはタッチが必須なので別
- **チップとして composer に積み、送信時に注記を足す**: 見た目は整うが、下書きとの二重状態、送信文字列の組み立て、外したときの扱いが増える。本文の文字列で足りる
- **添付としてアップロードする**: 実体を保存ディレクトリへ複製する。チェックアウトの中身はパスで読めるので、複製と掃除の責務が増えるだけ（[ADR 0080](0080-file-attachments.md) の添付は hwc の外にあるファイル用）
- **`./` の相対パス**: 短いが、ペインの cwd がチェックアウトの根でないとき別のファイルを指す（[ADR 0056](0056-project-picker.md)）。BFF から cwd を返して `../` を許すと、`./` で始まる相対パスだけを入れるという ADR 0056 の前提が崩れる
- **パスをクォートやバッククォートで囲む**: 見た目は区別できるが、hwc の本文はプレーンテキストで、プロジェクト選択も定型文も素の文字列を入れている。記号を増やすと TUI とコピー先で意味が変わる
- **行に「入力欄へ入れる」ボタンやメニューを足す**: タッチでも使えるが、行の操作が 1 つ増える。スマホは既存のコピーで足りる
- **行の中の文字を選択して運ぶ**: 選択の意味が曖昧になり、行の開閉・プレビューと競合する
