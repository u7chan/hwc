# ADR 0062: 選択ツールバーから引用とコピーを行う

- Status: Accepted
- Date: 2026-11-11

## Context

会話の一部を引用して返信したい、という要求は [ADR 0022](0022-reply-quote.md) で一度実装した。引用を別 state に持ち、入力欄の上にカードとして出し、送信時に先頭の blockquote として組み立てる形だった。この形では引用は 1 つに限られ、コメントを書いてから別の箇所を引用すると前の引用が置き換わる。また、選択メニューは選択の下に出るため、スクロールで選択が動くと位置を追えず、隠していた。

今回、選択メニューを次の仕様に寄せる。

- 選択した範囲の上端のすぐ上に、返信とコピーの 2 つのボタンを出す
- マウスのドラッグ中は出さず、ボタンを離したときに確定した選択で出す
- スクロール・リサイズでは選択に付いていく
- Esc・外側の押下・領域外へのスクロールで閉じる
- 引用は入力欄の下書き末尾へ足し、複数の引用とコメントを 1 回で送れる
- コピーは描画した Markdown の記法ごとクリップボードへ戻す
- ログなど Markdown でない領域は、選んだ字をそのままコピーする

BFF とセッションの入力契約は変えない。引用もコピーもクライアントで完結する。

## Decision

### 出る所と出るとき

- 対象はペイン詳細のスクロールする本文（`.hwc-output-scroll`）。選択の始まりと終わりが両方その中にあるときだけ出す。入力欄・ヘッダ・メタ行・領域の外へまたがる選択は対象外
- 空白だけの選択では出さない
- マウスはドラッグ中に評価せず、`pointerup` で確定した選択を見る。クリックだけで選択が畳まれた場合は出さない
- キーボードの選択は `selectionchange` のたびに評価し直す
- スマホは OS の選択メニューを差し替えられないため、hover できるポインタの画面だけに出す（ADR 0022 の制約を維持）

### 置き場所

- 選択範囲の外接矩形の上端のすぐ上に、横方向は範囲の真ん中にそろえる。選択の向きには依存しない
- 左右は本文の領域からはみ出さないよう、ツールバーの実幅を測って寄せる
- 範囲の上端が領域の上に隠れていて上に余地が無いときは、領域の上端に寄せて本文に重ねる
- スクロールと窓のリサイズでは `Range` の矩形を読み直して位置を更新する。範囲が領域の外へ完全に出たら閉じる
- ツールバーを出している間は、最新への自動追従を止める

### 消えるとき

- Esc、ツールバーの外側の押下、領域外へのスクロール、引用の実行で閉じる
- Esc と外側の押下で閉じたあとは、選択が変わるまで出し直さない。選択が変われば `selectionchange` で解除する
- 開閉は 150ms のフェードと上下 4px の移動を付ける。`prefers-reduced-motion: reduce` では遷移しない
- 閉じたあとも 150ms は DOM に残し、退出の遷移を見せる

### ボタン

- 返信とコピーは、左にアイコン、右にラベルを並べる。返信は差し戻す矢印、コピーは重ねた紙で表す
- 押しても選択は外さない。`pointerdown` の既定動作を止めて、押下で選択が折りたたまれないようにする
- 返信は押したあとに選択を外して閉じる。コピーは選択を残したまま、アイコンを ✓ に変える

### 引用

- 選択範囲は `normaliseQuote` で前後の空行を落とし、行ごとに `>` を付ける。空白行は `>` だけにする
- 入力欄の下書きの末尾へ、空行 1 つを挟んで足す。引用の後ろにも空行を 1 つ置き、カーソルをその位置へ移す
- 下書きが空なら引用だけを置く。下書きの末尾の改行は詰めて、引用との間を空行 1 つにそろえる
- 引用したら選択を外してメニューを閉じる。引用は下書きの一部なので、コメントを書いてから別の箇所を引用すると、そのまま複数の引用とコメントが 1 回で送れる
- 引用したときはコマンドのチップだけを外し、下書きは残す（ADR 0016）。送信は通常の本文として行い、`/compact` には戻さない
- 引くのは画面に描かれた文で、元の Markdown ではない。太字やリンクの書式は落ちる

### コピー

- 選択範囲を含む描画済みの本文を DOM から Markdown へ組み立てる。元の Markdown は持っていないため、タグ・クラス・`data-md-raw` を手がかりにする
- 対応する記法はインラインコード（`` ` ``）、太字（`**`）、斜体（`*`）、打ち消し（`~~`）、リンク（`[]()`）、見出し、引用、リストの項目、コードブロックのフェンス、表、画像記法
- ブロックの一部だけを選んだときは、そのブロックの印を付けない。項目の途中なら `- ` を付けず、コードブロックの途中ならフェンスで囲まない
- 項目の完了状態は画面のチェックボックスに合わせる。コピーしても保存はしない
- Markdown として描いていない領域（`.hwc-output` のログ、user 本文、エラー文など）は、選択範囲の描画テキストをそのまま写す
- コピーは既存の `copyText` を使い、HTTP では選択を保存・復元する `execCommand` の経路に落ちる。この経路は一時 textarea の後始末でフォーカス先の選択が消えるため、押したコピーボタンへフォーカスを移してから選択を復元する
- Ctrl+C の通常のコピーは変えない。描画された文がそのまま入る

### UI と制約

- 返信のラベルは「返信」のままにする。仕様上の「引用」と同じ操作
- 入力欄を持たない読み取り専用の画面とシェルのログは、コピーだけを出す
- 送信後の user 本文は、`>` を含めて送った文字列をそのまま出す。引用をカードに装飾しない（2026-11-11 改訂）。引用を下書きへ追記する形に変えたことで本文の途中にも引用が置けるようになり、先頭だけを装飾すると 2 つ目以降が素の `>` で残って、引用と本文の区別が崩れるため
- 選択の保存は下書きと同じ 250ms の debounce に任せる。引用専用の localStorage キーは使わない
- BFF、Herdr、pi の入力契約は変えない。引用は文字列として下書きに畳まれる

## Consequences

- 引用は下書きの一部になる。引用だけの送信、引用 + コメント、複数箇所の引用 + コメントを同じ経路で送れる
- 引用専用の `hwc-reply:*` は読まなくなる。既存の値は残るが、表示・送信には使わない
- コピーの Markdown は描画 DOM から復元する。元のソースと完全には一致しない。対応外の記法は描画テキストになる
- 表のコピーは簡易的なパイプ表になる。セル内の複雑な記法は 1 行に畳まれる
- 画像は描画時に `data-md-raw` へ元の記法を残す。実在が確認できず原文表示になった画像は、等幅の原文としてコピーされる
- 選択がスクロールで領域の外へ出ると閉じる。戻すと選択が残っていれば再び出る。Esc と外側の押下のあとは選択を変えるまで出ない
- 読み取り専用の画面とシェルでは返信を出さない。引用先の入力欄が無い、またはコマンド入力に引用を混ぜても意味がないため
- 選択メニューは引き続き PC のポインタ画面だけに出す。スマホは OS のメニューを使う
- 送信後の引用は `>` 付きの plain text になる。引用した範囲は読み手が記号で追うことになり、本文と見た目では区別されない

## Alternatives

- **引用を別 state のカードとして持ち続ける**: 1 つの引用しか持てず、コメントを挟んだ複数引用を 1 回で送れない（ADR 0022 の形）
- **元の Markdown の位置から切り出す**: パーサはソース位置を保持しておらず、描画テキストと選択範囲の対応も取れない。DOM から組み立てる方が変更が小さい
- **コピーを描画テキストのままにする**: コード・太字・リンクの記法が落ち、貼り付け先で意味が変わる
- **スクロール時に隠す**: 選択が動いても付いてこないため、長い本文の途中を引用しにくい
- **スマホにも独自メニューを出す**: OS の選択メニューを差し替える手段が無い
- **すべての引用ランを引用カードにする**: 見た目は揃うが、user 本文を分解する範囲が広がって手書きの `>` もすべて装飾され、表示だけの効果に対して例外が増える
