# ADR 0042: メッセージ内の画像は新しいタブではなくダイアログで拡大する

- Status: Accepted
- Date: 2026-11-08

## Context

[ADR 0041](0041-agent-message-images.md) は、エージェントが本文で示した画像をメッセージの下にサムネイルで出し、押したら配信 URL を新しいタブで開くことにした。サムネイルは会話の高さを保つため 180px に抑えてあり、拡大表示はブラウザ任せだった。

主端末はスマホで、画像を確かめる目的は「このモックの余白はどうなっているか」のような会話の続きを決めることにある。新しいタブへ移ると hwc を離れ、戻っても読んでいた位置と入力中の下書きの見え方が変わる。会話の流れを切らずに原寸を見たい。

hwc にはすでにモーダルの共通部品（`DialogShell`）があり、背景・Esc・フォーカスの復帰・退出アニメーションを 1 か所で持っている。確認ダイアログと同じ扱いにすれば、拡大のためだけの独自オーバーレイを増やさずに済む。

## Decision

- メッセージ内の画像（ユーザーの添付とエージェントが示したファイルの両方）のサムネイルは `button` にし、押すと同じ配信 URL を `DialogShell` のダイアログで開く。`aria-haspopup="dialog"` を付ける
- ダイアログにはファイル名・画像・「新しいタブで開く」リンク・閉じるボタン（44px）を置く。画像は `object-fit: contain` で、ヘッダーとフッターの分を引いた高さに収める
- 閉じる操作は閉じるボタン・背景の押下・`Esc`。フォーカスは開いたときに閉じるボタンへ移り、閉じたらサムネイルへ戻る（`DialogShell` の既存の扱い）
- 配信 URL は変えない。版を含む既存の URL をそのまま使うので、画像を作り直したときの扱いは [ADR 0041](0041-agent-message-images.md) のまま
- ギャラリー・スワイプ・ピンチの独自 UI は持たない。拡大はブラウザのピンチに任せ、保存や共有は「新しいタブで開く」から行う
- サムネイルの `alt` は空にし、ボタンの `aria-label` で「〜を拡大」と読ませる。ファイル名はダイアログの見出し（`aria-labelledby`）が担う

## Consequences

- 会話とスクロール位置はダイアログの背後に残る。閉じるとそのまま読んでいた場所に戻る
- ダイアログは入力欄を覆う。開いている間は下書きを編集できない
- 透過 PNG は `raised` の面の上に出るので、明るい画像でも輪郭が分かる
- 画像が 1 枚でも複数枚でも同じ操作になる。複数枚を続けて見るときは、閉じて次のサムネイルを押す
- 新しいタブは保存・共有・別アプリへ渡す経路として残る

## Alternatives

- **新しいタブだけで済ませる**: hwc を離れ、スマホでは戻ったときの位置が変わる。会話の続きを決める用途に合わない
- **独自の全画面オーバーレイ**: 背景・Esc・フォーカス復帰・アニメーションを `DialogShell` と二重に持つ
- **`<dialog>` と `showModal()`**: フォーカスの復帰をブラウザに任せられるが、既存のダイアログと機構が 2 つになる。`DialogShell` の挙動を変える必要が出たときに揃える
