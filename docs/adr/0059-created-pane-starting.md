# ADR 0059: 作ったばかりのペインは、エージェントが画面を引き継ぐまで入力を閉じる

- Status: Accepted
- Date: 2026-11-10

## Context

[ADR 0026](0026-new-pane.md) / [ADR 0027](0027-new-pane-agent.md) / [ADR 0038](0038-create-worktree.md) の作成は、ダイアログを閉じた時点で終わる。エージェントの起動は `agent.start` が受け持つが、成功は「TUI が入力を待っている」ことまでは保証しない。`agent_not_ready`（フォルダ信頼・ログインの待ち）は成功として扱うため（ADR 0027）、起動が終わっていないペインが開くこともある。また hwc は端末の出力を 2 秒間隔で読むので、開いた直後の画面にシェルのプロンプトと起動コマンドが残ることがある。

この間も入力欄は出ており、送信は Herdr の `pane.send_input` で端末へ文字を流す。エージェントがまだ端末を引き継いでいなければ、書いた文字はシェルに届く。ワークツリーを作った直後は、新しいスペースの root pane がそのまま開くので、この状態に当たりやすい。

## Decision

- エージェントを起動する作成が成功したとき、クライアントは `{ paneId, at }` を 1 つだけ覚える。シェルの作成では覚えない。入力の宛先がシェルに決まっているため。部分成功（起動失敗・リネーム失敗）でも覚えない。起動に失敗していればシェル、リネームだけ失敗していればエージェントの起動は済んでいる（両方失敗した場合は起動失敗を優先する）
- 覚えているペインでは、入力欄の代わりにスピナーと「エージェントを起動しています。準備ができるまでメッセージは送れません。」を出す。入力欄そのものを描かない。キャンセル・送信・添付・コマンドの入口も同時に消える
- 待ちは次のどれかで終わる
  - 応答から 3 秒（`STARTING_SETTLE_MS`）まで。出力のポーリングが 2 秒なので、起動前の画面が残り得る区間を覆う
  - 3 秒以降は、ペインでエージェントが検出されていれば開く
  - 検出されないままでも、応答から 10 秒（`STARTING_LIMIT_MS`）で開く。起動しなかったペインを hwc から操作できないままにしない
- 判定は `src/client/starting.ts` の純関数に置き、描画のたびに導出する。記録は期限で無効になるだけで、明示的に消さない（期限切れの記録は別のペインに一致せず、次の作成で置き換わる）
- 開いているペインを切り替えても記録は残す。選び直しで待ちを外せないようにする
- フォルダ信頼の確認（[ADR 0044](0044-pi-project-trust.md)）が出ている間は、従来どおり確認ビューが優先される。入力欄の代わりに確認を出す判断は変えない

## Why not

- **準備完了を `pane.chat` で判定する**: Codex は最初のメッセージを送るまでセッション参照が無く、会話が読めないのが正常な起動直後（E2E の `codex-start`）。読めることと入力を受け付けられることは別で、これを待つと正常なペインを閉じてしまう
- **BFF に待ち状態を持たせる**: どのペインを「今作った」かは要求したクライアントしか知らない。BFF に持たせると、作成していないクライアントにも同じ待ちを見せることになり、入力を止める理由をサーバー状態へ二重に持つことになる
- **時間だけで開ける**: 起動待ちが長いと、シェルへ文字が届く区間が残る
- **エージェントが検出されるまで無期限に閉じる**: 起動に失敗したペインを、hwc からも Herdr の TUI 以外では使えなくなる

## Consequences

- 作成が速くても、直後の 3 秒は入力欄が出ない。スマホで作成してすぐ打ち始めると、1 度待つことになる
- エージェントが起動しなかった場合、最大 10 秒は hwc から入力できない。Herdr の TUI では操作できる
- 再読み込みすると記録は失われ、待ちは解除される。作成直後の再読み込みは稀で、以降の危険な区間はエージェントの検出で判定できる
- 待ちの文言はエージェントの種類を問わない。`agent_not_ready` で信頼確認が出ているペインは、確認ビューが入力欄の代わりに出る
