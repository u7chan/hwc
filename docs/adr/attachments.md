# 添付は状態ディレクトリに保存し、エージェントには本文の注記でパスだけを渡す

- Status: Accepted

## Context

スマホのスクショや PC のファイル（zip・Office 文書・CSV など）をエージェントへ渡したい。hwc は Herdr の `pane.send_input` に文字列を流すだけで、エージェントのモデル呼び出しには触れない。どのモデルが画像を読めるか、どの形式を開けるかも hwc は知らない。

BFF はエージェントと同じユーザー・同じホストで動くので、BFF が保存したファイルはエージェントがパスで開ける。

## Decision

- 添付は状態ディレクトリの `attachments/<pane-id>/` に保存する（[状態の置き場所](state-storage.md)）。種別でディレクトリを分けない
- アップロードは生バイトのまま受け、元のファイル名を `X-HWC-Filename`（UTF-8 を percent-encode）で受ける。名前の sanitize と検証は `src/shared/attachments.ts` の 1 か所に置く。パス区切り・注記の区切り・制御文字を落とし、sanitize しても変わらない名前だけをパスへ連結する。同名は上書きせず連番を足す
- ペイン id もディレクトリ名になるため、`..`・区切り文字・制御文字を含む id は連結する前に弾く
- 型と上限は拡張子で決め、`Content-Type` は見ない（zip や Office 文書は `application/octet-stream` や空で来る）。上限は画像と非画像で分け、件数は合計で数える
- 本文の末尾に `<attached_files>` 注記で絶対パスだけを載せる。種別やサイズは書かない。マルチモーダル注入はしない
- 会話の履歴では BFF が注記を取り除き、ファイル名だけを返す。絶対パスは client へ渡さない
- 配信するのは画像 3 形式（png / jpeg / webp）だけ。SVG は同じオリジンでスクリプトが動く形式なので、添付としては保存も配信もしない。非画像は配信もダウンロードもさせない

## Consequences

- エージェントが添付を読めるかは CLI 次第で、hwc は実体を渡していない。Claude は保存先がチェックアウトの外なので、読むときに権限確認が出たら端末で承認する
- 添付は自動では消えない。ペインを作り直すと旧添付は参照されないまま残る
- アップロードは全量をメモリに受けてから書く。上限（非画像 25MB × 4 件）はこの同時保持を前提に決めている

## Alternatives

- **ペインの cwd 配下に保存する**: エージェントが相対パスで開けるが、作業ツリーを汚し、ペインを作り直すとパスが変わる
- **マルチモーダル注入**: モデルの対応を hwc が知る必要があり、Herdr の入力契約（文字列）を超える
- **ファイル名を query や multipart で送る**: query は名前がログと Referer に残る。multipart は生バイトの `Content-Length` 事前検査が使えなくなる
- **BFF で zip を展開し、xlsx を CSV に変換する**: 変換ツールの有無と失敗時の扱いが hwc の前提に増える。まずパスを渡すだけにする
