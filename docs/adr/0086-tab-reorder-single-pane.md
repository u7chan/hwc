# ADR 0086: 1 枚表示のタブはドラッグで差し替え、並びの変化を滑らせる

- Status: Accepted
- Date: 2026-11-15
- Revises: [ADR 0058](0058-split-view-tab-history.md) の「タブバー内の並べ替えは持たない」
- Revises: [ADR 0063](0063-tab-order-by-pane-layout.md) の `openTabs` の意味と 1 枚表示のタブ順
- Revises: [ADR 0064](0064-tab-strip-swap.md) のタブへのドロップの意味と、タブを滑らせない判断

## Context

[ADR 0063](0063-tab-order-by-pane-layout.md) で、PC の 2 枚以上の分割ではタブ順をセルの読み順に固定し、1 枚表示とモバイルは開いた順のままにした。分割ではタブの位置とセルの位置が 1:1 なので、手で並べ替える意味がない。1 枚表示には対応するセルが無く、並びは好みだけで決まるのに、整える手段が無い。

[ADR 0064](0064-tab-strip-swap.md) はタブへのドロップを固定ゾーンの入れ替えに使った。1 枚表示では固定ゾーンが 1 枚しかないため、この意味は成立しない。タブを掴んで別の位置へ運んでも何も起きない。

モバイルは横スクロール中のドラッグがスクロールと競合する（ADR 0063）。PC の 1 枚表示ではタブ列のスクロールはあるが、マウスのドラッグと衝突しない。

## Decision

### 対象

`wide` かつ `readingOrder(layout)` の長さが 1 以下。モバイルは対象外にする。`startPaneDrag` が既に `!wide` で止めており、タブ列の横スクロールを奪わない。

### ドロップの意味

`tabDropMode(view, source, target, wide)` が返す。

| 葉の数 | 意味     | 受け付ける範囲                                          |
| ------ | -------- | ------------------------------------------------------- |
| 2 以上 | `swap`   | 固定ゾーン（`readingOrder`）のタブ同士。ADR 0064 のまま |
| 1 以下 | `insert` | 開いているタブすべて                                    |

- `insert` は掴んだタブを列から外し、対象タブの前か後ろへ差し込む。対象タブの左右半分で決める
- `openTabs` に無いペインは差し込めない。一覧から開いていないペインをタブへ落としても、開く操作にはしない
- 起点はタブ・セル見出し・一覧の行のどれでも同じ（ADR 0064 の原則）。1 枚表示ではセルが動かないので、挿入で並べ替えてよい

### 状態

`moveTab(view, source, target, side)` が `openTabs` を並べ替える。`recent` は選択履歴なので触らない。`current` と `layout` も変えない。

`openTabs` の意味を「開いた順」から「タブの並び」に変える。新しく開いたタブは末尾に足す。分割に切り替えると表示順は `readingOrder` + `recent` になるので、手で並べた順はそこで消える（ADR 0063 の帰結として受け入れる）。

### 落とし先と枠

- 1 枚表示ではすべてのタブに `data-drop-tab` を付ける。分割では固定ゾーンだけ（ADR 0064）
- タブの隙間とタブ列の余白も差し込みの落とし先にする。ポインタより右にある最初のタブの前、余白なら末尾の後ろ
- 挿入は対象タブの内側に 2px の縦線で示す（`data-insert`）。スロット色のバーより後に描くため `::before` ではなく `::after` に置く
- 入れ替えは従来どおり `inset` の枠（`data-drop-target`）で示す
- プレビュー中は落とし先にしない（ADR 0064 の理由を流用）

### アニメーション

並びが変わるとき、タブを変更前の位置から滑らせる。

- 変更の直前に `[data-tab-pane]` の位置を控え、描画後の位置との差を `transform` で戻す。セルの FLIP と同じ仕組み（ADR 0061）で、state は増やさない
- 位置はタブ列のスクロールを含めた座標で比べる。選択タブへの自動スクロールが同じフレームで動いても、滑る距離が変わらない
- 位置を控えるのはドロップとタブを外したときだけ。分割中のタブ選択など、撮っていない操作では動かさない
- 分割に入るとき・1 枚に戻るときの並び替えも同じ経路で滑る
- 外すアニメーション中のタブは幅を動かしているので対象外
- `prefers-reduced-motion: reduce` では動かさない
- 並べ替えで選択中のタブが画面外へ出るので、タブ列の自動スクロールの依存にタブ順を足す

### 永続化

`openTabs` の変化として `hwc-split-view` に乗る。端末ごとの localStorage なので、PC で並べ替えてもスマホの並びは変わらない。スマホは開いた順のまま。

## Consequences

- 1 枚表示ではタブを好きな順にできる。新規タブと、閉じて開き直したタブは末尾に入る
- 分割した瞬間に手で並べた順は消え、読み順 + MRU になる。その入れ替わりはアニメーションで見える
- 分割中のタブ選択（`recent` が動く）は今までどおり即時に変わる。滑るのは撮った操作だけ
- 1 枚表示のドラッグは、掴んでいないタブも動かす。セルが無いので位置の対応は壊れない
- タブ列を横スクロールしているときの端での自動スクロールは持たない。可視範囲内の差し替えに限る
- タブの位置を控える DOM の走査が、ドロップと × のたびに 1 回増える

## Alternatives

- **分割でも挿入**: 掴んでいないセルまで動き、3〜4 枚で結果を予測しにくい（ADR 0064）
- **固定ゾーンの外のタブも分割で手で並べる**: `recent` は選択履歴から導出する値なので、並べ替えると意味が壊れる（ADR 0064）
- **入れ替えで並べ替える**: 末尾へ運ぶのに何度も往復する。ブラウザのタブの操作と違う
- **タブ順を別の state に持つ**: `openTabs` と二重管理になり、正が 2 つになる
- **モバイルでもドラッグ**: 横スクロールと競合し、押し間違いを招く（ADR 0063）
- **アニメーションなし**: 分割した瞬間にタブが飛び、順序が変わったことに気づきにくい
