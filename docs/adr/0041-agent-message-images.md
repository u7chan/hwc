# ADR 0041: エージェントが書いた画像をメッセージ内でプレビューする

- Status: Accepted
- Date: 2026-11-08

## Context

エージェントはスクリーンショットやモックをファイルに書き、本文にそのパスを書く。hwc ではパスが文字列のまま残るため、スマホから中身を見るには別のアプリで開く必要がある。モックや画面の確認を hwc の中で閉じたい。

hwc は Herdr の入力契約（文字列）しか持たず、モデルへ画像を注入できない。読めるのは pi のセッション JSONL と、BFF と同じユーザーで読めるファイルだけになる。

既存の判断との関係:

- Markdown の画像記法は描画しない（[ADR 0018](0018-pasted-image-attachments.md)）。履歴の画像は新しいタブで開く
- 添付は BFF の保存ディレクトリ配下の名前だけを扱い、絶対パスはクライアントへ渡さない
- 認証が無い LAN 公開（[ADR 0010](0010-lan-access.md)）。任意のパスを配信する口を増やすと、ホスト上のファイルを読める範囲が広がる

## Decision

- 対象は画像だけ。png / jpg / webp（拡張子 `jpeg` も受ける）。1 枚 10MB まで、1 メッセージ 4 枚まで
- 参照の書式は増やさない。BFF が `role: "agent"` の本文からパスの候補を拾い、実在するものだけを `ChatMessage.files: { name, version }[]` として返す。拾うのはフェンス外の本文にある、裸のパス・インラインコード・Markdown のリンクと画像の destination。1 通あたり候補は 20 件まで試す
- 根はワークスペースのチェックアウト（既存の `checkoutPaths`）と、[ADR 0051](0051-agent-html-preview.md) の追加根。絶対パスと相対パスのどちらも受け、`realpath` で解決した実体が根の配下にあるときだけ返す。symlink で根の外を指すものは落とす。通常ファイルで、0 バイトより大きく 10MB 以下に限る
- `name` は根からの相対パスだけ。絶対パスはクライアントへ渡さない。`version` は mtime とサイズ
- 配信は `GET /api/panes/:id/files?root=<番号>&path=<相対>&v=<version>`。ペインの実在と `chat: true` を確認してから、上と同じ解決を通す。根の番号は [ADR 0051](0051-agent-html-preview.md) と同じで、0 はチェックアウト、1 以上は追加根。型は名前の拡張子から決め、`X-Content-Type-Options: nosniff` と `Cache-Control: private, max-age=31536000, immutable` を付ける。`v` は内容の版なので、同じ URL の中では内容が変わらない
- snapshot の etag に `root:name@version` を混ぜる。本文が変わらないまま画像を作り直したときや、追加根の順が変わったときに、304 で古い URL が残らないようにする
- クライアントは既存の添付行（`.hwc-msg-attachments`）と同じ見た目で、エージェントのメッセージの下に出す。押すと配信 URL を新しいタブで開く。拡大表示は持たない（[ADR 0042](0042-image-preview-dialog.md) でダイアログに変更）
- SVG は対象外。同一オリジンでスクリプトが動く形式なので、添付と同じく保存も配信もしない
- パスを拾えなかったメッセージは今までどおり文字列のまま

## Consequences

- エージェントは特別な記法を知らなくてよい。本文にパスを書けば出る
- チェックアウトの外（`/tmp` など）に書いた画像は、`HWC_PREVIEW_ROOTS` に根を足せば出る。既定では出ないので、モックは `.artifacts/` などチェックアウトの内側に置くのが基本
- 本文のパス文字列は残る。コピーできるが、Markdown の画像記法で書くと記法も見えたまま画像が下に並ぶ
- パスの抽出は候補の列挙だけで、実在確認が唯一の絞り込みになる。本文に書かれた既存の画像パスは、意図しなくても出る
- 会話を取得するたびに、候補の数だけ stat が走る。候補は 20 件、採用は 4 件で止める
- 画像を作り直すと、次の会話取得で `v` が変わり、新しい絵になる
- 認証が無い LAN では、ワークスペース配下の画像を誰でも読める。元からペインの操作と端末出力ができたので、露出の種類は変わらない

## Alternatives

- **Markdown の画像記法だけを描画する**: 決定的だが [ADR 0018](0018-pasted-image-attachments.md) の判断を覆す必要があり、エージェントが記法を使わないと何も出ない
- **任意の絶対パスを配信する**: `/tmp` のモックも出せるが、ホスト上の任意の画像を LAN へ出す口になる
- **ペインの添付ディレクトリへコピーさせる**: 保存先をエージェントに教える必要があり、実在するファイルを二重に持つ
- **画像をデータ URL で本文へ埋め込む**: 会話の JSON が画像の分だけ膨らみ、etag も毎回変わる
