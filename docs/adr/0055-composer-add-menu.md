# ADR 0055: 入力欄の + メニューから画像を追加する

- Status: Accepted
- Date: 2026-11-10
- Revises: 2026-11-13 に「画像を追加」の受け付けをファイル全体へ広げた（[ADR 0080](0080-file-attachments.md)）

## Context

画像の添付はクリップボードへの貼り付けと、PC でのファイルのドロップだけで受け付けている（[ADR 0018](0018-pasted-image-attachments.md)）。スマホでは貼り付けの操作が長押しに隠れ、ファイルをドロップできないため、画像を送る入口が見えない。主端末はスマホなので、入力欄の近くに常設の入口が要る。

入力欄には、開閉ボタン・送信・モデルと使用量の札がある。下部の操作行は送信の右端が空いており、左端に余裕がある。ここに「入力を追加する」ボタンを置けば、画像の入口を足しても本文の幅を削らない。

同じ入口には、モノレポで修正対象のプロジェクトを選ぶ操作も載せる予定がある（[ADR 0056](0056-project-picker.md)）。入口を 2 つに分けず、+ のメニューを共通の置き場にする。

## Decision

- 入力欄の下部操作行の左端に、44 × 44px の + ボタンを置く。会話を持つペインだけに出し、シェルペインと、入力欄を 1 行に畳む分割セルでは出さない
- `+` を押すと、+ の上にメニューを開く。項目は「新しい会話」「会話を圧縮」、区切り、「画像を追加」「プロジェクトを選ぶ」にする。会話コマンドの追加は [ADR 0057](0057-composer-conversation-commands.md) に従う。将来の項目を先回りして置かない
- メニューは既存の `Menu` を使い、`side="above"` と専用の id を指定する。下方向にしか開かない既存の配置関数に、トリガーの上へ開く指定を足す
- 「画像を追加」は hidden の `<input type="file" accept="image/*" multiple>` を開く。`capture` は付けず、カメラを強制しない
- 選ばれたファイルは既存の `dropActionFrom` と `takeImages` を通す。形式・サイズ・枚数の判定、アップロード、失敗 notice は貼り付け・ドロップと同じ経路にする
- 4 枚添付済みのときは「画像を追加」を無効にし、理由をメニューの補助文に出す。画像を追加するとコマンドのチップは解除する。引用は残す
- 選択後のファイル入力の値は空へ戻し、同じファイルをもう一度選べるようにする
- 画像を選んだだけで入力欄へフォーカスを戻さない。スマホでキーボードを開き直さず、添付の確認と送信を選べるようにする

## Consequences

- iOS の写真ピッカーが HEIC をそのまま返すと、既存の形式判定で「対応していない画像形式です」になる。`accept` を `image/*` にしてピッカーから消さない代わりに、HEIC の変換はしない。実機で返る形式は別途確認する
- ファイル入力は `accept` を無視したファイルも返し得る。画像以外は既存の `dropActionFrom` が捨て、未対応の画像形式だけ notice にする
- `+` が 44px を占めるぶん、狭い画面ではモデル名の省略が早くなる。操作行の残り幅を情報と送信に渡すため、`hwc-input-tail` は残り幅を取って右端に寄せる
- メニューは + の上に重なり、会話の末尾を一時的に隠す。入力欄の外側をタップするか `Escape` で閉じる
- 画像の受け口は paste / drop / file input の 3 つになるが、保存先・上限・通知は 1 つの経路に集約したまま
- メニューに項目を足すときは、入力欄の送信契約を変えないものだけを載せる。画像とプロジェクトは本文を変え、会話コマンドは固定の `/new` `/compact` を送る。汎用のコマンドパレットにはしない（[ADR 0057](0057-composer-conversation-commands.md)）

## Alternatives

- **紙クリップの単独ボタン**: 画像の入口は増えるが、プロジェクト選択の置き場が別に要る。+ の 1 つにまとめる方が入力欄の操作が増えない
- **常時表示のファイル入力ラベル**: 実装は最小だが、ラベルの見た目をボタンに寄せると + と同じ場所を取る。メニューにすると項目の説明を添えられる
- **ボトムシート**: 2 項目には重く、会話を覆う面積が大きい。+ の上に小さく開く方が元の文脈を残せる
- **貼り付けとドロップだけを残す**: 実装ゼロだが、スマホで画像を送る入口が見えないままになる
- **`capture` 付きのカメラ入力**: 撮影は速いが、スクリーンショットや既存の写真を選べなくなる。写真ライブラリを優先する
