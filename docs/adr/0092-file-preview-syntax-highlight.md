# ADR 0092: ファイルプレビューを自前のトークナイザでシンタックスハイライトする

- Status: Accepted
- Date: 2026-11-17

## Context

ペインのファイルツリーから開くテキストは、行番号付きのプレーン表示で出している（[ADR 0090](0090-pane-file-tree.md)）。会話に出てこないソースを読むとき、色が無いと構造を追いにくい。

[ADR 0009](0009-dependency-policy.md) は依存を最小限に保つ。[ADR 0014](0014-markdown-rendering.md) は u7agent の Markdown パーサを移植したが、そのときシンタックスハイライトは削っている。

u7agent（`u7chan/monorepo` の `projects/u7agent`）には、外部ライブラリを使わないトークナイザがある（`client/src/lib/markdown/highlight.ts`）。言語ごとの順序つき正規表現と語の分類だけでトークン列を返し、HTML 文字列を組み立てない。

hwc のファイルプレビューは最大 256KB を 1 つの `pre` に出す。トークン 1 つが DOM ノード 1 つになるため、色付けには上限が要る。主な利用端末はスマホで、PC のブラウザより描画に時間がかかる。

テーマは 20 種類ある。コード用の色を各テーマに足すと 20 × 6 色の値を保守することになる。ANSI 8/16 色は `--ansi-*` として明暗 2 系統だけ定義され、`theme.test.ts` が 4.5:1 を固定している。

## Decision

- u7agent のトークナイザを `src/client/pane/highlight.ts` に移植する。外部ライブラリは足さない。`innerHTML` / `dangerouslySetInnerHTML` を使わず、トークン列を Preact の `<span>` にする（[ADR 0009](0009-dependency-policy.md)）
- 対象はファイルプレビューのソース表示だけにする。Markdown のコードフェンスは [ADR 0014](0014-markdown-rendering.md) のままハイライトしない
- 言語は拡張子で決める。u7agent と同じ対応表（TS / JS 系、JSON、C、C++、Java、Go、Rust、Python、Bash、CSS、HTML、Markdown、diff）とし、拡張子の無い `Dockerfile` だけ bash の規則を使う。判定できない拡張子は素のテキストにする
- トークン列は本文を欠落・改変しない。行番号は今までどおり本文とは別の `pre` に出す（[ADR 0090](0090-pane-file-tree.md)）
- ハイライトは 20,000 トークンで打ち切る。超えたらファイル全体を素のテキストにする（途中まで色付けしない）。打ち切りは上限を超えた時点で行い、巨大なファイルを最後まで走査しない
- 色は `--ansi-*` と `--color-muted` を使う。テーマごとのコード用変数は足さない。`--color-secondary` は solarized-light と rose-pine-dawn で 4.5:1 を割るため使わない
- 演算子と句読点は色を分けず、素のテキストとして出す。トークン数に対して span が増え、スマホの描画時間に効くわりに、読みやすさへの寄与が小さい
- 区切り文字の無い塊で走査が二次関数的に伸びないよう、規則の量化子を有限にする（コメント・文字列・リンク・HTML の属性名など）。連続する素の 1 文字と 1 文字語が 5,000 を超えたら色付けを諦め、全体を素のテキストにする

## Consequences

- ソースが色付きで読める。キーワード・文字列・数値・コメント・関数名・型名の 6 種類。色は端末出力と同じ ANSI 8 色で、テーマの明暗に追随する。テーマ追加時の色定義は要らない
- バンドルが増える（移植したトークナイザと対応表）。初期表示への影響は小さい
- トークナイザは u7agent と二重管理になる。修正は手で backport する（[ADR 0014](0014-markdown-rendering.md) と同じ）
- 20,000 トークンを超えるファイルは色が付かない。行番号と本文は最後まで出る。51KB の TS は 15,842 トークン、82KB の TS は 25,148 トークンだった
- 51KB の TS を開くのに、E2E の架空データで約 0.2 秒（headless Chromium、CPU 4 倍遅延で約 0.56 秒）かかった。同じ 82KB を素のテキストで出すと CPU 4 倍遅延で約 0.30 秒なので、色付けの分だけ余分にかかる。20,000 トークンの上限は、この実測と u7agent の「232 KiB / 46,000 トークンで 0.66 秒」から置いた
- 色は構文の近似で、意味（型・スコープ）は見ない。TS の型注釈と変数名の区別などは字面だけで決まる
- Markdown のコードフェンスは色が付かないまま（[ADR 0014](0014-markdown-rendering.md)）。必要になったら同じトークナイザを呼べる
- 演算子と句読点に色は付かない。VS Code などの既定テーマとは見た目が違う
- 区切り文字が無い塊（`[` や `${` の連続など）や、短い語の繰り返し（`ab.` など）は、色付けを諦めるか規則の上限で打ち切る。256KB の `[` で 20 秒超だった走査が、数ミリ秒になる

## Alternatives

- **外部ライブラリ（highlight.js / Prism / Shiki / lowlight）**: [ADR 0009](0009-dependency-policy.md) に反する。Shiki はバンドルが大きく、HTML 文字列を組み立てる経路にもなる
- **サーバーでハイライトして HTML を返す**: クライアントが HTML 文字列を挿入することになり、XSS の面が増える。BFF に表示の都合を持ち込む
- **テーマごとにコード用の色を定義**: 20 テーマ × 6 色の保守になり、テーマ追加のたびに増える。既存の ANSI 色で足りる
- **上限超過でも先頭だけ色付けする**: 同じファイル内で色が途切れ、どこまでが色付けの対象か分からない。全体を素にする
- **行ごとにトークン化する**: コメントや文字列が行をまたぐため、状態を持ち越す必要がある。本文全体を 1 回走査する方が単純
- **Markdown のコードフェンスにも適用**: [ADR 0014](0014-markdown-rendering.md) の判断を変えることになる。今回はファイルプレビューだけにする
- **演算子も色分けする**: 51KB の TS で span が 3,201 から 9,121 に増えた。CPU 4 倍遅延の描画は 559ms から 640ms になり、見た目の差に見合わない
