# ADR 0065: シェルペインの入力欄からエージェントを起動する

- Status: Accepted
- Date: 2026-11-11

## Context

[ADR 0027](0027-new-pane-agent.md) で、hwc は新しいペインにエージェントを起動できる。しかし起動の入口はペインの「…」メニューとスペースのメニューだけで、シェルペインを開いている間は気付きにくい。エージェントが終了してシェルに戻ったペイン（[ADR 0029](0029-preserve-last-pane.md)）でも同じで、もう一度起動するには ⋮ を開く必要がある。

シェルの入力欄に `pi` と打てば起動自体はできる。ただしモデルと effort を指定できず、Codex の `--no-daemon` も付かないため、hwc から会話を読めないペインになる。スマホでは CLI 名を打つこと自体も手間になる。

Herdr の `agent.start` は既存のシェルペインを受け付ける。分割直後のペインに使っているのと同じ呼び出しで、ペインを作らずに起動できる。hwc はシェルの前景プロセスを 3 秒ごとに読んでおり（[ADR 0045](0045-shell-pane-stop.md)）、起動できるかどうかの材料も既にある。

## Decision

### 入口

- シェルペインの入力欄のアクション行の左端に「エージェントを起動」を置く。会話ペインの + と同じ位置・同じ高さ（`--tap`）にし、置き場所を覚え直さずに済ませる
- 面は `raised`、文字は `text`、アイコンだけ `accent` にする。送信（アクセント塗り）と強さを揃えず、主操作を奪わない
- ターミナル出力の上には重ねない。出力は Herdr が持つライブな画面で、空状態は数秒しか出ないため、そこに置いた入口はすぐ消える
- 常設の帯は作らない。開発サーバーを眺めるためのシェルペインでも、入力欄の 1 行を常に消費するため
- 分割セル（`compact`）では + と同じ規則で隠す（[ADR 0055](0055-composer-add-menu.md)）

### 実行中のシェル

- クライアントは前景プロセスのポーリング結果が `running` のとき、ダイアログを開かずに notice で「コマンドが動いています。停止してから起動できます」と返す。無効化して無反応にはしない
- BFF も `agent.start` の `agent_pane_busy` を 409 `pane_busy` に写す。ポーリングは最大 3 秒古いので、画面が止め忘れを見落とす場合がある
- 既存のシェルへの起動では `agent_pane_busy` を待たない。分割直後の「シェルの準備待ち」と違い、同じ code が「コマンドが動いている」を意味するため、5 秒のリトライをすると失敗を遅らせるだけになる。待つかどうかは `agent.start` の `waitForShell` で切り替える

### ダイアログ

- 作成ダイアログ（[ADR 0027](0027-new-pane-agent.md)、[ADR 0030](0030-new-pane-model.md)）を流用し、起動用の表示に差し替える
  - 見出し「エージェントを起動」、説明は「シェルペイン `<id>` の上で起動する。作業ディレクトリとシェルの履歴は残る」
  - ペイン名の欄と「エージェント / シェル」の切り替えは出さない。ペインは既にあり、名前も変えない
  - エージェントのカード、モデル、effort、送信中と失敗の扱いは作成と同じ
  - 主操作は「起動」、送信中は「起動中…」
- 起動できたときは、作成と同じくペインを起動待ちとして記録し、入力欄をスピナーに差し替える（[ADR 0059](0059-created-pane-starting.md)）。モデルを指定した場合は、会話に載るまでの表示にも使う（[ADR 0033](0033-launch-model-before-first-message.md)）
- 失敗の見せ方は経路で分ける。timeout とペイン消失は再試行させず「閉じる」、`pane_busy`・起動失敗・不明はフォームを残して再試行できる
- エージェントの起動に失敗してもペインはシェルのまま残るので、ダイアログでそれを伝える

### API

- `POST /api/panes/:id/agent` を足す。body は `{ agent, model?, effort? }` で、`agent` は必須。名前は受け取らない
- BFF の状態にペインが無ければ 404、既にエージェントがいれば 409 `pane_not_shell`、body が不正なら 400、`agent_pane_busy` は 409 `pane_busy`、起動失敗は 502 `agent_start_failed`、それ以外の Herdr の失敗は既存の規則に写す。成功は `{ ok: true }`
- 状態の取り直しは Herdr の `pane.updated` に任せ、応答を待たない。focus / close / 分割と同じ規則
- `setupPane` を分割と共有する。分割もしないし名前も付け直さないので、呼ぶのはエージェントの起動だけになる

### エージェント名

- 同じペインで起動し直すと、前回のエージェント名が Herdr 側に残っているか分からない。名前は Herdr の照会用で、hwc はペイン id しか使わないため、既存のシェルへの起動では起動のたびに 4 文字の接尾辞を付ける（`hwc-w1-p1-3f9k`）
- 分割で作るペインは今までどおり `hwc-<pane id>` のまま

## Consequences

- シェルのスクロールバックは消えない。エージェントの TUI が同じ端末に描かれ、終了するとシェルに戻る
- 4 枚上限を消費せず、レイアウトも作業ディレクトリも保ったまま起動できる。分割で増やすより軽い
- 分割セルでは入口が出ない。広い画面で分割しているときは、ペインを 1 枚表示にするか ⋮ を使う
- 前景のコマンドを止めないまま押すと notice が出る。止めるのは既存の停止ボタン（[ADR 0045](0045-shell-pane-stop.md)）
- 起動に失敗してもシェルはそのまま残る。ダイアログの文言だけで、状態を変えない
- 起動したエージェントが終了すればシェルに戻り、入口がまた出る。⋮ を開き直す必要はない

## Alternatives

- **⋮ のメニューにだけ足す**: 実装は最小だが、気付きにくいという問題をそのまま残す
- **ターミナル出力の中央に大きい + を置く**: 出力は Herdr のライブな画面で、hwc が差し込める場所が無い。重ねるとログを隠し、空状態に頼ると数秒で消える
- **入力欄の上に常設の帯を置く**: 一番目立つが、シェルのペインすべてで縦を消費する。開発サーバーを見るためのペインでは邪魔になる
- **分割してエージェントのペインを作る**: 既存の「新しいペイン」で足りるが、4 枚上限を消費し、レイアウトが変わる。同じ場所と履歴を使い続けたい用途に合わない
- **CLI 名を打てばよいと案内する**: Pi は動くが、モデル・effort の指定と Codex の起動引数が付かず、hwc から会話を読めないペインになる

## Verification

- unit で、body の検証（agent 必須・モデルと effort の整合）、既存のシェルへの起動が分割も改名もしないこと、起動引数と `waitForShell: false`、`agent_pane_busy` を待たないこと、`agent_not_ready` を成功として扱うこと、ルートの 400 / 404 / 409 / 502 と状態を取り直さないこと、起動時のモデルが会話に載るまで表示されることを確認する
- 架空 Herdr の E2E で、待機中のシェルペイン（`notes`）の入力欄に入口が出ること、ダイアログから起動すると入力欄が起動待ちに変わり、そのあと会話ビューになることを確認する。前景でコマンドが動いているペイン（`shell`）では、押すと notice が出てダイアログが開かないことも確認する
