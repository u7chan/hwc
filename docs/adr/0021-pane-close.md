# ADR 0021: ペインを閉じる操作は詳細の見出しに置き、確認を挟む

- Status: Accepted
- Date: 2026-11-04

## Context

hwc にはペインを閉じる手段が無かった。不要になったペインは Herdr TUI で閉じるか、エージェントに指示するしかなく、一覧からスペースをまたいで片付けられない。一覧の行メニューには一度「ペインを閉じる」と確認ダイアログが入ったが、BFF に close のエンドポイントが無い時点で落とした。タブの × も同じ枝で試して外している。

Herdr は `pane.close`（params は `{ pane_id }`）を持ち、`pane.closed` は `STATE_EVENTS` に入っている。BFF はライフサイクルイベントを受けて `store.refresh()` し、SSE でスナップショット全体を配る。close の成否をクライアントが状態として持つ必要はなく、応答を待つ間に状態を取り直す必要も無い。

閉じると、開いていた作業は失われ、実行中のエージェントのプロセスも終わる。取り消せない操作なので、押した指の先で完結させない。

詳細のペイン見出しは名前・サブ・ペイン ID・コピーだけで、操作メニューを持っていなかった。一覧の行には既に「…」ボタンとメニューがある。

広い画面の `PaneDetail` は常に `.hwc-split-cell` の中にあり、`.hwc-split-cell` は `container: hwc-cell / size` を持つ。layout containment により fixed 子孫の包含ブロックになるため、セルの内側に fixed のメニューやダイアログを置くと画面全体ではなくセルだけを覆い、`hwc-menu` の viewport 座標もずれる。

選択の規則は「選んだペインがスナップショットから消えても id は残す。表示は一覧に戻り、戻ってきたときは同じペインを開ける」。TUI 側の close や `pane.exited` でも同じ経路を通る。ADR 0017 はアクティブの行について「行のメニューを出さない。操作は詳細に寄せる」と決め、`select` は詳細のタブバーとも共有している。

## Decision

- `POST /api/panes/:id/close` を足す。`application/json` 以外は 415、スナップショットが無ければ 502、BFF の状態にペインが無ければ 404、Herdr の失敗は focus と同じ規則（404 / 400 / 502）。成功は `{ ok: true }`
- 応答でスナップショットを取り直さない。状態は Herdr のイベント（`pane.closed`）に任せる。focus と同じ理由で、成功した close が再取得の失敗で 502 にならないようにする
- 入口は詳細のペイン見出しの「…」だけに置く。タブバーとツリーの行メニューには足さない
  - タブは表示と切り替えだけの面として維持する
  - ツリーの行は壊さない操作（コピー）だけを持つ。破壊的な操作は詳細に寄せる（ADR 0017 の適用範囲はアクティブの行だが、方向は同じ）
- メニューとダイアログは `.hwc-app` の直下に 1 つだけ置き、対象ペイン ID とトリガー矩形を持つ。セルの containment の外に出すため、セルごとに持たない
- メニューの外枠（背景・fixed 配置・`role="menu"`・Esc で閉じる）と位置計算の `menuPlacement(rect, viewport, height)` は一覧と共有する。スクロールで閉じるのは一覧の行のメニューだけにする。詳細の見出しは位置が動かず、出力は自動追従で勝手にスクロールするので、そこで閉じると項目を押せない
- 確認ダイアログを挟む。文言は開いた時点で固定せず、`pane.agentStatus` をそのまま読む。状態が変われば文言も変わる

| 状態      | 説明                                                                     | 確認ボタン       |
| --------- | ------------------------------------------------------------------------ | ---------------- |
| `working` | 実行中です。ペイン `<id>` を閉じると、開いていた作業は失われます。       | 実行中でも閉じる |
| `blocked` | 要対応の作業があります。ペイン `<id>` を閉じると、その作業は失われます。 | 要対応でも閉じる |
| それ以外  | ペイン `<id>` を閉じます。開いていた作業は失われます。                   | 閉じる           |

- 項目は常に活性にする。実行中でも閉じられる。暴走した・止まったエージェントを hwc から畳めることを残す
- 404（BFF の状態に無い / Herdr が `pane_not_found`）は成功として扱う。ペインが無いという目的の状態には達している。閉じなければ一覧に残るので、取り違えても再試行できる
- それ以外の失敗はダイアログ内に「閉じられませんでした。もう一度お試しください。」を出し、ボタンを戻す
- 送信中は確認・キャンセルと Esc・背景タップを受け付けない。結果の反映を 1 回に保つ。二度押しは in-flight の ref でも弾く
- クライアントは閉じたペインをローカルで消さない。表示は SSE のスナップショットで置き換える（ADR 0005）
- 選択の後継は確認を開いた時点のスナップショットから決め、`closing` に保持する。SSE が閉じたペインを落とした後では、次のペインを引けない
  - 後継は `nextPaneInTab`（同じタブの、隠していないペイン）。閉じたペインの次を探し、無ければ手前へ戻る
  - 選んでいないペインを閉じても選択は動かさない
  - スナップショットから消えただけのペイン（TUI の close、`pane.exited`、ワークスペース削除）では選択を動かさない。既存の規則を維持する
- 送信中は閉じる手段が無いので、`closePane` にクライアント側の期限（8 秒）を置く。BFF に届かない（通信断）場合に fetch が返らず、モーダルが残るため。abort は失敗として扱う

## Consequences

- 閉じたペインの作業は失われ、取り消せない。確認で伝えるが、元に戻す手段は持たない
- 最後のペインを閉じたときのタブ・ワークスペースの後始末は Herdr の挙動に従う。hwc 側で追加の削除はしない
- メニューは項目 1 つでも画面全体を覆う背景を出す。分割セルの外に置く以上、押した場所の近くだけで閉じる範囲は作れない
- `role="menu"` / `role="menuitem"` の矢印キー操作は持たない（既存の一覧メニューと同じ）
- 送信中はダイアログから出られない。キャンセルを活性に戻すなら、結果の反映をどう保つかを先に決める
- 閉じたペインの localStorage（`hwc-draft:<id>`、`hwc-hidden-panes`）は残る。表示には影響しないので後始末しない

## Alternatives

- **タブバーに ×**: タブは表示と切り替えの面として維持する。× はタブ自体を閉じる意味にも読める
- **ツリーの行メニューに足す**: 一覧の行は壊さない操作だけにし、破壊的な操作は詳細へ寄せる（ADR 0017 と同じ向き）
- **セルごとにメニューとダイアログを持つ**: `container-type` の内側では fixed がセル基準になり、画面全体を覆えない。共有する 1 つにトリガー矩形を渡す
- **確認を挟まず、直後に「元に戻す」を出す**: 閉じたペインの作業は戻せないので、確認の代わりにならない
- **`working` のときは閉じさせない**: 暴走・停止したエージェントを畳む手段を残す。止める手段が無いほうが困る
- **404 を失敗として扱う**: ペインが既に無いのに失敗を出すと、利用者は同じ操作を繰り返すことになる
