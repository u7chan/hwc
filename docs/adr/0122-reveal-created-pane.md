# ADR 0122: 作ったばかりのペインは、一覧の見える位置へ一度だけ送る

- Status: Accepted
- Date: 2026-11-21
- Amends: [ADR 0017](0017-active-agents-view.md) の「一覧のスクロール位置はスコープごとに控える」

## Context

hwc からワークツリー・スペース・ペインを作ると、ダイアログが閉じてそのペインが開き、エージェントの起動は応答を待たずに続く（[ADR 0038](0038-create-worktree.md)、[ADR 0084](0084-launch-after-create.md)）。作成したものが動き出すのを見る場所は一覧で、狭い画面では詳細から戻ったときに見る。

一覧の並びは Herdr のワークスペース順で、新しいワークスペースは末尾に付く（[ADR 0050](0050-active-lists-every-agent.md)、[ADR 0052](0052-workspace-order-drag.md)）。`すべて` と `アクティブ` は同じ順で並ぶ。一覧のスクロール位置はスコープごとに控え、戻ったときはその位置から始める（[ADR 0017](0017-active-agents-view.md)）。作成の入口は元のスペースの見出しメニューにあるため、作成後に一覧へ戻ると元のスペースの位置のまま、新しいワークツリーは画面の外にある。

実行中かどうかは、どちらのスコープでも行から読める。`すべて` の行にも状態記号と経過時間があり、アクティブの帯には状態の件数がある。足りないのは情報ではなく位置である。

スコープは端末ごとに保存する表示設定で、切り替えは利用者の操作（セグメントと帯の矢印）に限っている。作成をきっかけに自動で切り替えると、保存した既定も書き換わる。

## Decision

- hwc がペインを作ったとき（ワークツリー・スペース・分割・シェルからの起動）、ペイン id を 1 つだけ預かる。スナップショットにそのペインが現れ、一覧が見えているとき、一覧をそのペインの行へ一度だけ送る
- 送り先はペインの行。スペースの見出しではない。分割では新しい行が既にある場所の途中に増えるので、見出しへ送ると作った行から離れる
- 送る量は最小限にする。行がすでに見えていれば動かさない。上にはみ出していれば行の上端を一覧の上端へ、下にはみ出していれば行の下端を一覧の下端へ合わせる
- `アクティブ` の帯は上端に貼り付いて行を覆う。上へ送るときの上端は、帯の下端にする（帯の高さを空ける）
- 狭い画面では、詳細を開いている間は送らない。一覧は `display: none` でスクロールできず、送っても位置が残らないため。一覧が見える状態（詳細から戻る、設定を閉じる）になってから 1 回だけ送る
- 目印とフォーカスは足さない。作ったペインは選択中の行なので、行そのものが現在地を示す。フォーカスは入力欄や戻る操作の側に残す
- スコープは変えない。`すべて` にいても `アクティブ` にいても、その一覧の中で行まで送る
- 要求はクライアントの state に置き、当てたら捨てる。スクロール位置の記憶（[ADR 0017](0017-active-agents-view.md)）の仕組みは変えず、作成直後の 1 回だけ上書きする
- 要求は作ったときのスコープに結び付ける。別のスコープへ移ったら捨て、移った先の保存位置を動かさない。`アクティブ` でシェルを作った場合のように、行が最後まで現れない要求が、後のスコープ切り替えで効くのを防ぐ
- 行がまだ描かれていない場合（`アクティブ` で起動中のエージェントを待つ間）は、要求を捨てずに同じスコープで次のスナップショットから探し直す
- 設定は持たない

## Consequences

- 広い画面では、作成の直後に一覧が新しい行まで動く。詳細も同時に開くので、両方で作成したものが見える
- 狭い画面では、詳細から戻ったときに一覧が新しい行の位置から始まる。それまで見ていた位置は 1 回だけ置き換わる
- 一覧を読んでいる最中に作成すると、その行が見えていなければ一覧が動く。動く量は行が端に接する分だけ
- 作成したペインが一覧に出ないまま（`アクティブ` でシェルを作った場合など）は、スコープを切り替えるまで要求が残る。切り替えると捨てるので、`すべて` の位置は動かない。次の作成で置き換わる
- 一覧の行を手で畳んだ束の中に作った場合は、行が切り取られて見えないので何もしない（作成時は開くので通常は起きない）
- スコープの自動切り替えは無いので、`すべて` にいる人は `すべて` のまま新しい行を見る

## Alternatives

- **送信をきっかけに `アクティブ` へ切り替える**: 送った直後に実行中を見られるが、`アクティブ` も同じ並びなので新しい行が画面に入る保証がなく、切り替えても位置は解決しない。スコープは端末ごとの保存値なので既定も書き換わる。どの送信で切り替えるか（作成したペインの初回だけか、分割も含めるか）を判定する状態も要る
- **スペースの見出しへ送る**: ワークツリーやスペースの作成では見出しから行までが近いが、分割では見出しが上の方にある遠い行へ飛ぶ。既存の帯から `すべて` へ移る動き（見出しへ送って accent で示す）を流用すると、作った行ではなく見出しが目印になる
- **設定でオン／オフにする**: 作ったものが見つからない状態を選べる設定になる。オフにしたいという具体的な要求が出たときに、テーマや分割設定と同じ端末ごとの好みとして足せばよい
- **作成ではなく送信の時点で送る**: 送信の時点では一覧を読んでいる位置が変わっていることがあり、作成した行へ戻すと読んでいる場所を奪う。どのペインが作ったばかりかをクライアントで覚え続ける必要もある
