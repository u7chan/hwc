# ADR 0079: 再起動コマンドを設定に持たせ、シェルの無い端末からも反映・復旧できるようにする

- Status: Accepted
- Date: 2026-11-13

## Context

PR をマージしたあと、常駐している BFF は `main` を取り込むまで古いコードを配り続ける。開発機の前にいるときはシェルで `systemctl --user restart hwc` を叩けるが、出先ではスマホしか無い。

さらに、Bun の開発サーバーはクライアントのバンドルをプロセス内にキャッシュする。pull のように多数のファイルが一括で置き換わると、1 モジュールだけ古い本文のまま残ることがあり、追加した export を呼ぶ行が実行時にだけ失敗する（`... is not a function`）。これはブラウザのキャッシュではないので、サーバーを再起動するまで直らない。

git の `post-merge` フックでも再起動はできるが、スペースメニューのプルは BFF が `git pull` を待つので、フックが自分を止めるとその応答が落ちる。応答を返してから再起動するには、BFF 側に起点が要る。

## Decision

### 設定

- 設定画面に「再起動」セクションを置き、実行ファイルの**絶対パス**を保存する（`$HWC_STATE_DIR/restart.json`、[ADR 0018](0018-pasted-image-attachments.md)）
- シェル文字列は受けない。相対パス・制御文字・512 文字超は弾く。BFF はシェルを介さず、その実行ファイルを直接起動する
- 「プル成功後に実行」トグルを持つ

### 実行

- `POST /api/restart` は、設定済みで実行可能（通常ファイルかつ `X_OK`）なら 202 を返し、**応答を書き終えてから**起動する（`RESTART_DELAY_MS` = 100ms）。起動の可否は応答前の判定までで、終了は待たない
- 未設定は 409 `command_not_configured`、実行できないパスは 409 `command_not_executable`
- pull が成功したとき、トグルがオンなら同じ経路で起動する。fetch と pull の失敗では起動しない
- 終了コードが 0 以外のときだけログに残す

### 対象のリポジトリ

- コマンドは pull したチェックアウトを cwd として起動する（設定画面の「今すぐ再起動」では BFF の cwd）
- どのリポジトリを再起動してよいかはコマンドが cwd で判定する（例: `git rev-parse --show-toplevel` が HWC のチェックアウトか）。BFF はワークスペースの id やパスをコマンドに渡さず、HWC 自身を特別扱いしない

## Consequences

- サーバーを再起動すると、開いているページは HMR の再接続で読み直される
- 設定はマシン固有で、リポジトリには載らない。作り直したら入れ直す
- 任意の実行ファイルを設定画面から起動できる。認証は無いが、ペインから任意のコマンドを打てる既存の権限を超えない
- プル成功後の実行は全スペースで走る。ガードの無いコマンドを設定すると、ほかのスペースの pull でも HWC が落ちる
- コマンドが HWC を止めない場合（ログ出力など）は、応答後に非同期で走るだけで終わる

## Alternatives

- **git の `post-merge` フック**: リポジトリに同梱でき、ペインのシェルからの pull にも効く。ただし HWC のプルボタンでは応答を返す前に走るため、自己再起動するとその応答が落ちて失敗に見える
- **BFF が自分で `systemctl --user restart <unit>` を叩く**: unit 名と systemd 前提が BFF に入る。コマンドを設定に置けば、再起動以外の用途（依存を入れてから再起動など）にも使える
- **`process.exit` して supervisor の再起動に任せる**: `Restart=always` の無い起動方法（`bun run dev`）では落ちるだけで戻らない
- **再起動専用のボタンだけにしてプルと切り離す**: マージの反映を 1 操作で終えられない。同じコマンドを 2 つの起点から使う形にした
