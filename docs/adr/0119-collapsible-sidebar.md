# ADR 0119: 広い画面でペイン一覧を畳めるようにする

- Status: Accepted
- Date: 2026-11-21

## Context

幅 900px 以上では、ペイン一覧（サイドバー）と詳細を並べる PC レイアウトになる。iPad は横向きでこの幅に入る。一覧の幅は 340〜560px で、既定は 352px。iPad の 1024px 横向きでは詳細に 670px ほどしか残らず、分割表示では 1 セルが読み幅に届かない。

一覧の幅は境目のドラッグで変えられる（下限 340px）が、下限より狭くはできない。詳細だけを読みたいとき、一覧を退けて画面を使い切る手段が無かった。

## Decision

- 広い画面で、一覧を畳む／開くトグルを置く。畳んだ一覧は幅 0 まで隠し、詳細が全幅を使う。狭い画面は一覧と詳細を画面遷移で分けるので、対象外
- トグルは一覧と詳細の境目に張り付く取っ手とする。一覧を開いている間は境目に、畳んでいる間は画面の左端に出る
- 畳む・開くは 220ms で滑らせる（`prefers-reduced-motion` では即時）。畳んだ一覧はフォーカスも受けない
- 畳んだかどうかは端末ごとの見え方として localStorage に保存し、再読み込みでも保つ。BFF・Herdr には送らない。保存値が壊れていたら開いた状態に戻す
- iPad 専用の判定は持たない。幅 900px 以上のレイアウト全般に同じトグルを出す

## Consequences

- 畳んだ間は詳細が画面幅いっぱいになるので、設定のカテゴリ常設（[ADR 0085](0085-settings-index.md)）やファイルツリーの並べ方（[ADR 0090](0090-pane-file-tree.md)）は、既存どおり詳細の実幅で決まる
- 畳んでいる間は一覧のペイン状態（完了・待機）が見えない。必要なら開き直す
- 接続状態と設定は一覧の足元にあるので、畳んでいる間は見えず、設定へも入れない。開き直せば戻る
- 開閉のたびに詳細の幅が動くので、出力欄は幅の変化に追従して再配置される

## Alternatives

- **細いレールに畳み、状態マークだけ残す**: 畳んだままでも完了・待機に気付ける。ただし一覧とは別の縮小表示を設計・実装する必要があり、まず幅を取り戻す目的には過剰。必要になったら見直す
- **タブバーの左端にトグルを置く**: 広い画面では戻るボタンが空いている。ただし設定・空状態・読み込み中の詳細にはタブバーが無く、畳んだまま開けなくなる。詳細の状態に関わらず存在する境目に置く
- **一覧の幅の下限を下げる**: 3 段の字下げを引くとペイン名が数文字しか残らなくなる（`SIDEBAR_MIN_WIDTH`）。一覧が読める幅のまま、隠す選択肢を足す方がよい
- **一覧を詳細の上に重ねる（ドロワー）**: 開くたびに詳細が隠れ、ペインを選ぶ間は本文を見られない。畳んだ間は詳細を広げる、が目的
