# ADR 0078: 起動待ちの間は端末の途中画面と会話の空状態を出さない

- Status: Accepted
- Date: 2026-11-12
- Amends: [ADR 0074](0074-created-pane-starting.md)

## Context

[ADR 0074](0074-created-pane-starting.md) は、hwc が作ったペインでエージェントが端末を引き継ぐまで入力欄を閉じる。しかし本文は端末出力のままだった。起動直後は、シェルが受け取った起動コマンド（`pi`）、TUI の描画途中、会話が読めた直後の空状態が順に見える。入力欄も、スピナーが消えたあとシェル形式（`$`、起動の入口）を経てエージェント形式に変わる。どれも作業に必要な情報ではなく、起動が段階的に進んでいるように見えるだけ。

会話を読むエージェント（Pi / Codex / OpenCode）は、Herdr がエージェントを検出しても、セッションができるまで `pane.chat` が false のまま。この区間は端末出力が TUI の画面になり、入力もシェルの形に戻る。ADR 0074 の「3 秒後にエージェントが検出されていれば開く」では、この区間を覆えない。

## Decision

- 起動待ちの記録が効いている間、本文はスケルトンだけにする。端末出力も、会話のスナップショットも、空状態も出さない。確認ビュー（フォルダ信頼）と、閲覧のみの端末表示はこれまでどおり優先する
- 起動待ちの終わりを、入力の形が決まるまで延ばす。エージェントが検出されても、会話を読むエージェントは `pane.chat` が true になるまで待つ。会話を持たないエージェント（Claude）と、チャット非対応の未知のエージェントは、3 秒の settle が過ぎたら開く
- 上限は変えない。応答から 10 秒（`STARTING_LIMIT_MS`）を過ぎたら、会話が読めなくても開く。起動しなかったペインを hwc から操作できないままにしない
- 入力欄の代わりに置く起動待ちの行は、入力欄と同じ高さを取る。compact（分割セル）では 1 行分の高さに合わせる
- シェルのペインで外部からエージェントが起動した場合（Herdr TUI、手動の `pi`）は、hwc が起動を頼んでいないので待ちを入れられない。入力の `$` と左の余白は、切り替わりで幅が飛ばないよう短く畳む。`prefers-reduced-motion` では動かさない

## Why not

- **起動待ちの間も端末出力を出す**: 起動の途中経過そのもので、読む必要がない。今回の不満の直接の原因
- **3 秒だけで開く（ADR 0074 のまま）**: 会話が読めるまでの TUI と、シェル形式の入力が残る
- **会話が空の間もスケルトンを出し続ける**: 会話は読めており、入力もできる。読み込み中と区別がつかず、いつ送れるのか分からない
- **BFF に起動待ちを持たせる**: どのペインを hwc が起動したかは要求したクライアントしか知らない（ADR 0074）。本文のマスクもクライアントの導出に置く
- **すべてのエージェントで `pane.chat` を待つ**: Claude は会話を持たないため、いつまでも待つことになる。上限で開くとしても、起動待ちの表示を不必要に長くしない
- **外部起動も推測してマスクする**: 再読み込みやペインを開いた時点で既にエージェントがいるペインと区別できず、動いている TUI を隠してしまう

## Consequences

- 起動待ちの間は、入力欄がスピナーのまま最大 10 秒残る。エージェントが検出されても、会話が読めるまでは入力できない
- 会話を読むエージェントがセッションを作らない場合（フックの失敗、OpenCode のサービス停止など）は、10 秒後に端末出力へフォールバックする。それまではスケルトンになる
- 起動待ちの行が入力欄と同じ高さになるので、起動が終わったときに入力欄が下から伸びない
- スケルトンから会話への切り替わりは、会話が読めた時点で一度だけ起きる。空の会話なら、そのまま空状態になる
- 外部から起動したペインでは、シェル形式からエージェント形式への切り替わり自体は残る。`$` と入力欄の左余白だけが短く動く

## Verification

- unit で、会話を読むエージェントは `pane.chat` が true になるまで起動待ちが続くこと、Claude は 3 秒で開くこと、10 秒で必ず開くことを確認する
- 架空 Herdr の E2E で、新しいワークツリーを作った直後に本文がスケルトンで、`pi` のコマンドや TUI の途中、空状態が出ないこと、起動後に入力欄と会話（または空状態）へ一度で切り替わることを確認する
