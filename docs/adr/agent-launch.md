# エージェントは Herdr の agent.start で、モデルを明示して起動する

- Status: Accepted

## Context

hwc は新しいペインやワークツリーで、Pi / Claude / Codex / OpenCode を起動する。CLI の既定モデルに任せると、どのモデルで動くかを hwc から知る方法が CLI ごとに違い、Claude には手段が無い。最初の応答まで入力欄にモデルが出ない。

`agent.start` の待ちは長い（最大 30 秒にシェルの準備が加わる）。プロンプトは起動前に決まっていることが多く、起動を待ってから打たせる理由が無い。

## Decision

- ペインの作成とエージェントの起動を分ける。作成は分割（またはワークツリーの作成）と rename まで、起動は新しいペインが状態に現れてから `POST /api/panes/:id/agent` で Herdr の `agent.start` を呼ぶ。起動を待つ間も入力欄は打てるが、送信は準備ができるまで閉じる
- エージェント名は Herdr の制約に合わせて `hwc-<paneId>` を付ける。利用者のペイン名は label にだけ使う。cwd は指定せず Herdr の `terminal.new_cwd` に任せる
- 分割直後の `agent_pane_busy` は、シェルが受け付けるまで短い間隔でリトライする。`agent_not_ready` はエージェントが起動して最初の画面で止まっている状態（信頼確認・初回画面）とみなし、成功として扱う。hwc からその画面は操作しない
- hwc の画面からは、必ずモデルを明示して起動する。モデルが effort に対応するなら effort も選ぶ。既定はエージェントごとに 1 組を BFF が状態ディレクトリの `launch-defaults.json` に持ち、設定画面だけで変える。API はモデル未指定の起動も受け付ける
- 候補の取り方と起動引数はエージェントごとの ADR（[pi](pi-integration.md)、[Claude](claude-integration.md)、[Codex](codex-integration.md)、[OpenCode](opencode-integration.md)）が定める。候補は各 CLI が返す値と順序を保ち、共通の段階へ変換しない。選んだ値が起動する cwd で使えないときは、別の値へ黙って置き換えず起動失敗にする
- 候補を読むために起動する CLI のプロセスから `HERDR_*` を外す。呼び出し元のペインの状態を Herdr へ報告させない
- 起動に失敗したペインはシェルとして残す。利用者が「シェルとして使う」を選ぶまで、入力をシェルへ送らない。打った自然文をシェルコマンドとして実行しない
- BFF は起動時のモデルと effort をペイン id ごとにプロセス内で預かり、会話のスナップショットにモデルが無い間だけ補う。補ったスナップショットは etag に印を付け、補完前の etag に 304 を返さない。モデルが載ればセッションの値を正にする。預かりはエージェントが終わるまで残す。`/new` で会話が空に戻っても、起動時の指定を引き継いで表示するため。Claude のモデルと effort を切り替えたときは、切り替えた値に更新する（[Claude](claude-integration.md)）

## Consequences

- 候補を取得できないエージェントは hwc から起動できない。理由と再取得を出す
- 預かりは永続化しないので、BFF を再起動すると最初の応答までモデル名が出ない
- 起動時に選んだモデルは、最初の応答の前に TUI で切り替えられても変わらない。応答が記録されれば実際のモデルの表示に変わる

## Alternatives

- **CLI の既定で起動する**: 選ぶ手間は無いが、モデル表示の経路が CLI ごとに分かれ、Claude は最初の応答まで何も出ない
- **前回の起動値を初期値にする**: 設定画面が要らないが、一度試した高価なモデルが初期値に居座り、既定へ戻す手段も無い
- **起動まで 1 リクエストで待つ**: 失敗の扱いは単純になるが、その間ダイアログを閉じられず何も打てない
- **BFF に起動ジョブと状態を持たせる**: 待ちの終わりはスナップショットで判定できる。ジョブの寿命・再取得・失敗の配信が増える
