# ADR 0057: 会話コマンドは入力欄の + メニューに置き、メニューからの /new だけ確認する

- Status: Accepted
- Date: 2026-11-10

## Context

ペインの「…」メニューは「新しい会話」「会話を圧縮」「新しいペイン」を縦に並べていた。スマホでは行が 44px で、「新しい◯◯」が隣り合う。ペインを足そうとして上を押すと、会話のコマンドが実行される。`/new` は今の会話を hwc から見られなくするが、取り消す手段は無い。

入力欄の + メニューは、画像とプロジェクトを追加する置き場として始めた（[ADR 0055](0055-composer-add-menu.md)、[ADR 0056](0056-project-picker.md)）。入力欄の近くに常設され、項目ごとに補助文を出せる。会話コマンドもチャットの操作なので、同じ入口にまとめる方が「ペインを足す」操作から離れる。

入力欄を 1 行に畳む分割セルでは + を出さない（ADR 0055）。そのセルでも `/` と打てば候補は出る。

`/new` の入口は 3 つある。チップと直接入力は選んでから送信する 2 段階で、+ メニューは 1 タップで実行する。ペイン詳細は `.hwc-split-cell` の中にあり、ダイアログはセルの外（`.hwc-app` 直下）に出す必要がある（[ADR 0021](0021-pane-close.md)）。

## Decision

- ペインの共通メニューから「新しい会話」「会話を圧縮」を外す。メニューはペイン ID・スペースのパスのコピー、出力をクリア（シェル）、新しいペイン、ペインを閉じるだけにする
- 入力欄の + メニューの先頭に「新しい会話」「会話を圧縮」を置き、区切りの下に「画像を追加」「プロジェクトを選ぶ」を置く。+ の読み上げ名は「入力欄の操作」にする
- コマンドを持たない agent のペインでは、+ メニューに画像とプロジェクトだけを出す。区切りも出さない
- 実行可否は今までと同じ `commandAvailable` で決める。送信中、圧縮中、`working`、空の会話では無効。`compact` は履歴が閾値未満、圧縮済みでも無効。押せない理由は `COMMAND_BLOCK_NOTES` を項目の補助文に出す。押せる間は「このペインで会話を始め直す」「履歴を要約して縮める」を出す
- 実行は bare の `/new` / `/compact` を送る。`/new` は次の確認を挟む。`draft`・添付・引用は次のメッセージのために残す。`compact` の指示には使わない（指示付きはチップか直接入力）
- 入力欄の + メニューからの `/new` だけ、送信前に確認ダイアログを挟む。チップと直接入力の `/new` は確認しない。確認は「新しい会話を始めますか？」「ペイン `<id>` で新しい会話を始めます。今の会話には hwc から戻れません。下書きと添付は残ります。」とし、開いた後に `working`・送信中・圧縮中へ変わったら「始める」を無効にして理由を出す
- 確認ダイアログは `createPortal` で `.hwc-app` の直下に出す。セルの containment の内側に置かない
- 未完了の入力送信は App がペイン単位で保持し、+ メニューのコマンドも送信中は無効にする。成功・失敗のどちらでも応答後に解除する
- 表示中の詳細は自分の送信状態と会話のスナップショットで判定する。ペインのメニューは会話を読まない。クリア後の読み直しだけ、詳細の実行口（`PaneOutputHandle`）を使う
- 一覧の行メニューからは 2 コマンドを実行できない。実行するにはペインを開いて + を押す
- 入力欄を 1 行に畳む分割セルでは + を出さない。`/` と打ったときの候補だけが残る

## Consequences

- 入力欄の + メニューからの `/new` は 1 タップ増える。取り返しがつかない操作を、ペインを足す操作の隣から離すための代償
- 一覧から会話を始め直す・圧縮するには、ペインを開く。一覧の行メニューはペインとタブの片付けに専念する
- 入力欄の + メニューは 4 項目になり、会話の末尾を隠す面積が増える。画面より高くなれば内部をスクロールする
- 確認ダイアログは画面全体を覆う。開いた後に状態が変わった場合は、閉じてもう一度 + からやり直す
- 今のセッションは CLI のディスクに残るが、hwc から開き直す手段は無い。確認の文言はその前提で書く
- 入力欄の + メニューからの `compact` は指示を取らない。指示付きはチップか直接入力を使う
- 1 行に畳んだ分割セルでは、+ が無いので 2 コマンドは `/` の候補から選ぶ。項目の説明は出ない
- ペインのメニューは会話を読まなくなり、非表示ペインのチャット取得・送信中表示・コマンド実行の配線が消える
- コマンドの実行結果は今までどおり hwc に伝わらない。送信失敗だけ入力欄の notice に出す

## Alternatives

- **ペインのメニューに区切りだけ足す**: 隣接は弱まるが、「新しい◯◯」が同じメニューに残る。押し間違いの原因を消さない
- **+ の隣に `/` ボタンを置く**: コマンド専用の入口になるが、44px をもう 1 つ消費し、+ メニューと項目が重複する
- **コマンドをチップとして置くだけにする**: 送信前にもう 1 タップ必要になり、添付がある間のチップの規則とも絡む。`compact` の指示入力が `draft` を奪う
- **すべての `/new` に確認を出す**: チップと直接入力は選んでから送るので、毎回モーダルが挟まる。ADR 0016 の代替案で一度落としている
- **+ メニューの中で確認する**: ダイアログを出さずに済むが、ペインを閉じる確認と見た目が揃わず、失われるものの説明を置く幅も足りない

## Verification

- unit: `commandBlockReasonFor` が `new` と `compact` で別の理由を返すこと
- 架空 Herdr の E2E: + メニューの並びと補助文、実行中・空の会話・圧縮済みの無効状態、`/new` の確認とキャンセル、`/compact` の送信、ペインのメニューに 2 コマンドが無いこと、分割セルで + が出ないことを確かめる
