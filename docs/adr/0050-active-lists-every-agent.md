# ADR 0050: アクティブはエージェントのいるペインを状態に関わらず並べる

- Status: Accepted
- Date: 2026-11-09（2026-11-10 改訂）
- Supersedes: [ADR 0017](0017-active-agents-view.md) の対象・並び・帯の件数・窓口

## Context

ADR 0017 は `アクティブ` の行を `working` / `blocked` / `done` に限り、`idle` と `unknown` を出さなかった。待機中のペインを探すには `すべて` のツリーをたどるしかなく、エージェントを並行で動かすと待機中のものがツリーに埋もれる。Herdr 本家の agents パネルは、起動しているエージェントを状態に関わらず並べる。状態は色と記号で示すもので、一覧から外す条件ではない。

`idle` を出さない前提で作られていたのが「窓口」で、最後にメッセージを送ったペインを 1 行だけ例外として `idle` でも残していた。`idle` の行が常に出るなら、窓口は同じペインを二重に持つだけになる。窓口は localStorage の記憶（`hwc-sent-pane`）と、`blocked` を要対応の側へ回す例外も抱えており、`idle` を出さない前提が外れると説明できなくなる。

## Decision

### 対象

- `active` の行は `pane.agent !== null` のペインすべて。`idle` と `unknown` も出す。シェル（`agent` が `null`）だけを外す
- 窓口（`src/client/sent.ts`、`hwc-sent-pane`、`sentPanes` / `recordSent` / `sentForSave`）を廃止する。送信は一覧と並びを変えない

### 並び

- 束の中は親ペイン（[ADR 0054](0054-favicon-parent-status.md)）を先頭に固定し、残りを `要対応 → 完了 → 実行中 → 待機 → 不明`（`blocked` → `done` → `working` → `idle` → `unknown`）に並べる。上から「自分が動く番 → 読む番 → 待つ番」に揃える。待機と不明を最後に置き、動いている行や未読の完了を押し下げない。同順位は state の並び（ワークスペース → タブ → ペイン）
  - 親は状態ではなく役割の印で、位置が状態で変わると戻り先を探すコストと押し間違いにつながる。親以外の並びは変えない
- 束の順は、親を含めた束の中で最も緊急な行の順位。同順位は state の並び（ワークスペースの順）。ADR 0017 の「窓口の `at` の降順」は持たない
- `activePanes(state)` は絞り込みだけを行い、並びは state のまま返す。表示順は `activeGroups(state)` が持つ
- 帯の件数は `blocked` / `done` / `working` の 3 つだけ。待機と不明は数えない。待機はどの帯にも並ぶ既定の状態なので、数字にしても「自分が動く番」を見つける助けにならない
- 右端の時刻は変えない。待機の行は `done` と同じく、分かっていれば終わった時刻を淡く出す

### 既読

- `agent.focus` を離れたときに送る仕組みは ADR 0017 のまま残す。ただし目的は「行を消す」から「完了の印を Herdr の seen に合わせて消す」に変わる。行は消えず、完了から待機へ移って束の最後に下がる
- 送る条件（離れる時点で `done`）、保留を持つ場所、失敗を通知しない扱いは変えない

### 空状態

- 帯が 1 つも無いときだけ出す。文言は「エージェントがいません」とし、待機中も並ぶこと、シェルだけのスペースは `すべて` に出ることを添える

## Consequences

- 待機中のエージェントを `アクティブ` から直接開ける。`すべて` のツリーをたどる必要が無くなる
- 行はエージェントが終了する（`pane.agent` が `null` になる）まで残る。`done` を読んでも行は消えないので、エージェントを終了しない限り一覧は短くならない。以前より行数が増える
- 完了を読むと行は待機の位置へ下がる。ただし親ペインは先頭に固定されたままなので動かない。順位が変わるのは既読のときだけで、待機の行同士は state の並びのまま
- 束の先頭行は「自分が動く番」ではなく親になる。要対応や未読の完了は親の次に並ぶが、状態は行の記号と時刻、帯の件数で読める
- 親のエージェントが終了すると、[ADR 0054](0054-favicon-parent-status.md) の定義に従って次のエージェントへ王冠が移り、先頭の行も入れ替わる
- 最後に話した相手を上位に出す仕組みは無くなる。名前と帯で探す。`すべて` のツリーと、詳細の選択の復元（[ADR 0029](0029-preserve-last-pane.md)）は残る
- スコープの件数（`アクティブ` のラベル）は、エージェントのいるスペースの数になる。待機だけのスペースも 1 と数える
- `hwc-sent-pane` は読まない。保存済みの値が残っていても使わない（移行処理は持たない）
- 待機の行が常に並ぶので、エージェントを多数起動したスペースの帯は長くなる。折りたたみや絞り込みは持たない

## Alternatives

- **親も状態順に並べる**: 親の位置が状態ごとに変わり、戻り先を探すコストと押し間違いが残る。`すべて` のツリーでは親の位置が状態で動かないため、2 つのスコープでも振る舞いが揃わない
- **親を帯に統合する**: 帯は `すべて` へ移る入口なので、押す意味が二重になる。会話の入口として 1 行残す
- **窓口を「最近話した相手」の並びとして残す**: `idle` の行が常に出る以上、窓口は同じペインをもう一度上に出すだけになる。localStorage のキーと `blocked` の例外を抱えたまま、得られるのは並びの優先度だけ
- **`done` / `working` / `blocked` を先に、`idle` は折りたたむ**: 待機中のペインを開くのに 1 手増え、Herdr 本家の agents パネルとも形が変わる
- **待機も帯の件数に含める**: どの帯にも待機の数が並び、要対応と完了の数字が埋もれる。件数は「自分が動く番」の目印に限る
