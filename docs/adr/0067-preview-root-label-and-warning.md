# ADR 0067: プレビューの根のラベルと、配信できないスクリプトの案内

- Status: Accepted
- Date: 2026-11-11
- Revises: [ADR 0051](0051-agent-html-preview.md) の「見つけ方」の `ChatFile`、「配信」の応答ヘッダー、「画面」のチップとヘッダー

## Context

[ADR 0051](0051-agent-html-preview.md) は本文のパスから HTML を見つけ、プレビューで配信すると決めた。[ADR 0066](0066-tmp-preview-root.md) は追加根の既定を `/tmp` にした。どちらも、チップはベース名と固定の種別（`mock.html HTML`）しか出さず、配信は「HTML を配信できる」ことだけを条件にしている。

そのため 2 つの失敗が起きる。

- 同じベース名がチェックアウトと `/tmp` にあると、チップを押すまでどれか分からない。`ChatFile.root`（0 = チェックアウト、1 = `/tmp`、2 以上 = 追加根）は配信の URL にしか使っていない
- HTML が読み込むスクリプトを配信できないと、iframe の中が無言で白くなる。ルート相対の参照（`/src/client/main.tsx`）はサイト直下に解決されて BFF のルートに一致せず 404、相対の参照（`./app.tsx`）は配信 allowlist に無いので JSON の 404 になる。`/tmp` を既定根にした後、本文中の `index.html` がチェックアウト直下のアプリシェルを拾い、チップは出るがプレビューは真っ白になった

2 つは独立している。ラベルは同名の取り違えを減らすが、チェックアウトのファイルには付かないので、この実機事象を救うのは案内の方になる。

## Decision

### 根のラベル

- チェックアウト以外の根にあるファイルに、根の短いラベルを付ける。BFF が `ChatFile.rootLabel?: string` としてファイルごとに載せ、チェックアウトの根では持たない
- ラベルは根の**設定値の文字列**から作る。`realpath` は使わない
  - `resolve(root) === "/tmp"` のときは `/tmp`
  - それ以外は設定値の basename。basename が空、または `/` のときは `追加根`
  - 0 番がチェックアウトのときだけラベルを持たない。チェックアウトを持たないペインでは `/tmp` が 0 番になり、そこにはラベルが付く
- 文字列から作るのは 2 つの理由から。番号で `/tmp` を決めると、テストが `previewRoots` に注入した一時ディレクトリにも `/tmp` が付く。`realpath` で決めると、`/tmp` が symlink の環境で別名になる
- 絶対パスをクライアントへ渡さない契約（[ADR 0041](0041-agent-message-images.md)）は維持する。出すのは固定表記の `/tmp` と、利用者が設定した追加根の basename だけ
- クライアントは `"/tmp"` を許可し、それ以外で `/` や `\` を含む値は捨てる。長さの上限は設けず、描画側の `max-width` と ellipsis で抑える
- ラベルは表示だけに使う。チップの `title` は今までどおり根からの相対パス。プレビューのヘッダーと iframe の `title` にも同じラベルを出し、読み上げで根が分かるようにする
- タブストリップの名前はベース名のままにする。プレビューは同時に 1 つしか開けず、幅を優先する
- `rootLabel` は `etag` に混ぜない。設定から導出で、根の設定が変われば番号か名前も変わるため

### 配信できないスクリプトの案内

- 配信時、HTML の中の `<script src>` を走査し、参照先の拡張子が allowlist（`previewContentType`）に無いものが 1 つ以上あれば `x-hwc-preview-warning: script` を付ける
- iframe の中身は書き換えない。CSS やモックの挙動を変えないため
- 走査対象は相対 URL とルート相対 URL だけ。スキーム付き・`//` 始まり・`data:` は対象外にする。外部のスクリプトは hwc が配信していないので判断しない
- クエリとハッシュは落として拡張子を見る。属性の順序と引用符（`'` / `"` / なし）に依存せず、大文字の拡張子も同じに扱う
- HTML コメントとインライン `<script>` の中身は走査しない。コメントアウトされたタグや、文字列から組み立てた `<script src>` で案内を出さない
- 走査は配信で読んだバイト列を使い、追加の `readFile` をしない
- クライアントはプレビューを開くときと再読み込み時に同じ URL へ HEAD を送り、ヘッダーがあれば iframe の上に 1 行の案内を出す。値が `script` のときだけ出し、未知の値は無視する。HEAD が失敗した・遅いときは案内を出さず、プレビューは今までどおり動かす
- HEAD は親ページと同じオリジンから送る。sandbox の iframe とは別経路なので、`Access-Control-Expose-Headers` は付けない。ヘッダーを読むのはクライアントだけで、iframe の中のモックには渡さない

## Consequences

- 同じベース名がチェックアウトと `/tmp` にあると、チップの種別欄で押す前に見分けられる。チェックアウトのファイルは今までどおり種別だけで、チップは混まない
- `HWC_PREVIEW_ROOTS` の basename が衝突すると（`/srv/a/mock` と `/srv/b/mock` はどちらも `mock`）、ラベルでは区別できない。番号と URL は別なので配信は壊れない
- 白紙の理由が 1 行で読める。ただしスクリプトが 1 つ欠けるだけで白紙とは限らないので、文面は「表示されないことがある」に留める
- 案内は HEAD の応答後に出すので、遅いときは iframe が 1 行ぶん下へ動く。頻度が低いので許容し、気になればプレビューのレイアウトで吸収する
- `index.html` のような一般名がチェックアウト直下の実在ファイルを拾う挙動は残る。ラベルと案内で「読める失敗」に変えるのがこの判断の範囲
- 検出（本文のパスからファイルを拾う規則）と配信の allowlist は変わらない。ラベルとヘッダーは既存の 1 か所の表を引くだけで、2 つ目の一覧を作らない

## Alternatives

- **根の番号で `/tmp` を決める**: チェックアウトを持たないペインでは `/tmp` が 0 番になり、テストが注入した一時ディレクトリにも `/tmp` が付く。番号は配信の URL と共有していて、表示の都合で意味を足せない
- **`realpath` したパスからラベルを作る**: `/tmp` が symlink の環境で別名になる。設定値は利用者が書いた文字列なので、表示もそれに合わせる
- **長い basename のラベルを捨てる**: 同名の取り違えを減らすための表示なので、黙って消すと元の欠陥に戻る。描画側で ellipsis に抑える
- **検出を絞って裸の `index.html` を拾わない**: 恣意的な規則になり、`mock.html` のような正当な裸名も落とす
- **iframe の中身に案内を差し込む**: モックの CSS と script の前提が変わる。応答ヘッダーなら中身に触れない
- **クライアントが HTML を取得して走査する**: HTML をもう一度取り、走査の規則をクライアントにも持つ。allowlist の 2 重管理になる
- **スクリプトを配信できるようにする（`.tsx` の配信・インライン module の import 解決）**: 変換を hwc に持ち込むことになり、モックの置き方の自由度が下がる。静的ファイルだけを配る前提を崩さない
