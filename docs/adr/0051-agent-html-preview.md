# ADR 0051: エージェントが書いた HTML をプレビューする

- Status: Accepted
- Date: 2026-11-09
- Extends: [ADR 0041](0041-agent-message-images.md) の対象を画像から HTML へ広げる

## Context

エージェントはデザインのモックやレポートを HTML で書き、本文にパスを残す。ADR 0041 は画像だけを配信し、HTML は文字列のままだった。スマホから中身を見る手段が無く、モックの確認は hwc の外に出る。画像で作った「本文のパス → メッセージの下のチップ → ダイアログ」の導線を HTML にも広げたい。

ただし画像と違い、HTML は同じオリジンで開くと script が BFF を叩ける。認証の無い LAN 公開（[ADR 0010](0010-lan-access.md)）なので、モックの script が `/api/state` を読み、`/api/panes/:id/input` を送れる状態は避けたい。ADR 0018 が SVG を配信しないのも同じ理由で、HTML は「配信しない」で済ませられない。

画面の置き場所も画像とは違う。画像は一瞬で見終わるのでダイアログ（ADR 0042）で足りるが、モックは操作しながら見る。PC では会話と同じタブの中で切り替え、スマホでは全画面で見たい。

追記: 当初は画像をチェックアウトだけから拾っていた。画像の配信も根の番号を受けるようにしたため、追加根の画像を同じチップ・ダイアログで出せるようになり、この制限を外した。

## Decision

### 見つけ方

- 対象は `role: "agent"` の本文が示す HTML（`html` / `htm`）。画像と同じ検出を通り、`ChatFile.kind` で `image` と `html` を分ける
- 根はワークスペースのチェックアウト。ADR 0041 の `realpath` と配下判定をそのまま使う
- `HWC_PREVIEW_ROOTS`（`:` 区切りの絶対パス）で追加の根を明示できる。チェックアウトの外へ書いたファイル（`/tmp` の画像やモックなど）を見るための唯一の口で、既定は空。相対パスは採らない
- 検出はチェックアウト → 追加根の順に試し、見つかった根の**番号**を `ChatFile.root`（0 = チェックアウト）に記録する。相対名だけを持つと、別の根に同名ファイルがあるときに配信が別の実体を引く
- 画像（`kind: "image"`）も HTML と同じ根から拾う。`GET /api/panes/:id/files` は `root` クエリで根の番号を受け、`/preview` と同じ順で解決する。チップの URL にも根の番号を入れる。チェックアウトを持たないペインでは、追加根が 0 番から並ぶ
- 「生成したファイルの台帳」は持たない。作成者の証明はできず、エージェントの協力が要る。境界は「本文にパスが書かれたもの」＋「根の配下」の 2 つにする

### 配信

- `GET /api/panes/:id/preview/<根の番号>/<根からの相対パス>`。パス形式にするのは、HTML の中の `./app.css` `./app.js` `./shot.png` をそのまま解決させるため。根の番号をパスの先頭に置くのは、相対参照でも根が変わらないようにするため（クエリに置くと、HTML からの相対参照が落とす）
- 画像は `GET /api/panes/:id/files?root=<根の番号>&path=<相対>&v=<版>`。根の番号の解決はプレビューと同じ。版を URL に含めるので `immutable` でキャッシュできる
- 根の番号が範囲外・非整数のときは 404。`HWC_PREVIEW_ROOTS` の順が変われば番号も変わるが、会話を取得し直せば新しい番号になる（保存しない）
- 配信する形式は 1 か所の allowlist だけ: `html` `htm` `css` `js` `mjs` `json` `svg` `gif` `woff` `woff2` と、添付と同じ画像 3 形式。`nosniff` を付ける
  - ADR 0018 が SVG を配信しないのは添付の経路。svg はモックの装飾（ロゴなど）で普通に参照され、単体で開いても下の CSP で不透明なオリジンになるため、参照アセットとしてだけ配信する
- `cache-control: no-store`。書き直した HTML を再読み込みでそのまま見たいので、版を URL に入れない（画像の `/files` は `immutable` + `v` で分ける）
- `access-control-allow-origin: *` をこのルートにだけ付ける。sandbox で文書のオリジンが不透明になるため、ES modules と `fetch` は CORS になる。ほかの API は今までどおり読めない
- ファイルが消えている場合、`html` の要求には最小の案内ページを返す。iframe に生の JSON を出さない

### 分離

- iframe は `sandbox="allow-scripts"` だけ。`allow-same-origin` を付けない。付けるとモックが `parent.document` から自分の sandbox を外せて、以降は同じオリジンの script になる
- 応答にも `content-security-policy: sandbox allow-scripts` を付ける。ダイアログの「新しいタブで開く」で iframe の属性が外れたときの保険
- `allow-top-navigation` / `allow-popups` / `allow-forms` は付けない。モック内のリンクは iframe の中で遷移する

### 画面

- プレビューはタブストリップの 1 項目。`PaneState` は偽装しない。ペイン id は Herdr の契約で、`localStorage`・メニュー・会話取得のすべてに効いており、架空の 1 件を混ぜると分割の枚数・一覧・既読が静かに壊れる
- 選ぶと detail 領域をプレビューが占有し、分割は一時停止する。分割トグルは無効にする
- ペインのタブを選ぶとプレビューは閉じずに隠れる。閉じるのはプレビュー自身のヘッダーの `閉じる` だけ
- 対象のペインが消えたらプレビューも捨てる。状態は App のローカルにだけ持ち、再読み込みでは復元しない
- ヘッダーは `ファイル名` `再読み込み` `新しいタブ` `閉じる`。モバイルでもダイアログは使わず、既存の一覧 ↔ 詳細の画面遷移に乗る。再読み込みは `no-store` の URL を作り直す

## Consequences

- エージェントは特別な記法を知らなくてよい。本文に HTML のパスを書けばチップが出る
- CSS / JS / 画像を分けたモックも、同じ根の中ならそのまま動く。`fetch` と ES modules も CORS の許可で動く
- 書き直しの反映はヘッダーの再読み込み。会話を取り直さないので、位置も下書きも動かない
- プレビューは iframe で不透明なオリジンになる。`localStorage` や Cookie に依存するモックは動かないが、デザインモックには要らない
- チェックアウトの外に書いた HTML は、`HWC_PREVIEW_ROOTS` に根を足すまで出ない
- 追加根にしかない画像も、HTML と同じチップ・ダイアログで出る。配信は同じ根の番号を使う
- 根の中の HTML と画像は LAN の誰でも読める。元から画像と端末出力が読めていたので、露出の種類は増えるが範囲は根の中に限られる
- プレビューの状態は保存しない。再読み込みすると閉じる

## Alternatives

- **偽のペインとして分割セルに出す**: 会話と並べて見られるが、`splitPanes`・`MAX_PANES_PER_TAB`・`hidden`・選択の全部に「ペインでないセル」が入り込む。まずタブの切り替えで足りる
- **ダイアログで出す**: 画像と同じ機構で済むが、モックを操作している間に入力欄と会話を覆い、PC の広い画面を活かせない
- **別ポート・別オリジンで配信する**: sandbox 無しで済むが、WSL2 のポート転送をもう 1 本増やす。ネイティブ Linux へ移す前提でも運用の前提が増える
- **クライアントが HTML を取得して blob URL で iframe に入れる**: 相対参照が解決できず、直接開いたときの隔離も効かない
- **本文をサニタイズして hwc の DOM に埋め込む**: script を落とすとタブ切替のようなモックが動かない
- **生成したファイルの台帳を持つ**: エージェントに登録させる必要があり、登録漏れで「出ない」理由が画面から分からなくなる
- **相対名だけでファイルを指す**: 同名ファイルが別の根にあると、チップと配信が別の実体を指す。根の番号を契約に足す方が小さい
