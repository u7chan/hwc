# ADR 0063: タブ順はセルの読み順に固定し、木の外は MRU で並べる

- Status: Accepted
- Date: 2026-11-11
- Revises: [ADR 0058](0058-split-view-tab-history.md) のタブ順、[ADR 0059](0059-tab-close-detaches.md) の後継、[ADR 0061](0061-split-view-directional-tree.md) の色の割り当て

## Context

[ADR 0061](0061-split-view-directional-tree.md) のタブバーは `openTabs` の開いた順で、色は `leafPanes` の深さ優先だった。2x2 の木は `row(col(A,B), col(C,D))` なので、DFS は左上→左下→右上→右下になり、利用者の読む順（左上→右上→左下→右下）と 2/3 番目が入れ替わる。T 字も同じ。タブの位置とセルの位置が対応しないため、色と名前を目で追う必要があり、同名のペインが多いとどれがどれか分からなくなる。

タブを選んでも `openTabs` は変わらないので、タブ自体は勝手に並ばない。問題は、タブ順がセルの並びを表していないことと、色の番号が読み順でないこと。

## Decision

### 状態

`SplitView` に `recent` を足す。`openTabs` は開いた順のまま、`recent` は最後に選んだ順（MRU）で、`openTabs` と同じ集合の並べ替え。実在する `current` があるとき、その ID が先頭になる。

- `openTabs`: 全スペースを跨ぐ開いた順。モバイルと PC の 1 枚表示のタブ順に使う
- `recent`: MRU。PC の 2 枚以上の分割で、固定ゾーンの外のタブの順に使う
- `current`: 選択。実在するなら `recent` の先頭
- `layout`: 方向つきの二分木（[ADR 0061](0061-split-view-directional-tree.md)）

表示順は状態に持たず、描画時に `readingOrder` と `tabPanes` で導出する。

### 読み順

`readingOrder(layout)` は葉の画面上の矩形を求め、上端→左端で並べる。

- 2 分割（左右）: 左→右
- 2 分割（上下）: 上→下
- 4 分割（2x2）: 左上→右上→左下→右下
- 3 分割（T 字）: 左上→右上（縦長）→左下

木の構造順（`leafPanes`）は 3 枚=T 字、4 枚=2x2 の組み直しに使うので残す。表示と色は `readingOrder` を使う。

### タブ順

- PC（`wide`）で葉が 2 枚以上のとき: 固定ゾーン = `readingOrder(layout)`、その右に `recent` から固定ゾーンを除いたもの（左が新しい）
- それ以外（モバイル、PC 1 枚）: `openTabs` の開いた順

1 枚のときに固定ゾーンを作らないのは、固定ゾーンが current の 1 枚だけになり、タブを選ぶたびに current が先頭へ動くため。モバイルはセルが見えず、横スクロール中の並べ替えは押し間違いを招く。

### 色

- 固定ゾーンの index + 1 を `--color-slot-1..4` に割り当てる。1=青、2=紫、3=青緑、4=ピンク
- モバイルは色を出さない。PC 1 枚は現在タブに slot 1 を出す
- 色はペインではなく位置を表す。タブが固定ゾーンを出ると色を失い、入るとそのセルの色を得る

### 選択と変形

- 固定ゾーンのタブを選んでも並びは変えない
- 固定ゾーンの外のタブを選ぶと current の葉を置き換える。置き換えられたペインは右ゾーンの先頭（固定ゾーンのすぐ右）へ出る。直前まで current で `recent` の先頭に居たため
- 並びが変わるのは、ドラッグ・分割・ペインの close で layout が変わったときだけ

### 後継と補充

- タブを外したときの後継は、表示順の次（無ければ手前）。後継が木に無ければ最初の葉
- 自分自身の端へのドロップで空くセルには、表示順で次（無ければ手前）の、木に無いタブを入れる

### 永続化

- キーは `hwc-split-view` のまま。`{ openTabs, recent, current, layout }`
- `recent` は `openTabs` の並べ替えとして正規化する。欠けているタブは開いた順で末尾に足す。重複と実在しない ID は落とす
- current が実在するときは `recent` の先頭へ移す
- 葉は `openTabs` に含める。保存値に無ければ足す
- `recent` が無い旧値は `openTabs` から作り、current を先頭にする
- モバイルも同じ `openTabs` / `recent` / `current` / `layout` を保存する。表示順だけ端末で変える

## Consequences

- PC の 2 枚以上の分割で、タブの位置・色・セルの位置が一致する。4 枚以下ならタブは選択で動かない
- 2x2（`row(col, col)`）と T 字では、色 2/3 が入れ替わる。これは読み順に合わせた結果
- 5 枚以上では、固定ゾーンの外のタブを選ぶとタブの入れ替わりが起きる。セルと色は動かない。押し出されたペインは固定ゾーンのすぐ右に出る
- モバイルと PC 1 枚ではタブ順が開いた順のまま。PC の分割に切り替えたときだけ読み順になる
- `recent` が 1 つ増える。表示順は導出するので、タブ順そのものは保存しない
- 既存の保存値は `recent` を開いた順から補う。タブの並びは再読み込みで変わる可能性がある

## Alternatives

- **右ゾーンも開いた順**: 状態は増えないが、押し出されたペインが右の奥に埋もれる
- **色をペインに固定**: 5 枚以上で色が重複し、どのセルかを示せなくなる
- **モバイルも読み順**: セルが見えないうえ、横スクロール中にタブが動く
- **1 枚でも固定ゾーン**: current が常に先頭へ動き、モバイルのタブが毎回並び替わる
- **DFS のままタブだけ読み順**: 色とタブの番号がずれる
- **タブ順を state に保存**: layout から導出できるので、二重管理になる
