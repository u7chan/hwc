# ADR 0029: スペースの最後のペインは削除せず、エージェントだけ終了を要求する

- Status: Accepted
- Date: 2026-11-05

## Context

Herdr は最後のタブの最後のペインを閉じると、スペース自体も削除する。GUI の「ペインを閉じる」からスペースまで失うのは、不要なエージェントだけ片付けたい操作として重すぎる。[ADR 0021](0021-pane-close.md) の「最後のペインの後始末を Herdr に任せる」を変更する。

Pi は `/exit` ではなく `/quit` を持つ。Claude Code / Codex / OpenCode も `/quit` を受け付ける。GUI の `agent.start` はシェル上で起動するため、エージェントが終了してもシェルを残せる。一方、`exec pi` など PTY 直下のプロセスを置き換えた場合は、エージェント終了でもペインとスペースが消える。

## Decision

- 最後かどうかは、スペース内の全タブ・全ペインで数える。非表示のペイン、シェル、別タブも含め、別スペースの枚数は含めない
- 最後以外は既存の「ペインを閉じる」と確認ダイアログを維持する
- 最後のペインが Pi / Claude / Codex / OpenCode なら、詳細メニューを「エージェントを終了」に切り替える。確認では終了要求であることと、ペイン・スペースを残すことを伝える。既存のターン停止ボタンは変更しない
- 最後のペインがシェル・未知のエージェントなら削除を無効にし、スペースを残すためであることをメニューに添える
- `POST /api/panes/:id/close` は最後のペインを拒否する。`POST /api/panes/:id/exit` は最後の既知エージェントだけを受け付ける。異なる操作への自動切り替えはせず、現在の構成と要求が一致しなければ 409 `pane_action_changed`
- close / exit は BFF 内で直列化し、操作前にスナップショットを再取得する。GUI から同時に 2 枚閉じる要求が届いても、同じ古い枚数を見て両方削除しない。再取得に失敗したら 502 とし、キャッシュの状態で続行しない。送信後は再取得せず、Herdr のイベントと SSE に任せる
- exit は `pane.process_info` で PTY 直下の PID とフォアグラウンドのプロセスグループを確認する。同一、欠落、不正な応答なら 409 `agent_exit_unsafe` とし、入力しない。シェルが別のフォアグラウンドジョブを待っている場合だけ、`agent.prompt` に `/quit` を送る。同 API の実プロセス検査で、シェルに戻った対象への送信を拒否する
- `Ctrl+D` は送らない。Pi では入力が空のときだけ終了し、シェルへ届くとシェル自体が終了するため。失敗時に `pane.close`、シグナル、別のキーへフォールバックしない
- 確認中に構成が変わっても、確認した close / exit の意図は切り替えない。現在の状態と一致しなくなったら確認ボタンを無効にし、閉じて操作し直すよう案内する
- exit 後も選択とペインをローカルで変更しない。成功応答は終了要求の送信成功であり、プロセス終了の保証ではない。8 秒のクライアント期限と二重送信防止は close と共通にする

## Consequences

- 最後のシェルは GUI から削除できない。スペース自体を片付ける操作は Herdr で行う
- 要対応のエージェントは `agent.prompt` が拒否するため、確認画面などを Herdr 側で解消する必要がある。未送信の TUI 入力や拡張にも左右されるので、終了完了を楽観的に表示しない
- PTY 直下で起動したエージェントやプロセス情報を読めない環境では、最後のエージェントの終了も拒否する
- Herdr の close API は条件付き削除を持たない。BFF 内の要求同士は直列化するが、状態確認と実行の間に TUI や別クライアントが削除する競合まで原子的には防げない

## Alternatives

- **確認文にスペース削除を追記するだけ**: エージェントだけ終了したい目的を満たさない
- **終了後に空のペインを作り直す**: 先にスペースが消えるうえ、同じペインの復元にはならない
- **終了できなければペインを強制削除する**: 保護したいスペースを失うため採らない
