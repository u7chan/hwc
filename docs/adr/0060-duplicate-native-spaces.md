# ADR 0060: 同じ場所を指す Herdr ネイティブスペースを束ね、重複だけを閉じられるようにする

- Status: Accepted
- Date: 2026-11-10

## Context

Herdr の `worktree.open` は既に開いているチェックアウトを返すが、`workspace.create` は同じディレクトリでも新しいスペースを作る。実際に、同じパス・同じラベルの `mypi` が 2 つ、どちらもシェルだけで並んでいた。Herdr TUI でも別スペースとして見えるため、hwc だけが同じ場所を 1 つに潰すと、TUI と Web でスペースの数と操作対象が食い違う。

`すべて` のツリーは `worktree.repoName` でリポジトリ束を作る（[ADR 0047](0047-worktree-task-summary.md)）。Herdr が管理しないスペースは、`worktree` が null か、git から補った `managed: false` の表示用情報だけを持つ（[ADR 0059](0059-git-kind-from-checkout.md)）。前者は単独グループになり、後者は `repoName` でリポジトリ束に入るが、同じ場所の重複は依然として別の行になる。ADR 0017 は「シェルだけのスペースも残す。ノイズが問題になったら別 Issue で扱う」としており、この ADR がその別 Issue にあたる。

ADR 0034 は「リポジトリ本体のスペースを閉じる操作は持たない」と決めた。理由は、`workspace.close` がチェックアウトのフォルダを残すため、ワークツリーの片付けには向かないというもの。重複スペースの整理では、フォルダが残ることは目的に合う。

## Decision

### 識別

- 同じ正規化済みパス・同じラベルの、Herdr が管理しないスペース（`worktree?.managed !== true`）を同じ場所とみなす。キーは `placeOf` が返す `place:<path>:<label>` とする
- git から補った表示用の worktree 情報（`managed: false`）は、場所の同一性や close の可否に使わない。Herdr が管理するワークツリー（`managed: true`）だけをリポジトリ束に任せる
- ラベルだけでは束ねない。既定ラベルはディレクトリ名なので、別の場所の同名を混ぜ、意図的に同名で分けたスペースも潰す
- パスだけでは束ねない。同じチェックアウトを別名で使い分ける意図を潰す
- パスが無いスペースは束ねない。パスは `WorkspaceState.path`（Herdr の worktree 情報が無いスペースでは先頭ペインの cwd）を使う
- 同じ場所のスペースが 2 つ以上あるときだけ場所の束を作る。1 つのときは今までどおり単独のスペースとして描く

### ツリー

- 場所の束は `すべて` の最上位に 1 つ置く。見出しは場所のラベル、アイコンは代表の `WorkspaceGlyph`（リポジトリ / linked worktree / 非 git）、右端はメンバーの中で最も行動が必要な状態（`blocked` → `working` → `done` → `idle` → `unknown`）にする。畳んだ状態で代表 1 つの状態だけを出すと、もう片方の要対応や実行中を見落とすため
- 名前の行にスペース数の札を出す。副題はエージェントの有無（`シェルのみ` / `エージェント N`）か、PR のタイトル、無ければペイン数にする（ADR 0053 の規則を場所の束にも適用する）
- 代表は Herdr の並びで先頭のメンバー。代表の中身はリポジトリ束のホストと同じく、束の見出しの直下に置き、代表自身の見出しは出さない
- 余分なスペースは `スペース 2`、`スペース 3` の子見出しにする。子は自分のメニューと開閉を持ち、`スペースを閉じる` の対象になる。同じラベルを繰り返さない
- 場所の束は既定で畳む。メンバーが focus されているときと、利用者が開いた記憶があるときだけ開く。畳んでいてもスペース数の札で実体が残っていることは見せる
- 並べ替えは場所の束を 1 単位とし、メンバー全 id を `workspace.move_block` でまとめて動かす（ADR 0052）
- Herdr が管理しないスペースでも、同じ場所の重複がなければ今までどおりリポジトリ束に残る。場所の束は重複があるときだけリポジトリ束より優先する
- `アクティブ` はワークスペース単位のまま変えない。帯・親ペイン・件数はスペース単位で決まっており（ADR 0050 / ADR 0054）、シェルだけの重複はそもそも出ない

### 閉じる

- `POST /api/workspaces/:id/close` を足す。対象は、同じ場所に他にも Herdr が管理しないスペースがあるスペースだけ。`managed: true` のワークツリー、パスが無いスペース、最後の 1 つは 409 `not_duplicate_space` で拒否する
- BFF は `workspace.close` を `close_group` なしで呼ぶ。linked worktree の削除は今までどおり `worktree.remove` を使う
- 消えたスペースは目的の状態に達しているため、Herdr の `workspace_not_found` は 404 とし、クライアントは成功として扱う（ペインの close と同じ）
- `workspace_group_close_required` は 409 で返し、グループを巻き込む閉じ方はしない
- 入口はスペースのメニューに `スペースを閉じる` として置く。確認で、実行中のエージェントも終了すること、チェックアウトのファイルは残ることを伝える。自動では閉じない
- 最後の 1 つを閉じられない規則は UI と BFF の両方に置く。UI は重複が 2 つ以上あるときだけ項目を出し、BFF は要求時点の状態で同じ条件を確認する
- 同じ場所の close は BFF の in-flight ガードで直列化する。対象 id を `workspace.close` の前に印を付け、後続の要求は重複数から外して 409 にする。close 成功後は状態をバックグラウンドで取り直し、状態から id が消えるまで印を残す。Herdr の `workspace_not_found` も同じ扱いにする

### 状態の持ち方

- 束ねはクライアントの派生ビュー（`groupWorkspaces`）で行い、BFF の状態や Herdr のスペースを書き換えない
- 自動クローズ、BFF 側の重複排除、hwc 側の作成ブロックは持たない。Herdr ネイティブの `workspace.create` は hwc の外で起きる

## Consequences

- 同じ場所の重複は 1 行にまとまり、開くと代表のペインと余分なスペースの見出しが出る。畳んだ状態でも `2` の札と状態で重複の存在は読める
- 重複の片方にエージェントが居ても、スペース数の札と最も緊急な状態で見つけられる。閉じるときは確認が入る
- 同じパス・別ラベル、別パス・同じラベルは束ねない。利用者が意図的に分けたスペースを勝手に混ぜない
- Herdr が管理しない git チェックアウトは、重複がなければリポジトリ束に残り、リポジトリのアイコンで見える（[ADR 0059](0059-git-kind-from-checkout.md)）
- 最後の 1 つは閉じられない。重複を片付けた後は、通常の単独スペースとして残る
- 同じ場所の close が同時に 2 つ来ても、片方だけが成功して 0 スペースにはならない。状態の反映が遅れている間は、残ったスペースの close も一時的に 409 になる。状態が届けば解ける
- パスは先頭ペインの cwd に由来する。ペインの cwd が変わると場所のキーも変わり、束が解けることがある。Herdr のワークスペース情報に cwd が無いため、これは受け入れる
- 場所のキーは開閉の記憶（localStorage）にも使う。スペースをリネームすると束が解け、記憶は新しいキーに引き継がれない
- 代表を閉じると次のメンバーが代表になる。代表の切り替えで束の見出しのメニュー対象が変わるが、同じパスなのでブランチ・PR・同期の値は同じ
- `アクティブ` に両方のスペースのエージェントが居る場合は、今までどおり 2 つの帯になる。場所で束ねるのは `すべて` の整理に限る
- hwc から作るワークツリーは `worktree.open` 相当の重複防止が Herdr 側にあるため、この変更の対象外

## Alternatives

- **ラベルだけで束ねる**: 実装は小さいが、別の場所の同名を混ぜる。既定ラベルがディレクトリ名なので誤爆しやすい
- **パスだけで束ねる**: 同じチェックアウトを別名で使い分ける意図を潰す。子に残すとしても、束の見出し名をどちらにするか決められない
- **1 行に完全統合する**: 見た目は最小になるが、スペース単位のメニュー・focus・close の対象が消える。実体が残っている以上、閉じる対象を見せる必要がある
- **BFF で重複を消す**: Herdr が状態の正という原則に反する。スペース id を合成すると、Herdr のイベント・メニュー・並べ替えの対応も失う
- **すべてのネイティブスペースを閉じられるようにする**: ADR 0034 の「リポジトリ本体は閉じない」を広く崩す。重複の整理に限定して例外を最小にする
- **重複を自動で閉じる**: 実行中のエージェントやプロセスを予告なく終わらせる。確認を挟む
- **`アクティブ` も場所で束ねる**: 帯・親ペイン・件数の規則をスペース単位から変える必要があり、今回の目的（`すべて` の重複整理）に対して範囲が広い
