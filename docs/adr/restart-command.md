# 再起動は設定した実行ファイルを BFF が直接起動し、プルの成功後にも走らせる

- Status: Accepted

## Context

PR をマージしたあと、常駐している BFF は `main` を取り込むまで古いコードを配り続ける。開発機の前ならシェルで再起動できるが、出先ではスマホしか無い。

さらに、Bun の開発サーバーはクライアントのバンドルをプロセス内にキャッシュする。pull のように多数のファイルが一括で置き換わると 1 モジュールだけ古いまま残ることがあり、サーバーを再起動するまで直らない。

git の `post-merge` フックでも再起動はできるが、スペースメニューのプルは BFF が `git pull` を待つので、フックが自分を止めるとその応答が落ちる。応答を返してから再起動するには、BFF 側に起点が要る。

## Decision

- 設定画面で実行ファイルの**絶対パス**を保存する（状態ディレクトリの `restart.json`）。シェル文字列は受けない。相対パス・制御文字・長すぎる値は弾く。BFF はシェルを介さず、その実行ファイルを直接起動する
- `POST /api/restart` は、設定済みで実行可能なら 202 を返し、応答を書き終えてから起動する。終了は待たない
- 「プル成功後に実行」がオンなら、プルが成功したときに同じ経路で起動する。コマンドはプルしたチェックアウトを cwd として起動する
- どのリポジトリなら再起動してよいかはコマンドが cwd で判定する。BFF はワークスペースの id やパスを渡さず、hwc 自身を特別扱いしない

## Consequences

- 手順と復旧は [docs/deploy.md](../deploy.md) を正とする
- LAN 内の誰でも再起動を叩ける。実行するのは保存済みのファイルだけで、引数やシェル文字列は渡せない。保存するパスの変更も LAN 内から行える（[LAN 公開](lan-access.md)）

## Alternatives

- **git の `post-merge` フック**: リポジトリに同梱でき、シェルからの pull にも効くが、hwc のプルでは応答を返す前に走り、自己再起動でその応答が落ちる
- **BFF が `systemctl --user restart <unit>` を叩く**: unit 名と systemd の前提が BFF に入る
- **`process.exit` して supervisor に任せる**: `Restart=always` の無い起動方法（`bun run dev`）では落ちるだけで戻らない
