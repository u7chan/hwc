# E2E

E2E のスクリーンショットを PR に貼るため、実 Herdr のワークスペース名・ブランチ・ユーザー名・パス・会話を画面に出さない。開発用の BFF（:30000）は実 Herdr につながっているので、E2E には使わない。

## 起動

```bash
bun run e2e:serve
```

`http://127.0.0.1:31000/` を Playwright CLI で開く。ポートは `PORT` で変えられる。`HOST` は `127.0.0.1` に固定する。

起動ログの `hwc ready: ... (e2e)` と、設定画面の revision `e2e` で、架空環境であることを確認できる。

## 架空 Herdr

`e2e/fake-herdr.ts` が Unix ソケットで次のメソッドに応答する。

- `session.snapshot`
- `events.subscribe`
- `pane.read`
- `pane.clear`
- `pane.process_info`
- `pane.layout`
- `pane.get`
- `pane.send_input`
- `pane.send_keys`
- `agent.focus`
- `pane.split`
- `pane.rename`
- `agent.start`
- `agent.prompt`
- `pane.close`
- `worktree.create`
- `worktree.remove`
- `workspace.create`
- `workspace.close`
- `workspace.move_block`

`pane.clear` は架空の端末出力を最後の 1 行だけにして、実 Herdr の画面・スクロールバックのクリアを模す。`pane.close` はスナップショットからペインを消して `pane.closed` を流す。`worktree.remove` は
linked worktree のスペースをスナップショットから取り除き、`workspace.closed` を流す（実際の
チェックアウトのフォルダには触らない）。`worktree.create` は起点スペースの worktree 情報、
または cwd と架空 git に登録したリポジトリから、リンクされたスペース・タブ・root pane をスナップショットに
足して `workspace.created` / `pane.created` を流す（実際の `git worktree add` はしない）。
起点に worktree 情報が無ければ補い、`workspace.updated` も流す。
`workspace.create` は `cwd` を作業ディレクトリにしたスペース・タブ・root pane を足して、`workspace.created` / `pane.created` を流す。worktree 情報は持たせない。
`pane.split` は
`target_pane_id` のタブにシェルペインを 1 枚足し、`pane_info` を返して `pane.created` を流す。
`pane.layout` はそのタブのセルを等幅のグリッドとして返す（E2E 用の固定形で、実際の分割方向は
BFF の unit で確かめる）。`pane.rename` はラベルを変えて `pane.updated` を流す。`agent.start` は
架空のエージェントをペインへ付け、`pane.updated` を流す。分割したペインでも既存のシェルペインでも
同じで、後者の場合はペインを増やさない。Codex は架空の thread id と空の会話を
用意し、既存の `review` ペインには架空の user / assistant の会話を入れる。`agent.focus` は
フォーカスを移して `pane.focused` を流す。実 Herdr と同じく seen も進むので、対象が `done` の
ときは `idle` に戻し、そのタブとスペースの集約状態を残りのペインから引き直して `pane.updated`
を流す。hwc の既読はこの遷移で完了から待機に変わる（行そのものは残る）。
`pane.send_keys` は `esc` を受けるとペインの `agent_status` を `idle` に戻し、`pane.updated` を流す。pi のペインが `working` の間なら、実 pi と同じく本文の無い `stopReason: "aborted"` の assistant をセッションへ追記して葉にする（hwc は描画しないので、会話は止めた発言で終わって見える）。Claude のペインで応答待ちの sidecar（`<root>/claude/pending/<session uuid>.json`）に質問があれば、実機の Claude Code と同じく、assistant の tool_use と `is_error` の tool_result と user の `[Request interrupted by user for tool use]` を transcript へ書く（sidecar は残す。Esc は hook を呼ばないため）。`pane.send_input` は Claude のペインでは送信 text を transcript の user として追記し、sidecar を消す（`UserPromptSubmit` の hook に相当）。質問への回答（[Claude 連携](adr/claude-integration.md)）は、この 2 つを通して確かめられる。pi のペインでは、フィクスチャ専用の `/ask` と `/ask-text` が pending を置いて `blocked` にし、answer が現れると pending を消して `working → idle` に戻す（下の「pi の ask_user」）。Claude のペインが `/model <alias>` を受けたとき、BFF が置いた許可の印（`<root>/claude/model-switch/<session uuid>.allow.json`）があれば、確認ダイアログを開かずに、`PostModelSwitch` の hook と同じ完了の記録（`<session uuid>.done.json`）と、`/model` の `<local-command-stdout>` を transcript へ書く。印が無い `/model` は何もしない（実機では確認ダイアログが開く。失敗の経路はリクエストの差し替えで確かめる）。`/effort <level>` は `Set effort level to <level>` の `<local-command-stdout>` を transcript へ書く。どちらも会話の発言にはならない。
`workspace.move_block` は `workspaces` を並べ替えて `workspace.reordered` を流す。実 Herdr と同じく、
渡された id の列を 1 ブロックとしてアンカーの前へ置く。
`workspace.close` はスペース・タブ・ペインをスナップショットから取り除き、`workspace.closed` を流す。
実際のチェックアウトのフォルダには触らない。
BFF は実 Herdr と同じようにイベントで状態を取り直す。

`<root>/bin/git` は `e2e/fake-git.ts` を起動する。`remote -v` と `for-each-ref` は
`<root>/git-state.json` の架空の remote URL / upstream / ahead / behind を返し、`fetch` は何も変えない。
`rev-parse` は fixture に登録した cwd をリポジトリとして返す。Herdr が worktree を持たない
`plain-checkout` の git 種別を BFF が補うために使う。
remote URL は GitHub の予約済みでない架空のパス（`example/acme-dashboard`）にする。
`pull --ff-only` は behind を 0 にして状態ファイルを書き換えるので、BFF が状態を取り直すと
見出しの `↓N` が消える。実リポジトリ・実リモート・認証には触れない。

シェルペインの「…」メニューには「出力をクリア」が出る。選ぶと BFF が `pane.clear` を呼び、
架空の端末出力は最後の 1 行（プロンプト）だけになる。hwc はペイン詳細の実行口から直ちに
出力を読み直し、メニューを閉じる。エージェントのペインにはこの項目を出さない。

`web` の `shell` ペイン（`w1:p2`）は、fixture で `bun --watch src/server.ts` が動いている。
架空 Herdr はこれを実プロセス（`e2e/fake-listen.ts`）として待ち受けさせ、`pane.process_info` には
その pid を返す。詳細のタブ名はペイン名ではなくプログラム名とポート（`bun <port>`）になり、
入力欄が空の間は送信ボタンが停止に変わる。停止を押すと架空 Herdr が `C-c` を受けて前景コマンドを消し、次のポーリングでタブ名が
`shell` に戻り、ボタンも送信に戻る。入力に文字を入れると、動いている間でも送信ボタンになる。

このペインの端末出力には ANSI の SGR と裸の URL を含めてある。詳細の出力欄が色付きになり、
URL が下線付きで新しいタブに開くことを目視できる。

`plain-checkout` の `worker`（`w5:t2` の `w5:p2`）は、Herdr のラベルを持たない pi のペインで、端末タイトルはスペース名と同じ `plain-checkout` になる。タブと一覧は、この端末タイトルではなくエージェント名の `pi` を出す（下の「ペイン名」）。

`scratch` の `folder-trust` と `folder-trust-saved` は、架空の Codex のフォルダ信頼確認を表示する。前者は会話なし、後者は保存済み会話を持つが `idle` のまま確認待ちになる。「信頼して続行」の Enter を受けると確認を消し、前者には空の会話を作って `idle` にする。「ターミナルで操作」では架空 Herdr へのキー送信がなく、確認が残ることを確かめる。表示するパスと注意文は `e2e/fixtures/folder-trust.ts` の架空データだけを使う。

`scratch` の `codex-start` は、会話 ID がまだない起動直後の Codex を表す。通常の入力待ちなら端末出力と入力欄が表示され、最初のメッセージを送れることを確認する。

`scratch` の `pi-trust` は、架空の Pi のプロジェクト信頼確認を表示する。会話を持たず `idle` のまま確認待ちになる。入力欄の代わりに確認ビューが出ること、「信頼して続行」の Enter で確認が消えて端末表示と入力欄に戻ること、「ターミナルで操作」では架空 Herdr へのキー送信がなく、確認が残ることを確かめる。表示するパスと注意文は `e2e/fixtures/folder-trust.ts` の `PI_TRUST_SCREEN` だけを使う。

モデル選択では、`pane.get` が fixture の cwd を返す。Pi の一覧は架空 CLI から、OpenCode の一覧と新規セッションは `e2e/fake-opencode.ts` の loopback サービスから読み書きする。候補の正は `e2e/fixtures/scenario.ts` の `STARTUP_MODELS`。Claude の候補は hwc の固定リスト（エイリアスと effort の段階）で、サービスは起動しない。表示名は `<root>/bin/claude` の `list_models` から読む（[Claude 連携](adr/claude-integration.md)）。`agent.start` は受け取った引数を架空の端末出力にも残し、モデル指定した OpenCode には架空のセッション参照を付ける。

OpenCode のサービスの自動起動は、架空の `<root>/opencode/service.json` だけを一時退避してダイアログを開き、そのままモデル一覧が出ることで確かめる。PATH 上の架空の `opencode`（`e2e/fake-opencode-cli.ts`）が `service start` だけを受け、控えの `service.fixture.json` から接続情報を戻す（[OpenCode 連携](adr/opencode-integration.md)）。起動失敗の表示は、`service.json` と `service.fixture.json` の両方を退避して開き、「OpenCode サービスを起動できませんでした。再取得すると起動し直します。」と「再取得」が出ることを確認する。モデル欄は無効で、作成ボタンも押せない（[起動](adr/agent-launch.md)）。控えを戻して「再取得」を押すと、ダイアログを開き直さずにモデル一覧が復帰することも確かめる。設定画面の「エージェント」→「OpenCode」でも同じ表示と再取得になる。

effort は同 fixture のエージェント別候補を使う。モデルを選択したときだけ候補が読まれ、モデル・エージェント・シェルの切り替えで選択が解除されることを確かめる。effort に対応するモデルでは、effort も選ぶまで作成ボタンを押せない。`@demo/beam-small` は effort 非対応、長いモデル名は選択肢が異なるモデルを表す。`@demo/start-fails` は起動に失敗するモデルで、`agent.start` が `agent_spawn_failed` を返す。新しいペインとワークツリーの起動失敗（シェルを残してペイン内に行を出す）を、実 CLI に触れずに確かめるために使う。Pi は架空 RPC の `get_state` / `get_available_thinking_levels`、Codex は `model/list`、OpenCode は `variants` を通す。Pi は実物と同じく、最初のメッセージを送るまで架空セッションを作らない。起動したペインのチャットのモデル・effort 表示は、送信前は BFF が起動時の指定で補い（[起動](adr/agent-launch.md)）、送信後は架空セッションに記録された値になる。モデルを指定せずに起動した Pi は、チャット画面を開いたときに架空 RPC の `get_state` から既定を読み、解決中はスケルトンが出る。hwc の画面はモデルを指定して起動するので、この経路は起動 API を直接呼んだときだけ通る。既定は `DEFAULT_PI_MODEL` / `DEFAULT_PI_EFFORT` で、架空 Herdr が `agent.start` に記録する値と揃えてある。取得失敗・遅い応答によるモデル間の取り違えはブラウザのリクエスト差し替えで確かめる。

Claude の会話は `CLAUDE_CONFIG_DIR`（E2E では `<root>/claude`）配下の `projects/<project>/<session uuid>.jsonl` を読む（[Claude 連携](adr/claude-integration.md)）。fixture が架空の transcript を 2 本書く。会話を表示する `quickstart`（`w2:t2` の `w2:p2`、待機）は、`w2:t1` に足すと分割セルになり読み幅が半分になるため別タブに置く。transcript は 248 往復の履歴（500 メッセージの上限を超え、`truncated` になる）と、そのあとの行（同じ `message.id` の text 連結、tool_result、`isMeta`、TUI のダイアログで答えた質問、添付チップ、書式の崩れた注記）で作る。TUI で答えた質問は、tool_result の `toolUseResult.answers` から、選択肢と選択済みを持つ質問と回答のバブルになる。添付付きの user の 1 行は、実機と同じく貼り付けの `<pasted_content>` で包んで書く。最後の完了応答は 5 分前に送った `api-quickstart-cache` の要求に対する 1h の書き込みで、開いたときにタイマーのアイコンと `55:xx` が出て待機中も減る。要対応の `writer`（`w2:p1`）には、待ちに入る前の会話で終わる transcript と、質問を持つ hook の sidecar を足し、`blocked` のまま応答待ちのカードを出す（[Claude 連携](adr/claude-integration.md)、下の「blocked + 応答待ちの作り方」）。tool_use と tool_result の突き合わせ、input の検証、上限、キャッシュ期限の導出は `src/server/chat/claude.test.ts` と `claude-sidecar.test.ts` で確かめる。実ホームの `~/.claude` は読まない。

Codex のモデル一覧と会話は架空 App Server の JSON-RPC を通す。初期化後の `config/read` / `model/list` / `thread/read` / `thread/turns/list` にだけ応答する。モデル指定した新規ペインは、そのモデルを架空の thread に記録する。入力は本番と同じ Herdr の `pane.send_input` 経由で受け、架空の user と assistant の item を追加する。チャット表示、送信後の確定、起動時のモデル引数を、実 Codex や実会話へ触れずに確認する。

`pane.process_info` は、エージェントのペインでは親シェルと別の前景グループ（エージェント自身）を返す。シェルのペインは、fixture の `foreground` にコマンドを持つときだけ別グループになり、それ以外はプロンプトで待っている形を返す。`pane.send_keys` が `C-c` を受けると、そのペインの前景コマンドを消して端末出力に `^C` を追記する。
`agent.prompt` は既知のエージェントへの `/quit` だけを受け付け、ペイン・タブ・スペースを残して
エージェントとセッション参照を外し、`pane.updated` を流す。実 Herdr と同じく、終了したエージェントの
画面は消さずに末尾へシェルのプロンプトを足す。要対応のペインは実 Herdr と同じく
`agent_blocked` で拒否する。最後のエージェントの終了要求、拒否、残ったシェルの削除禁止を確認する。

`frontend` の user メッセージの 1 通は `<attached_files>` 注記を持ち、`empty-state-reference.zip` が履歴のチップに出る。大きさは fixture が `<root>/attachments/w1:p1/` に置いた 2MB の実ファイルから BFF が `stat` で引くので、チップは `2.0MB` になる。

`pane.send_input` は送信 text を端末出力へ追記し、`agent_session`（`kind: "path"`）を持つペインでは架空セッションの JSONL にも追記する。`frontend` の架空セッションには末尾に `hwc-capabilities` を置き、`/hwc-rewind <entryId> <requestId>` は user メッセージではなく、対象メッセージの親を `leafId` にした `hwc-rewind` の marker を追記する。その後に送る編集後の本文は marker の子になる。追記するのは user メッセージ 1 行だけで、それまでの葉を `parentId` にする。確定後の送信カードを画面で確かめるために要る。セッションがまだ無いペインでは、この追記の前にヘッダと `model_change` / `thinking_level_change` を書く。

シェルのペイン（エージェントがいないペイン）で `cd <絶対パス>` を送ると、スナップショットの `cwd` を変える。`git checkout <ブランチ>` を送ると、その cwd の `.git/HEAD` を書き換える。どちらも実 Herdr と同じくイベントは流さない。ライブ更新（[Herdr 連携](adr/herdr-socket.md)）を確かめるための入力で、実 Herdr には無い。`cd` が受け付けるのは fixture の根の下にある実在のディレクトリだけで、外や存在しないパスは無視する。HEAD の書き換えも根の下だけに限る。

`frontend` の架空セッションは、最後のターンが失敗した状態（`stopReason: "error"` と `errorMessage`、本文は空）で終わる。同じ失敗をリトライの回数だけ並べてあり、Web では 1 行に畳まれて「3 回」と出る。その行が圧縮後の usage を変えないことも確かめる。

その手前の assistant メッセージは、チェックアウト内の `docs/preview/app-icon.png` を裸のパスで、`docs/preview/empty-state.png` と `docs/preview/empty-state-light.png` を画像記法で指す。どれも実在する PNG（`src/client/assets/apple-touch-icon.png`）を fixture がコピーしたもの。連続した画像記法は本文のその位置に 1 行で並び、押すとダイアログで拡大でき、背景・`Esc`・閉じるボタンで閉じる。裸のパスのほうは位置が無いので、今までどおりメッセージの末尾にサムネイルの行が出る（[ファイルの配信](adr/file-serving.md)）。セッションの葉から `parentId` を遡る読み取りに乗せるため、失敗したターンの鎖もこのメッセージを親にする。

送信前の添付チップも同じように拡大できる。入力欄に画像を貼り付けるかドロップし、アップロードが終わってサムネイルが出てから押すとダイアログが開く。`Esc` で閉じるとサムネイルへフォーカスが戻り、チップは残ったままになる。チップは送信するまで残り、別のペインを開いて戻っても同じチップが出る（[添付](adr/attachments.md)）。

画像以外のファイルも貼り付け・ドロップ・+ から添付できる。チップには元のファイル名と大きさが出て、押しても何も開かない。送信すると履歴にも名前と大きさのチップが並び、`GET /api/panes/:id/attachments/<name>` は 400 を返す（配信するのは画像 3 形式だけ）。履歴の大きさは BFF が保存済みファイルを `stat` した実バイト数で、入力欄は選んだ `File.size`。消えたファイルは大きさだけ落ちて名前が残る。

入力欄の + からは、同じ経路でファイルを選べる。ファイル入力に `accept` は無く、`dropActionFrom` と `takeFiles` を通る。Playwright では「ファイルを追加」を押した後の File chooser に `upload` でファイルを渡す。名前は `X-HWC-Filename`（percent-encode）で送られ、保存名になる。

`+` の「プロジェクトを選ぶ」は、`<root>/bin/git` の `ls-files` が返すマニフェストから候補を作る。架空 Herdr の `pane.get` は `…/work/acme-dashboard` を cwd として返し、偽 git はその cwd に対して `package.json`、`packages/api/package.json`、`packages/web/pyproject.toml`、`apps/desktop/Cargo.toml` を返す。cwd 自身の `package.json` は候補から外れるので、`desktop`、`api`、`web` の 3 件になる。実ファイルは作らない。

pi のペインでは、あわせてセッションの隣に live の sidecar（`<session>.jsonl.thinking.json`）を書く。まず `waiting` で `working` にし、1.2 秒後に折り返す長さの `thinking` と `tokPerSecond: 42.3` を上書きし、6 秒後に消して `idle` に戻す。実物の pi 拡張はターン中に phase・thinking の末尾・生成速度を上書きし続ける（[pi 連携](adr/pi-integration.md)）。E2E ではこの 2 段階で、段階の行が会話のスクロール領域の外（入力欄の直上）に出て、スクロールしても残ること、生成速度が経過時間の左に出て右端の時間が動かないこと、thinking がまだ無い待機中も帯の高さが変わらず、末尾 2 行だけが出てターン終了で消えることを確かめる。入力欄を 1 行に畳むセルでは thinking と生成速度を出さず、段階と経過時間だけになる。停止ボタン（`esc`）でも sidecar を消す。

Claude のペインでは、フィクスチャ専用の入力 `/activity`（添付注記なし）が同じ役割を持つ。実物と同じく prompt・`api-request`・assistant・`tool_use`・`tool_result` を時間差で架空の transcript へ追記し、段階の切り替わりと 10 秒の保持を確かめられるようにする（[Claude 連携](adr/claude-integration.md)）。完了する assistant は 1h キャッシュの書き込みを持つので、応答が載ると残り時間が約 60 分へ戻る。架空の transcript の `version` は 2.1.328 に揃えてある。

`/cache` `/cache-soon` `/cache-renew` `/cache-expire` `/cache-off`（添付注記なし）もフィクスチャ専用で、1h キャッシュの表示を 1 時間待たずに確かめる。それぞれ 1h の書き込み、約 5 分後に切れる 1h 書き込み、期限内の読取だけの応答、2 時間前に送った要求の 1h 書き込み、5m の書き込みを追記する。`/cache-soon` のあとに `/cache-renew` を送ると、残り時間が約 5 分から約 60 分へ延びることが見える。`/new` は Claude のペインを空の新しいセッションへ切り替える（旧 transcript は残るが参照しない）。`/model` の結果を書くと期限が取り下げられ、表示が消える。

`/done`（添付注記なし）はフィクスチャ専用の入力で、実 Herdr には無い。受け取ったペインを `done` にする。実 Herdr の `done` は既読でしか `idle` に戻らず、hwc からは作れないため、一覧の終了時刻と端末間の一致を確かめる入口として置く。

`/compact`（添付注記なし）を受け取ると、実 Herdr の pi 拡張と同じく `agent_status` は `working` にせず、1.2 秒後に架空の compaction をセッションへ追記して `idle` のままにする。hwc 側のローカルな「会話を圧縮しています」と、完了ログの位置・所要時間を E2E で確かめるため、最後の user メッセージを kept の先頭にする。

追記しない条件:

- `agent_session` を持たないペイン（シェルや、会話を読まないペイン）。端末出力にだけ追記する
- text が空、または空白だけの送信
- 添付注記（`<attached_files>`）の無い `/new` と `/compact`（`/compact <指示>` を含む）。会話を残さないか、履歴を置き換える
- 同じく添付注記の無い `/reload`。実 Pi と同じくセッションに何も書かず、`agent_status` も `working` にしない。hwc は控えを履歴に残す
- 添付注記の無い `/hwc-rewind <entryId> <requestId>`。専用の marker を追記し、本文としては残さない
- 同じく添付注記の無い `/activity`。Claude の transcript にだけ進行行を追記し、user メッセージとしては残さない

添付を持つペインで `Enter` が送信になるときは、常に本文の送信になる（[添付](adr/attachments.md)）。タッチ端末では `Enter` が改行になる。`/compact` と打っても添付と一緒に送れば本文として扱われるので、注記があるときはコマンドではなく通常本文として追記する。

## 入力の + メニュー

入力欄の下部左端の + から、会話のコマンドを実行し、定型文・ファイル・プロジェクトを追加する。

1. `review` を開き、+ を押す。+ の上に「新しい会話」「会話を圧縮」、区切り、「定型文を引用」「ファイルを追加」「プロジェクトを選ぶ」が開き、`Escape` か外側のタップで閉じる。`frontend`（実行中）では 2 つのコマンドが無効になり、補助文に「実行中は使えません」が出る。`new`（空の会話）では「会話が始まると使えます」になる。
2. `review` で「新しい会話」を選ぶと確認ダイアログが開く。「キャンセル」では会話が残り、「始める」では会話が空になる。チップや直接入力の `/new` は確認を挟まない。ペイン見出しの「…」メニューには 2 つのコマンドが出ない。
3. `review` で「会話を圧縮」を選ぶと `/compact` が送られ、履歴に控えと「会話を圧縮しています」が出る。`review` は Codex なので、架空 Herdr は完了の compaction を追記しない。進捗行の「中断」でローカルの表示を畳む。指示付きの圧縮はチップか直接入力で行う。
4. 「ファイルを追加」を選び、`src/client/assets/apple-touch-icon.png` をアップロードする。入力欄の上に添付チップが出て、書きかけの本文は残る。4 件添付すると「ファイルを追加」が無効になり、理由が補助文に出る。同じ手順で `report.zip`（Playwright の `setInputFiles` に buffer と名前を渡す）を選ぶと、画像と同じ枚数の枠で名前と大きさのチップになる。10MB を超える画像と 25MB を超えるファイルは、送信前に notice で断られる。
5. 「プロジェクトを選ぶ」を選ぶ。`desktop`、`api`、`web` が名前と相対パスで並ぶ。検索欄に `web` と入れると `web` だけに絞り込まれる。
6. `web` を選ぶとダイアログが閉じ、本文に `./packages/web/` が入り、入力欄にフォーカスが戻る。`Escape` で閉じた場合は + にフォーカスが戻り、本文は変わらない。
7. 会話を持つペインを選び、分割セルで入力欄が 1 行に畳まれる幅にすると + は出ない。2 つのコマンドは `/` と打ったときの候補だけになる。狭い画面でも送信ボタンは右端に残り、モデル名だけが省略される。
8. 空表示と取得失敗は、ブラウザのリクエスト差し替えで確かめる。`frontend` の `/api/panes/w1:p1/projects` を `{"projects":[],"truncated":false}` にすると「このディレクトリ配下に他のプロジェクトはありません。」、502 にすると再試行が出る。
9. PC の幅で `frontend` の入力欄に `@` を打つ。入力欄の上に「プロジェクト」の見出しと、`desktop apps/desktop`、`api packages/api`、`web packages/web` の 3 行が重なり、先頭が面の色で強調される。会話の位置は動かない。`@ap` と打つと `api`、`desktop` の 2 件に絞られる。`↓` で強調が動き、Tab か Enter か行のクリックで `@ap` が `./apps/desktop/` に置き換わる。Enter は送信されず、入力欄のフォーカスとキャレットは挿入した文字列の直後に残る。語の途中（`a@ex`）や、一致のない語（`@zzz`）では候補が出ない。
10. `@pack` と打ち、Esc で候補を閉じる。本文は変わらず、もう 1 文字打つと開き直る。閉じたあとの Enter は送信になる。候補が出ているときの Shift+Enter は改行のまま。`frontend` の `/api/panes/w1:p1/projects` を 30 件の一覧に差し替えて `@` を打つと、一覧がスクロールになり、`↑` で最後の行へ折り返し、強調した行が常に見える。語を打つと先頭に戻る。
11. 1600px で `review` を `frontend` の右端へドラッグして 2 セルに分ける。+ は出ないが、`frontend` のセルで `@` を打つと、候補がそのセルの中で入力欄の上に重なり、セルの幅と高さを超えない。本文の途中に `@` を足しても、そこだけが置き換わる。
12. 390px 幅（`--mobile`）では `@` を打っても候補は出ず、Enter は改行になる。

## Claude の会話

Claude の transcript の射影は、`acme-dashboard (docs)` の `quickstart`（`w2:t2` の `w2:p2`、待機）で確かめる（[Claude 連携](adr/claude-integration.md)）。

架空 Herdr の `agent.start` は Claude の session / transcript を作らないため、E2E で hwc から Claude を起動すると 10 秒後に `unknown`（起動を確認できません）へ落ちる。実機（Herdr 0.9.5 / Claude Code 2.1.327、2026-11-19）では `agent.start` の直後に `agent_session`（`kind: "id"`）が付き、`pane.chat` が true になる。fake に起動時のセッションを足すのは、起動直後の会話が要る E2E の拡張で行う。

1. `すべて` から `acme-dashboard (docs)` を開き、`quickstart` のペインを開く。会話の先頭に「古い会話は省略されています」が出て、本文は transcript の末尾 500 件になる。「クイックスタートの手順を、今のコマンドに合わせて見直してください。」の user 行、同じ `message.id` の text を連結した agent 行（「まず `bun install` …」「そのあと `bun run dev` …」が 1 行）、`quickstart-review.pdf` のチップが出る。`<pasted_content>` で包んだ行は「その 2 点でお願いします。」だけが本文になり、タグと前後の空行は出ない。tool_use / tool_result / thinking / 内部エントリの行は無い。
2. 「この行は注記の書式が崩れています。」の行は本文だけで、`<attached_files>` も絶対パスも残らない。チップも出ない。
3. 同じペインで 2 回目の取得が 304 になることを、DevTools のネットワークで `/api/panes/w2:p2/chat` の応答を見て確かめる。会話が変わらない間は 200 が返らない。
4. 端末出力へのフォールバックは、起動ログの `hwc e2e fixture: <root>` が示す `<root>/claude/projects/<project>/<session uuid>.jsonl` を消して確かめる。次の取得が 502 になり、本文が `claude · quickstart` の端末出力に切り替わる。ファイルを戻すと会話に戻るが、見つからなかった結果を 4 秒だけ覚えるので、戻した直後は端末出力のままになる（[Claude 連携](adr/claude-integration.md)）。
5. `acme-dashboard (docs)` の `writer`（`w2:t1`）は `blocked` で、質問は hook の sidecar（`<root>/claude/pending/<session uuid>.json`）にあり、transcript には質問の tool_use が無い（実機の Claude Code は待ちの間これを書かない。[Claude 連携](adr/claude-integration.md)）。会話は端末出力へ切り替わらず、末尾に「Claude からの質問」のカードが出る。カードは外側の帯 1 枚（会話の左右へ 16px はみ出す）で、質問が 2 つなので上に質問ごとのタブ（見出し・範囲・確認）が並ぶ。1 ページに 1 問だけが出て、1 問目は質問文・選択肢（label と description）が罫線で区切った行になり、2 問目の複数選択には「複数選べます」が付く。入力欄・引用・添付・`/` の候補は出ず、代わりに「Claude の応答待ちです」の行が出る。transcript にある解決済みの Read の tool_use は、カードにならない。
6. カードの「端末出力を見る」を押すと body が `claude · docs` の端末出力に変わり、上に「端末で応答してください。」と「会話に戻る」が出る。「会話に戻る」で会話とカードに戻る。再読み込みすると会話に戻る（切替はローカルの状態）。
7. 解決は transcript の tool_result で知る（Esc は hook を呼ばない）。起動ログの `hwc e2e fixture: <root>` が示す `<root>/claude/projects/<project>/<session uuid>.jsonl` に、`pending-tool-2` の assistant の tool_use と、`tool_use_id` が同じ tool_result の user を 1 行ずつ追記すると、次の取得（5 秒以内）でカードが消える。架空 Herdr の `agent_status` は `blocked` のままなので、カードが消えたあとは端末出力になり、入力欄は閉じたまま（実機では Esc で `idle` に戻り、入力欄が戻る）。sidecar のファイルが残っていても、カードは戻らない。
8. 応答待ちが読めない `blocked` のペインは、今までどおり端末出力になる。sidecar のファイルを消すと、次の取得でカードが消えて端末出力になる。
9. 質問に答える（[Claude 連携](adr/claude-integration.md)）。カードの選択肢は押せる。開いているタブだけ見出しが出て、ほかは番号か回答済みのチェックになる。単一選択（見出し）は 1 つだけで、選ぶと選択の印が出てから自動で次のページへ進む。複数選択（範囲）は複数を選べ、自動では進まず「確認へ」で進む。選ぶと行の面・チェック・アクセント文字で示す。「その他（自由入力）」を押すと選択肢が外れて入力欄が開き、文字を入れるまで「次へ」「確認へ」は無効のまま。「確認」は答えの一覧で、行を押すとその質問へ戻れる。全問に答えてある状態で 1 問だけ直すと、単一選択は選ぶと自動で、複数選択と自由入力は「確認へ」を押すと、次の質問ではなく確認へ戻る。答えていない質問があるあいだは「未回答が N 問あります」が出て「この内容で答える」は無効。全問に答えて押すと、押した間だけスピナーが出て、架空 Herdr が Esc で質問を閉じ、本文（1 行目が `質問への回答:`、続けて `質問: 選んだラベル` を質問ごとに 1 行）を送る。会話には、質問ごとに、選択肢と選択済みを持つ質問（agent）と回答（user）のバブルが並び、素の `質問への回答:` の本文は出ない。回答には「選択肢」または「自由入力」の種別が付き、複数選択は選んだラベルが `, ` でつながる。カードは消えて入力欄が戻り、`[Request interrupted by user for tool use]` の行は出ない。ダブルタップしても発言は 1 件。
10. 失敗の表示は、`/api/panes/<id>/answer-question` の応答を差し替えて確かめる（Playwright の `route`。URL の `:` はエンコードされるので `**/api/panes/*/answer-question` で一致させる）。502 は「回答できませんでした。端末で答えてください。」、413 は「回答が長すぎて送れません。短くしてください。」が出て、選択は残り、再度押せる。
11. 空の会話では `/new` `/compact` の候補が消える。fixture の Claude は会話を持つため、この判定は `src/client/commands.test.ts` で確かめる。
12. モデルとエフォートを切り替える（[Claude 連携](adr/claude-integration.md)）。`quickstart` で + を押すと、「新しい会話」「会話を圧縮」の下に「モデルとエフォートを変更」が出る。Pi の `frontend` と Codex の `review` には出ない。押すとダイアログが開き、モデルは `Sonnet 5.5`、エフォートは `xhigh`（会話の最後の応答の値）が選ばれ、何も変えない間は「切り替える」が無効。モデルを `Opus 5.5` に変えると「モデルを変えると、次の応答は会話全体を読み直すため…」の警告が出て、エフォートだけを変えると出ない。「切り替える」を押すと押した間だけスピナーが出て、架空 Herdr が `/model opus`、続けて `/effort <選んだ値>` を受け、ダイアログが閉じ、入力欄のチップが `Opus 5.5` と選んだエフォートになる（次の応答が載るまでは BFF が補う）。開き直すと現在の値が選ばれ、「切り替える」は無効に戻る。エフォートだけを切り替えても、チップのモデルは戻らない。
13. 切り替えの失敗は、`/api/panes/<id>/switch-model` の応答を差し替えて確かめる（Playwright の `route`。`**/api/panes/*/switch-model`）。502 は「切り替えを確認できませんでした。端末で確かめてください。」、409 は「今は切り替えられません。応答が終わってから、もう一度お試しください。」が出て、選択は残り、再度押せる。実行中・応答待ちのペインで項目が無効になる判定は `src/client/model-switch.test.ts` で確かめる。

## Claude の実行中の段階

Claude の帯は transcript の進行行から導く（[Claude 連携](adr/claude-integration.md)）。`quickstart`（`w2:p2`、待機）で確かめる。フィクスチャ専用の入力 `/activity` は実 Herdr には無い。送るとペインを `working` にし、架空の transcript へ 2 秒後に prompt と `api-request`、16 秒後に assistant の本文と `tool_use`、20 秒後に `tool_result` を追記する。prompt の 6 秒後から 500ms ごとに mod と同じ形の速度（`68.4`）を `<root>/claude/live/<session id>.json` へ上書きし、16 秒後に消す（[Claude 連携](adr/claude-integration.md)）。実在の `~/.claude` は読まない。

1. `quickstart` を開き、`/activity` を送る。すぐに帯が出て 3 点と経過時間だけになり、その下に thinking 用の 2 行の空きができる。ターンの最初の取得では新しい prompt がまだ書かれていないので、段階は出ない。本文がまだ無いので、空きの左にバーは出ない。
2. 2 秒ほどで「考えています」に変わり、続けて経過時間の左に `68.4 tok/s` が出る。応答本文がまだ無いので、2 行の空きは空のまま。16 秒ほどで「Read を実行中」に変わり、速度は消え、1 行目に `quickstart.md` が出る。帯の 2 行目に「手順を確認しています。」が出る。バーは 2 行分の空きを占め、本文 2 行でちょうど埋まる。会話の末尾に同じ文が載っても帯からは消えず、次の本文が来るかターンが終わるまで残る。空きの高さはこの間ずっと同じで、会話の見える範囲が動かない。
3. 本文が 1 行のときも確かめる。`tool_use` が追記されてから `tool_result` が来るまでの間（16 秒から 20 秒の間）に、`<root>/claude/projects/<project>/<session uuid>.jsonl` の `tool_use` の `name` を対象を持たない `TodoWrite` に、`input` を `{}` に書き換える。次の取得で「TodoWrite を実行中」になり、本文は方向の 1 行だけになる。バーは 2 行分のままなので、段階の行との間に空き 1 行が入り、本文はその下端に付く。
4. 20 秒ほどで transcript に `tool_result` が書かれ、次の取得は `activity: null` になる。帯は直前の「Read を実行中」と対象の `quickstart.md`、「手順を確認しています。」をそのまま保つ（最後に非 null を得てから 10 秒）。
5. 10 秒ほど待つと保持が切れ、段階が消えて 3 点と経過時間だけになる。2 行の空きは残る。
6. 停止ボタンで `idle` に戻すと帯が消える。もう一度 `/activity` を送ってから `/blocked` を送ると、本文が端末出力に変わり、入力欄と帯が消える。`/done` で戻すと会話表示に戻り、帯は出ない。
7. `/compact` を送る（+ のメニューか直接入力）。「会話を圧縮しています」の帯が出て、その下に thinking の 2 行の空きは出ない。`中断` を押すと帯が消えて元の表示に戻る。Claude は `compaction` を返さないので、この表示は中断するまで残る。
8. 分割セル（2 枚以上）では compact になり、Claude でも 2 行の空きを出さず、段階と経過時間だけになる。単体では `showActivityFrame` を `src/client/activity.test.ts` で確かめる。

## 過去の発言の編集

pi のセッションに `hwc-capabilities` があるときだけ、ユーザーメッセージのメタ行に鉛筆が出る（[pi 連携](adr/pi-integration.md)）。`frontend` の架空セッションには capability を置いてある。

1. `frontend` は最初 `working` なので、入力欄から短い本文（例: `あとで確認します`）を送り、6 秒ほどで待機に戻す。`編集の動作を確認します。` の吹き出しにホバーすると、コピーと並んで鉛筆が出る（触れる端末では常に表示）。入力欄に下書き（例: `下書き`）を入れてから鉛筆を押すと、入力欄がその本文に変わり、「編集中」のチップが出る。下書きは消えない。
2. チップの × を押すと入力欄が `下書き` に戻る。もう一度 `編集の動作を確認します。` の鉛筆を押し、本文を `編集後の本文` に書き換えて送信する。架空 Herdr が `/hwc-rewind` の marker を追記し、BFF が編集後の本文を送る。会話は対象の親まで戻り、編集後の本文が新しい枝として出る。`下書き` は入力欄に残る。
3. `review`（Codex）や `new`（空の会話）には鉛筆が出ない。添付付きの発言と、セッションの葉である発言にも出ない。実行中は出ない。
4. `frontend` で本文を送り、応答が返る前に停止ボタン（Esc）を押す。架空 Herdr が本文の無い `aborted` の assistant を追記して葉にするので、会話は止めた発言で終わって見えるが、その発言には鉛筆が出る（葉ではないため）。押して本文を変えて送ると、空の assistant は枝ごと外れる。
5. 失敗は `/api/panes/w1:p1/edit-message` の応答を差し替えて確かめる。`{"error":"send_failed","rewound":true}` の 502 では「会話は戻りましたが、送信できませんでした。もう一度送信してください」が出て、編集チップと本文が残る。同じ `requestId` で再送すると成功する。`{"error":"edit_failed"}` の 502 では「編集を開始できませんでした。もう一度お試しください」が出る。

## 定型文

設定で登録した定型文を、入力欄の + から本文へ引用する。

1. 設定の「定型文」で「定型文を追加」を押し、名前と本文を入れて保存する。一覧に行が増え、名前と本文の 1 行目が出る。行を押すと編集フォームが開き、名前を変えて保存すると一覧に反映される。
2. `frontend` を開き、+ を押す。区切りの下の先頭に「定型文を引用」があり、補助文は「設定で登録した文から選ぶ」。押すとダイアログが開く。
3. 定型文のボタンを選ぶと本文プレビューと文字数が出て、「引用する」が押せる。ボタンのタップだけでは入力欄は変わらない。矢印キーでも移動できる。
4. 「引用する」を押すとダイアログが閉じ、入力欄に本文が入り、フォーカスとカーソルが本文の末尾へ移る。送信はしない。
5. 入力欄に書きかけを置いて同じ操作をすると、空行 1 つを挟んで後ろに入る。`/compact` のチップ中は「定型文を引用」が無効になり、補助文に「圧縮の指示には使えません」が出る。
6. 検索に一致しない語（例: `デプロイ`）を入れると「一致する定型文がありません。」が出て、「引用する」が無効になる。検索語を消すとボタンが戻る。`Escape` で閉じると + にフォーカスが戻り、本文は変わらない。
7. 0 件の状態（設定で最後の 1 件を削除）では、+ の「定型文を引用」が無効になり、補助文が「設定で登録できます」になる。
8. 保存の失敗は `PUT /api/templates` を 500 に差し替えて確かめる。設定のフォームは入力を残したまま「保存できませんでした。」を出す。読み込みの失敗は `GET /api/templates` を 502 にすると、設定は「定型文を読み込めませんでした。」と再試行、ダイアログも同じ理由と再試行を出す。

## 新しいペインの既定

新しいペインのモデルと effort の初期値は、設定画面でエージェントごとに決める（[起動](adr/agent-launch.md)）。既定は状態ディレクトリの `launch-defaults.json` にあり、E2E では起動のたびに空から始まる。

1. 設定を開く。「エージェント」のまとまりに Pi / Claude / Codex / OpenCode が並び、どの行も `未設定` になっている。
2. 「Claude」を開き、モデルに `Sonnet 5.5`、エフォートに `high` を選んで「保存」を押す。「現在の既定」と一覧の行が、モデル名 `Sonnet 5.5` の右に effort の札 `high` を並べた表示になる（Claude は表示名にし、Codex / OpenCode は provider を落としたモデル id にする。Pi だけ `provider/model` のまま）。同じ値のままでは「保存」を押せない。
3. 「新しいペイン」を開いてエージェントのカードで Claude を選ぶ。モデルは `Sonnet 5.5（既定）`、エフォートは `high（既定）` で選ばれており、すぐに「作成して起動」を押せる。選択肢も設定の行と同じラベルになる（Codex と OpenCode の選択肢は provider の無い id だけ。Pi だけ `provider/model` のまま）。Pi のカードに戻すと、Pi の既定（未設定なら「モデルを選択」）に切り替わる。
4. Claude のままモデルを `Opus 5.5` に変えると、エフォートは「エフォートを選択」に戻り、作成ボタンは押せない。`Sonnet 5.5（既定）` に戻すと `high（既定）` が選ばれる。
5. 既定のモデルが候補に無い場合は、ブラウザのリクエスト差し替えで `GET /api/launch-defaults` に `{"defaults":{"claude":{"model":{"provider":"claude","id":"missing"},"effort":"high"}}}` を返して開き直す。モデルは「モデルを選択」になる。エフォートだけが候補に無い場合（`"effort":"none"`）は、モデルが選ばれてエフォートは未選択になる。`GET /api/launch-defaults` を 500 にしても、既定なしとして開いて選べば起動できる。
6. Claude の既定で起動し、`/chat` を 502 にしても、入力欄に `Sonnet` と `high` が出る（[起動](adr/agent-launch.md)）。モデルのチップを開くと、パネルに `ⓘ`、識別子 `sonnet`、「起動時の指定。最初の応答で実際のモデルに確定します」が出る。コピーするのも `sonnet`（[Claude 連携](adr/claude-integration.md)）。会話が読める Claude ペイン（fixture の `quickstart`）では、チップが `Sonnet 5.5`、パネルが `claude-sonnet-5-5` で、`ⓘ` と注記は出ない。
7. 設定の「Claude」で「解除」を押すと、行が `未設定` に戻り、ダイアログも「モデルを選択」で開く。
8. `@demo/beam-small`（effort 非対応）を既定にすると、行はモデルだけになり、ダイアログはエフォート欄を「なし」で無効にしたまま作成ボタンを押せる。

1. `アクティブ` を開く。エージェントのいるペインが、待機中も含めて帯ごとに並ぶ。各帯の先頭は親ペインで、状態が変わっても動かない（王冠はそのスペースにエージェントが 2 枚以上いるときだけ出る）。残りは state の順（タブ → ペイン）のままで、状態では並べ替えない。`acme-dashboard` では `frontend`（親・実行中）、`review`、`new`、`api`（完了）の順で並ぶ。`scratch` では `notes`（エージェントなし）が出ず、`folder-trust-saved` などの待機が帯に並ぶ。
2. `acme-dashboard` の帯で `api`（完了）を開き、`一覧へ戻る` で戻る。`api` は `待機` になり、帯の件数から完了が消える。行の位置は動かず、最後に残る。
3. `すべて` に切り替えて、シェルだけのペインと待機のペインがツリーに出ることを確かめる。Herdr に worktree として登録されていない `plain-checkout` も、git 管理下ならシェルではなくリポジトリのアイコンで出る。
4. `すべて` で行の途中までスクロールしてから `アクティブ` に切り替え、`すべて` に戻る。位置はスコープごとに控えられ、上端は行の途中ではなく行の先頭から始まる。
5. `acme-dashboard (checks)` の帯は `review`（待機）1 行になり、`acme-dashboard` の帯とは別に並ぶ。`acme-dashboard (docs)` の `writer` と同じく、スペースごとに 1 つの帯になる。

### 帯からすべてへ移る

1. `すべて` で `acme-dashboard` のリポジトリ束を畳む。
2. `アクティブ` に切り替える。帯の名前・ブランチ・件数を押しても何も起きず、`すべて` に切り替わらない。`すべて` へ移れるのは右端の → だけ。
3. → にポインタを載せると、矢印の 32px の枠だけが塗られ、矢印が `accent` になる。名前とブランチは変わらない。
4. `acme-dashboard (docs)` の帯の → を押す。
5. `すべて` に切り替わり、リポジトリ束・`acme-dashboard (docs)` のスペース・代表タブが開き、`docs` の見出しが見える。見出し行には `accent` の枠が付く。一覧の終わりが近くて見出しを上端まで送れないときも、上端で行を半分に切らず、切れていた行の先頭から見せる。
6. 別の行を選ぶ、見出しを開閉する、`アクティブ` に切り替えると、枠が消える。

### 行のメニュー

各行の右端の「…」から、ツリーと同じペインのメニューを開く。メニューを開くだけでは、行の選択と既読は変えない。

1. `アクティブ` を開く。`scratch` の `folder-trust` 行の「…」を押す。メニューが開き、同じスペースに 5 枚（エージェント 4 枚 + `notes` のシェル）あるため最後の項目が「ペインを閉じる」になる。行は開かず、選択も変わらない。
2. 「ペインを閉じる」を選ぶと、要対応の確認ダイアログが出る。キャンセルでメニューも確認も閉じ、行は残る。
3. `acme-dashboard (docs)` の `writer` 行の「…」を押す。同じスペースに `quickstart`（`w2:t2`）がいるので「ペインを閉じる」になる。`quickstart` の行の「…」から先に閉じる（待機なので確認は出ない。Claude の会話の手順は閉じる前に済ませる）。`writer` が最後のペインになり、「エージェントを終了」と「最後のペインとスペースは残します」が出る。`writer` は要対応なので、確認すると Herdr が終了を拒否し、ダイアログに失敗が出る（失敗表示の経路）。
4. `scratch` の `folder-trust` 行の「…」からペインを閉じると、閉じた行だけが消え、帯は残りのエージェントで残る。完了した行を開いて離れたときの既読は、従来どおり行を開いた場合だけ進む。
5. 終了できる経路は「エージェントの終了」の手順で `scratch` の `folder-trust-saved` だけを残し、`アクティブ` のその行の「…」から「エージェントを終了」を選ぶ。確認すると、その帯が `アクティブ` から消え、`すべて` ではスペースとシェルが残る。
6. PC 幅では、ポインタを載せた行・選択中の行だけ「…」が出る。390px では常に出る。狭い行ではタブ名、次に時刻が省かれ、名前と 44px の操作領域が残る。

### 経過時間と終了時刻

時刻は BFF が持つ。一覧の右端は、実行中が経過、完了と待機が終了時刻（時:分）になる。

1. `アクティブ` を開く。`acme-dashboard` の `frontend`（実行中）の右端が、開いた時点から増える経過（`3s`、`1m 4s` など）になる。
2. `frontend` の終了時刻を作る。終了時刻は `working` から `done` へ移ったときにだけ記録し、フィクスチャで `done` を作る入力は `/done` だけ。`frontend` を開いて入力欄に `/done` と入れると、停止ボタンではなく送信ボタンになる（停止は入力が空のときだけで、文字・添付・引用があれば実行中への追加指示の送信になる）。そのまま送って一覧に戻ると、`frontend` が `完了` になり、右端が経過から終了時刻（時:分）に変わる。入力欄を使わない場合は `POST /api/panes/w1:p1/input` に `{"text":"/done","submit":true}` を直接送っても同じになる。
3. 再読み込みしても同じ終了時刻が残る。起点と終了時刻は状態ディレクトリの `pane-times.json` にあり、BFF の再起動でも状態が一致する間は引き継がれる。
4. localStorage を共有しない別のブラウザ（シークレットウィンドウなど）で `アクティブ` を開くと、同じ終了時刻になる。経過は 1 秒の位相で揺れるので、比べるのは固定値の終了時刻にする。
5. `frontend` の行は比べ終わるまで開かない。開いて離れると既読が進んで `待機` に戻り、行の状態が変わる。

## ファビコンと親マーク

ファビコンは、スペースの左端にいる最初のエージェント（親）の完了と、全エージェントの要対応・作業中を見る。タイトルは `HWC` のまま変えない。

1. `アクティブ` を開く。`acme-dashboard` の `frontend` と、`scratch` の `folder-trust` に王冠の親マークが付く。`acme-dashboard (checks)` はエージェントが 1 枚だけなので付かない。
2. `すべて` に切り替え、同じ王冠がツリーのペイン名の横に出ることを確かめる。
3. `frontend` を開く。詳細の見出しに王冠が出る（1 枚表示でも分割セルでも、ブランチかリポジトリ名の横）。同じスペースの `shell` の見出しには出ない。`checks` の `review` にも出ない。
4. `link[rel="icon"]` を調べる。PNG のリンクが残り、SVG の `href` が `data:image/svg+xml,` で始まる。fixture では `writer` と `folder-trust` が `blocked` なので、点は赤になる。SVG favicon を持たないブラウザは PNG でアイコンを出す。
5. `document.title` が `HWC` のままであることを確かめる。

## 一覧の並べ替え

`すべて` の束の並びは Herdr のワークスペース順で、ネイティブ Herdr と同じ。

1. `すべて` を開く。`acme-dashboard`（リポジトリ束）、`scratch`、`sandbox`（重複した 2 スペースの束）が並ぶ。
2. `scratch` の見出しを長押しする（PC は見出しを少しドラッグする）。掴んだ束のカードが破線の青い枠で囲まれ、見出しは読める濃さのまま中身が淡くなり、指の近くに束の名前が出る。落とし先の境界に「ここに移動」の線が出る。破線はカードの角丸に沿う。ラベルは指の反対側に出て、追従するガイドと重なっても手前に残る。
3. `acme-dashboard` の上へ落とす。`scratch` が新しい位置へ動くアニメーションが見え、先頭へ移る。架空 Herdr の並びも変わる。
4. `acme-dashboard` の見出しにフォーカスし、`↓` を押すと 1 つ下がる。`↑` で戻る。
5. 同じ位置へ落としても通信しない。`アクティブ` に切り替えても、同じ Herdr の順で帯が並ぶ。
6. 失敗時は `/api/workspaces/move` に 502 を返して確かめる。一覧は Herdr の順のままで、上部に「並べ替えを保存できませんでした。」が出る。
7. 動きを減らす設定（`prefers-reduced-motion: reduce`）では、落とした後のアニメーションが出ないことを確かめる。

### メニューから先頭へ移動

1. `すべて` を開き、先頭以外の束の見出しメニューを開く。「先頭へ移動」があり、先頭の束のメニューには出ない。
2. 押すとメニューが閉じ、その束が先頭へ 220ms で滑り、動いた束はしばらく影で浮かぶ。`アクティブ` に切り替えても同じ先頭にある。
3. `アクティブ` の帯のアイコンから同じメニューを開いても同じ。`acme-dashboard (checks)` の帯で押すと、同じリポジトリの `acme-dashboard` と `acme-dashboard (docs)` も束ごと先頭へ上がる。
4. 一覧を下までスクロールしてから押すと、先頭へ寄せて移動先の帯が見える。
5. 失敗時は `/api/workspaces/move` に 502 を返して確かめる。「並べ替えを保存できませんでした。」が出て、並びは変わらない。
6. `prefers-reduced-motion: reduce` では滑らないが、位置は先頭へ変わる。
7. 移動の応答を保留したまま別のスペースを削除しても、解放後の移動で FLIP が出る。ブラウザのリクエスト差し替えで `/api/workspaces/move` の応答を遅らせ、その間に `POST /api/workspaces/w2/remove-worktree` を送り、`Element.animate` が削除時ではなく移動時に呼ばれることを確かめる。

## 重複したスペース

Herdr ネイティブの `workspace.create` は同じディレクトリでも新しいスペースを作る。hwc は同じ
パス・同じラベルのスペースを 1 つの場所に束ね、余分なスペースを閉じる入口を出す。
fixture の `sandbox` は同じ場所を指す 2 スペースで、どちらもシェルだけ。

1. `すべて` を開く。`sandbox` が 1 行にまとまり、名前の横に `2` の札、副題が `2 ペイン`、右端にシェルの記号が出る。
2. `sandbox` の見出しを開く。代表スペースのシェルペインと、`スペース 2` の見出しが出る。
3. `スペース 2` の見出しの先頭アイコンからメニューを開く。「スペースを閉じる」を選び、確認で「実行中のエージェントも終了するが、チェックアウトのファイルは残る」ことを確かめる。
4. 閉じると `sandbox` の束が 1 スペースに解け、`2` の札が消える。残ったスペースは通常の 1 スペースとして見える。他にスペースがあるので、メニューの「スペースを閉じる」は残る。
5. 代表スペースを閉じた場合も、残ったスペースが代表になる。
6. `アクティブ` にはシェルだけなので `sandbox` は出ない。重複の整理は `すべて` で行う。

## スペースを閉じる

最後の 1 つを除いて、どのスペースもメニューの一番下から閉じられる。
フォルダは残るので、`ワークツリーを削除` とは別の項目として扱う。

1. `すべて` を開き、`acme-dashboard`（リポジトリ本体）の見出しメニューを開く。`新しいワークツリー` の下に、危険色の「スペースを閉じる」がある。
2. 選ぶと確認ダイアログが出て、スペースのパス、実行中のエージェントも終了すること、チェックアウトのファイルは残ることが分かる。取り消すと何も変わらない。
3. `scratch`（git 管理外）のメニューにも「スペースを閉じる」がある。
4. `acme-dashboard (docs)`（linked worktree）のメニューには「スペースを閉じる」が出ず、「ワークツリーを削除」だけが出る。
5. 最後の 1 つのスペースでは項目が出ない。fixture は常に複数のスペースを持つため、この規則は `src/client/select.test.ts` と `src/server/app.workspace-lifecycle.test.ts` で確かめる。

## ワークツリー作成

スペース見出しの先頭アイコンから開くメニューで作るワークツリーは、次の手順で確かめる。

1. `acme-dashboard`（リポジトリ本体）の見出しの先頭アイコンを押してメニューを開き、「新しいワークツリー」を選ぶ。
   ダイアログの見出しが「新しいワークツリー」で、ブランチ名と保存先が Herdr 任せである旨が出る。
2. モデルとエフォートを選んで「作成して起動」を押すと、架空 Herdr にリンクされたスペースが 1 つ増え、hwc が
   その root pane を開く。ダイアログはワークツリーと root pane ができるまでで閉じ、起動は裏で続く。
   開いた直後は本文がスケルトン、入力欄はエージェント仕様で送信ボタンがスピナーのまま、入力を待つ。
   シェルの起動コマンドや Pi の TUI の途中、空状態は出ない。数秒で入力欄と会話（空状態を含む）に
   一度で切り替わる（[起動](adr/agent-launch.md)）。
   入力欄のモデル表示は起動時の指定で補われる（[起動](adr/agent-launch.md)）。
3. linked worktree（`acme-dashboard (docs)`）の見出しのメニューには「新しいワークツリー」が無い。
4. 4 ペインのタブを持つスペースでも、「新しいペイン」だけが無効で「新しいワークツリー」は押せる。
   4 枚のタブは既存のダイアログで 2 枚追加して用意してよい。
5. 起動失敗は、モデルに `@demo/start-fails` を選んで作成すると確かめられる。ワークツリーと
   root pane は残り、ペインの入力欄の上に起動失敗の行と「再試行」「シェルとして使う」が出る。
   下書きは残り、「シェルとして使う」で `$ コマンドを入力` のシェルに切り替わる。
6. `worktree_open_failed`（結果不明）はブラウザのリクエスト差し替えで
   `/api/workspaces/:id/create-worktree` に 502 を返して確かめる。再送のボタンは出ず、「閉じる」だけになる。
7. Herdr の worktree 情報を持たない `plain-checkout` でも、メニューに「新しいワークツリー」が出る。
   シェルを選んで作成すると root pane が開き、一覧には `plain-checkout` の配下に新しいワークツリーが増える。
   起点の登録情報は架空 Herdr が補い、BFF の状態では `managed: true` に変わる。事前登録の操作は挟まない。
   非 git の `scratch` と linked worktree のメニューには作成項目が出ない。

### 作ったペインの位置

hwc が作ったペインは、一覧の見える位置へ一度だけ送る。動かす量は行が端に接する分だけで、すでに見えている行では動かない。

1. 900px 以上、一覧がスクロールする高さ（1024×700 など）で `すべて` を開き、一覧を先頭まで戻す。
   `acme-dashboard` の見出しメニューからワークツリーを作る。作成後、一覧は新しい行まで動き、
   ワークツリーの見出しと行が見える。行は選択中の面（現在行）になっている。
2. `frontend` のペイン見出しから「新しいペイン」を作る。新しい行がすでに見えているので、
   一覧は動かない（スクロール位置が変わらない）。
3. 390×667 など、新しい行が一覧の外に来る高さで `すべて` を開く。見出しメニューから
   ワークツリーを作る。作成後は詳細が開くので一覧はまだ動かない。`一覧へ戻る` を押すと、
   一覧はその行の下端が一覧の下端に接する位置から始まり、行が見えている。
4. 同じ高さで `アクティブ` を開いてワークツリーを作る。起動が終わって行が現れるのを待ち、
   `一覧へ戻る` を押す。一覧は新しい帯の行が見える位置まで動く。
5. 1280×900 の `アクティブ` で一覧を少し下へスクロールし、見えている帯のメニューから
   「… に新しいペイン」を作る。上へ送るときは、作成した行が貼り付いた帯の下に見える
   （行の中央が帯に覆われない）。
6. 1280×560 の `すべて` の位置を 0 にし、`アクティブ` に切り替えてシェルのペインを
   帯のメニューから作る（`アクティブ` はシェルを並べないので行が無い）。
   `すべて` に戻しても、位置は 0 のままで動かない。

## 分割ビューとセルのタブ

PC の分割は、セル（グループ）ごとのタブと方向つきの二分木で持つ。`hwc-split-view` には `{ current, layout }` を保存し、葉は `{ kind: "leaf", tabs, active }`、全体は最大 4 セル。開いたタブは木から導出し、MRU は持たない。

1. 1600px で `frontend` を開く。セルは 1 枚でセル枠は出ない。上端が 44px のタブ列、その下が見出しになる。タブ列は `frontend` 1 つで、タブの面が選択中。見出しにはペイン名・種類アイコン・現在のスペースが出ず、ブランチ `feat/empty-state`・PR `#481`・ファイル・ID・メニューが出る。
2. `checks` の `review` を一覧から開く。同じセルのタブ列に `review` が増え、`review` が active になる（セルは 1 枚のまま）。`frontend` のタブを選ぶと active が戻る。active と current はこのセルで一致する。
3. 同じセルの中で、`frontend` を `review` の右半分へドラッグする。並びが入れ替わり、active と current は変わらない。タブ列の隙間へ落とすと、同じ位置へ入り、移したタブが active かつ current になる。
4. `review` をそのセルの**右端**へドラッグする。ドラッグ中だけ、タブと同じラベルとグリップがポインタの近くに付いてくる。落とすと 1x2 になり、左セルは `frontend`、右セルは `review` の 1 枚になる。current は `review` で、右セルのタブ面だけが濃い。セルに枠は出ず、区切りは 1px の隙間。
5. 左セルの本文を押す。current が `frontend` に移り、左のタブ面が濃く、右の `review` は淡くなる。一覧の current 行も `frontend` になる。
6. 右セルの `review` を、左セルのタブ列の `frontend` の右半分へドラッグする。右セルが空になって畳まれ、1 セルに戻る。タブは `frontend` → `review` の順になり、`review` が active かつ current。
7. もう一度 2 セルにする。`review` を右端へドラッグする。右セルの `review` を左セルの**中央**へドラッグすると、左の末尾へ移り、右セルが畳まれる。中央のプレビューは「ここへ移動」で、アクセント色の枠になる（4 色は無い）。
8. 端への分割を確かめる。一覧の `shell` の行を左セルの下端へドラッグすると、左セルが上下 2 段になる（「下に追加」）。セルの端は親と直交する向きだけが対象になる（親が row なら上下、col なら左右）。同じ向きのネストになる端はプレビューが出ず、落としても何も起きない。
9. 4 セルまで並べられる。2x2 にしてから、まだ開いていないペインの行をセルの端へドラッグしてもプレビューは出ない。中央へ落とすとそのセルの末尾にタブとして入る。タブ数は無制限で、セルのタブ列は横スクロールする。
10. タブの × を押す。active を外すと同じセルの次（末尾なら手前）が active、非 active を外しても active は変わらない。最後のタブを外すとそのセルが畳まれ、隣のセルが広がる。current を外したときは同じセルの後継、セルが消えたら読み順の次のセルの active（無ければ手前）。タブは幅を詰めながら淡く消え、本文も 180ms で淡く消える。`prefers-reduced-motion` では即時に外れる。ペインは一覧に残り、Herdr 側で動き続ける。ペイン見出しのメニューから閉じた場合も、ペインが消えたスナップショットを待たずに同じアニメーションが出て、終わってから一覧が更新される。
11. 再読み込みする。`{current, layout}` から、セルごとのタブ・active・current が復元される。旧形式（葉が `pane`）の保存値は layout を読まず、current の 1 枚のセルで始まる。
12. 1600px で 2 セル（左 `frontend`、右 `review`、current は右）にしてから 390px に縮める。詳細にはフォーカス中の右セルだけが 1 セルとして出て、左セルは状態に残る。右セルのタブ列だけが見え、戻るボタンがその左端にある（接続が正常でないときは右端に接続チップも出る。PC では戻るボタンを出さない）。1600px に戻すと 2 セルが復元され、current も右のまま。
13. 390px の 1 セル表示でも、タブ列は詳細の上端にある。戻るを押すと current が null になり一覧へ戻る。一覧から別のセルのペインを開くとそのセルがフォーカスされ、投影が切り替わる。分割の操作は出ない。
14. 一覧の行からも同じ落とし先を使える。行をセルの端へドラッグすると分割、中央へドラッグすると末尾への移動。ドラッグ後の click で一覧の行が開き直らない。`すべて` のツリーのペイン行でも同じ。束の見出しのドラッグは並べ替えのままで、分割のプレビューは出ない。
15. 2x2 で、各セルのタブ列（44px）と見出し（56px）の下に会話と入力欄が残ることを目視する。狭いセルでは入力欄が 1 行に畳まれる（既存の container 判定）。タブ列 + 見出しで会話が潰れる場合は、見出しの詰めを別途検討する。

## PR のチップ

PR のチップは、1 枚表示と分割セルのペイン見出し、アクティブ帯のワークツリー見出しに出る。1 枚表示では、狭い画面ではブランチの右、広い画面ではブランチを出さないのでエージェント記号の右に出る。分割セルは自分のスペースの PR を出すので、同じ PR が並ぶこともあれば、別の PR が並ぶこともある。

1. `acme-dashboard` のペインを狭い画面で開く。見出しは `feat/empty-state` と `#481` になる。
2. `#481` をタップすると `https://github.com/example/acme-dashboard/pull/481` が新しいタブで開く。
3. `acme-dashboard (docs)` のペインは `docs/quickstart` だけで、チップは出ない（ペイン見出しに merged は出さない）。
4. 広い画面でも、見出しはブランチ `feat/empty-state` と `#481` を出す。
5. `acme-dashboard` のペインを 1 つ目のセルに、`acme-dashboard (checks)` の `review` を 2 つ目のセルに入れる。1 つ目のセルは `#481`、2 つ目は `#483` になり、それぞれの URL が開く。`checks` のチェックアウトはローカル名 `worktree/review-checks`、push 先は `feat/checks` で、PR は push 先の名前で引いている（ローカル名だけでは `#483` は出ない）。

## HTML のプレビュー

エージェントが本文で示した HTML は、メッセージの下のチップからプレビューのタブで開く（[ファイルの配信](adr/file-serving.md)）。fixture は `docs/preview/` に HTML・CSS・JS を分けて置いている。

1. `frontend` ペインの最後のメッセージにある `mock.html HTML` のチップを押す。そのペインのセルのタブ列の末尾に `mock.html のプレビュー` が増え、タブ列の下がプレビューになる。グリッドは隠れる。
2. iframe の `一覧` を押すと中身が切り替わる（`docs/preview/mock.js` が動いている）。枠・余白・色は `docs/preview/mock.css` が当たっている。
3. ペインのタブ（`frontend`）を選ぶと会話に戻り、プレビューのタブはそのセルの末尾に残る。もう一度プレビューのタブを選ぶと戻る。対象ペインをタブから外すと、プレビューのタブも消える。
4. プレビューのタブの ×（PC は hover / focus、モバイルは常時）と中クリックでも閉じられる。ヘッダーの `閉じる` と同じく、タブが消えてペインのタブが選ばれた状態に戻る。
5. モバイル幅でも同じ手順で全画面になり、ダイアログは出ない。

### 根のラベル

チップの種別欄は、チェックアウトのファイルでは `HTML` のまま、チェックアウト以外の根のファイルでは `HTML · /tmp` のように根を添える。既定の fixture の `mock.html` はチェックアウトにあるので、ラベルは付かない。同じベース名を `/tmp` 側にも置くときだけ、fixture に次を足す。

1. `frontend` の `mock.html HTML` のチップを押す。ヘッダーは `mock.html` で、根のラベルは付かない。
2. `e2e/fixtures/scenario.ts` の `createScenario` で、架空 Herdr の root（`e2e/fake-herdr.ts` の `mkdtemp`）の下、`work/` の外に `mock.html` をコピーする（例: `<root>/tmp-preview/mock.html`）。`work/*` の外に置くのは、他のペインのチェックアウトと解決先が紛れないようにするため。自ペインのチェックアウトの外なので、root 1（`/tmp`）で解決する。
3. fixture のセッションに、その絶対パスを本文に書いた `assistant` のメッセージを 1 通、最後に足す。
4. `bun run e2e:serve` で起動し、`frontend` を開くと、チップが `mock.html HTML` と `mock.html HTML · /tmp` の 2 つになる。ヘッダーは `mock.html · /tmp` になり、iframe の `title` も同じ文字列を含む。
5. 足したメッセージが最後になるので、「HTML のプレビュー」の手順 1 の「最後のメッセージにある」は、その `a7-preview` のメッセージを指すと読み替える。新しいメッセージを `a7-preview` より前に置くなら、この読み替えは要らない。
6. 確認したら fixture の変更は戻す。

### 描けない HTML の案内

HTML が配信できないスクリプトを読み込むと、iframe の上に 1 行の案内が出る。既定の `docs/preview/mock.html` は `./mock.js` だけを読むので出ない。

1. `frontend` の `mock.html` を開く。案内の行は出ず、iframe の `一覧` の切り替えが動く。
2. 案内を出すには、fixture の `docs/preview/mock.html` の script を配信できない参照に差し替える（例: `<script type="module" src="./mock.ts"></script>`）。開き直すと iframe の上に案内が出て、中身は白いままになる。`再読み込み` でもう一度 HEAD を送り、案内は残る。
3. `<script src="./mock.js"></script>` に戻すと、開き直しで案内が消える。CSS と JS の応答自体には案内を出さない。
4. 確認したら fixture の変更は戻す。案内の行が出たままの画面を、他の手順のスクリーンショットに使わない。

`/tmp` は追加根の既定なので、fixture に置いてもチップとプレビューになる（[ファイルの配信](adr/file-serving.md)）。`HWC_PREVIEW_ROOTS` はさらに別の場所を足す設定で、fixture では使わない。追加根の検出と配信は BFF の unit / API テストで確認する。

### 根の外にあるファイルの案内

チェックアウトと `/tmp` の外に書かれた HTML と画像はチップにならず、メッセージの下に 1 行の案内が出る。既定の fixture には置いていないので、確かめるときだけ足す。

1. `e2e/fixtures/scenario.ts` の `createScenario` で、チェックアウトと `/tmp` の外（例: `/var/tmp/hwc-demo/outside/shell-agent.html`）にファイルを作る。
2. fixture のセッションに、その絶対パスを本文に書いた `assistant` のメッセージを 1 通足す。
3. `bun run e2e:serve` で起動し、`frontend` ペインで案内の行を確認する。

確認したら fixture の変更は戻す。案内の行は全メッセージに出る振る舞いなので、既定の fixture に入れると他のスクリーンショットにも写る。

## ワークツリーの概要

一覧のワークツリー見出しには、ブランチの最新 PR のタイトルを出す。チップは open と merged のとき、ツリーのメニューは state を問わない。

1. `アクティブ` を開く。`acme-dashboard` の帯は 1 行目に `Add an empty state to the dashboard` と `#481`、2 行目に `feat/empty-state` が出る。

3. `acme-dashboard (docs)` の帯は 1 行目に `Write the quickstart guide`、2 行目に `docs/quickstart` が出る。チップは `#482` で、緑色のマージ記号が番号の手前に付く（merged）。
4. `すべて` に切り替える。`acme-dashboard` の見出しの 2 行目が同じタイトルになる。`…` を開くと `PR #481 を開く` があり、リンク先が同じ URL である。
5. `acme-dashboard (docs)` の見出しは、タイトルの手前にマージの記号だけが出る（番号は帯とメニュー）。
6. PR の無い `scratch` の見出しは、今までどおりペイン数だけを出す。

5. ファイルツリーを開き、フォルダの行の右端の「…」を開く。フォルダ名の下に末尾が `/` の絶対パスが出て、コピーアイコンでその文字列が入る。同じメニューの `新しいスペース` は、そのフォルダを作業ディレクトリにしたスペースの作成ダイアログを開く。

## ライブ更新

Herdr がイベントを出さない cwd とブランチを、可視中だけ取り直して追う（[Herdr 連携](adr/herdr-socket.md)）。既定は 3 秒で、設定の「ライブ更新」から変えられる。

1. `scratch` の `notes` を開き、ファイルツリーを開く。根が `…/work/scratch` で、実ファイルが無いので「空のディレクトリ」と出る。入力欄に `cd <root>/work` を送る（`<root>` は起動ログの `hwc e2e fixture:` のパス）。何もせずに 4 秒ほど待つと、ツリーの一覧が `acme-dashboard` / `acme-dashboard-checks` / `acme-dashboard-docs` / `plain-checkout` / `sandbox` / `scratch` に入れ替わり、一覧の `scratch` のスペースメニューのパスも `<root>/work` に変わる（再読み込みはしない）。
2. `plain-checkout` の `shell` を開き、`git checkout feat/live` を送る。4 秒ほどで、ペイン見出しと一覧の行のブランチが `feat/live` に変わる。上流が無いので数字は出ない。
3. 設定の「ライブ更新」を開き、「オフ」を選ぶ。設定の一覧に戻ると行の値が「オフ」になっている。`shell` で `git checkout feat/off-test` を送っても、5 秒待ってブランチは `feat/live` のまま。
4. 「3 秒」に戻すと、その場で取り直してブランチが `feat/off-test` に変わる。設定の行の値も「3 秒」に戻る。
5. 設定を閉じて再読み込みしても、選んだ間隔が残る（`localStorage` の `hwc-live-update`）。

## 設定

設定の入口は一覧の足元の歯車 1 つ。開いている間も歯車のままで、面と色で現在地を示す。

1. 900px 以上の幅で、一覧の足元の歯車を押す。設定の左上に「← 設定」のバーが出て、歯車が選択中の色になる。左の列に「設定」の見出しは重ねない。
2. `Esc` を押すと設定が閉じ、焦点が歯車へ戻る。バーの ← でも同じように閉じる。
3. 設定を開いたまま一覧のペインを押すと、設定は閉じてそのペインが開く。焦点は押した行に残る。
4. 900px 未満では、バーの ← も `Esc` も 詳細 → 一覧 → 元の画面の順に戻る。設定を閉じた後、焦点は一覧の足元の歯車へ戻る。
5. 一覧のメニューや、設定の中の確認ダイアログが開いている間の `Esc` は、そちらだけを閉じる。設定は開いたままになる。
6. 「定型文」でフォームを開いている間は、バーの名前が「定型文を追加」「定型文を編集」に変わる。
7. エージェントの行のマークは本家の配色になる。Pi は 3 色（コーラル・青・黄）、Claude はオレンジ、Codex は黒（ダークでは白）、OpenCode はグレーの輪郭と内側のシェード。左の列で Claude を開いて現在地にしても、マークだけはブランド色のまま（面と名前は現在地の色）。同じマークが、一覧の行・ペイン見出し・入力欄のチップ・作成ダイアログのカードでも同じ色になる。
8. 900px 以上の幅で一覧を開いたまま設定を開く。境目の取っ手は出ず、境目の線を挟んだドラッグ（幅の変更）だけが残る。設定を `Esc` で閉じると、取っ手が元どおり出る。
9. 900px 以上で取っ手を押して一覧を畳み、900px 未満へ狭める。詳細が全画面なら `一覧へ戻る` で一覧を出し、足元の歯車で設定を開く。900px 以上へ広げると取っ手が出ており、押すと一覧が開き、設定を開いたまま取っ手が消える。900px 以上で一覧を畳むと足元の歯車は画面外かつ `inert` で触れられないため、畳むのは先に済ませる。

### エージェントのグローバルスキル

設定画面のエージェント詳細は、その CLI がグローバルに認識するスキルを読み取り専用で並べる（[グローバルスキル](adr/agent-skills.md)）。E2E では `HWC_SKILLS_HOME` により、起動ログの `hwc e2e fixture: <root>` の下の `home/` だけを読み、実ホームのスキルは出さない。

1. 設定 → エージェント → Pi を開く。「グローバルスキル 3 件」が出て、押すと由来ごとの見出し（`~/.agents/skills` に 2、`~/.pi/agent/skills` に 1）の下に、`gh` / `review` と `imagegen` が並ぶ。見出しにホバーしても、塗りが角丸からはみ出さない。
2. `review` を押すと、その行に説明が 3 行で畳まれて出る（SKILL.md では `>-` で折り返している）。`gh` を押すと `review` は閉じ、`gh` の 1 行の説明が出る。もう一度押すと閉じる。
3. Claude を開くと「2 件 · 無効 1」で、`xlsx` に「無効」が付き、名前が沈む（`settings.local.json` の `skillOverrides`）。`review` は description を書いていないので、行は押せず矢印も出ない。`xlsx` は押すと説明が出る。
4. Codex を開くと「2 件 · 無効 1」で、`gh` に「無効」が付く（`config.toml` の `[[skills.config]]`）。
5. OpenCode を開くと 3 件で、無効は無い。`review` は `~/.claude/skills` と `~/.agents/skills` の両方にあるが、ID が同じなので登録順で後に来る `~/.agents/skills` の 1 行だけになる。スキルの追加・削除はできない。
6. 一覧を開いたまま別のエージェントへ移ると、一覧は畳まれた状態に戻る。
7. キーボードで見出しや行へフォーカスすると、輪郭は行の内側に収まる。

## ファイルツリーの表示

設定の「表示」で、ファイルツリーの位置・文字の大きさ・幅・アイコンを端末ごとに選ぶ（[状態の置き場](adr/state-storage.md)）。

1. 設定の「表示」を開き、最下部へスクロールする。「ファイルツリーの位置」の下に「文字の大きさ」（小 / 標準 / 大）と「幅」（狭 / 標準 / 広）が並び、どちらも「標準」が選ばれている。「サンプル」に、`invoice-summary.test.ts` などの行が実際のツリーと同じ寸法で出る。幅の下には「アイコン」（なし / 色分け）があり、「なし」が選ばれている。
2. 標準の文字は、設定を足す前と同じ `--text-body`（1280px では 15px、390px では 17px）。文字を「大」、幅を「広」にすると、サンプルの幅が 340px、文字が標準の 1.2 倍（1280px では 18px）になり、行の高さは 44px のまま変わらない。「小」にすると標準の 0.85 倍になる。
3. 1280px の幅でペインを開き、ファイルツリーを開く。ツリーが 340px で会話の脇に並び、行の文字が 18px になっている。見出しの区切り線もツリーの幅に揃う。
4. 1100px へ狭める（セルは 748px）。「広」は並べるのに 340 + 420 = 760px が要るので、ツリーは会話の上に重なる。幅を「標準」（680px で足りる）に戻して開き直すと、並んだままになる。
5. 再読み込みしても選んだ段階が残る（`localStorage` の `hwc-file-tree-size` / `hwc-file-tree-width`）。
6. 「アイコン」を「色分け」にすると、サンプルの行の左に種類の印が出る。`invoice-summary.test.ts` はコードの山括弧、`logo.svg` は画像、`package.json` は中括弧で、それぞれテーマの種類色になる。`src` と `server` は開いたフォルダ（面が薄く塗られる）、`routes` は閉じたフォルダになる。
7. 1280px の幅で `frontend` のファイルツリーを開く。フォルダの行はシェブロンの代わりにフォルダの形になり、開くと形が入れ替わる。`bin` / `docs` / `src` はフォルダ、`.gitignore` と `README.md` は書類、`package.json` と `docs/ci.yml` は中括弧、`bun.lock` は鍵、`src/main.ts` は山括弧で、種類の色が付く。`.gitignore` のような地の色のままの行と、淡色の行には色を付けない。
8. 再読み込みしても選んだ段階が残る（`localStorage` の `hwc-file-tree-size` / `hwc-file-tree-width` / `hwc-file-tree-icons`）。

3. 900px 未満では左右 16px のまま変わらない。

## 通知

設定画面の「通知」から、司令塔の完了と要対応を Discord Webhook へ送る（[Discord 通知](adr/discord-notification.md)）。E2E では `HWC_E2E_DISCORD_WEBHOOK_SINK` により、送信は実 Discord ではなく架空のファイルへ記録する。**実 Discord へは送らない。**

起動ログの `hwc e2e fixture: <root>` が示す `<root>/discord-webhook.jsonl` が sink。送信のたびに `{"content":"..."}` が 1 行追記される。

1. 設定を開く。「通知」は未登録で、Discord の欄に URL 入力と「登録」が出る。スイッチはオフ。
2. `https://discord.com/api/webhooks/1234567890/e2e-discord-token` を入れて「登録」を押す。「登録済み」と末尾 4 文字（`…oken`）だけが出て、URL 全文は画面にも応答にも出ない。
3. 再読み込みして設定を開く。登録済みのまま復元される（`<root>/notifications.json`）。
4. 「テスト通知」を押す。成功の文言が出て、`<root>/discord-webhook.jsonl` に「hwc のテスト通知です。このチャンネルに完了通知と要対応の通知が届きます。」が 1 行追記される。
5. スイッチと「完了通知の対象」を切り替える。「すべての作業」を選んで再読み込みすると、選んだ状態が残る。「要対応の通知は、この対象に関係なく送ります。」が出ている。
6. 「変更」は空の入力から始まり、「キャンセル」で元の登録済み表示に戻る。「削除」は確認のあと未登録になり、スイッチの状態は変わらない。
7. 読み込み失敗は、ブラウザのリクエスト差し替えで `/api/notifications` に 502 を返して確かめる。「通知の設定を読み込めませんでした。」と「再試行」が出て、「未登録」とは出さない。
8. 自動送信は、`acme-dashboard` で通知を有効にし、`/done` を送って親と子を `done` にする。山ごとに 1 回だけ sink に追記され、`done` のまま留まっても増えない。実 Herdr には `/done` が無いので、フィクスチャ専用の入力で確かめる。
9. 要対応は、`acme-dashboard` の `review` を開き、フィクスチャ専用の `/blocked` を送る。`hwc: acme-dashboard が対応を待っています\nペイン: review\nブランチ: feat/empty-state` が 1 行追記される。`/blocked` をもう一度送っても増えない。`/done` で解除してから `/blocked` を送ると、もう 1 行追記される。「完了通知の対象」が「PR がある作業だけ」でも送られる。

## pi の ask_user

mypi の `ask_user` は、セッションの隣の pending `<session path>.ask.json` をカードにし、answer `<session path>.ask.answer.json` で答える（[pi 連携](adr/pi-integration.md)）。E2E では `new`（`w1:p4`、pi、空の会話）の入力欄にフィクスチャ専用の `/ask` または `/ask-text` を送る。架空 Herdr が pending を置いて `blocked` を流し、answer が現れると pending を消して `blocked → working → idle` を流す。

1. `new` を開き、`/ask` を送る。会話の末尾に「pi からの質問」のカードが出て、質問文の改行が保たれ、「そのまま進める」が `推奨💡` 付きで先頭に並び、続いて「いったん止める」「その他（自由入力）」が出る。カードは外側の帯 1 枚で、選択肢は枠付きの箱にせず罫線で区切った行になる。入力欄・引用・添付・`/` の候補は閉じ、「pi の質問です。カードから答えると、入力欄が戻ります。」が出る。
2. 選択肢を 1 つ選んで「この内容で答える」を押す。押した直後に、選んだラベルが「送信中」のユーザーバブルとして出る。「回答を送りました。応答を待っています。」に変わり、3 秒ほどで pending が消えてカードが閉じ、`blocked → working → idle` のあと入力欄が戻る。会話には質問（エージェント）と回答（ユーザー）のバブルが残り、質問には選択肢・選択済み・推奨、回答には「選択肢」または「自由入力」の種別が付く。`<root>/agent/sessions/empty/session.jsonl.ask.answer.json` が、答えている間に `{ "v": 1, "id": ..., "answer": { "kind": "option", "label": "そのまま進める" } }` になっていることを確かめる（架空 Herdr は 3 秒後に消す）。
3. `/ask` で「その他（自由入力）」を選び、textarea に本文を入れて答えると、text 回答になる。`/ask-text` を送ると、カードには選択肢が無く、最初から textarea が出る。改行とタブを含む本文を入れて答えると、answer は `{ "kind": "text", "text": "..." }` になり、前後の空白だけが trim される。空欄では「この内容で答える」を押せない。
4. カードの「端末出力を見る」で端末出力に切り替わり、「会話に戻る」でカードへ戻る。端末出力を見ている間は「pi の応答待ちです。回答は Herdr のターミナルで行ってください。」になる。
5. 回答の送信に失敗したときは、カードに入力と失敗の行が残る（書き込み失敗はブラウザのリクエスト差し替えで確かめる）。同じ質問への 2 回目の送信は 409 になり、answer は上書きされない。

## データを変える

`e2e/fixtures/scenario.ts` を編集する。ワークスペース、タブ、ペイン、端末出力、pi セッション、ブランチはすべてここで作る。`acme-dashboard (checks)`（`w4`）は、別スペースの同名ペイン（`review` と `shell`）を並べるために置いている。`w1` の `review` / `shell` と同じ名前で、スペースだけが違う。

実在のユーザー名・ホスト名・リポジトリ名・パスを書かない。スクリーンショットに写る値はすべて架空にする。

### 実行中のモデルカタログを変える

モデル上限の追従は、起動ログの `hwc e2e fixture: <root>` が示す架空カタログだけを書き換えて確かめる。実際の Pi の agent dir は使わない。

1. `bun run e2e:serve` で起動し、設定画面の revision が `e2e` であることを確認する。
2. `frontend` ペインを表示する。初期データには圧縮後の usage があり、コンテキストは `14k/200k (7.0%)` になる。狭い表示では割合だけになる。
3. 起動ログから得た `<root>` を使い、表示中モデルの上限だけを変更する。

   ```bash
   FIXTURE_ROOT='<root>'
   bun -e '
     const file = Bun.file(process.argv[1]);
     const store = await file.json();
     store.anthropic.models.find(model => model.id === "claude-sonnet-4-5").contextWindow = 1_000_000;
     await Bun.write(file, JSON.stringify(store));
   ' "$FIXTURE_ROOT/agent/models-store.json"
   ```

4. ペインを可視状態に保ち、次のポーリングで `14k/1.0M (1.4%)` に変わることを確認する。working は 2 秒 / idle は 5 秒周期なので、待ち時間は最大 5 秒程度に通信・処理時間を加えたものとする。BFF の再起動・会話 JSONL への追記・ブラウザのリロードは行わない。
5. 同じ操作で `contextWindow` を `200_000` に戻し、上限と割合も元に戻ることを確認する。

override の追加・変更・削除や読み取り失敗からの復旧、ETag の安定性は BFF の unit / API テストで確認する。

### Claude のコンテキスト使用量

fixture の `w2:p2`（`quickstart`）は、mod が書く live ファイル（`<root>/claude/live/<session uuid>.json`）に `context: { tokens: 122_600, window: 1_000_000 }` を持つ（[Claude 連携](adr/claude-integration.md)）。速度は `null` のままで、メーターだけを確かめる。

1. `acme-dashboard (docs)` の `quickstart` を開く。入力欄の左下のモデル表示の横に `123k/1.0M (12.3%)` とバーが出る。390px では `12.3%` だけになる。
2. メーターを押す（PC はポインタを載せる）と、使用量 `122,600` と設定枠 `1,000,000` が出る。
3. live ファイルの `at` は起動時のままなので、表示までの時間が 2.5 秒を超えていてもメーターが出る。速度だけが鮮度で消える（[Claude 連携](adr/claude-integration.md)）。
4. `<root>` の live ファイルを消す。5 秒以内の取得でメーターが消え、モデル表示だけになる。

### blocked + 応答待ちの作り方

応答待ちは、hook が書く sidecar `<root>/claude/pending/<session uuid>.json`（`<root>` は起動ログの `hwc e2e fixture: <root>`）に置く。実機の Claude Code は、待ちの間は transcript に質問の tool_use を書かない（[Claude 連携](adr/claude-integration.md)）ので、transcript は待ちに入る前の会話で終わらせる。fixture の `w2:p1` がこの形で、架空 Herdr のペインを `blocked` にし、`agent_session` は `CLAUDE_PENDING_SESSION`、sidecar は `e2e/fixtures/scenario.ts` の `claudePendingSidecar`、transcript は `claudePendingTranscript`。

1. 質問のカード: sidecar の `pending` を `kind: "question"`（`toolUseId`、`tool: "AskUserQuestion"`、`questions[].{question,header,multiSelect,options[].{label,description}}`）にする。外側の `sessionId`、`at`（24 時間以内）、`toolUseId`、`tool` も要る。読むときに 4 問、1 問 10 選択肢、質問文 2000 文字を超えた分を切り、制御文字を落として改行を空白にする。`questions` が配列でない、`options` が空、`label` が空の `pending` は、カードにならない。
2. 承認のカード: `pending` を `{ "kind": "tool", "toolUseId": "...", "tool": "Bash", "summary": "..." }` にする。要約は 1 行（200 文字まで）で、`Write` の `content` のような input 全体は sidecar にも画面にも載らない。要約を `null` にすると名前だけになる。
3. カードなし: sidecar のファイルを消す、`pending` を `null` にする、`at` を 24 時間より前にする、`sessionId` を別のものにする、のいずれか。解決済みは、transcript に `toolUseId` が同じ tool_result を持つ user entry を足す（Esc は hook を呼ばないので、sidecar が残っていてもカードは戻らない）。`blocked` のまま pending が無い（末尾が user の本文など）と、カードは出ずに端末出力になる。fixture の `w2:p2`（待機）はカードが出ない。
4. フォールバック（実機では使われない）: sidecar が無いときは、transcript の active branch の末尾が tool_result を持たない assistant の tool_use ならカードにする。CLI が待ちの間に tool_use を書く版が出たときのための経路で、E2E では `claudePendingTranscript` の末尾にその tool_use を一時的に足し、sidecar を消して確かめる。確認後に戻す。
5. 表示中に sidecar や transcript を書き換えると、5 秒間隔の取得で次のスナップショットに変わる。実 Herdr では `agent_status` と sidecar がずれる瞬間があるので、カードは `blocked` の間だけ出す。
