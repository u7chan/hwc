アクティブ一覧から
エージェントを閉じる

非ワークツリーの帯（例: tmp）でも、アクティブ一覧の行から直接エージェントを終了できるようにします。 閉じる操作は、ツリーの行と同じメニューと確認ダイアログを再利用します。

課題

アクティブの行は状態を見る面で、閉じる入口は詳細の見出しと「すべて」のツリーだけです。非ワークツリーの帯には 「ワークツリーを削除」もないため、片付けたいエージェントのために画面を移る必要があります。

提案

各行の右端に「…」を置き、ツリーと同じペインのメニューを開きます。最後のペインは 「エージェントを終了」、複数ペインなら「ペインを閉じる」。実行前に既存の確認を挟みます。

適用範囲

ADR 0017 / 0021 を改訂し、全帯の行に「…」を出します。行は読む面のまま、破壊的な操作だけを メニューの奥に置く形です（ADR 0081）。

エージェントを終了しますか？

ペイン w9:p1 のエージェントに終了を要求します。ペインとスペースは残します。

  1. 1 「…」は行の開く操作と別のボタン。押しても行の選択や既読は変えません。
  2. 2 ツリーと同じペインのメニュー。ペイン ID・パス・新しいペイン・閉じるを同じ順で並べます。
  3. 3 最後のペインは「エージェントを終了」。ペインとスペースは残ります。複数ペインなら「ペインを閉じる」。

メニューは帯の上に重なります。確認を押した後は、実際には Herdr のイベントで行の状態が変わります（このモックでは行は動きません）。

4. 入口の比較

「行から閉じる」以外の入口も比べました。行の対象と操作を一致させ、全帯で同じ学習になる点で、行メニューを推奨します。

案 入口 良い点 気になる点
A. 行メニュー 各行の「…」 対象が行と一致する。全帯で同じ操作。既存の PaneMenu / CloseConfirm を再利用できる。 行に操作を足すため、ADR 0017 / 0021 の改訂が必要。
B. 帯メニュー 帯のアイコン 非ワークツリーの帯だけに足せる。 複数エージェントがいると対象が曖昧。行から遠く、どのペインを閉じるか選びにくい。
C. 行に × を常設 行の右端 最短で閉じられる。 破壊的な操作が常に見え、誤タップしやすい。確認の前に触れてしまう。

5. 実装メモ

見た目の提案と、実装の前提です。

行の構造

行を「開くボタン + メニューボタン」に分けます。選択中・スロットの枠は行全体に掛け、メニューを開くだけでは 選択・既読を変えません。ツリーの行と同じ骨格にそろえます。

既存の部品を使う

メニューは PaneMenu、確認は CloseConfirm、 送信は既存の POST /api/panes/:id/close / /exit です。新しい API は要りません。

狭い幅

操作領域は 44px を確保します。幅が足りないときはタブ名、次に時刻を譲ります。タブ名は視覚的に隠すだけで、 読み上げには残します。

適用範囲

非ワークツリーだけに限定すると、同じ見た目の行でも帯によって「…」の有無が変わります。全帯に適用します。 ワークツリー帯は「ワークツリーを削除」と併存します。

ADR の改訂

ADR 0017 / 0021 の「アクティブの行にはメニューを出さない」を、「行は状態を読む面のまま、 破壊的な操作だけをメニューの奥に置く」へ更新しました（ADR 0081）。

決定

非ワークツリーに限定せず、全帯に適用しました（ADR 0081）。同じ見た目の行で操作の有無が変わらず、 ワークツリーの行でも「エージェントを終了」だけを行えます。
