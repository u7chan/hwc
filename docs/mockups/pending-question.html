質問カード — 境界とページ切り替え

いま困っているところ（スクリーンショットから）

  • 会話との境目がない。質問が直前の発話の時刻（21:58）からそのまま続き、区切りは見出しの小さな 1 行だけ。
  • 選択肢の境目がない。行に枠も線もなく、どこまでが 1 つか分からない。説明の「推奨 💡」が別の項目に見える。
  • 押せる面に見えない。細い空の丸だけで、選んだ後の面も薄い。
  • Claude の複数質問が縦に積まれる。3 問で画面 2〜3 枚ぶんになり、どこまで答えたかが分からない。

枠の案（上の「枠」で切り替え）

「カードの中にカード」（外枠＋枠付きの選択肢）は、容器が二重になって AI が作った画面に見えやすい。案4〜6 は容器を 1 階層に絞り、区切りは罫線・面・塗りのどれか 1 つに決める。

  • 案4 罫線 — 容器なし。会話との境目は全幅の罫線、選択肢の境目は行の罫線。選択は行の塗り＋印＋文字色で示す。一番軽く、現行の「面も枠も持たせない」方針に近い。境目が罫線 1 本なので、弱いと感じたら案5。
  • 案5 帯 — 面は外側の 1 枚だけ。会話列の左右いっぱいに広げ、角丸も側面の枠も持たない。中は案4と同じ罫線の行で、箱にしない。境目が一番はっきり。
  • 案6 塗り — 外枠なし。見出しの罫線（会話の「圧縮の境目」と同じ語彙）で切り離し、選択肢は枠の無い塗りの行にする。押せる範囲が塗りで分かる。縦は一番食う。
  • 参考: 案1 タイル・案2 グループ（枠の中に枠）、案3 レール（左の線＋枠付きタイル）。比較用に残しているだけで、採らない。

ページ切り替えの案（「ページ」で切り替え。Claude の複数質問だけに効く）

  • 案A タブ＋確認 — Claude Code のダイアログと同じ。見出しがタブで、どの質問へも行き来できる。最後に確認ページ（答えの一覧。行を押すと直せる）。
  • 案B ステップ — 「2 / 3」と進捗バー。順番に進み、最後のページがそのまま送信。タップ数は少ないが、送る前に見直す場所はない。
  • 共通: 単一選択は選ぶと自動で次へ（上のチェックで切替）。複数選択と自由入力は「次へ」で進む。質問が 1 つのとき（pi の ask_user は常に 1 問）はページを出さない。

採用（実装済み）

  • 枠は案5（帯）。元の「境界がわかりづらい」に一番直接効き、容器は 1 つだけで入れ子にならない。選択肢が罫線の行なので、説明つきの 2〜4 択でも縦が増えにくい。もっと軽くしたいときは案4。
  • ページは案A（タブ＋確認）。Claude 側の「見出し」を活かせ、間違えて自動で進んでも戻れる。確認ページが誤送信の最後の砦になる。 単一選択は選ぶと自動で次へ進む（実装では常に ON）。

実装への影響

  • 変更は src/client/pane/pending.tsx と src/client/styles/parts/chat.css だけ。回答は今までどおり全問まとめて 1 回送るので、契約・BFF・ADR は変えない。
  • 案5 の帯は、会話の左右へ 16px はみ出させる。狭い画面（余白 16px）では画面端まで届き、広い画面では本文の外へ張り出す。広い画面の --hwc-gutter は % を含む式で、子孫の負のマージンでは親と同じ幅に解けないため、余白いっぱいには広げない。 面は --color-content に文字色を 5% 混ぜた色（--color-surface はライトで会話の地と同じ白、--color-raised は一部テーマで補助文字が 3.3:1 まで落ちる）。
  • 持つ state はページの番号だけ。回答済み・未回答・次へ進めるかは選択から毎回導く。
  • 「最初の未回答」「そのページへ進めるか」は純関数にして answer.ts に置き、unit で確かめる（DOM のテストは書かない）。
